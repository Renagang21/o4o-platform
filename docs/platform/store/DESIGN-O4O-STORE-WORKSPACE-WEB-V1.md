## 2026-10-16 고객 안내·제작·수정 흐름 승인 반영

사용자는 조사 제안을 바탕으로 TODO 작성 → 코드·문서 대조 → TODO 수정 → 구현·검증·push를 지시했다.
이번 종료점은 **commit·push이며 PR은 생성하지 않는다.** 기존 네 목적지와 URL·권한·저장 계약을 유지한다.
작업 범위와 점검 후 TODO는 [WO](../../work-orders/WO-O4O-STORE-GUIDANCE-SIMPLIFICATION-V1.md), 실행 근거와 미확인 범위는 [CHECK](../../checks/CHECK-O4O-STORE-GUIDANCE-SIMPLIFICATION-V1.md)를 따른다.

- **고객 화면**: 태블릿은 제목·QR을 가리지 않고 필요한 제품·안내를 눌러 살펴본다. 설명·추가 자료·제품은 하나의 본문 스크롤을 사용한다. 제품·자료 선택은 키보드로도 조작하고 상세는 닫기·Escape 후 원래 선택으로 돌아간다.
- **휴대전화**: 기존 ScreenSet 원본을 사용하되 대기 영상·자기 QR은 제외한다. 관리 이름을 고객 제목으로 노출하지 않으며 고객용 제목이 없으면 기본 제목을 쓴다. 상품에 지정한 기존 QR의 연결 안내는 재스캔 대신 직접 연다.
- **기본 배치**: 기존 키로 `제품·안내 함께 보기`(`corner_information_basic_v1`), `제품 자세히 보기`(`product_focus`), `안내 읽기`(`corner_overview_qr`)를 제공한다. 기존 `product_grid_qr`·`idle_touch_video`는 자동 변환하지 않고 조회·편집·같은 키 저장을 유지한다. 상품 이미지를 사용하지 않는 기존 표시 정책도 유지한다.
- **제작**: 제목·본문·제품을 중심에 두고 추가 정보·대기 영상·배치·관리 이름은 필요할 때 펼친다. 접어도 입력을 보존한다. 공유 제작기는 Store·운영자·공급자의 기존 API/출처를 주입받으며 새 모델·엔진을 만들지 않는다.
- **저장과 재시도**: 중복 저장과 저장 중 닫기를 막는다. 실패 안내는 입력과 함께 유지한다. 헤더 생성 후 블록 저장이 실패하면 같은 작성 세션에서 생성 ID를 재사용한다. 서버 전체 transaction이나 브라우저 재시작 후 재개를 보장하는 기능은 아니다.
- **수정·적용**: 현재 사용 중인 안내에서 제작 화면으로 바로 이동한다. 편집 전에 현재 사용 위치와 저장 영향 범위를 안내하고, 저장 후 사용할 위치를 선택한다. 실제 기기 재생은 저장·적용 설정과 구분한다. 운영 화면에 별도 편집기를 복제하지 않는다.
- **읽기와 대기 전환**: ScreenSet의 제품 상세·자료 상세·확대 QR을 보고 있을 때는 최소 2분 동안 무조작 대기 전환을 유예한다. 이후 초기 대기 화면으로 돌아갈 때 열었던 상세·확대 QR을 정리한다. 일반 화면의 설정된 대기 시간과 legacy 모드는 유지한다.
- **QR 제작**: 기존 자동 주소를 기본으로 사용한다. 주소 변경은 선택 사항으로 접어두며 기존 주소·연결·생성 계약은 유지한다.
- **사이니지**: 재생목록·요일·시간을 중심으로 입력하고 기간·우선순위는 상세 설정으로 둔다. 제목이 비어 있으면 선택한 재생목록에서 관리 이름을 채우되 수동 입력은 보존한다. 요약은 현재 시간의 **일정**이며 실제 기기 재생 완료 표시가 아니다.

AI 대화창·자동 생성·경험 학습은 이번 범위에 없다. 사이니지 즉시 송출 엔진, 새 범용 편집기, 원장 통합, API/DB/권한 계약 변경도 추가하지 않는다.
실계정·실제 매장 기기·인쇄/스캔 검증은 수행하지 않는다. 아래 과거 기획 TODO를 이번 구현 완료 여부로 역해석하지 않는다.

## 2026-10-15 화면 재배치 승인 반영

사용자는 AI 연결에 앞서 현재 기능의 화면 배치부터 정돈하도록 승인했다.
기존 경로·권한·편집기·저장 계약을 유지하고 매장 화면에 다음 배치를 적용한다.
브라우저 검증은 실제 화면 컴포넌트에 합성 API를 연결해 수행했다.
이 절은 아래 최초 초안의 명칭과 첫 화면 배치를 구체화하며 공통 AI 구현·운영 배포 완료를 뜻하지 않는다.

| 목적지 | 첫 화면 | 상세 접근 |
|---|---|---|
| 내 매장 홈 | 업무 시작 → 확인할 일 → 핵심 현황 | 최근 QR 활동은 펼칠 때 조회, 상세 분석은 기존 화면 |
| 상품·거래 | 내 상품 / 공급·주문 | 모집·신청, 사업별 거래·외부 채널은 접어서 접근 |
| 안내 만들기(기존 콘텐츠 작업실) | 새 안내 준비 / 내 안내 / 자료 찾기 | 기존 상품 설명·태블릿·QR·사이니지·POP·블로그 편집기 |
| 매장 운영(기존 매장에서 활용) | 사용 중인 안내 확인 / 적용·출력 / 상담 요청 / 이용 현황 | 게시 설정·스케줄·TV 재생·POP 출력 |

- 목적지 첫 화면의 하위 메뉴와 본문 카드 중복을 제거한다. 상세 화면에는 목적지 복귀와 접힌 전체 업무 진입을 둔다.
- 상위 권한/capability 필터를 통과한 항목만 묶는다. 매장 선택·정보·구성원·이용 사업·My Home 진입은 유지한다.
- 미구현 한국어·다국어 상담 예고 카드는 노출 보류한다. 기존 상담 요청은 유지한다.
- 기존 실기능의 코드·데이터·URL은 삭제하지 않는다. 블로그·POP 등은 미사용으로 단정하지 않고 상세 진입으로 유지한다.
- 통합된 진행 작업 이력은 아직 없으므로 가상 '이어할 일'을 생성하지 않는다. 새 AI 창·새 작업 이력은 후속 범위다.
- 화면 재배치 검증은 [CHECK](../../checks/CHECK-O4O-STORE-WORKSPACE-SCREEN-PLACEMENT-V1.md)에 기록한다.

사용자는 AI를 제외한 화면·기능 정돈을 하나의 개발 묶음으로 완료하도록 승인했다.
최신 `origin/main` `e6202355a`에서 새 작업 트리를 만들고, 미병합 개발 PR #619·#625를 포함해 다음 흐름을 정비했다.
각 화면을 새로운 공통 편집기나 작업 관리 시스템으로 통합하지 않고 기존 저장소·편집기를 재사용한다.

- 내 매장 소유 제품 이용에 서비스 가입 조건을 새로 붙이지 않는다. 소비자 commerce, 공통 Core, 서버 API·DB·의존성 변경은 없다.
- 새 AI 대화창·자동 생성·추천·학습·작업 이력은 만들지 않는다. 기존 외부 도구 보조 기능은 유지한다.
- 검증과 통합 경계는 [AI 제외 업무 흐름 CHECK](../../checks/CHECK-O4O-STORE-NON-AI-WORKFLOW-COMPLETION-V1.md)를 따른다. 실계정·운영 데이터·실기기 검증과 main 병합·배포는 이번 개발 완료에 포함되지 않는다.

## 2026-10-16 후속 안내 업무·공통 AI 진입 승인 반영

사용자는 남은 작업을 TODO·문서·코드로 검증한 뒤 한 묶음으로 개발하고 push까지 완료하도록 지시했다.
이 절은 [후속 WO](../../work-orders/WO-O4O-STORE-GUIDANCE-COMPLETION-V1.md)의 반영 범위이며,
아래 최초 기획이나 앞선 AI 제외 작업의 당시 범위를 소급해서 바꾸지 않는다.

| 업무 | 현재 반영 |
|---|---|
| 사이니지 만들기 | 자료 선택·영상 확인 후 초안 저장. 이름은 첫 자료에서 정하고 필요하면 변경한다. 기존 이름 우선 제작 URL도 유지하고 생성한 대상을 바로 열어 자료를 추가한다. |
| 수정·활용 | 저장된 사본 미리보기·수정 → 별도 게시 확인 → 선택 안내의 일정 작성 → 기존 재생 화면. 현재 일정에서도 같은 안내를 바로 수정한다. 기기 재생 완료를 표시하지 않는다. |
| 실패·복귀 | 확인된 항목 거부는 같은 초안에 미완료 자료만 재시도한다. 응답 유실처럼 결과가 불명확하면 재전송을 막고 저장된 목록에서 확인한다. 일정 입력은 실패·목록 재조회 중에도 보존한다. |
| 원장·재생 | 매장 snapshot 재생목록과 방송 media 재생목록은 합치지 않는다. 기존 일정 수정은 원래 ID 축을 유지한다. 재생 선택에서 전달한 매장 ID는 기존 게시 자료 reader로 읽고, ID 없음(404)일 때만 기존 방송 reader를 사용한다. |
| 태블릿·QR | 선행 세 기본 배치·같은 안내 수정·저장→위치 적용·휴대전화 직접 링크·출력을 유지한다. 인쇄 QR의 주소 유지와 수정 후 휴대전화 확인 안내를 보강한다. |
| 공통 AI 진입 | 내 매장의 네 목적지에서 같은 선택적 대화 UI를 제공한다. 공통 `/api/ai/query`의 question/summary/draft를 사용하며 문맥은 현재 업무 이름·사용자 입력·최근 대화로 한정한다. 직전 질문에 이어 답하고 작은 결과부터 만들도록 요청한다. |
| AI 작업 연결 | 답변 복사와 상위 권한 필터를 통과한 기존 업무 링크를 제공한다. 서비스 지정 경로의 서비스가 우선이며, 서비스 가입 없는 매장 사용자는 기존 일반 O4O 질의를 쓸 수 있다. 서비스 가입·자료 접근권을 부여하지 않는다. |
| AI 격리·실행 | 매장·계정·서비스 전환 시 화면의 대화/입력/지연 응답을 분리한다. 한도·설정 없음·시간 초과·빈 응답을 처리하며 자동 유료 재시도는 없다. 게시·적용·주문 도구를 실행하거나 별도 Task/Memory 원장을 만들지 않는다. |

기존 제작기의 내부 AI OFF 정책·외부 AI 결과 가져오기·직접 작성은 유지한다. 이 추가 UI는 공통 질의 채널의 매장 진입이며
은퇴한 제작형 AI endpoint를 복구하지 않는다. 사용자 간 경험 공유·개인화·게시 도구·비공개 업무 자료 자동 조회는
공통 AI 기반의 별도 계약 범위다. 이번 변경을 그 기능들의 완료나 실계정·실기기 검증 완료로 해석하지 않는다.
검증 결과와 현장 확인표는 [CHECK](../../checks/CHECK-O4O-STORE-GUIDANCE-COMPLETION-V1.md)에 둔다.

## 1. 기획 목표

거래, 자료 준비·제작, 매장 현장 활용을 업무 목적에 따라 구분한다.
정보시스템에 익숙하지 않은 직원도 완성된 자료를 찾아 현장 업무를 수행할 수 있어야 한다.
승인 직원은 매장 업무 전체를 사용할 수 있으며, 쉬운 진입을 제공하는 것이 권한 제한을 뜻하지 않는다.
직원 초대 → 직원 수락 → 경영자 최종 승인 및 접근 해제는 My Home에서 관리한다.

AI는 각 메뉴에 업무 성격에 맞게 배치한다. O4O 전체 공통 AI Core + Extension 정비는 별도 담당 범위다.
O4O 부담 유료 AI 기능을 배제하지 않는다. 기술·사업 변화에 따라 제공 업체와 비용 정책을 변경할 수 있도록 연계한다.
내 매장에서는 공통 AI에 전달할 업무 요구와 문맥을 정의하며 자체 AI Core를 신설하지 않는다.

## 2. 상단 메뉴와 보조 진입

| 상단 메뉴 | 직원이 묻는 질문 | 하위 기능 |
|---|---|---|
| 내 매장 홈 | 지금 할 일이 무엇인가? | 현황, 진행 중인 작업, 업무 바로가기, 자료·기기 문제 안내 |
| 상품·거래 | 어떤 상품을 취급하고 주문할까? | 내 매장 상품, 공급 상품, 모집, 장바구니·결제, 주문 내역, 기존 사업별 거래 진입 |
| 콘텐츠 작업실 | 어떤 자료로 무엇을 만들까? | 자료 가져오기, 내 자료함, 파일·참고 자료, 제작·편집, 번역·다국어, 결과물 미리보기 |
| 매장에서 활용 | 완성된 자료를 어디에서 어떻게 쓸까? | 실행 현황, QR 배치·출력, 사이니지 적용·스케줄·재생, 태블릿 적용, 상담 요청, 활용 분석 |

보조 진입: 매장 선택·설정, 이용 사업, My Home. 신청·가입 상태와 구성원 관리를 억지로 네 업무 메뉴에 넣지 않는다.
모바일은 동일한 네 메뉴를 유지하되 줄바꿈 또는 메뉴 선택 방식으로 제공하고 가로 넘침을 피한다.
상단 업무 메뉴와 현재 업무의 하위 탐색을 구분한다. 기존 전체 사이드바를 그대로 중복 노출하지 않는다.
사업별 상품·주문은 서비스 식별과 권한을 유지한 채 진입시킨다. 메뉴 통합이 거래 원장 통합을 뜻하지 않는다.

## 3. 자료·제작·활용 경계

자료 가져오기 → 내 자료함 → 활용 형태 제작·미리보기 → 매장 적용 → 상태 확인·교체·종료.

- 콘텐츠 작업실: 자료 보관과 제작은 같은 공간. QR·사이니지·태블릿·POP 제작 진입을 함께 제공한다.
- 매장에서 활용: 완성된 결과물을 선택해 사용 위치에 적용한다. 편집이 필요하면 작업실로 이동한다.
- 작업실에서 ‘매장에서 사용’으로 연결하고, 활용 화면의 ‘수정’은 대상 자료를 선택한 상태로 작업실에 연결한다.
- 기능별 사본 화면이나 매체별 상품 설명 원장을 새로 만들지 않는다. 기존 저장·resolve 계약을 활용한다.
- 공급자·사업 제공 원본과 매장 소유 사본을 구분한다. 가져온 독립 사본은 원본 수정에 자동 동기화되지 않는다.
- ‘제작 완료’, ‘게시 상태’, ‘실제 배치’, ‘기기 동작’은 서로 다르다. 공통 상태 이름이 기존 API 상태를 덮어쓰지 않게 한다.
- 현재 게시 자료의 수정 반영 시점은 매체별 기존 계약을 조사해 표시한다. 버전·예약 게시·복구를 이미 지원한다고 가정하지 않는다.
- 인쇄된 QR 링크와 기존 북마크는 메뉴 재배치로 깨뜨리지 않는다.

## 5. 대표 업무 흐름

### 익숙하지 않은 직원: 현장 적용

매장에서 활용 → 완성된 자료 찾기 → QR·태블릿·사이니지 및 사용 위치 선택 → 실제 적용 내용 확인 → 적용 결과 확인.
필수 설정을 순서대로 안내하고, 상세 제작 설정은 필요한 경우에만 작업실에서 연다.
자료 없음, 기기 미연결, 조회 실패를 각각 구분한다. 오류를 빈 자료함으로 표현하지 않는다.

### 제작 담당 직원: 자료 기반 제작

콘텐츠 작업실 → 소유 자료 또는 이용 가능한 원본 선택 → 가져오기/기존 자료 사용 → 목적·언어·형태 선택 → 편집 및 AI 도움 → 미리보기 → 저장 → 매장에서 사용.
기존 편집기로 가능한 범위부터 연결한다. 모든 매체의 편집기를 하나로 합치는 작업은 선행하지 않는다.

### 경영자: 거래와 현장 확인

상품·거래 → 공급 상품·거래 조건 확인 → 주문 → 상품을 대상으로 자료 준비 → 현장 적용 확인.
경영자·직원 접근 범위는 실제 서버 계약을 확인한다. 메뉴 재배치만으로 신규 권한을 부여하지 않는다.

### 향후 한국어·다국어 상담

매장에서 활용 → 직원 보조 상담 또는 소비자 직접 상담 → 사용할 수 있는 매장 자료·언어 선택 → 상담.
상담은 향후 기능으로 기획하며 기존 ‘상담 요청’을 AI 상담이 구현된 증거로 읽지 않는다.
직원 내부 자료와 소비자 공개 자료를 구분하고 소비자에게 비공개 거래·운영 정보를 전달하지 않는다.

## 6. 메뉴별 AI 요구사항 — 별도 담당과의 연결

| 메뉴 | 필요한 도움 | 전달할 문맥 |
|---|---|---|
| 홈 | 현황 설명, 할 일 정리, 업무 이동 | 선택 매장, 접근 가능한 상태·업무 링크 |
| 상품·거래 | 탐색·비교·설명, 주문 준비 | 상품·공급자·사업 식별, 기존 거래 권한 |
| 작업실 | 문구·요약·번역, 활용 형태에 맞는 제작 | 자료 참조, 출처·소유 관계, 목적·언어·형태 |
| 활용 | 적용 도움, 자료 찾기, 상담 지원 | 결과물·배치·기기, 실행 가능한 작업, 상담 공개 범위 |

연결 요구: 매장·사용자·서비스 문맥, 자료 참조, 허용 도구, 결과 저장 대상, 실행 확인, 사용량·비용 정책, 오류 상태.
AI 담당이 정할 계약과 대조한 뒤 연결한다. 이 기획안에서 AI API·스키마·Core 인터페이스를 확정하지 않는다.
AI 미연결 상태에서도 자료 편집과 현장 적용이 가능해야 한다.
유료 호출을 일괄 금지하거나 O4O가 항상 부담하는 구조로 고정하지 않는다.

## 7. 코드·문서 조사 결과와 경계

- 현행 storeMenu.ts는 제품·경영지원·실행·자료함·사이니지·분석·설정과 약국 메뉴를 나열한다. 업무 중심 상단 그룹은 미구현이다.
- StoreLibraryNavigation은 원본/내 사본을 구분하지만 내 자료함 안에 게시·활용 상태도 함께 둔다. 목표 업무 경계에 맞춰 진입 정리가 필요하다.
- 기존 실행 관리 설계는 제작 화면과 운영 화면 분리를 명시한다. 이번 방향과 부합한다.
- StoreExecutionPage는 QR·태블릿 목록을 조합한다. 매장 전체 기기 상태를 완전히 관측한다고 주장하면 안 된다.
- UnifiedStoreLayout의 StoreOwnerOnly 주석에는 과거 상품 화면 설명이 있으나 현행 App의 일반 상품 라우트는 그 가드로 감싸지 않는다. 확인한 실제 전용 적용은 구성원 관리다. 주석과 실제 계약을 구분한다.
- 상품 상세/메뉴 정본에는 과거 HUB·퇴역 서비스·옛 상품 콘텐츠 원장 서술과 정정 절이 혼재한다. 과거 표만으로 메뉴를 복구하지 않는다.
- 소비자 QR·태블릿은 정보 전달이다. 공급자→매장 B2B 거래와 소비자 주문·결제를 혼합하지 않는다.
- UI 배치 정비로 신규 schema, 자료 원장 통합, 기존 Core 재작성, 운영 데이터 변경을 요구하지 않는다.
