## 1. 초기 원칙 — Coverage First

초기 목표는 좋은 설명서가 아니라 **넓은 커버리지**다.

1. 기준 식별축은 **상품명**이다. 바코드·이미지·브랜드 DB는 초기 선정 기준이 아니다.
2. **브랜드 DB를 먼저 만들지 않는다.** 브랜드는 상품 데이터에서 파생되는 값이다.
3. 시장에서 실제 제품임을 합리적으로 확인할 수 있으면 생산 대상이다.
4. 의약품·건기식·의료기기 수준의 승인·안전 게이트를 만들지 않는다.
5. **애매하다는 이유로 쉽게 제외하지 않고, 서로 다른 제품을 억지로 합치지도 않는다.**
6. 공개적으로 접근 가능한 정보만 사용한다. **인증우회·차단우회는 하지 않는다.**

## 2. 후보 수집 기준

### 2-1. 소스와 우선순위 (파일럿 실측)

| 소스 | 상태 | 비고 |
|------|------|------|
| 식약처 의약품안전나라 기능성화장품 보고 | ✅ 사용 | 공개 목록·상세. 모집단 약 180,420건 |
| Olive Young Global best-seller (공개 JSON) | ✅ 사용 | **국문·영문 상품명 동시 제공** — EN 설명서의 유일한 근거원 |
| 화해 랭킹 (공개 SSR JSON) | ✅ 사용 | 카테고리 트리 전 구간. 고유 5,250건 확보 |
| Olive Young Korea | ⛔ 제외 | HTTP 403 봇 차단 → 차단우회 금지 원칙에 따라 **우회하지 않고 제외** |
| YesStyle | ⛔ 이번 제외 | 목록 클라이언트 렌더링, 공개 JSON 미확인 |

**규칙 S1.** 접근이 차단된 소스는 우회하지 않고 제외하며, 제외 사실을 산출물 meta에 남긴다.

### 2-2. 표본 추출

**규칙 S2. 유명제품 위주로 고르지 않는다. 계통표본(systematic sampling)만 쓴다.**

- 기능성: `page[k] = round(k × (총페이지-1) / 49) + 1`, 부족분은 `probe += 37`로 결정론적 보충
- 일반: 화해 풀 전체에 `index = floor(k × pool/need)`

> 파일럿 초기에 화해 결과를 트리 앞부분에서 잘라 썼더니 **스킨케어에 전량 쏠렸다.**
> 풀을 모두 모은 뒤 표본을 뽑는 순서를 지켜야 한다.

### 2-3. 후보 판정 3값

| 값 | 의미 |
|----|------|
| `TARGET` | 시장 실재가 합리적으로 확인됨 → 생산 대상 |
| `UNCONFIRMED` | 데이터 자체가 비어 제품을 특정할 수 없음 |
| `CHECK` | 사람 판단이 필요 (색상/호수·선택형 구성·비화장품 의심) |

**규칙 S3.** 품절이나 공식 홈페이지 부재만으로 `UNCONFIRMED` 처리하지 않는다.
소매 진열 데이터에 존재하면 그 자체가 시장 실재 근거다.

**규칙 S4 (파일럿에서 추가). 뷰티 랭킹 소스는 화장품 전용이 아니다.**
화해·올리브영 상위 노출에 건기식(락토핏·구미·단백질쉐이크)·디바이스·물티슈가 섞인다.
→ **판매처 카테고리를 먼저 보고**(`이너뷰티|건강|디바이스|물티슈|기타`) `CHECK`로 표시한다.
제외가 아니라 CHECK다(원칙 5).

## 3. 설명서 단위 — 상품명 기준

**소비자가 하나의 상품명으로 인식하는 제품 = 1 설명서 단위.**

| 같은 설명서 단위 | 별도 제품 |
|---|---|
| 색상·호수 차이 | 제품 핵심명이 다름 |
| 용량 차이 | Toner / Serum / Cream 등 제품 유형이 다름 |
| 1+1 · 트윈팩 · 번들 · 기획세트 | Tone-up / Matte / Waterproof 등 실제 성격이 다른 별도 제품 |
| 본품 / 리필 | |

**규칙 U1. 애매하면 자동 병합하지 않는다.** 코어명이 **완전히 일치**할 때만 병합하고,
유사하지만 다른 건은 `POSSIBLE_SAME_UNIT`으로 사람 판단에 넘긴다.
→ 파일럿 실측: 병합 6건, 병합 후보 이관 6건. **대량 오병합 없음.**

### 3-1. 상품명 정규화 규칙 (적용 실적 포함)

소매 판매명에는 제품 정체성과 무관한 노이즈가 **체계적으로** 붙는다.

| ID | 제거 대상 | 적용 |
|----|-----------|-----:|
| R01 | 판매채널 전용/단독 표기 `[only 화해]` `(올영단독)` | 30 |
| R02 | 리뉴얼/차수 코드 `(2607)` | 29 |
| R03 | 증정·기획 구성 괄호 `(+티트리 토닉 30ml)` | 93 |
| R04 | 기획·세트·묶음·트윈팩·1+1 | 59 |
| R05 | 용량(영문 단위) `400ml` `50g` | 161 |
| R05K | 수량(한글 단위) `70매` `10포` | 49 |
| R06 | 수량 곱셈 `x2` | 1 |
| R07 | 본품 / 리필 | 6 |
| R09 | 브랜드 접두 (상품명이 브랜드로 시작) | 92 |
| R10 | 선행 대괄호 판촉 문구 | – |
| R11 | 유통기한 괄호 | – |
| R12 | `+ … 증정` 꼬리 | 2 |
| R13 | 구성품 나열 꼬리 (`+` 앞에 이미 제품 유형이 나온 경우만) | 9 |
| R14 | `N종` 구성 표기 | – |
| R08 | 잔여 기호 정리 | 30 |
| C01–C03 | 색상·호수·톤 → **제거하지 않고 `variants`로 보존** | 13 |

**규칙 N1 (파일럿에서 발견). 한글 단위 앞에 `\b`를 쓰면 안 된다.**
JS의 `\b`는 `[A-Za-z0-9_]` 기준이라 한글 뒤에서 성립하지 않아 `70매`·`더블기획`·`본품`이 남는다.
→ `(?![가-힣])`를 쓴다. 이 한 건으로 독립 대조 일치율이 **65.6% → 75.3%**로 올랐다.

**규칙 N2. `+` 뒤를 무조건 자르지 않는다.**
`그린티 + LHA …`처럼 제품명 일부인 경우가 있다. `+` **앞에 이미 제품 유형이 나온 경우에만** 자른다.

### 3-2. 정규화 품질의 객관 지표 — 독립 대조

화해는 판매명(`goods.name`)과 플랫폼 정리명(`product.name`)을 함께 준다.
**판매명만 입력으로 쓰고, 정리명은 우리 결과를 채점하는 독립 기준으로만 쓴다.**

- 대조 353건 / 일치 308건 → **87.3%**
- 일치 판정은 3단계: ① 완전 일치 ② 문자 다중집합 일치(표기 순서 차이) ③ 색상 variant를 되돌린 뒤 일치

**규칙 N3. 판매처가 판매명에 없던 자체 메타데이터를 붙이는 경우**(`[SPF50+/PA++++]`, `(리뉴얼)`,
수식어를 뒤 대괄호로 이동)는 **우리 오류가 아니다.** 대조 함수에서만 보정하고,
그 보정을 정규화 본체에 넣지 않는다.

## 4. 제품 유형 판정

**규칙 T1. 유형은 판매처 카테고리를 먼저 쓰고, 이름 키워드는 보조로 쓴다.**
이름 추측으로만 판정했을 때 미판정 279건 → 카테고리 우선 도입 후 **83건**.

**규칙 T2 (표본 검수에서 발견). 한국어 상품명은 뒤쪽이 핵심어다.**
`… 앰플 마스크`는 마스크다. 먼저 나온 키워드가 아니라 **가장 뒤에 나온 키워드**로 판정한다.

**규칙 T3 (표본 검수에서 발견). 카테고리 마디 중 유형으로 쓸 수 없는 것이 있다.**

- 너무 넓은 상위 마디: `스킨케어` → 이걸 유형으로 쓰면 `벨레다 카렌듈라 베이비 오일`이 토너가 된다.
- 제형 마감 마디: `스틱`·`리퀴드`·`펜슬` → 상위 마디(`컨실러` = 메이크업)가 실제 유형이다.
- 분류축: `매트`·`글로시`·`20대`·`남성` 등

## 5. 최소 설명서

### 5-1. 필수 6항목

브랜드 / 상품명 / 제품 유형 / 한 줄 제품 설명 / 확인 가능한 주요 특징 / 사용방법

**규칙 G1. 빈 항목을 억지로 채우지 않는다.** 필수 6항목이 모두 찬 건만 `COMPLETE`,
나머지는 `PARTIAL`로 두고 **무엇이 비었는지 항목명으로 남긴다.**

### 5-2. 근거 출처를 항목마다 남긴다

| 태그 | 의미 |
|------|------|
| `MFDS_REPORT_EFFICACY` / `MFDS_REPORT_OFFICIAL` | 식약처 보고 공식 원문 그대로 |
| `RETAIL_LISTING` | 판매처 진열 데이터(용량·색상 등 사실값) |
| `HWAHAE_REVIEW_TOPIC` | 브랜드 주장이 아니라 사용자 리뷰에서 반복 확인된 표현 |
| `CATEGORY_GENERIC` | 제품 고유 정보가 아닌 **유형별 일반 사용 안내** |
| `RETAIL_BRAND_PREFIX_MATCH` | 소매 데이터에서 실제 관측된 브랜드명과의 접두 일치 |

**규칙 G2. 유형별 일반 사용 안내를 제품 고유 사용법인 것처럼 쓰지 않는다.**
반드시 `usageSource: CATEGORY_GENERIC`으로 구분하고, 제품별 실제 사용법이 확보되면 대체한다.

### 5-3. Product Highlight

**규칙 G3. 전성분표에서 마케팅 효능을 추론하지 않는다.**
우선순위: 브랜드 공식 표현 > 공식 글로벌 표현 > 주요 판매처 제품 설명 > 시장 반복 표현.

### 5-4. 영어 설명서

**규칙 G4. 공식 영문명이 없으면 영어 설명서를 만들지 않는다.**
한국어 상품명을 임의로 영역하지 않는다. 제품명·성분명·수치·사용방법·주의사항 같은
사실정보는 어떤 경우에도 새로 만들지 않는다.

## 6. 파일럿이 드러낸 구조적 한계 (V0 시점 정직한 기록)

### 6-1. 식약처 기능성 보고 데이터만으로는 최소 설명서가 완성되지 않는다

**보고 데이터에는 소비자 브랜드가 없다.** 있는 것은 책임판매업자(법인명)뿐이다.
→ 기능성 단위 459건 **전건 브랜드 결측**. 소매 데이터에서 관측된 브랜드명과의 접두 일치로
회수한 것은 25건(5.4%)뿐이다.

**규칙 L1.** 기능성 census는 **소매 데이터와 짝지어야** 소비자용 설명서가 된다.
보고 데이터 단독으로는 "규제 정보"이지 "설명서"가 아니다.
브랜드는 추측으로 만들지 않고, 관측된 브랜드명과 접두가 일치할 때만 회수한다.

### 6-2. 영어 설명서의 병목은 번역이 아니라 공식 영문명 확보다

902 단위 중 공식 영문명이 있는 것은 92건(10.2%)뿐 — 전부 Olive Young Global 출처다.
→ EN 커버리지를 늘리려면 **영문명을 함께 주는 소스를 늘리는 것**이 유일한 길이다.
