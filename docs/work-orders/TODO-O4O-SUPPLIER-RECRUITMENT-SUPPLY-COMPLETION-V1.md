## 조사 후 확정 계약

- 일반 공개 모집의 기존 가격 미확정 상태를 보존한다. 새 UI는 현재 Neture 일반 모집만 생성하며 공급가를 명시적으로 입력한다. 구 클라이언트의 공급가 없는 생성 요청과 기존 이력은 유지한다. 기존 복수 서비스 API 계약은 가격을 생략한 경우 유지하되, 가격을 포함한 요청에 Neture 이외 대상이 섞이면 전체 거부한다.
- 기존 Neture 일반 모집은 공급자 상세에서 미확정 공급가를 한 번 확정한다. 현재 화면의 확정가 수정 기능은 만들지 않는다. 이는 과거 확정 가격을 일괄 변경하거나 새 장기 가격 정책을 정하는 작업이 아니다. 이전 서비스·협업체 모집을 일반 공개로 재분류하지 않는다.
- 기존 integer 컬럼의 범위인 1~2,147,483,647원만 허용한다. 공급자가 입력한 금액만 사용하며 소비자가/일반 상품가·수수료로 추정하지 않는다. 공급자 본인·active supplier guard와 모집 소유권, 일반 모집/서비스/모집중 상태를 확인한다.
- 기존 행 잠금으로 동시 최초 확정은 하나만 반영한다. 같은 가격 재확인은 성공, 다른 가격은 409다. 응답 유실 후 입력을 보존하고 동일 금액으로 확인한다. 충돌은 최신 모집 정보 확인을 제공한다. 마감/재개·노출 검토는 부분 필드만 갱신해 확정가를 덮어쓰지 않는다.
- 상세 조회의 기존 users/organization_members UUID와 신청자의 문자열 ID JOIN 오류를 canonical DB에서 재현·수정한다. 새 원장·migration은 없다.
- 약국의 기존 공급 SQL·장바구니·checkout을 재사용한다. 가격 확정이 참여 승인·매장/제품 공급 자격을 만들지 않는다. 기존 주문의 가격 snapshot은 보존한다. 미확정 수취 주체/실 PG 정책은 이번 작업으로 결정하지 않으며 실결제 완료를 선언하지 않는다.
- 실제 계정·기기·PG/은행 왕복은 유예된 운영 검수로 남긴다. 정산 알림 실패 복구는 이번 가격/주문 연결의 필수 경로가 아니므로 기존 정산 결과·알림 정책을 변경하지 않는다. AI 작성 기능은 수정하지 않는다.
