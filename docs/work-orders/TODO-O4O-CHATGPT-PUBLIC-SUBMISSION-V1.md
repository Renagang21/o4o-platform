## 3. 로컬·사용자에게 필요한 잔여 작업만 인계

다음은 기존 운영 연결을 다시 만들거나 전체 smoke 10개를 반복하라는 지시가 아니다. 이미 끝난 PR·배포·검증을 재실행하지 않는다.

1. **기존 시험 기록 cleanup 확인**: 비공개로 보관 중인 시험 연결 식별자를 사용해 남은 연결·자격·요청 기록의 수를 읽기 전용으로 확인한다. 새 승인 요청을 반복하지 않는다. 기록이 남아 있으면 API 프로세스 실행·cleanup 조건·만료 이력을 조사하고, 임의 SQL 삭제나 새 DB 변경을 하지 않는다. 확인한 시각(Asia/Seoul)·잔여 건수·다음 조치를 기존 CHECK에 추가한다.
2. **로컬 소유 자원 정리**: 시험 전용 Chrome 창만 종료하고, PR #794 포함·로컬 clean·보존할 파일 여부를 확인해 자신의 worktree/branch를 저장소 절차로 정리한다. 다른 세션 자원은 변경하지 않는다. 이 클라우드는 로컬 PC의 파일·프로세스를 직접 제어하지 못한다.
3. **OpenAI 계정 작업**: 사용자가 직접 신원·운영 주체 인증을 하고, 소유할 조직/프로젝트를 확인한다. 도메인 challenge의 정확한 주소·토큰을 확인한다. 로그인 자격·토큰을 채팅이나 Git에 전달하지 않는다. 도메인 challenge 응답의 최소 구현·검증은 값과 경로가 확정되면 이 클라우드에 맡길 수 있다.
4. **운영 주체 결정**: 인증된 developerName, 실제 지원 페이지와 접수 담당, 최종 로고, 제공 국가를 확정한다. 개인 계정 별명·임의 지원 메일·임의 사업자 정보를 대신 입력하지 않는다.
5. **정책·심사 접근 확인**: 준비 자료 §8의 문안을 현재 게시 정책과 대조해 운영 주체가 확정한다. 심사자가 즉시 사용할 수 있는 샘플 계정 접근 방식은 기존 인증 경계 안에서 정한다. 계정 발급·합성 자료 생성이 필요하면 구체 범위·보관·정리 계획을 확정한 뒤 진행한다.
6. **영상·등록용 5+3 시험**: 준비 자료의 합성 자료와 대본으로 실제 심사 계정에서 시험하고 촬영한다. 자료·계정 정보는 비공개 심사 입력란으로 관리한다. 공개 자료에는 환자·고객·실사용자의 정보를 포함하지 않는다.

운영 주체·브랜드·지원 담당·정책 문안은 사용자 결정이 필요한 항목이며, 파일 작성까지 로컬에서 해야 한다는 뜻은 아니다. 확정한 공개 정보·브랜드 자산·영상 URL을 받으면 manifest 완성·ZIP 조립·정적 검증과 실제 challenge 응답 구현은 이 클라우드에서 이어간다. 로컬에만 가능한 실계정·브라우저·현재 운영 DB 확인을 넘기고, 준비 문서·패키지 작성은 중복 요청하지 않는다.

로컬 보고는 각 항목의 결과·미확인 이유·공유 가능한 산출물 위치만 전달한다. 코드 수정이 발견되면 근거와 변경 범위를 확인하고 표준 개발·검증 절차를 따른다. 현재 기능에 문제가 없으면 추가 기능 개발·운영 배포를 하지 않는다.
