대량 실행은 기존 pending/reviewing 후보 상태·검토 노트만 변경하는 기능이다. 상품 정본·식별자 생성, 실제 운영 후보 변경, 알림 발송, 운영 배포·migration은 실행하지 않는다.


## 구현·검증

- 순수 표시용 분류는 DB 상태를 바꾸지 않는다. 현재 수집기의 상수로 확인한 식약처 의료기기·의약외품·건강기능식품·e약은요 4개 출처의 external_api 자료만 별도 풀로 표시한다. 일반 외부 API 요청·출처 미지정 후보는 운영 검토에 유지한다. 원본 검증 flag·식별자 누락·등록 경로·다음 작업을 안내한다. 의료기기는 약품 분류의 미상 대신 의료기기로 표시한다.
- 운영 검토 대기 합계에서 수집 자료를 분리했다. 수집 자료는 pending/reviewing 모두 등록 전 자료로 유지한다. 원래 pending 상태나 rawPayload를 데이터 정비로 일괄 재작성하지 않는다.
- 목록·요약·사전 확인·실행은 같은 서버 필터와 서비스 범위를 사용한다. 출처/사유/대량 등록 조건은 전체 범위에 적용된다. 중앙 관리자·Neture 호스트는 neture+공통 후보 범위를 고정한다. 다른 서비스 요청은 서버에서 거부한다.
- 검색 전체 선택은 표시 페이지와 독립적이다. 확인 시 DB 시각·row xmin·사용자·필터·작업·검토 기록을 fingerprint로 묶고, 실행 때 행 잠금 하에서 대조한다. 이는 인증 토큰이 아니라 동시 변경 감지용 지문이다. 인증·역할·현재 중앙 위임은 매 요청 기존 guard가 재검증한다.
- 사전 확인 이후 새 후보는 제외한다. 변경된 후보가 있으면 전체 작업이 409로 중단된다. 만료 10분, 최대 100,000건, 잠금 3초/statement 30초 제한. 단일 트랜잭션의 집합 UPDATE로 처리하며 재실행은 이전 지문으로 통과하지 않는다.
- 검토 시작은 pending만, 보완 기록/보관/반려는 pending·reviewing이면서 Master에 연결되지 않은 후보만 대상으로 한다. 보완·반려 기록은 필수이며 기존 검토 노트는 덧붙여 보존한다. 원천 데이터·정식 상품·식별자는 일괄 작업에서 변경하지 않는다.
- 등록 검토는 기존 의약품·공급자 단건 API와 전체 관리자 write guard를 재사용한다. 의료기기 등 일반 등록 경로 미지원 데이터에는 그 사유를 표시한다. 새 공공 의료기기 등록 정책·Gate B apply는 구현/실행 범위가 아니다.
- 직접 소비처: 관리자 중앙 후보 화면, Neture operator 후보 화면. 기존 관리자 상품 DB drawer도 공급자 등록 Adapter를 재사용한다. 문의함 `OperatorInbox`의 업무 카드는 수집 준비 자료라는 별도 이름/링크를 유지하며 대기 합계를 별도로 계산하지 않음을 확인했다. 다른 서비스 공통 UI/권한/메뉴는 변경하지 않는다.
- 로컬 PostgreSQL: 22 tests PASS(전용 schema). 가상 후보 10,021건 전체 갱신, 다른 서비스·설명 수집 namespace·등록 완료/연결 후보 제외, 새 후보 제외, 동시 변경/재실행/다른 사용자/다른 필터 거부, 노트 보존, HTTP 인증/위임 경계 확인.
- 관리자 UI 24 tests + Neture API 범위 2 tests PASS. 데스크톱 1440px·모바일 390px 합성 브라우저: 대기 합계/자료 분리, 12,000건 전체 선택→필수 기록→대상 확인→단일 실행, 본문 가로 넘침 없음 PASS.
- API·관리자 타입 검사, 관리자·Neture 빌드, 공통 패키지 빌드 확인. ESLint 신규 error 없음(기존 ref cleanup warning 유지).
- CI의 기존 disposable PostgreSQL job에 새 전체 선택 회귀 테스트를 추가해 중요 DB 검증이 skip 상태로 끝나지 않게 한다. CI·Codex 지적 보완 및 최종 기술 gate는 PR 상태를 기준으로 완료한다.
