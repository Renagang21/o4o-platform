# 기존 상품·설명서 편집과 갱신 검토 연결 V1

> **상태**: COMPLETED · **작성일**: 2026-10-25
> **범위**: 일반 상품 수정 및 관리자 설명서 저장의 실변경을 갱신 검토로 연결. 조사·구현·검증·push를 한 번에 수행. PR·main 병합·배포·운영 데이터 변경·AI 확장 제외.

## 조사·구현 계약

- 일반 기본정보 수정은 NetureCatalogService.updateProductMaster, 관리자 설명서 저장은 createCandidate→setCanonical에 모여 있다.
- 기존 인증·역할·상품 보호 필드·설명서 유형/언어 계약을 유지한다. 공통 DB 관리자의 갱신 화면 접근 권한을 서비스 관리자에게 추가하지 않는다.
- 상품명·브랜드명·규격·원산지·태그·분류·브랜드 참조·의약품 분류의 실제 저장 값이 바뀌었을 때만 기존 canonical 유형·언어별 갱신 검토를 생성한다. 설명서가 전혀 없으면 STORE/ko의 미등록 설명서 검토를 남긴다.
- 관리자 설명서는 본문/요약의 실제 변경을 기준으로 한다. 첫 등록도 검토 대상으로 남기고 같은 본문·요약 재저장은 정본을 교체하거나 갱신 작업을 추가하지 않는다.
- 편집과 변경 근거·갱신 작업·알림은 같은 transaction에서 저장한다. 실패하면 원본 변경도 rollback한다. 동시 동일 저장과 응답 유실 후 같은 값 재저장은 중복 작업을 만들지 않는다.
- 일반 편집은 보정 승인 작업으로 위장하지 않는다. 별도 변경 이벤트·실제 경로·처리자·전후 값을 기록하고 갱신 이용 목적은 미지정 상태에서 관리자가 선택한다.
- 설명서 연동은 관리자 직접 저장 경로에만 명시적으로 적용한다. 공급자 후보 제출·일괄 수집·다른 검수 정책을 자동 확대하지 않는다. 상품 직접 SQL 전체 감지나 과거 데이터 backfill은 없다.
- 최신 main 23717b6dc0에 미병합 선행 c88dbaf014를 포함했다. startup의 신규 초대 보관 worker와 기존 상품 worker를 모두 보존해 충돌을 해결했다. main에는 쓰지 않았다.
