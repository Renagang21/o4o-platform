## 코드·문서 대조와 확정 구현

- CertificateService는 발급→수강 enrollment 연결을 별도 save하고 폐기·갱신에는 감사 저장이 없다. 폐기 body.reason은 controller에서 버린다.
- 기존 Certificate의 user/course unique와 발급 1회 정책, renew의 현재 시각 기준 만료 갱신·재활성화 정책을 유지한다. 자동 발급 조건은 변경하지 않는다.
- 개인정보 보유 정본과 privacy-retention.service의 action_logs 365일 집행을 확인했다. 신규 schema/보유 정책 없이 action_logs에 업무 사유와 최소 상태/행위자/대상/시각을 저장한다. 일반 로그에는 사유를 출력하지 않는다.
- 운영 이력은 기존 requireLectureOperator + course.serviceKey=lecture 경계 아래 별도 조회로 제공한다. 기존 본인 전용 수료증 조회·PDF와 공개 진위 필드에 우회 권한을 추가하지 않는다.
- row lock+동일 transaction 감사로 쓰기 실패 롤백, request ID 재시도로 갱신 중복 반영을 방어한다. 일반 PATCH의 유효성/만료 수정도 감사에서 빠지지 않게 한다.
- 과거 처리 이력을 소급 생성하지 않는다. 이력 없음은 미발급/미처리 증거로 표시하지 않는다. 중앙 관리자·다른 서비스는 확장하지 않는다.
