## 완료 기준

정상 확인·근거 대기·보류·검토 완료를 구분하고 다음 작업 시점을 확인할 수 있다. 같은 범위·원문에서 중복 작업을 만들지 않으며 실패한 점검은 정상으로 표시하지 않는다. 기준 변경 전 작업은 당시 기준을 유지한다. 실제 상품 테이블 쓰기를 차단한 격리 DB에서도 전체 흐름이 통과해야 한다. 운영 실데이터를 테스트 보정하지 않는다.

## 구현 확인

- 기존 preview는 조회 전용으로 유지하고 새 runs API가 페이지 실행 기록을 저장한다. 원본 선택 검증은 최신 값과 다시 비교한다.
- 실행과 작업 버전은 별도 settings key로 저장한다. 같은 상품을 동시에 선택한 요청은 기준 행 잠금 후 기존 작업으로 연결된다.
- 현황은 사용 중인 기준의 상품·기준별 최신 작업을 집계한다. 기준 변경은 과거 완료를 덮어쓰지 않고 재점검 조건으로 분리한다.
- DB statement timeout과 오래된 실행 복구를 지원하고, 늦은 응답의 과거 이력 덮어쓰기를 조건부 저장으로 방지한다.
- 대량 전수 순회·예약 실행·상품 반영·외부 AI 호출은 구현하지 않았다. 수동 결과 페이지가 전체 상품 검토 완료를 의미하지 않음을 화면·문서에 명시했다.

## 검증 결과·인계

- API Jest 95개 통과: 기존 공통 상품 DB 권한 계약, 신규 조회·쓰기 경로의 권한·입력 검증, PostgreSQL 통합 8개 포함.
- 관리자 Vitest 11개 통과: 기존 작성·선택·저장 흐름, 검토 종료·날짜 입력, 작업 재사용·저장 이력, 실패 실행 재시도, 현황 조회 실패·오래된 응답 무시.
- 격리 PostgreSQL 15에서 상품·설명서 테이블 쓰기 금지 trigger와 작업 전후 전체 내용 비교 통과. 동시 선택·완료일 재저장·기준 버전 보존·도래 필터·과거 메모 수정·중단 복구 후 늦은 완료 요청 경합을 검증했다.
- `@o4o/types` build, API 및 admin TypeScript 검사, admin Vite build 통과. 변경 파일 ESLint 오류·경고 없음.
- Chromium 합성 fixture 1440px/390px: 검토 완료·다음 점검 표시, 기존 작업 재사용, 근거 대기·재확인일 저장 후 새로고침·재개, 저장 이력, 실패 실행 재시도 통과. 페이지 오류·가로 넘침 없음. 운영 실계정 smoke는 실행하지 않았다.
- 문서 링크·민감정보·diff 검사 확인. 기획안의 후속 구현 안내와 현행 보정 작업 운영 문서를 함께 갱신했다.
- 기존 개발 branch `wo/product-correction-workspace`에 연속 작업으로 commit·push한다. main이 앞선 상태에서 자동 merge/rebase하지 않으며 통합 담당에게 인계한다. PR/CI·병합·운영 배포는 실행하지 않는다.
- 실제 상품 데이터가 없는 합성 fixture 환경과 본 세션 전용 DB container만 테스트에 사용한다. 테스트 DB·임시 서버는 검증 후 종료한다. 개발 checkout은 후속 수정용으로 유지한다.

후속 범위는 원본 반영(P2), 예약 점검(P3), AI 실행(P4), 대량 점검 cursor·전용 운영 저장소 설계다. 이번 push가 이 범위의 구현이나 배포 완료를 뜻하지 않는다.
