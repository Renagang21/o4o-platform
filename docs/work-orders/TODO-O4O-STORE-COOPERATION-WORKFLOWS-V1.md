## 조사 후 보완 근거

- 주요 목적지는 취급상품/내 자료함을 먼저 열고 공급·제공 자료·모집은 접힌 메뉴에 둔다. 상세 화면에는 `BusinessTabs`가 있지만 공급/자료의 가입 조회 실패를 빈 목록으로 바꾼다.
- 공급 화면의 `source` 하나가 사업과 공급 종류를 동시에 표현해 종류 탭을 누르면 사업 선택이 해제된다. 사업 탭을 우선하고 종류는 보조 조건/표시로 정돈한다.
- 약국 조직 신청의 일반 공개 모집은 기존 사용자 단위 bridge를 실행하지 않는다. 공급 옵션의 모집 경로는 사업 가입을 JOIN하므로 일반 공개 모집의 명시 조건 연결이 누락된다.
- 사본에는 이미 `semiFranchiseKey/Name`이 있으므로 새 출처 원장이나 동기화 batch가 필요하지 않다. 조회는 불변 snapshot 출처를 사용한다.
- 현재 `pharmacy-payment.service.ts`는 test/disabled를 구분하고 live PG는 거절한다. 이 상태를 실결제 완료로 표현하지 않는다.

## 최종 보완과 결과

- 가입 조회는 Store 로컬 훅·탭으로 묶고, 계정/선택 약국별 세션에서 읽는다. 서비스 미가입 매장의 소유 컨텐츠에는 약국 가입 조회를 실행하지 않는다.
- 담기·참여 신청·주문 취소 실패를 목록 조회 오류와 분리했다. 중복 실행을 막고 실패 시 같은 상품/모집과 입력 수량·선택 협업체를 유지한다.
- 제공 자료와 내 사본 사이를 이동할 때 협업체 조건을 보존한다. 편집 후 출처 표시는 사업명을 우선한다.
- 일반 모집 생성은 현재 `supplyUnitPrice`를 입력하지 않는다. 가격이 없는 모집은 기존 표시·신청을 유지하고 주문 조건 확인 필요로 남긴다. 공급자 공급가 입력·확정은 후속 범위이며 이번 변경이 신규 모집의 실주문·실결제를 완성했다고 주장하지 않는다.
- 별도 정기 동기화 batch·사업별 복제 원장·원본 자동 동기화를 추가하지 않았다. 기존 원장의 자격/공급 SQL과 사본 provenance를 요청 시 조회한다.
