## 목적과 경계

경영자·직원의 PC/모바일 읽기 전용 점검에서 확인한 운영 오류, 상품 목록의 과도한 세로 배치, 안내 작성 후 상품 문맥 유실을 고친다. 상품 한 개의 기존 정보·연결된 안내를 확인하고 기존 편집기로 이어간다.

현재 URL·선택 매장·서비스·기능 이용 자격·직원 접근·소비자 commerce 금지와 공급자 B2B 계약을 유지한다. 공통 Core/API 계약·DB·의존성을 변경하지 않는다. 실제 업무 데이터 저장·유료 AI·기기 변경은 하지 않는다.

## 조사 후 확정한 구현 범위

- 운영 화면은 링크를 기능별로 거르면서 태블릿 조회를 항상 실행해 `SERVICE_FEATURE_REQUIRED`를 발생시킨다. 제공되지 않는 자원은 요청하지 않는다. 권한을 풀거나 서비스 가입을 추가하지 않는다.
- 상품 화면은 주요 등록 버튼을 유지하되 여러 보조 메뉴가 모바일에서 목록을 밀어내지 않게 배치한다. 기존 업무를 제거하거나 가짜 진입점을 추가하지 않는다.
- 상품 작성 진입은 현재 URL과 매장/서비스에 속한 복귀 문맥을 전달한다. 취소 시 상품 목록으로 복귀하고, 자료함 직접 작성의 기존 동작은 보존한다. URL이나 이름을 접근 권한 근거로 쓰지 않는다.
- 브라우저 뒤로에도 선택을 복원하도록 출발 history entry에 같은 문맥을 기록한다. 상품 진입에서 저장·기존 안내 편집으로 이동할 때 중간 작성 entry를 교체해, 뒤로 이동 시 빈 작성 모달이 재개방되지 않게 한다.
- `handledProductContentApi.byProduct`, `storeDescriptionApi.list`, `getLocalProduct`를 재사용한다. O4O 설명은 읽기 전용, 매장 직접 등록 설명은 기존 필드·편집 경로를 유지한다. 연결된 안내는 기존 direct/snapshot 편집 route로 연다.
- 새 안내 작성을 시작하면 참조 영역은 접고 제목·본문 편집으로 집중시킨다. 접기/펼치기로 참조 정보를 재조회하지 않으며, 선택 태그도 접어 둔다. 직접/사본 편집의 명시적 복귀 링크에서는 미저장 내용을 확인한다.
- 공통 AI는 현재 화면·이전 대화 기반 동작을 유지한다. 서버가 질문·응답·contextData를 사용자 기준 이력으로 저장하므로 상품 정보 자동 첨부·편집기 응답 적용은 매장 정보의 소유·이력 접근·보존 기준 확인 후 별도 연결한다. 이번에 별도 AI/Memory/Task/이력 저장소를 만들지 않는다.
- 기존 RichTextEditor·저장·productRef·저장 후 QR/매장 활용 경로를 재사용한다. 저장과 실제 게시·출력·기기 반영을 구분한다.

## 검증 경계

변경한 실제 화면을 합성 API로 PC·모바일 검증하고, 지연·실패·권한 없음·빈 결과·대상 전환을 구분한다. 운영 실계정은 앞서 승인된 읽기 전용 범위만 가능하며, 이번 코드의 배포 전 실사용 완료로 보고하지 않는다. 자격정보·운영 응답·실제 계정/매장/상품 식별값은 기록하지 않는다.

## 문서 정합

콘텐츠 제작 구 정본의 `product_ai_contents`·구 POP/내부 AI 표현은 최신 상품 소유권·후속 완료 기록과 차이가 있다. 이번 WO는 기존 저장소와 현재 공통 AI만 사용하며 정본 판정을 변경하지 않는다.
