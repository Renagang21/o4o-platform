## 사용자 확정 기준

업무 대상(회원/콘텐츠)이 아니라 조치의 성격으로 나눈다. operator는 회원 승인·반려·서비스 이용 정지/해제·포럼 중지/재개·콘텐츠 일상 처리를 맡는다. admin은 영구 삭제·데이터 병합·서비스 전체 설정 등 제한된 관리 조치를 맡는다. 서비스 admin과 전체 관리자는 다르다. 사용자 추가 지시로 전체 활성 서브도메인·협동조합·약국 협력사업의 메인/개별 사업 운영자와 약사회 분회까지 조사·정비 범위에 포함한다. 플랫폼 전체 관리자 구현은 다른 담당자의 트랙을 유지한다. 동일 계정의 서비스 간 권한을 자동 전파하지 않는다.

### 4.2 구현 기준 보완

- 기존 보호가 있는 펀딩·공통 회원 경계를 임의 재작성하지 않는다. 가입 종료(soft)·가입 관계 삭제(hard)를 활동/첨부파일까지 지우는 완전 삭제로 표시하지 않는다. 법정·감사 보존 및 전 서비스 identity 삭제는 별도 범위 확정이 필요하다.
- 포럼은 새 중지에서만 복구 추적을 남기고, 기존 archived 게시글을 추측 복원하지 않는다. 현재 권한 확인 뒤 원장/게시글·감사를 한 transaction에 둔다. 이미 있는 admin 영구 삭제 진입은 보존한다.
- 상품의 휴지통 복구는 ‘휴지통에서 복원(비활성 유지)’이며 재승인/재게시를 자동 수행하지 않는다. 대량 병합의 부분 성공은 명시하고 재시도 전에 읽기 복구를 강제한다.
- 공급 조직 governance는 상품 승인/진열까지 바꾸는 기존 계약이다. 이를 회원 정지와 같은 버튼으로 operator에 열지 않는다. 현재 상태/역할 서비스의 transaction 지원을 재조사하고 부분 저장 원인을 제거한다.
- 일반 자료 감사의 기존 best-effort 정책 전체를 일괄 변경하지 않는다. 이번 영구 삭제/병합/포럼 상태 전이에는 필수 감사를 transaction에 포함한다. 일반 자료의 이력 보장 강화는 별도 명시 항목으로 남긴다.
- 이번 단계에서 메인/지역 operator를 구분할 실제 관계가 없는 곳은 전체 접근 권한을 추측 부여하지 않는다. 소속 사업/분회 기반 정상 경계 회귀와 누락된 메인 운영 계약을 분리한다.

### 4.3 구현 중 추가 재대조 (추가 코드 변경 전 기록)

- 공급자 역할 서비스는 이미 `EntityManager` 인자를 받는다. 별도 ‘부분 성공/복구 API’를 만들기보다 상태·조직·역할·감사를 같은 transaction에 넣어 원인을 제거한다.
- 공통 회원 삭제 controller의 ‘아무 서비스 admin’ 검사를 선택 서비스 admin 검사로 좁힌다. 앞단 정책도 같은 제한을 하지만 controller를 직접 재사용할 때도 지켜야 한다.
- KPA 전용 회원 관계 삭제는 audit와 `memberRepo.remove`가 기존 queryRunner 밖에서 실행된다. 동일 manager로 옮기고, 공통/전용 가입 정리 모두 활성 운영 tier 대상의 가입 삭제로 중앙 역할 보호를 우회하지 못하도록 차단한다.
- 삭제 사전 위험도 API의 전 서비스 게시글 건수는 실제 삭제 범위가 아니다. Neture 확인창은 명시 서비스 상세 확인 + 실제 가입 정리 범위를 표시하며, KPA 확인창도 활동 전체 제거와 구분한다.
- 주문 상품 식별자는 `neture.neture_order_items.product_id`, 통합 주문 `checkout_orders.items[].productId`이고 현재 계약에서 Offer ID다. 상품 완전 삭제는 이 이력과 장바구니 연결을 제거하지 않고 차단한다. 새 결제·환불·은행 조회 기능은 추가하지 않는다.


### 4.4 최종 모바일 재확인 보완

가입 정리 확인창의 실제 모바일 스크린샷에서 KPA admin 본문의 가로 overflow를 확인했다. AdminLayout의 flex 본문 최소 폭을 0으로 제한하고, 긴 가입 정리 확인창은 viewport 안에서 스크롤하도록 공통 확인창 panel을 보완한다. AdminRoutes 소비처 구조를 확인하고 Neture/KPA의 PC·390px/844px 확인창·취소·테이블 진입을 재검증한다. 운영 범위·권한을 바꾸는 조치는 아니다.

| 포럼/강의 외부 첨부 정리 | 기존 relational purge와 이번 tx/audit는 외부 object storage 첨부를 완전 제거하지 않음 | 소유·공유 참조 추적, 삭제 큐·실패 재처리·잔존 확인. 외부 삭제를 DB transaction rollback으로 복구할 수 있다고 가정하지 않음 |
| 자료·기존 일괄 조치의 이력 보장 | 일반 자료 audit hook과 일부 기존 심사는 best-effort | 조치별 필수/보존 이력 판정 후 같은 transaction 또는 실패 재처리 보장. 이번 작업이 모든 기존 감사 경로를 원자적으로 바꾼 것은 아님 |
| 실제 PostgreSQL 동시성·삭제 및 운영 검증 | 이번 검증은 합성 API/transaction 대역·브라우저 fixture 중심 | 명시 승인된 격리 DB에서 FK/CASCADE·감사 실패 rollback·동시 승인/삭제·동시 병합·역할 지정/정리 경쟁 검증, 통합 담당의 PR/CI/운영 확인 |

상품 hard delete는 확인된 주문 스냅샷/장바구니 참조가 있으면 차단한다. FK 없는 JSON 참조에 새 주문이 동시에 생기는 경쟁까지 이 변경으로 해결됐다고 보고하지 않는다. 포럼 재개는 감사에 기록한 게시글 ID와 보관 당시 수정 시각이 모두 일치할 때만 복구한다. 중지 후 수정된 글과 감사 보존기간이 지난 추적 없는 글은 그대로 둔다.
