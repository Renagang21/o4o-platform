## 실행 계약

- P2 상품 반영 transaction에 상품/유형/언어별 설명서 재검토 작업을 연결한다. 전문인·AI 지원·QR 이용 목적을 관리자가 지정하고 수동 종료한다. QR 공식 DB 채택 보류·매장 제작물 경계를 유지한다.
- 대량 점검은 최초 후보 UUID 모집단을 고정해 25개 단위 cursor로 나눈다. 실행 중 추가 상품은 다음 실행 대상이며 현재 조건을 벗어난 상품은 제외 수로 기록한다. 후보 점검 완료와 사람의 검토 완료는 구분한다.
- 한 실행 최대 50,000개다. 초과 범위를 몰래 자르지 않고 거부하여 상품군/검색으로 나누도록 한다. 중단·재개·취소·실패 재시도와 기록을 보존한다.
- 기준 snapshot 고정. 실행 도중 기준 변경은 경고하고 기존 결과를 최신 기준 결과로 바꾸지 않는다. 선택 작업 생성 시 기존 최신 기준 검사를 유지한다.
- 예약은 기본 꺼짐, 관리자가 명시적으로 생성한다. 한국시간, 간격·최초 예정일 관리. DB 행 잠금/SKIP LOCKED와 회차 고유 key로 다중 인스턴스 중복을 방지한다.
- 기존 in-process scheduler 패턴을 재사용한다. 인스턴스 실행 중 tick/부팅 시 처리하며 상시 외부 cron 보장은 없다. 마지막 tick·지연·누락 회차를 화면에 노출한다. 누락 회차는 한 번으로 합치고 수를 남긴다.
- 실패는 최대 3회 자동 재시도 후 관리자가 재개/취소한다. 일시 중지는 자동 재개하지 않는다. 장기 열린 실행이 있으면 같은 예약의 다음 실행을 중복 생성하지 않는다.
- 알림은 관리자 전용 화면 내 보관·확인 처리다. 이메일·Slack·외부 발송은 없다. 알림 확인이 실제 작업 완료를 의미하지 않는다.
- 모든 신규 관리 API는 platform:super_admin. 기존 settings namespace만 확장하고 migration/운영 상품 보정/AI 호출은 없다.
