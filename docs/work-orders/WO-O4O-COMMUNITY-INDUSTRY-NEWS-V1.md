## 최소 구현 경계

기존 cms_contents의 community-editorial 예약 범위와 초안을 재사용한다. AI 일일 실행 예약/결과도 같은 비공개 예약 범위(kind=news-review, status=draft)에 저장하여 새 테이블·migration·queue·추천 플랫폼을 만들지 않는다. 기존 공통 AI Core·관리자 모델 설정·원자 quota·사용량 기록을 사용한다. 운영 데이터·실계정·실제 유료 모델 호출로 테스트하지 않는다. 수집 차단을 다른 프록시/실행 채널로 우회하지 않는다.

## 2026-10-21 구현·검증 결과

## 남은 외부 연결

실제 세 매체 요청은 2026-10-21에도 프록시 CONNECT 403이다. 런타임 허용 목록에서 데일리팜·약사공론은 확인되지만 접속은 거부되며 메디파나(`medipana.com`, `www.medipana.com`)는 목록에 없다. 환경 설정 적용 후 각 사이트의 제공 피드/API·수집 허용 경로를 실제 확인해야 한다. 검증되지 않은 RSS 주소나 HTML 선택자를 추정하여 수집기를 만들지 않는다. 환경 접속 문제가 해소되면 제공된 제목·요약의 수집·중복 방지·정기 실행을 별도 후속 작업으로 연결한다. 이 외부 연결은 아래 사용자 지정 1단계 배포와 구분한다.

사용자가 커뮤니티 뉴스의 main 병합·배포를 지시했다. 등록한 기사 초안 정리 기능을 우선 출시하며, 자동 기사 수집·정기 실행은 미구현으로 남긴다. PR #748을 최신 main과 통합한 뒤 CI·자동 리뷰·배포 판정 및 서빙 결과를 확인한다. 기존 실제 수집 차단 기록은 당시 관측이며 오늘 재검증한 것으로 간주하지 않는다. 실제 운영 DB 데이터 생성·삭제나 유료 AI 호출 테스트는 이 통합 검증에 포함하지 않는다.

## 2026-10-23 수집·정기 실행 구현 검증

- 각 매체가 첫 화면에 선택한 주요 기사 제목·제공 부제·원문 링크만 최대2개 수집한다. 새로운 매체나 기사 상세·본문은 요청하지 않는다. 공개 RSS도 확인했으나 별도 CDN 연결 없이 검증한 첫 화면을 사용한다.
- robots.txt → 안내된 대기 → 첫 화면 순서로 고정 출처에만 요청한다. 15초 timeout·robots 100KB/HTML 2MB·redirect 금지이며 레이아웃 변경과 매체 장애는 빈 결과 성공으로 숨기지 않는다.
- 수집 예약을 네트워크 요청 전 커밋하고 한국 날짜별로 공유한다. 수집된 원문 URL을 정규화하여 기존 뉴스·다음 날 수집과 중복 저장하지 않는다. 실패 매체는 별도 상태로 표시하고 다른 매체 결과를 유지한다.
- 기존 startup/종료에 앱 내 30분 tick을 연결했다. 한국시간08시 이후 첫 가동/tick에서 그날 수집·AI 초안 정리를 준비한다. Cloud Run min-instances=0인 기존 배포 정책은 바꾸지 않아 상시 시각 실행을 보장하지 않으며, 서비스 가동 시 일일 예약으로 보충한다. 별도 scheduler 인프라·상시 인스턴스 비용을 추가하지 않는다.
- 시스템 실행은 실제 운영자 계정을 가장하지 않는다(createdBy/userId NULL). AI 전역 활성화와 기존 platform/service quota를 확인하며 운영자 실행과 같은 일일 AI 예약을 사용한다. 공개 요청 경로에 수집·AI 호출을 넣지 않으며 자동 게시·공개 전환은 없다.
- 운영자는 뉴스 탭에서 수집 상태/매체별 신규 건수·일부 장애를 보고 직접 수집할 수 있다. 조회는 외부 수집/AI를 실행하지 않는다. 검토 패널에서 기존 편집 초안에 적용 후 저장·게시한다.
- 실제 외부 읽기: 세 사이트 첫 화면/robots HTTP200, 실제 collector가 매체별2개·총6개 제목/링크를 추출함을 확인. 관리형 클라우드 CONNECT에는 테스트 도구에서만 proxy agent를 주입했으며 프록시 정책을 우회하지 않았다. 운영 코드의 Axios·parser는 기존 의존성을 재사용한다.
- API 정책/예약/transport/AI adapter/job 23개, 격리 PostgreSQL 홈/수집/예약16개, HTTP 인증/무캐시/actor 위조 차단3개, 웹14개 테스트 통과(합계56개). 유료 모델은 mock이며 운영 DB 쓰기 없음.
- 공유 패키지 빌드·API 타입 검사·웹 production build·ESLint·cognitive complexity15·문서 민감정보·diff 검사 통과. 기존 번들 크기/Browserslist 경고는 유지한다.
- Chromium 실제 빌드 + 합성 API로 PC1440/모바일390 홈·수동 수집·일부 매체 실패·AI 초안 적용을 확인했다. JS 예외·가로 넘침0. 운영 Google 로그인 검증으로 간주하지 않는다.

문서 정합: 과거403/수집 미구현 기록과 사용자 보류 이력은 당시 상태로 보존하고, 오늘의 접속 해소·수집 구현 및 정기 실행의 가동 조건을 구분했다. 최종 CI·리뷰·main·배포 상태는 확정 후 후속 기록한다.

수집 UI 후속 회귀: 늦은 수집 응답이 편집 중인 제목·본문을 초기화하거나 다른 탭/페이지의 목록을 덮어쓰지 않도록 현재 목록 범위를 확인해 목록만 갱신한다. 패널 종료 뒤에는 갱신 callback을 실행하지 않는다. 웹14개·build·lint·complexity 검증 통과.
