## 최초 조사 근거

기존 HUB는 KPA 가입 대기/Neture 상품 승인 통계 두 개만 집계하며 작업 목록이 비면 수집 실패와 무관하게 모든 서비스 정상으로 표시한다. 콘텐츠 0/0도 실제 집계 없이 기본값을 표시한다. 권한 할당과 서비스 운영자는 같은 사용자/역할 원장을 투영한다. 관리자 계정은 전용 안내와 달리 neture:admin/operator도 조회해 모든 역할을 표시한다. 추가 지정 기능이 서비스 계정을 후보로 쓰므로 목록 필터만 좁히면 정식 전체 관리자 지정 동선이 사라지는 문제까지 함께 조사한다.

## 조사 후 확정한 작업안

- 상태 대상은 PHARMACY_COLLABORATORS 4곳 + 현행 독립 서비스 5곳 + 대표 홈/내 매장/전체 관리자 3곳, 총 12개 공식 HTTPS 주소다. 서비스 identity나 사업 활성 원장을 새로 만들지 않는다. 예전 sites 기반 monitor는 복구하지 않는다.
- 서버 소유 allowlist만 점검하며 사용자 URL·인증 cookie/token을 외부로 보내지 않는다. redirect를 따라가지 않는다. HTML 크기/시간/동시성 제한, 동일 origin 앱 JS 응답, 60초 결과 재사용으로 반복 부하를 제한한다. 로그인/서비스 식별/업무 실행은 미검증으로 표시한다.
- 상태의 원장은 기본 접속 점검 결과다. 가입 대기·승인율·콘텐츠 수·업무 trigger는 제거한다. 실패/미확인/오래된 결과를 정상으로 표시하지 않는다.
- 전체 관리자 목록/표시 역할을 platform:super_admin으로 제한하고 정식 추가 지정 API를 기존 사용자 후보 검색과 연결한다. 서비스 계정의 공통 활성 변경은 이 endpoint에서 거부한다. 본인·마지막 관리자·Google·Demo 보호는 유지한다.
- 서비스 관리자·운영자는 서비스별 역할만 표시하고 기존 지정/해제 계약을 유지한다. 전체 관리자는 별도 화면에서 관리한다. 권한 할당 메뉴/옛 URL은 통합하며 기타 기존 역할의 회수 기능은 접힌 보조 영역에 보존한다. 일반 회원 가입·업무 처리는 서비스 책임이다.
- 공용 패키지 변경 없음. admin 메뉴/config의 다른 소비처와 기존 관리자 계정 화면의 두 진입 경로를 함께 대조한다. 역할 원장 변경·자동 migration/backfill·운영 권한 회수는 하지 않는다.
