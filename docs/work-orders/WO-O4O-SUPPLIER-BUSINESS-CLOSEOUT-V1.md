## 조사 후 보정한 범위

- 재시도 식별자는 기존 supply_proposals.id(UUID)를 사용한다. 동일 공급자·요청자·정규화 조건만 같은 응답으로 재사용하며, 동일 UUID의 변경 payload는 409다. transaction advisory lock + 기존 PK로 동시 요청을 보호한다. requestId 생략 호출은 종전처럼 별개 제안 생성이다. 새 table/column/migration 없음.
- 계정+서버 확인 공급자별 sessionStorage에 같은 탭에 작업 사본을 보관하고 마지막 사용 후 24시간 이내 사본만 복원한다. 전송 직전 동일 requestId/조건을 기록하고 응답 불명 상태는 수정 없이 같은 요청으로 확인한다. 새 내용은 접수 목록 확인 후 별도 초안으로 명시 전환한다. 보관 실패·범위 조회 실패는 화면에 알리고 메모리 입력 경로를 유지한다.
- 약국 검색은 본인 기존 제안 응답의 대상 ID/이름으로 한정한다. 신규 약국 ID 지정은 유지한다. 전 약국 검색 API·타 공급자 거래정보·협업체 active 가입 검증을 새로 만들지 않는다.
- 기존 비AI 정비 완료 범위는 중복 구현하지 않는다. 주문·배송·재고·정산 및 콘텐츠·프로필은 관련 회귀와 실제 격리 DB 테스트로 다시 확인한다. 운영 업무 round-trip은 생성/정리 대상과 운영자 승인이 없으므로 이번 push의 완료 근거로 주장하지 않는다.
- 공용 pharmacy-management API 타입에 optional requestId만 추가한다. 호출처 census: Neture의 공급 제안 초안·목록, 약국 입력 선택지·이벤트 및 테스트. KPA/Store/협동조합의 operator API와 기존 제안 심사 화면 동작은 불변이다. CHECK에 소비처·검증 결과를 남긴다.
