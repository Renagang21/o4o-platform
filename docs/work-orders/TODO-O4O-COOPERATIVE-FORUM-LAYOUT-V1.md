## 조사 후 보완 (기준 main `5c6150a6b0`)

- 일반 포럼은 businessKey → communityKey의 기존 게시판 API를 재사용한다. 일반 회원 글쓰기와 운영자의 게시판 개설 화면을 분리한다. 별도 커뮤니티 가입은 만들지 않는다.
- 운영자 게시 공간은 기존 `semi_franchise_contents`의 자체 작성·공급자 승인 원장을 재사용한다. 회원 화면은 기존 showcase API의 게시·노출된 content만 표시하며 제품 카드는 서비스 화면으로 분리한다. 별도의 공지 테이블이나 일반 포럼 글에 표시만 붙이는 방식은 사용하지 않는다.
- showcase API는 게시 날짜·공지 분류·고정 여부를 제공하지 않는다. 이번 홈은 운영자가 정한 진열 순서의 주요 소식·자료를 표시하며, 독립 공지 분류·상시 고정 기능이 구현되었다고 표현하지 않는다.
- 홈은 주요 소식·자료 → 최근 조합원 이야기의 본문과 참여 상태·운영 진입의 보조 영역으로 정리한다. 비회원에게 회원 데이터를 요청하지 않는다.
- 기존 `/materials`, `/community`, `/operator?tab=contents` 및 콘텐츠 편집 URL을 유지한다. 운영 메뉴의 선택은 URL에 남겨 직접 진입·뒤로가기를 지원한다.
- 공통 운영 UI에는 허용 탭을 하나씩 전달해 콘텐츠·공급 업무를 분리한다. 공통 패키지는 수정하지 않는다.
- 최근 main에 추가된 연합회·개별 조합 Hero 편집을 보존하여 해당 운영 메뉴에 연결한다.
- 조합 admin의 가입 기준·operator 관리는 별도 설정 업무로 분리한다. 일반 operator에게 설정 편집을 노출하지 않는다.
- 연합회도 조합 심사 업무·연합회 operator 관리·홈 편집을 구분한다. 산하 조합 admin 지정은 기존 조합별 상세에서 유지한다.

## 구현 결과

- 일반 게시판의 글쓰기와 운영자 게시판 개설을 각 참여 화면·운영 업무로 분리했다.
- 공식 소식·자료의 별도 목록·직접 상세와 홈 요약을 연결했다. 제품 및 hidden 항목은 공식 목록에서 제외한다.
- 홈의 본문·참여 안내, 내부 화면의 간결한 조합 제목, 모바일 상단 메뉴를 정리했다.
- 연합회/조합 운영 메뉴를 업무별로 분리하고 선택한 업무만 연결한다. 기존 역할·승인 API는 유지한다.
- 별도 공지 분류·고정, 댓글·수정·삭제·중재 화면은 이번 구현 범위가 아니다. [설계의 제한](../design/DESIGN-O4O-COOPERATIVE-FORUM-LAYOUT-V1.md)을 참조한다.
