## 완료 계약

기준 수정 → 대상 점검 → 상품 선택 → 근거 확인 → 승인·선택 반영 → 설명서 갱신 검토 → 다음 점검을 기존 관리자 권한 안에서 이어간다. 이미 배포한 P1/P2·정기 작업을 재구현하지 않는다. AI·QR 공식 DB 채택 보류·기존 승인 경계를 유지한다.

- 기준 초안 4종(함량/기준량, 포장/총량, 제품 고유 사용법, 전문 참고 근거)을 편집 가능한 미저장 입력으로 제공한다. 운영 seed·자동 기준 등록·상품 오류 확정은 하지 않는다.
- 상품별 현행 기본정보·정본 원문/출처·기존 검토·구조화 근거/변경안·반영 이력·설명서 갱신을 제한된 페이지 조회로 연결한다. 기존 적용 API와 쓰기 권한을 그대로 사용한다.
- DB 기반 tick 중복 방지·실패/성공 heartbeat·재시작 후 cursor 복구를 보완한다. API 서버가 쉬어도 별도 실행 가능한 한정된 one-shot worker를 API 이미지에 포함한다. 기존 migration runner나 공개 HTTP 작업 endpoint를 재사용하지 않는다.
- 독립 worker는 기본 무실행/help 경로와 명시적 실행 옵션을 두고 시간·tick 예산 및 graceful stop·DB 정리를 제공한다. 운영 Cloud Run Job/Scheduler/IAM·비밀·배포 설정 자체는 변경/실행하지 않고 인계 안내만 준비한다. 외부 호출이 실제로 설정되기 전 정시 실행을 보장한다고 표시하지 않는다.
- 50,000개 합성 상품의 대량 점검·중복·실패 복구·원본 불변을 격리 PostgreSQL로 검증한다. 검증 수치와 한계를 CHECK에 기록한다.
- guide는 최신 배포 사실과 이번 미병합 변경을 구분해 갱신한다. 과거 WO/CHECK 본문은 소급 재작성하지 않는다.
