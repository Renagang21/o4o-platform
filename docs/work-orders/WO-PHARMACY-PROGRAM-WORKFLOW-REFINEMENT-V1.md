## 조사 결과와 경계

실제 대상은 `packages/operator-core-ui/modules/pharmacy-management`의 기존 협력사업 업무다.
Neture는 전체 담당 사업, 약국 사업자 웹은 businessKey=pharmacy와 자체 게시판 주소로 소비한다.
소비처는 Neture App의 wrapper route와 KPA Society App의 직접 route 두 곳이며 약사회 분회는 없다.
새 서비스 간 공통화를 추가하지 않고 기존 공유 모듈 안의 책임을 정리한다.

현재 OperatorSemiFranchisePage(635줄)는 담당 사업·5개 탭 조회·심사·표시를 함께 소유한다.
confirm/prompt 사유는 저장 실패 시 사라지며 재시도 때 다시 입력해야 한다.
조회 예외는 쓰기 예외와 분리돼 있으나 성공 후 조회 실패임을 더 분명하게 안내할 수 있다.
기존 조회 sequence와 사업/탭 전환 방어, 동기 중복 guard, 실패 목록 재조회, 403 서버 담당 판정은 보존한다.
콘텐츠 폼(216줄)은 읽기 오류 재시도·보관 잠금·이전 저장의 이동 방어를 이미 갖추었으므로 재설계하지 않는다.

모집 조건 승인은 담당 운영자, 참여 승인은 공급자의 기존 approveApplication이다.
운영자에게 공급자의 참여 승인 권한을 새로 만들지 않는다. 이벤트 가격 수정 API도 없다.
게시 콘텐츠는 활성 사업 가입 약국의 원본에 보이며 기존 내 매장 사본은 독립 사본이다.
운영자 처리 후 서버의 기존 이용 가능 판정이 참여자/내 매장 목록을 결정한다.
API/DB/권한·결제·이벤트 2단계 수동 인덱스 전환·실계정 쓰기는 이번 범위에서 제외한다.
