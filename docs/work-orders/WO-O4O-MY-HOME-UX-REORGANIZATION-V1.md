## 문제와 결과

모아보기는 역할별 첫 업무만 보여주고 직원 관리 폼이 업무 진입보다 앞서 있다.
여러 공간을 이용하는 사용자가 이름으로 목적지를 찾고 다시 방문할 수 있도록,
현재 접근 가능한 업무·참여 공간을 검색·즐겨찾기·최근 이동으로 정리한다.
개인의 전체 공간이며 매장 하나를 골라 개인 서비스까지 제한하는 구조가 아니다.

## 확정 범위

- 모아보기 순서: 내 업무 바로가기 → 최근 알림/매장 직원 및 초대 → 상세 화면 진입.
- PC는 알림과 초대를 두 열로, 모바일은 한 열로 제공한다. 기존 공통 헤더·탭·URL을 유지한다.
- 업무 진입은 현재 home-entry 모델의 실제 목적지만 사용하며 공간 이름·업무 분류·선택 안내를 표시한다.
- 공간 검색, 즐겨찾기 최대 6개, 최근 이동 최대 4개와 최근 이동 지우기를 제공한다.
- 저장은 브라우저·계정별 식별자 배열만 사용한다. 서버 동기화·토큰·이동 URL·개인정보 원문을 저장하지 않는다.
- 현재 접근 가능한 모델과 매번 대조한다. 저장 실패/손상 시 기본 탐색과 현재 화면의 설정 변경은 유지한다.
- 내부 링크 선택과 handoff 발급 성공을 최근 이동으로 기록한다. 도착·업무 완료 기록을 주장하지 않는다.
- 직원 관리 폼은 접힌 상태로 시작하고 펼칠 때 선택 매장의 회원/구성원을 조회한다.
  받은 초대 수락·거절·승인 대기 확인은 접힌 상태와 매장 없는 사용자에게도 제공한다.
- 선택 영역의 대상 매장을 표시한다. 기존 명시적 Store 재선택·서버 권한 판정을 유지한다.
- 별도 조회 실패·재시도, 계정/매장 변경과 늦은 응답, 뒤로가기 복구를 검증한다.

## 사용자별 이동 시나리오

| 사용자 | 진입과 다음 행동 |
|---|---|
| 일반 회원 | My Home → 개인 커뮤니티/참여 공간 검색·진입, 상세 기록은 기존 활동·참여 서비스 |
| 단일 매장 경영자 | 내 업무 바로가기의 매장명 → 기존 Store handoff; 직원 관리는 My Home에서 펼침 |
| 복수 매장 경영자 | 각 매장 이름으로 구분·고정 → 기존 목적지의 매장 선택 → 실제 운영 |
| 매장이 없는 초대 직원 | 모아보기의 받은 초대 → 수락/거절, 수락 뒤 승인 대기; 매장 개설을 요구하지 않음 |
| 공급자 겸 개인 이용자 | 현재 이용 가능한 공급자 업무와 개인 참여를 같은 목록에서 구분해 선택 |
