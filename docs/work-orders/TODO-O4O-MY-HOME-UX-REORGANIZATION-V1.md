## 1. 목표와 진행 방식

My Home은 사람 기준으로 여러 서비스와 업무 공간을 찾고 이어가는 출발점이다.
현재 화면을 기능별로 조금씩 덧붙이기보다, 정보구조·상태·대상 매장 표시를 먼저 정리하고
합의된 한 묶음을 구현·검증·PR로 제공한다. 구현 내부는 작은 단계·집중 검증으로 진행한다.
일괄 개발은 전체 변경의 무검증 일괄 배포를 의미하지 않는다.

이번 회차는 TODO와 문서·코드 대조를 작성한다. 아래 개발안은 검토 초안이며 현행 정본을 대신하지 않는다.
개발 시점의 최신 main에서 대조를 갱신한 뒤 대상·수용 기준을 고정한다.
대표 홈, 개인 My Home, 매장 업무, 사업 참여 공간의 소유·권한 경계를 유지한다.

## 4. 한 번에 개발할 범위의 권장안

### 기본 묶음 — 기존 계약으로 가능한 재구성

- 업무 목적지를 찾기 쉬운 위치에 배치하고 매장명·사업명·업무 구분을 함께 표시한다.
- 확인할 알림·초대와 상세 관리 화면을 시각적으로 구분한다.
- 직원 초대·승인·해제 기능은 My Home 안에서 계속 접근 가능하도록 한다.
  기본 요약/접힘 방식과 빈 초대 영역의 노출 조건은 설계에서 확정한다.
- 참여 서비스·개인 활동·경영 현황·계정 설정의 탐색을 일관되게 정리한다.
- 개인/선택 매장 조회 범위와 이동 후 재선택 안내를 명확히 한다.
- 계정·매장 변경, 조회 실패, 빈 상태, 뒤로가기 복구를 포함해 완성한다.

### 확장 후보 — 개발 범위 고정 전에 저장 방식을 결정

즐겨찾기와 최근 이용은 UI 배치만으로 생기지 않는다. 기본 묶음과 함께 넣을 경우 아래 계약을 먼저 확정한다.

- 저장은 초기안으로 현재 브라우저·계정별 개인 설정을 검토한다. 기기 간 동기화는 별도 범위다.
- 저장 대상은 현재 진입 모델의 식별자만 사용한다. 인증값·handoff 발급 URL·일회성 코드·개인정보 원문을 저장하지 않는다.
- 표시할 때 현재 접근 가능한 EntryItem과 다시 대조한다. 탈퇴·정지·권한 해제된 목적지는 다시 노출하지 않는다.
- 저장 거부·손상·계정 전환·초기화에서도 기본 탐색이 정상 동작한다.
- 목적지 이동 클릭을 최근 기록으로 남기면 “최근 이동”으로 명명한다.
  목적지 도착·업무 재개가 관측되지 않으면 “최근 완료”나 “이어할 작업”으로 주장하지 않는다.
- 고정 개수와 순서, 중복 제거, 초기 상태, 최근 항목 지우기, 키보드 조작을 설계에 명시한다.

새 DB/API·서버 동기화가 필요해지면 기본 묶음에 조용히 포함하지 않고 별도 요구사항으로 분리한다.
이미 있는 모든 권한 있는 목적지를 기본 탐색으로 제공하는 것은 즐겨찾기 부재 때문에 막히지 않는다.
