## 확정 흐름

대상 선택/이메일 → 초대 발송 → 본인 확인·수락 → 일상업무 전체 기본 제공 → 필요 시 담당 업무 변경·저장. 전체 관리자/서비스 Admin·독립 사업 내부 권한은 부여하지 않는다. 기존 계정의 서비스·조직 범위·유효기간·정지 상태를 덮어쓰지 않는다.

## 구조 조사와 구현 범위

현재 동일 사용자의 같은 역할은 활성 한 행만 허용한다. 기존 역할을 중앙 범위로 바꾸는 방식은 기존 권한을 훼손할 수 있다. 기존 역할은 그대로 두고, 기존 `central_operation_menu_grants`에 명시적 업무 운영자 위임 표시를 추가해 중앙 업무 설정을 구분한다. 새 권한 원장·Core·역할 종류·인증 체계를 만들지 않는다. 과거 global/조직 역할과 과거 설정만으로 중앙 접근을 새로 허용하지 않는다.

새 초대의 기본 업무는 서버의 현행 일상업무 목록으로 정한다. 과거 수락 대기 초대의 업무는 수신자에게 보여 준 범위대로 보존하며 새 발송 방식으로 재작성할 때만 전체 기본값을 사용한다. 실제 권한의 유효성·membership·조직·자격 및 Google 검사는 유지한다. 업무 운영자 해제는 중앙 위임만 회수하고 기존 서비스 권한을 보존한다.

기존 설정 테이블 확장 migration은 코드와 격리 DB에서 준비·검증하되, 운영 DB DDL 적용은 실행하지 않는다. 운영 적용 전에 AGENTS.md §5의 명시적 DB write/DDL 승인 경계를 확인한다.

## 로컬 구현·검증

검증 상세는 [CHECK](../checks/CHECK-O4O-ADMIN-OPERATOR-INVITE-FIRST-V1.md)를 따른다. 기존 역할과 Core writer/entity는 변경하지 않는다. 기간 제한이 없는 해제된 중앙 전용 역할은 새 초대의 명시적 본인 수락으로만 복원하며, 독립 서비스/조직의 비활성 역할과 기간 제한은 보존한다.

운영 적용 대상은 `AddAdminOperationsDelegation1793586897000`: 기존 설정 테이블에 `admin_operations boolean NOT NULL DEFAULT false` 한 컬럼 추가다. 기존 데이터의 자동 권한 확대나 backfill은 없다. 명시적 위임이 존재하면 down은 거부한다. 운영 DB에 적용하지 않았으며 main 병합/배포도 실행하지 않았다.
