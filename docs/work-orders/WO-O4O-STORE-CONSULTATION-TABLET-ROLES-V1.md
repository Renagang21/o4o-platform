## 1. 배경 — 매장에서 일어나는 상담

- 상담은 매대와 매장 안에서 일어난다. 서비스상 화면은 **약사 · 근무자 · 소비자** 3종이고, 매장마다 종류별로 **여러 대**를 둔다.
- **문의와 답변은 한 화면에서 끝난다.** 태블릿이 여러 대여도 한 상담은 태블릿 한 대에서 진행한다(2대 짝짓기 없음).
  1. 소비자가 약사에게 문의: 약사 태블릿을 둘이 함께 본다. 화면은 약사용이다. 음성 입력은 누가 해도 된다.
  2. 소비자가 근무자에게 문의: 근무자 태블릿을 함께 본다. 화면은 근무자용이다. 음성 입력은 누가 해도 된다.
  3. 소비자가 키오스크에 입력: 소비자 화면이다. 옆의 약사 · 근무자도 그 소비자 화면을 보며 응대한다.
- 어떤 태블릿을 누가 쓸지는 매장 내부 규칙으로 정한다. 시스템은 태블릿마다 이름을 붙여 구분하게 해 준다.

## 2. 사용자 결정 (2026-11-13)

| 항목 | 결정 |
|---|---|
| 화면 종류 | 약사 · 근무자 · 소비자 3종, 종류별 복수 추가 |
| 다국어 | **모든 상담 태블릿의 기본 사항** — 고객 언어 선택 · 자동 감지 · 번역 · 음성 입력 · 읽어 주기 |
| 기존 방식 | 매대 2대 연결(연결 코드) · 관리자 일반/대형 배치 설정은 **새 구조로 교체** |
| 근무자 입력 | 자유 문장 · 음성 허용(기존 안내 문구 6개 고정 해제) |
| 키오스크 답변 | **안내 수준 AI 답변** — 근무자 수준(상품 · 위치 · 일반 안내 · 약사 연결). 복용 · 약 선택 같은 전문 상담은 「약사에게 문의」 안내 |
| 노출 수준 | 약사 = 전문(질병 · 증상 · 성분 등 제한 없이) / 근무자 = 소비자 수준 + 제품 위치 · 가격 등 판매 정보 / 소비자 = 일반 B2C 수준 |
| 가격 | **지금 구현하지 않고 가능하도록 준비만** — 소비자 그룹별 가격, 약국의 일시 가격 변경을 나중에 보여 줄 수 있어야 한다 |

## 3. 단계

### 1단계 — 약사 · 근무자 태블릿 목록 · 단일 화면 (완료 · 이 branch)

- 서버
  - `GET/PUT /api/v1/neture/pharmacy/consultation-tablets` — `organizations.metadata.consultationTablets` 에 `{ id, role: pharmacist|staff, name }` 목록(최대 30). 조회는 매장 구성원, 저장은 매장 경영자(표현 설정과 같은 owner 재확인 UPDATE). **schema 변경 없음.**
  - `floor-staff` 의 고객 방향 자유 문장 허용. 안내 문구(`phrase`)도 계속 받는다. 이용 자격(`multilingual-staff-response`) 검사는 그대로.
  - 상담 방식 표시 이름: `floor-pharmacist` → 약사 상담, `floor-staff` → 근무자 상담. **mode key 는 바꾸지 않았다.**
- 매장 화면
  - 내 매장 → 상담: 약사 태블릿 · 근무자 태블릿 목록. 경영자가 이름을 붙여 추가 · 삭제한다. 등록 전에는 종류별 기본 1대가 보인다.
  - 태블릿 링크: `/consultation/staff?store=&role=pharmacist|staff&tablet=&name=`. `role` 이 있으면 그 종류의 상담 방식만 고른다(약사: `floor-pharmacist` → `counter-pharmacist`, 근무자: `floor-staff` → `counter-staff` 중 이용 가능한 앞쪽). 이용 자격 · 결제 구조는 바꾸지 않으려고 기존 방식 key 를 재사용했다.
  - 다국어(고객 언어 선택 · 자동 감지 · 번역 · 음성 · 읽어 주기)는 약사 · 근무자 태블릿 모두 기존 그대로 동작한다.
  - 고객 화면 연결 UI 를 쓰지 않는다(`counter = false`). 근무자 화면에 음성 입력과 「자주 쓰는 안내 문구」 빠른 입력을 둔다.
  - 「매대 소비자 화면」 링크를 뺐다. `/consultation/customer` 경로와 서버 기기 API 는 정리 단계까지 남는다.
- 관리자: 일반/대형 배치 화면에 「현재 매장 상담 화면에 반영되지 않음 · 정리 예정」 안내를 붙였다.
- 노출 수준 확인: 약사 방식만 판단 지원(전문 참고 · 성분 · 주의)을 받는다(서버 `consultation-guidance.ts` `supportMaterial` · `searchSupportProducts` 가 약사 방식 외 403). 근무자는 상품 찾기 · 위치 · 게시된 제품 설명 · 약사 연결 안내만 받는다.

### 2단계 — 소비자 화면(키오스크) · 안내 수준 AI (다음 실행자)

- [ ] 기기 인증: 키오스크는 직원 로그인 없이 쓴다. 경영자가 상담 화면에서 소비자 태블릿을 등록하면 연결 코드로 기기 자격을 1회 발급한다. 기존 `store_consultation_stations` 의 `device_hash` · `pairing_hash` 재사용 가능성을 먼저 검토하고, 새 테이블이 필요하면 §5 승인(migration lane) 후 진행한다.
- [ ] 태블릿 목록 role 에 `consumer` 추가(서버 schema · 매장 화면).
- [ ] **다국어 기본**: 키오스크 화면 문구 · 질문 입력(문자 · 음성) · 답변 · 읽어 주기를 소비자 언어로 제공한다. 언어 자동 감지와 직접 선택을 함께 둔다. 기존 상담 언어 목록(`CONSULTATION_SCREEN_LANGUAGES`) · 화면 문구(`consultationLocale`) · 음성 runtime 을 재사용한다.
- [ ] 소비자 질문 → 번역 → 상품 후보(이름 · 위치 · 게시된 소비자용 설명) → 안내 답변. 소비자에게 보이는 자료는 B2C 공개 범위만 쓴다. 전문 참고 · 약사 판단 지원 자료는 넣지 않는다.
- [ ] 복용 · 약 선택 · 증상 판단 질문은 답하지 않고 「약사에게 문의」로 안내한다. 이 판정과 출력 검증을 서버에서 한다(모델 출력만 믿지 않는다).
- [ ] AI 비용 주체 · 한도 · 중지 정책은 기존 상담 runtime(`consultationRuntimeSchema` · policy executor)을 따른다. 기기 요청에 rate limit.
- [ ] 키오스크 화면에서 경영자 · 직원 메뉴로 나갈 수 없게 한다(기존 `CustomerConsultationPage` 의 인증 밖 구조 참고).

### 가격 표시 준비 (구현 보류 — 설계 조건만)

- 가격은 화면 표시 시점에 서버가 **매장 · 소비자 그룹 · 일시 변경 기간**을 보고 결정한다. 화면 · 상담 상태에 가격을 저장하지 않는다.
- 근무자 화면 · 소비자 화면은 같은 가격 결정 지점 하나를 쓴다.
- 결정할 수 없으면(그룹 미상 · 기간 겹침 · 원천 없음) 가격을 숨기고 「매장에 문의」로 안내한다.
- 가격 원천은 기존 상품 · 공급 구조(B2B 계약 · 매장 상품)를 먼저 조사해 정한다. 새 가격 테이블 · 소비자 그룹 테이블은 §5 승인 대상이다. 소비자 commerce 경계([`O4O-STORE-COMMERCE-BOUNDARY-V1`](../baseline/O4O-STORE-COMMERCE-BOUNDARY-V1.md))를 먼저 확인한다.

### 3단계 — 정리 (contract)

- [ ] 2단계 배포 후 고객 화면 짝짓기(`/consultation/customer` · `consultation-device/*` · station pairing) 사용처를 확인하고 제거한다.
- [ ] 관리자 일반/대형 배치 설정(`PharmacyConsultationLayoutsPanel` · `/admin/pharmacy-consultation-layouts` · `/pharmacy/consultation-layout`) 제거.
- [ ] `counter-*` 방식과 이용 자격 key(`multilingual-consultation` 등) 통합 여부 — 결제 · 이용권 영향이 있어 사업 판단 후 진행.
