## 1. 배경 — 매장에서 일어나는 상담

- 상담은 매대와 매장 안에서 일어난다. 서비스상 화면은 **약사 · 근무자 · 소비자** 3종이고, 매장마다 종류별로 **여러 대**를 둔다.
- **문의와 답변은 한 화면에서 끝난다.** 태블릿이 여러 대여도 한 상담은 태블릿 한 대에서 진행한다(2대 짝짓기 없음).
  1. 소비자가 약사에게 문의: 약사 태블릿을 둘이 함께 본다. 화면은 약사용이다. 음성 입력은 누가 해도 된다.
  2. 소비자가 근무자에게 문의: 근무자 태블릿을 함께 본다. 화면은 근무자용이다. 음성 입력은 누가 해도 된다.
  3. 소비자가 키오스크에 입력: 소비자 화면이다. 옆의 약사 · 근무자도 그 소비자 화면을 보며 응대한다.
- 어떤 태블릿을 누가 쓸지는 매장 내부 규칙으로 정한다. 시스템은 태블릿마다 이름을 붙여 구분하게 해 준다.

## 2. 사용자 결정 (2026-11-13)

| 항목 | 결정 |
|---|---|
| 화면 종류 | 약사 · 근무자 · 소비자 3종, 종류별 복수 추가 |
| 다국어 | **모든 상담 태블릿의 기본 사항** — 고객 언어 선택 · 자동 감지 · 번역 · 음성 입력 · 읽어 주기 |
| 기존 방식 | 매대 2대 연결(연결 코드) · 관리자 일반/대형 배치 설정은 **새 구조로 교체** |
| 근무자 입력 | 자유 문장 · 음성 허용(기존 안내 문구 6개 고정 해제) |
| 키오스크 답변 | **안내 수준 AI 답변** — 근무자 수준(상품 · 위치 · 일반 안내 · 약사 연결). 복용 · 약 선택 같은 전문 상담은 「약사에게 문의」 안내 |
| 노출 수준 | 약사 = 전문(질병 · 증상 · 성분 등 제한 없이) / 근무자 = 소비자 수준 + 제품 위치 · 가격 등 판매 정보 / 소비자 = 일반 B2C 수준 |
| 가격 | **지금 구현하지 않고 가능하도록 준비만** — 소비자 그룹별 가격, 약국의 일시 가격 변경을 나중에 보여 줄 수 있어야 한다 |

## 3. 단계

### 1단계 — 약사 · 근무자 태블릿 목록 · 단일 화면 (완료 · 이 branch)

- 서버
  - `GET/PUT /api/v1/neture/pharmacy/consultation-tablets` — `organizations.metadata.consultationTablets` 에 `{ id, role: pharmacist|staff, name }` 목록(최대 30). 조회는 매장 구성원, 저장은 매장 경영자(표현 설정과 같은 owner 재확인 UPDATE). **schema 변경 없음.**
  - `floor-staff` 의 고객 방향 자유 문장 허용. 안내 문구(`phrase`)도 계속 받는다. 이용 자격(`multilingual-staff-response`) 검사는 그대로.
  - 상담 방식 표시 이름: `floor-pharmacist` → 약사 상담, `floor-staff` → 근무자 상담. **mode key 는 바꾸지 않았다.**
- 매장 화면
  - 내 매장 → 상담: 약사 태블릿 · 근무자 태블릿 목록. 경영자가 이름을 붙여 추가 · 삭제한다. 등록 전에는 종류별 기본 1대가 보인다.
  - 태블릿 링크: `/consultation/staff?store=&role=pharmacist|staff&tablet=&name=`. `role` 이 있으면 그 종류의 상담 방식만 고른다(약사: `floor-pharmacist` → `counter-pharmacist`, 근무자: `floor-staff` → `counter-staff` 중 이용 가능한 앞쪽). 이용 자격 · 결제 구조는 바꾸지 않으려고 기존 방식 key 를 재사용했다.
  - 다국어(고객 언어 선택 · 자동 감지 · 번역 · 음성 · 읽어 주기)는 약사 · 근무자 태블릿 모두 기존 그대로 동작한다.
  - 고객 화면 연결 UI 를 쓰지 않는다(`counter = false`). 근무자 화면에 음성 입력과 「자주 쓰는 안내 문구」 빠른 입력을 둔다.
  - 「매대 소비자 화면」 링크를 뺐다. `/consultation/customer` 경로와 서버 기기 API 는 정리 단계까지 남는다.
- 관리자: 일반/대형 배치 화면에 「현재 매장 상담 화면에 반영되지 않음 · 정리 예정」 안내를 붙였다.
- 노출 수준 확인: 약사 방식만 판단 지원(전문 참고 · 성분 · 주의)을 받는다(서버 `consultation-guidance.ts` `supportMaterial` · `searchSupportProducts` 가 약사 방식 외 403). 근무자는 상품 찾기 · 위치 · 게시된 제품 설명 · 약사 연결 안내만 받는다.

### 2단계 — 소비자 태블릿(키오스크) · 다국어 · 안내 수준 AI (완료 · 이 branch)

- 서버(`services/consultation-kiosk.ts` · routes)
  - 태블릿 목록 role 에 `consumer` 추가.
  - `POST /pharmacy/consultation-tablets/:tabletId/pairing` — 매장 경영자만 10분 연결 코드 생성(등록된 소비자 태블릿만).
  - `POST /pharmacy/consultation-kiosk/{claim,context,search,answer,pharmacist,speech/:operation}` — 로그인 없는 기기 자격(64자 token, hash 저장). rate limit 은 IP + token.
  - 기기 등록은 기존 `store_consultation_stations` 행(`mode='consumer-kiosk'`, `station_key='kiosk-<tabletId>'`)을 쓴다 — **schema 변경 없음**. 질문 · 답변은 저장하지 않는다.
  - 매 요청마다 ① 기기 token ② 태블릿이 목록에 consumer 로 남아 있는지 ③ 연결 코드를 만든 경영자가 근무자 상담 방식(`floor-staff` → `counter-staff`)을 지금 쓸 수 있는지 다시 확인한다. 하나라도 빠지면 즉시 차단.
  - 답변은 기존 근무자 안내(`ConsultationGuidanceService.prepare`)만 쓴다: 상품 이름 검색(원문 + 한국어 번역), 위치(번역), 게시된 소비자용 제품 설명(질문이 있으면 AI 가 게시 문단 최대 3개 선택 · 번역, 길면 원문 언어로 표시). 약사 판단 지원 · 전문 참고 자료는 쓰지 않는다. 기기 응답에서 직원용 증명 · 내부 값은 뺀다.
  - 복용 · 약 선택 · 증상 · 추천 질문(기존 `consultationIntent` 서버 판정, 원문과 번역 모두)은 상품 검색 · 자료 준비 없이 약사 연결 안내로 바꾼다.
  - 90초 상담 정리 작업이 키오스크 행의 연결 코드 · 기기 자격을 지우지 않도록 제외. 매대 상담 시작이 `kiosk-` 키를 가로채지 못하게 막음.
- 매장 화면
  - 내 매장 → 상담에 「소비자 태블릿(키오스크)」 칸: 경영자가 추가 · 삭제 · 연결 코드 생성, 직원은 조회만.
  - `/consultation/kiosk` — 로그인 · 매장 관리 화면 밖. 연결 코드 입력 → 언어 선택(자동 감지는 관리자 설정 시) → 상품 찾기(문자 · 음성) → 위치 / 제품 설명 / 질문 → 읽어 주기. 「약사에게 문의」 버튼 상시. 화면 문구 7개 언어(`kioskLocale.ts`).
  - 마지막 조작 2분 뒤 · 화면 이탈 시 처음 화면으로(다음 고객 보호). 기기 자격이 끊기면(401 · 태블릿 삭제 · 경영자 권한 철회) 연결을 지운다.
- 남은 확인: 실제 기기 · 브라우저 음성 · 운영 자료로 확인하지 않았다(§4).

### 2-1단계 — 태블릿별 음성 자동 감지 언어 (완료 · 이 branch, 2026-11-13 사용자 지시)

- 배경: 관리자 「Google 음성 자동 감지 후보 · 최대 3개」는 플랫폼 전체 설정이었다. 3개 상한은 Google Speech-to-Text 자동 감지가 요청당 후보를 최대 3개 받는 제약이다(후보가 적을수록 정확). 이 후보는 자동 감지로 말할 때만 쓰이고, 언어를 직접 고른 인식 · 문자 번역 · 브라우저 음성 인식에는 영향이 없다.
- 결정: 매장 위치 · 고객층에 따라 필요한 언어가 다르므로 **태블릿마다 후보 최대 3개**를 매장 경영자가 정한다. 관리자 설정은 「기본 후보」로 남아 태블릿에 설정이 없을 때 쓴다.
- 서버: `consultationTablets[].speechLanguages`(선택 · 7개 언어 중 1~3개 · 중복 금지). 직원 음성 인식은 요청의 `tabletId` 로 서버가 저장 목록에서 후보를 읽고(화면이 보낸 언어 목록은 쓰지 않음), 키오스크는 기기에 연결된 태블릿의 후보를 쓴다. 직원 상담 context(`?tablet=`) · 키오스크 context 는 실제 후보를 돌려준다.
- 화면: 내 매장 → 상담의 각 태블릿에 「음성 자동 감지 언어」(경영자 편집 · 직원 조회). 키오스크 언어 버튼은 후보 언어를 앞에 둔다. 관리자 설정 화면 문구를 「기본 후보」로 바꿨다.
- 문서: [`DESIGN-O4O-STORE-CONSULTATION-DATA-SCOPE-V1`](../design/DESIGN-O4O-STORE-CONSULTATION-DATA-SCOPE-V1.md) §1 화면 구조 · 음성 후보 문단 갱신.

### 2-2단계 — 키오스크 검색 결과에 위치 바로 표시 (완료 · 2026-11-13 사용자 제안, #1049 병합 후 새 branch)

- 배경: 소비자는 상품을 찾으면 「어디 있는지」를 가장 먼저 묻는다. 이전에는 이름 목록 → 상품 선택 → 「위치 보기」 두 단계가 필요했다.
- 서버(`consultation-kiosk.ts` `search`): 검색 결과(최대 20개) 각 상품에 `location { text, language }` 를 붙인다. 위치는 매장이 등록한 고객 안내 문구(`staffSupport.locations`)다.
  - 외국어 고객이면 **서로 다른 위치만 모아 번호 붙인 한 덩어리로 번역 1회**(입력 1,000자 이내). 줄 수 · 번호가 맞을 때만 쓰고, 하나라도 어긋나거나 번역이 실패하면 한국어 원문을 보여 준다(잘못된 상품에 위치가 붙지 않게). 권한 · 상담 변경 오류는 그대로 올린다.
  - 위치 미등록 상품은 「직원에게 위치를 문의」 안내. 원문 검색어와 번역 검색어가 같은 상품을 찾을 때 먼저 찾은 위치를 빈 값으로 덮어쓰던 문제도 고쳤다.
- 화면: 결과마다 위치를 바로 표시(`lang` 속성). 상품을 고르면 위치와 읽어 주기 버튼을 보여 주고, 「위치 보기」 버튼은 뺐다. 제품 설명 · 질문 흐름은 그대로.
- 노출 범위: 위치는 매장이 고객 안내용으로 등록한 정보라 소비자(B2C) 수준을 넘지 않는다.

### 가격 표시 준비 (구현 보류 — 설계 조건만)

- 가격은 화면 표시 시점에 서버가 **매장 · 소비자 그룹 · 일시 변경 기간**을 보고 결정한다. 화면 · 상담 상태에 가격을 저장하지 않는다.
- 근무자 화면 · 소비자 화면은 같은 가격 결정 지점 하나를 쓴다.
- 결정할 수 없으면(그룹 미상 · 기간 겹침 · 원천 없음) 가격을 숨기고 「매장에 문의」로 안내한다.
- 가격 원천은 기존 상품 · 공급 구조(B2B 계약 · 매장 상품)를 먼저 조사해 정한다. 새 가격 테이블 · 소비자 그룹 테이블은 §5 승인 대상이다. 소비자 commerce 경계([`O4O-STORE-COMMERCE-BOUNDARY-V1`](../baseline/O4O-STORE-COMMERCE-BOUNDARY-V1.md))를 먼저 확인한다.

### 3단계 — 정리 (contract)

- [ ] 2단계 배포 후 고객 화면 짝짓기(`/consultation/customer` · `consultation-device/*` · station pairing) 사용처를 확인하고 제거한다.
- [ ] 관리자 일반/대형 배치 설정(`PharmacyConsultationLayoutsPanel` · `/admin/pharmacy-consultation-layouts` · `/pharmacy/consultation-layout`) 제거.
- [ ] `counter-*` 방식과 이용 자격 key(`multilingual-consultation` 등) 통합 여부 — 결제 · 이용권 영향이 있어 사업 판단 후 진행.

## 4. 배포 후 Demo 확인 (1 · 2단계)

- 매장 경영자: 내 매장 → 상담에서 약사 · 근무자 태블릿 추가 · 삭제, PC/mobile 에서 목록 · 링크 확인.
- 매장 직원: 목록 조회만 되고 추가 · 삭제 버튼이 없는지 확인.
- 근무자 태블릿 화면: 자유 문장 번역 · 음성 버튼 · 안내 문구 빠른 입력 · 판단 지원 패널 없음.
- 약사 태블릿 화면: 약사 자격 계정에서 판단 지원 표시, 자격 없는 계정은 이용 확인 안내.
- 음성 자동 감지 언어: 운영 설정이 Google 음성일 때 태블릿 후보를 베트남어 · 태국어 등으로 바꾸고 자동 감지로 말해 인식 언어 확인. 브라우저 음성 설정에서는 영향이 없음을 확인.
- 키오스크 검색 결과 위치: 위치를 등록한 상품 · 미등록 상품을 한국어 · 영어로 검색해 결과 목록에 위치 · 미등록 안내가 바로 보이는지.
- 소비자 태블릿: 경영자가 키오스크 추가 → 연결 코드 → 다른 브라우저(로그인 없음)에서 `/consultation/kiosk` 연결 → 영어 · 한국어로 상품 찾기 · 위치 · 제품 설명 · 질문 · 읽어 주기 → 「두통약 추천」 같은 질문이 약사 안내로 바뀌는지 → 2분 뒤 초기화 → 목록에서 삭제하면 키오스크 연결이 끊기는지. 운영 데이터를 남기지 않는다(질문 비저장).

## 5. 문서 정합

- 해당 없음(기준 문서 변경 없음). 상담 운영 안내 문서에 2대 연결 설명이 있으면 3단계에서 함께 정비한다.
