대상은 **일반의약품 OTC** 중 다음 기준에 맞는 성분·함량·제형 그룹이다.

```text
일반의약품 OTC
+ 같은 성분
+ 같은 함량
+ 같은 제형
+ 같은 투여경로
+ 허가 효능·용법이 실질적으로 같은 그룹
```

설명서 작성 단위는 ProductMaster 1건이 아니라 다음 그룹이다.


포장단위, 바코드, 병/PTP, 30정/100정/300정 차이는 설명서 분리 기준으로 삼지 않는다.

## 6. read-only 검증 기준

각 그룹별로 다음을 확인한다.

| 항목 | 확인 내용 |
| --- | --- |
| OTC 여부 | `drug_category='otc'` 기준, rx 혼입 여부 확인 |
| 성분 | name 괄호/원문/e약은요에서 성분 일치 확인 |
| 함량 | specification 또는 허가 원문 기준 확인 |
| 제형 | 정/캡슐/연질캡슐/시럽 등 혼재 여부 확인 |
| 제조사 수 | distinct manufacturer_name |
| ProductMaster 수 | 그룹 내 master count |
| 포장단위 수 | distinct specification, 단 설명서 분리 기준 아님 |
| e약은요 | `SharedProductDescription` source_type='mfds_easy_drug' 보유 수 |
| 원문 | 효능·용법·주의·상호작용·보관 필드 확인 |
| 위험 요소 | 복합제, 함량 혼입, 제형 혼입, 전문약 혼입, 유사 성분 혼입 |

`ProductDrugExtension`의 임상 텍스트 필드는 아직 비워두는 정책이므로, 이 필드를 채우거나 설명서 SSOT로 사용하지 않는다.

## 8. AI 에이전트 프롬프트 초안 작성

이번 작업에서는 설명서 5개 작성과 함께, 이후 자동 초안 생성을 위한 프롬프트 초안을 CHECK 문서에 포함한다.

프롬프트는 최소한 다음 규칙을 포함해야 한다.

```text
너는 O4O 약국 매장용 일반의약품 설명서를 작성한다.
입력은 성분·함량·제형 그룹과 e약은요/허가 원문이다.
제품명 중심으로 쓰지 말고 성분 중심으로 쓴다.
질환명과 증상명을 회피하지 않는다.
약국 매장 내에서 약사 상담과 함께 사용되는 설명서다.
허가 원문 의미를 강화하거나 축소하지 않는다.
치료 보장, 절대 우월, 부작용 없음 표현을 쓰지 않는다.
같은 성분·함량·제형의 제품은 같은 설명서를 공유한다.
포장단위 차이는 설명서에 반영하지 않는다.
하단의 성분 기준 선택 문구를 반드시 넣는다.
```
