# 공급자 1차 정비

> **상태**: ACTIVE · **작성일**: 2026-10-09
> **승인 근거**: 사용자 지시 “진행하라”; 일반 공개 모집은 운영자의 노출 승인 없이 게시.
> **범위**: 공급자 지표 집계, 결제 후 배송 안내, 공개 모집과 세미프랜차이즈 모집의 구분.

## 적용 결정

- 각 서비스에서 발생한 주문은 공통 결제 프로세스를 거친다. 공급자의 주문 처리는 결제 완료 후 최종 배송을 위한 주문 확인·배송 준비·송장 등록·배송 완료다. 결제·배송 상태 전이와 연결 조건은 변경하지 않는다.
- 일반 공개 모집은 공급자가 게시하면 내 매장에서 즉시 조회·신청할 수 있다. 모집의 과거 노출 대기·반려 값은 공개 모집의 노출 조건으로 사용하지 않는다. 기존 데이터의 승인 이력은 일괄 변경하지 않는다.
- 대상 세미프랜차이즈가 지정된 모집은 사업별 노출 승인과 활성 가입 조건을 유지한다. 과거 약국 서비스(`neture-pharmacy`, `kpa-society`) 모집 중 대상 ID 없이 공급가가 설정된 행도 기존 pharmacy 모집으로 취급한다. 일반 공개 모집 생성 경로는 공급가를 설정하지 않는다.
- 일반 모집에 참여했다고 제품이 자동 등재되거나 세미프랜차이즈 공급·주문 권한이 부여되지 않는다. 사업별 제품 승인과 기존 공급 접근 판정은 유지한다.
- 대시보드 SQL은 CheckoutOrder의 camelCase 컬럼을 사용한다. 결제된 주문만 집계하고 취소·환불 주문을 제외한다. 상품별 주문 수는 실제 포함된 상품에만 계산한다. 필수 SQL 실패는 0건으로 숨기지 않으며 지표 화면에 실패를 표시한다.

## 제외 및 인계

AI 지원·내부 실행은 도입하지 않는다. 정비 후 별도 기획으로 결정한다. 인증·운영자 화면은 별도 담당 범위다.

인증 담당: 공급자 접근 판정이 main context·활성 공급자 resolver·개별 활성 검사에 분산되어 있다. library, tablet/signage, 일반 supplier API의 판정 기준을 비교하고 승인된 정책으로 통일할 필요가 있다. 이번 작업은 인증 미들웨어를 변경하지 않는다.

운영자 담당: 일반 모집의 노출 심사 큐·안내는 더 이상 게시 조건이 아니다. 사업 대상 모집만 심사 대상으로 안내하도록 별도 정비가 필요하다. 현재 review API의 일반 모집 노출 값 변경은 공개 조회·신청에 영향을 주지 않는다.

문서 정합: 기존 공급자 경계 및 약국 commerce 설계의 “모집 전체에 운영자 노출 승인”, “대상 NULL 모집은 모두 pharmacy” 문구와 이번 승인 결정이 다르다. Frozen 문서와 canonical index는 임의 수정하지 않는다. 해당 정책의 문서 정비는 별도 문서 작업으로 인계한다. 공급가가 있는 과거 사업 모집의 가입·공급 조건은 유지한다.

## 검증 및 반영

실제 PostgreSQL의 transaction-local TEMP TABLE로 공개 pending/rejected 모집의 조회·신청, 미가입/미승인/마감 모집 차단, 중복 신청, 과거 공급가 모집의 가입 조건, 공급자·상품별 주문/매출·기간 집계 및 SQL 오류 전파를 확인한다. 운영 데이터 write나 schema migration은 없다.

API 빌드, 변경한 두 웹 서비스 타입 검사, web-neture 회귀 테스트와 웹 빌드 결과는 PR에 기록한다. main 통합과 배포는 별도 승인 대상이다.

검증 결과: API 4개 suite / 59개 test, web-neture 46개 file / 375개 test 통과. 두 웹 서비스 타입 검사 및 production build, API build 통과. 초기 의존 패키지 빌드 전 API 검사와 잘못된 cwd의 웹 테스트 실행은 실패했으며, 패키지 빌드 및 올바른 root/config로 재실행했다. 실계정 브라우저 smoke·배포·운영 migration은 수행하지 않았다.
