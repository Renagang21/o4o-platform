## 1. 파서 변경 항목

### 1-1. spec 파서 하드닝
| 항목 | 처리 |
|---|---|
| 단위 | `ug`·`µg`·`㎍` → `μg` · `㎎` → `mg` · 전각숫자 → 반각 |
| 수식어 | `RAE`/`RE`/`NE`/`DFE`/`α-TE` + **깨진 변형** `a-TE`·`mga-TE`·`mgα-TE` → `α-TE` 정규화 |
| 라벨 공백 | 원료명 내부 공백 1회 허용(`비타민 E :`) · 콜론·단위 주변 공백 허용 |
| 표시량 접두 누락 | `표시량` 없어도 매치 |
| 선행 괄호 | `셀렌 : (55 μg/7,500 mg)의 80~150%` 형태 허용 |
| 오탐 가드 | 비율(`의 x~y%`/`이상`) **필수** 유지 → `납(mg/kg) : 1.0 이하` 류 배제. NONFUNC 라벨 확장(헥산 등) |
| 수치 | **불변**(표기 정규화만, 값·기준량 변경 0) |

### 1-2. 기능성 귀속 파서 (`parseFnAttribution`)
`[원료]` 브래킷 · `1) 원료 : 기능성` 번호목록 · 인라인(registry 폴백) 3형식 지원. 명시 구조가 있으면 **그 구조만** 사용해 한 기능성을 여러 원료에 임의 귀속하지 않는다. 구분자에 슬래시(`A 필요 / B 필요`) 추가.

### 1-3. ⚠️ 생산 select 귀속 정책 — **원복(중요)**
공용 귀속 파서를 생산 select 에 그대로 물렸다가 **회귀를 실측**하고 되돌렸다.

- 증상: D+E LIVE 24 중 **14 오탈락**, D+Se+Zn LIVE 8 중 3 오탈락.
- 원인 2건(**둘 다 파서 버그, 콘텐츠 결함 아님**):
  1. **인라인 오귀속** — 라벨 없는 MAIN_FNCTN 에서 비타민D 기능성 `칼슘과 인이 흡수되고 이용되는데 필요` 가 **칼슘**으로 귀속 → 부원료 오탐 HOLD. (`20040020028661` 실측: BASE 는 `비타민E`+`비타민D` 2 spec 뿐)
  2. **슬래시 미분리** — `[비타민D] A 필요 / B 필요 / C 도움` 이 한 문장으로 뭉쳐 `mapFunctionEn` 실패 → 귀속 실패 HOLD. (`20120019007515`)
- 조치: 생산 select 의 **귀속은 기존 TARGET 스코프 registry 방식 유지**(검증된 계약), **spec 파싱만 공용 모듈로 일원화**. 슬래시 구분자는 공용 모듈에 반영.
- 근거: 생산 select 의 질문은 "이 제품이 **이 조합과 정확히** 일치하는가"(TARGET 스코프면 충분), 감사의 질문은 "이 제품의 **실제 전체 조합**이 무엇인가"(전역 발견 필요) — 목적이 달라 귀속 정책을 분리한다. **spec 결과는 동일 모듈이라 항상 일치**(§4 실측 AGREE 6/6).
