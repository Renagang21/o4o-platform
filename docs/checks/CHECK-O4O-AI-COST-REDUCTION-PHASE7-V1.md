## 1. 이번에 확인한 것

실제 상담 서비스·업무 Extension·기존 policy runtime을 연결하고 DB 응답과 공급자 경계만 합성 응답으로 대체했다. 상품 검색 계획 → 게시 자료 선택 → 번역 → 약사 초안의 전체 흐름을 두 번 실행했다. 직접 캐시 helper만 시험하거나 새 유료 호출 체계를 만든 것이 아니다. 모든 수치는 이 합성 시나리오의 결과이며 실제 사용자의 반복률이나 청구 금액이 아니다.

| 측정 대상 | 세션 재사용 없이 2회 | 같은 세션으로 2회 |
|---|---:|---:|
| 검색 계획 policy 실행 | 2 | 1 |
| 게시 자료 선택 policy 실행 | 2 | 1 |
| 번역 policy 실행 | 2 | 1 |
| 약사 초안 policy 실행 | 2 | 1 |
| 합계 | 8 | 4 |
| fixture DB 조회 | 50 | 86 |

같은 입력의 검증된 결과는 두 방식에서 같았다. DB 조회는 재사용하더라도 현재 자료·권한을 확인하기 때문에 증가했다. 이 수치는 SQL fixture의 호출 횟수이며 DB 실행시간·비용·운영 query plan을 측정한 것이 아니다. 호출 50% 감소를 서비스 전체 비용 50% 절감으로 해석하지 않는다. 실제 policy의 retry/fallback·가격·공급자별 과금은 fixture가 대신하지 않는다.

추가 확인:

- 두 전체 상담을 동시에 시작해도 네 단계 모두 한 번씩 실행한다.
- 60초 만료 뒤 네 단계를 다시 실행하며, 다음 고객의 세션은 독립적으로 실행한다.
- 원천 변경 시 기존 초안의 사용 확인은 409로 실패하고 유료 호출을 추가하지 않는다. 새 준비에서는 검색 계획은 재사용하고 자료 선택·번역·초안을 새로 실행한다.
- 매장 표현 설정 변경 시 기존 초안 근거를 거부하고 새 초안에는 새 서버 설정을 전달한다.
- 현재 권한 철회·다른 actor/store 접근은 재사용된 전문 초안을 반환하지 않는다. 실제 약사 자격/직원 승인 정책은 기존 관련 suite의 검증도 함께 수행한다.
- 수치가 틀린 번역은 재사용 결과에 남기지 않는다. 같은 세션에서 정상 응답으로 재시도할 수 있고 이후 정상 결과만 재사용한다.
- 번역 정책을 중지하면 이미 준비한 재사용 결과도 반환하지 않는다.
- 실제 화면 흐름에서 같은 상담의 번역 요청은 같은 세션을 보내고, 새 상담·내용 지우기 후에는 새 세션을 보낸다. client actorId·organizationId·reuseKey를 추가하지 않는다.

공급자 응답은 합성이므로 수치·출처 검증의 동작은 확인하지만 실제 한국어 품질·임상 유용성·문체 준수를 확인한 것은 아니다. 질문/근거 원문이나 credential은 결과 로그에 출력하지 않는다.

## 3. 배포 후 측정 절차 — 아직 미실행

통합·배포를 담당하는 세션에서 다음 순서로 확인한다. 이 문서 자체는 배포나 계정 권한 변경을 실행하는 지시가 아니다.

1. **대상 버전 확인:** 3~6차 PR #1044와 후속 7차가 반영된 API/매장 버전을 확인한다. 2차 ChatGPT 도구 PR #1042는 별도 선행 대상이다. 현재 branch의 사전 PASS를 배포 증거로 쓰지 않는다.
2. **계정·자료 확인:** `docs/TEST-ACCOUNTS.md`와 Demo 정본을 따른다. Demo 경영자/직원은 현재 자격·매장 승인을 별도 확인한다. 약사 전용 검증은 실제 자격을 확인한 계정으로 하며 직원 Demo를 약사로 임의 승격하지 않는다. 관리자 자료 준비는 적법한 관리자 계정이 있을 때만 수행한다. 합성·삭제 가능한 표본을 사용하고 기존 QR·상품 자료를 변조하지 않는다.
3. **동일 조건 비교:** 같은 상품·근거 버전·질문·언어·모델·정책·동시성·관측 시간대로 재사용 세션을 생략한 기준 경로와 동일 세션을 보낸 경로를 비교한다. 전용 계정/시간 창에서 1회·2회·다음 고객·60초 초과·다중 서버를 구분한다. 운영 설정에 재사용 끄기 스위치가 있다고 가정하지 않는다. 브라우저가 보내는 인증된 요청의 선택 필드 비교이며 client 문자열로 유료/무료 요청 경로를 판정하지 않는다.
4. **호출과 비용 대조:** 기존 `[AI_EXTENSION]`의 extensionId/context.requestId/providerRequestId/stage와 기존 `ai_usage_logs`·가격/예약/정산·관리 화면을 사용한다. `started`·`provider-completed`·`completed`를 세 번의 호출로 합산하지 않는다. 원장에는 캐시 hit가 새 실행으로 기록되지 않으므로 API 요청 수는 별도로 센다. scope PRODUCT_CONTENT는 검색 계획/선택/초안을 공유하므로 scope 합계만으로 단계를 구분하지 않는다. Google 번역/음성 등 별도 과금 경로도 빠뜨리지 않는다. 예상 가격과 실제 청구를 나눠 기록한다.
5. **부하·실패 포함:** 요청 수, 성공/거절/실패, 실제 provider attempt와 retry, prompt/completion token, 가격 버전별 추정 비용, 확정 청구, 브라우저 end-to-end p50/p95, DB query 수/시간, 인스턴스 수를 기록한다. 캐시 hit를 제외한 원장 duration만으로 전체 UX 지연을 추정하지 않는다. 실패 후 재작업과 전문가 검수 시간을 포함하고 집계에 다른 업무가 섞이면 비용을 확정하지 않는다.
6. **권한·자료·화면 회귀:** 두 매장/이용자·다음 고객·모드 전환·자격/직원 승인 철회·자료 폐기/수정·표현/모델 변경 후 이전 결과가 남지 않는지 PC/mobile에서 확인한다. 권한 상태 변경은 운영 데이터를 임의 수정해서 재현하지 않고 승인된 시험 범위 또는 격리 환경을 사용한다.

재사용이 프로세스별이므로 서버 재시작·여러 인스턴스·TTL 초과·용량 초과는 다시 생성될 수 있다. 이를 사용자 격리 실패로 판정하지 않으며, 공급자 호출량 비교에는 실제 조건을 함께 적는다.

- **neture.co.kr 초기화면:** 2차의 인증된 ChatGPT 조회/저장 경로 검증과 별개로 o4o 자체 요청은 기존 유료 경로를 유지한다. 이번 상담 합성 수치를 초기화면 절감액으로 확대하지 않는다. 초기화면 안의 ChatGPT 요금제 연동은 실제 참여 조건 확인/참여 후 구현하는 기존 결정 그대로다.
