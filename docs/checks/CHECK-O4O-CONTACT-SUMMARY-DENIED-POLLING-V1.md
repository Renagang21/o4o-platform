## 문제와 변경

공급자 Demo로 로그인한 운영 브라우저에서 문의 관리 권한 확인 API가
`403 FORBIDDEN`을 약 30초 간격으로 반복 반환했다. 문의 관리 링크는 숨겨지고
오류 알림은 없어 권한 차단 자체는 정상이다. 일반 공급자 역할과 서비스 문의 운영자는 구분한다.

`useServiceContactCount`가 최신 요청에서 403을 받으면 해당 effect의 주기 조회를 중지한다.
창 포커스 복귀 시 서버 권한을 다시 확인하고, 성공하면 기존 주기 조회를 재개한다.
계정·서비스·활성화 조건이 바뀌면 기존 범위의 거절 상태를 이어받지 않는다.
일시적인 서버 오류는 주기 재시도를 유지하며, 오래된 응답은 권한 상태를 덮어쓰지 않는다.
서버 권한 조건·API 계약·의존성 변경은 없다.

## 공통 소비처 영향

| 소비처 | 확인 범위 |
|---|---|
| NetureGlobalHeader | 대표·공급자·펀딩·커뮤니티·CarePharm 호스트 공통 헤더 |
| KpaGlobalHeader | 약국 경영지원·사업 서비스 헤더 |
| ServiceContactPage | 서비스 문의 관리 화면 링크 |
| SiteShell | 강의 운영자 링크 |
| DirectoryShell | 약사회 분회 링크 |
| ConnectedApp | 약사협동조합 링크 |

symbol·import/export·API 경로·소스 파일명 소비처를 검색했다.
허용 계정의 메뉴 노출과 재조회, 거절 계정의 메뉴 숨김은 유지한다.

## 검증

- 수정 전 새 회귀 테스트에서 거절 후 90초 동안 4회 조회하는 문제 재현.
- 공통 shared-space-ui 전체 23개 파일, 210개 테스트 통과(문의 요약 9개 포함).
- 변경 파일 ESLint 및 diff 공백 검사 통과.
- 실제 수정 컴포넌트의 로컬 Playwright fixture: 1440px·390px 모두 통과.
  403 후 주기 조회 중지, 포커스 복귀 후 권한 회복, 주기 조회 재개,
  권한 해제 시 링크 숨김·조회 중지, 계정/서비스 전환 후 재조회 확인.
  page error 0, 업무 데이터 write 0. fixture는 모의 API이며 운영 배포 검증이 아니다.
- 소비처 관련 테스트: 약국 경영지원 헤더 4개, 강의 shell 3개, 분회 shell 2개, 협동조합 연결 화면 6개 통과.
- 강의 shell 테스트에서 기존 중복 React key 경고가 관측됐다. 이번 변경과 무관한 범위이며 테스트는 통과했다.
- Neture 전체 회귀·빌드와 PR의 최종 CI·리뷰 결과는 PR 설명·체크를 기준으로 확인한다.
