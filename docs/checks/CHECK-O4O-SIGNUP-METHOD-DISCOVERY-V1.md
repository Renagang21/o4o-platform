## 원인·수정 범위

Google·카카오 가입 컴포넌트는 이미 존재하지만 닉네임·이름·연락처·비밀번호·약관을 포함한 이메일 폼 아래에 배치돼 있었다. 첫 화면에서는 이메일 가입만 제공하는 것처럼 보이고 소개 문구에는 카카오가 빠져 있었다.

Neture의 `SignupPage`에서 Google·카카오를 먼저 표시하고 이메일 가입은 하단 버튼으로 선택하게 한다. 상단 안내는 “개인정보 보호를 위해 Google·카카오 가입을 권장합니다.” 한 문장이다. 이메일 가입을 선택하면 소셜 컴포넌트를 내리므로 확인 메일 안내 뒤에도 다른 가입 방식이 이어서 나타나지 않는다. 가입 화면에 아이디 통합 설명은 넣지 않는다.

공통 `GoogleContinue`에 기존 기본값을 유지하는 선택적 `personalizedButton` 표시 옵션을 추가했다. Neture 가입 화면에서만 끄고 GIS의 `medium`/`signup_with` 버튼을 사용한다. [Google 공식 문서](https://developers.google.com/identity/gsi/web/guides/personalized-button)는 `medium` 버튼에서 기존 계정 이름·이메일 맞춤 표시가 나오지 않음을 명시한다. 로그인 모달·다른 소비처의 기본 버튼은 바꾸지 않는다. API·OAuth 설정·약관 동의·계정 생성·회원 권한·비밀번호 규칙을 변경하지 않는다. 제공자 미설정·조회 오류·가입 동의 판정도 유지한다.

사용자는 비밀번호 불일치 제보를 입력 실수로 정정했다. 해당 검증은 수정 대상에서 제외한다. 사용자 화면의 입력값·개인정보는 코드·문서·합성 fixture에 복사하지 않는다.

## My Home 아이디 연결 조사

기존 `/mypage/settings`에는 `SocialAccountConnections`와 `PasswordSecuritySettings`가 이미 연결돼 있다. 현재 계정 재인증, 연결할 Google·카카오 계정 인증, 명시적 최종 확인을 거쳐 같은 O4O 계정의 로그인 수단을 추가한다. 같은 계정의 이메일 비밀번호도 설정할 수 있다. 다른 계정에 이미 연결된 소셜 identity는 서버가 충돌로 거절하며, 이메일 일치만으로 합치지 않는다.

따라서 한 O4O 계정에서 Google·카카오·이메일을 사용하는 기능은 기존 구현을 재사용한다. 별도로 이미 생성한 O4O 계정들의 자료·업무 권한을 병합하거나 여러 동일 제공자 아이디를 묶는 기능을 완료했다고 주장하지 않는다. 사용자가 뜻한 통합 범위는 별도 확인 질문으로 구분했다. 이 조사에서 실제 계정 연결·자료 이전·권한 합산을 실행하지 않았다.
