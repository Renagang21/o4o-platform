## 원인·정비

기존 수정 모드 선택은 같은 회원의 detail을 지우고 다시 조회·마운트했다. 수정 폼은 긴 상세의 맨 아래에 있었고 상단 버튼은 항상 상세보기를 강조했다. 처리 후에는 성공·실패에 관계없이 상세 모드로 다시 조회했다. 운영 화면의 순간 깜빡임을 이 한 경로로만 단정하지 않으며, 확인한 전환·표시·입력 초기화 경로를 정비하고 실제 브라우저에서 검증했다.

같은 회원의 보기↔수정은 현재 데이터를 유지해 전환하고 현재 모드를 버튼·제목에 표시한다. 두 모드는 같은 필드 배치를 사용한다. 일반 검증/409 오류는 draft와 함께 표시하며 명시적인 최신 조회로 초기화한다. 401/403은 계정·권한 변경 보호를 우선해 사적인 필드·선택·목록을 제거한다. 기존 리스트 체크·상단 작업·다음 회원 검토는 유지한다. 이력·과거 입력은 접고 이용 해지 설명은 해당 작업에서만 표시한다.

## 수정·권한 경계

- 공통 이름·닉네임·휴대전화·이메일: 중앙 회원 업무 권한, 사유·최신 회원 버전. 이메일 변경은 근거 확인·중복 검사 후 미확인으로 바꾸며 이전 확인/복구 링크와 세션을 무효화한다. 새 주소 확인 메일을 요청할 수 있다. Google/Kakao subject·사용자 ID·권한·동의를 입력 필드로 덮어쓰지 않는다.
- 약사 면허: 별도의 자격 검토 권한·정정 근거·현재 자격 버전 및 기존 승인 면허 중복 검사를 요구한다. 누락 면허를 대리 보완하거나 기존 면허를 변경하면 pending으로 두고 승인 정보는 초기화한다. 기존 근거 확인·본인 승인 금지·가입/계정 조건을 유지한 승인 API로 후속 처리한다.
- 약국·기존 가입 사업자 정보: 기존 각 업무 위임·사유·버전·근거 확인을 유지한다. 약국 신청 면허번호도 보완한다. 이미 승인/정지된 약국은 변경 면허에 일치하는 승인 자격이 먼저 있어야 한다. 증빙 파일·조직 소유·계정/자격/약국 승인 상태를 임의 변경하지 않는다.
- 운영 권한이 있는 다른 계정의 인증 정보는 일반 담당자가 정정할 수 없다. 전체 관리자·Demo 보호 및 현재 DB 위임 재검증을 유지한다. 정보 저장과 자격·약국 승인은 구분한다.

## 임시 비밀번호·My Home

기존 이메일 비밀번호 수단이 있는 활성·이메일 확인 회원에게 중앙 담당자가 본인 요청·전달 대상을 확인해 발급한다. 현재 사용자 ID와 버전·권한을 같은 transaction에서 검증한다. 자기 계정·platform 계정·Demo·권한 없는 다른 운영 계정은 거절하며 소셜 전용 계정의 첫 수단을 만들지 않는다.

보안 난수 144bit와 정책 충족 접두부를 사용하고 기존 유일 저장소에서 bcrypt cost12 해시만 저장한다. 24시간 만료를 서버 로그인 검증에 적용한다. 기존 비밀번호·복구 링크·세션은 폐기한다. 발급 원문은 no-store 응답으로 한 번 표시하고 회원 변경/화면 종료 시 없어진다. 감사에는 발급 사유·처리자·만료만 저장하며 원문/해시를 넣지 않는다. 사용자의 My Home 기존 변경 기능에 임시 상태를 표시하며, 본인 현재 비밀번호 검증을 통과한 새 비밀번호 저장은 임시 만료를 해제하고 이전 세션을 폐기한다. 전체 관리자 로그인은 Google 전용이다.

공통 변경 영향: auth-client의 password status에 선택적 만료 필드를 추가했으며 기존 필드는 그대로다. PasswordSecuritySettings의 현재 실제 서비스 소비자는 Neture My Home이다. 다른 소셜·가입·비밀번호 복구 API의 기본 동작을 유지한다. 레거시 users.password/service_credentials/PasswordModal은 복구하지 않는다.
