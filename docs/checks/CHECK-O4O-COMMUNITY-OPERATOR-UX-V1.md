# 커뮤니티 운영 화면 안정성 및 공지 관리 검증

- 날짜: 2026-10-11 (Asia/Seoul)
- 작업: [WO](../work-orders/WO-O4O-COMMUNITY-OPERATOR-UX-V1.md)
- 기준: main `05bf209a49`, branch `wo/community-operator-ux`

## 변경과 경계

회원 목록·이력, 운영자 지정, 개설 심사의 늦은 응답을 격리하고 행 간 중복 처리를 차단했다. 실패 시 재조회와 결과 안내를 제공한다. 독립 커뮤니티의 기존 moderator에게 공지 고정·해제 버튼을 연결했다. 일반 회원 및 기존 Neture forum 소비처에는 버튼을 노출하지 않는다.

공지 변경은 명시적인 커뮤니티 키와 게시글 ID를 사용한다. 쓰기 성공 후 결과 조회가 실패하면 읽기만 재시도한다. 화면 이동 후 이전 요청의 응답을 반영하지 않는다. 기존 역할, 지정 후보 자격, 마지막 admin 보호, 게시판당 공지 한 건이라는 서버 계약을 유지한다. 서버·DB·의존성 변경은 없다.

회귀 테스트는 필터/커뮤니티 전환의 역순 응답, 이력 조회 후 필터 변경, 여러 행 중복 처리, 개설 심사 중 이탈, 공지 실패·재조회·페이지 이동을 포함한다. 브라우저 검증은 mock API를 사용하며 운영 서버의 데이터 변경을 수행하지 않는다.

작업 중 origin/main이 `9d1ee57f90`으로 진행했으며 변경 대상과 hook 및 App 소비처에 겹치는 변경이 없음을 확인했다. 자동 병합·배포는 수행하지 않는다.

## 사용자가 직접 확인할 항목

- 실계정으로 개별 커뮤니티 A/B와 회원 상태 필터를 빠르게 전환할 때 목록·이력이 현재 선택에 맞는지 확인한다.
- operator는 조회·승인·반려, admin은 정지·해제·탈퇴까지 기존 정책대로 동작하는지 확인한다.
- 서비스 admin의 개별 admin/operator 지정·회수, 후보 자격 안내와 마지막 admin 보호를 확인한다.
- desktop/mobile에서 공지 고정·해제와 다른 글 고정 시 기존 공지 해제를 확인한다.
- 일반 회원은 공지 버튼이 없고, 권한 회수 후 서버가 변경 요청을 차단하는지 확인한다.
- 처리 실패 시 오류 안내·재시도, 성공 후 새 상태 반영을 확인한다.

인증된 Google 브라우저 세션이 없어 실계정·운영 API 검증은 수행하지 못했다. 이 항목은 완료로 처리하지 않는다.
