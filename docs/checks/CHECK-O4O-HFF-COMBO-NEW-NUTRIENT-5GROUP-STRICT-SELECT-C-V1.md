## 4. BLOCKER 상세 — 은닉 원료가 가드를 우회한 경로

**대상**: `20040015104115` **리버케어지티** (그룹 5, ELIGIBLE 통과)

```
BASE_STANDARD  ○ 디에콜(Dieckol) 함량 : 9.9mg/850mg(표시량의 80∼120%)   ← 기능성 원료
               ○ 비타민B1 함량 : 표시량(1.2mg/850mg)의 80~180%   … (B군 5종)
MAIN_FNCTN     [곰피추출물]간 건강에 도움을 줄 수 있음(May help to liver health)
               [비타민B1] 탄수화물과 에너지 대사에 필요 …
생산 귀속       비타민B1 => ["간 건강에 도움을 줄 수 있음(May help to liver health)   탄수화물과 에너지 대사에 필요"]
```

**결함 ①  SPEC_RE 비율 포맷 미커버 → 가드 우회**
`SPEC_RE` 는 기준량 뒤 비율을 `[)] [의] X~Y%` 로만 허용한다. 실데이터 `9.9mg/850mg(표시량의 80∼120%)` 는
**기준량 뒤 괄호 안에 `표시량의` + 비율**이 오므로 매칭 불발.
불발이면 라벨이 `byKey` 에도 `unknownLabels` 에도 안 남아 **통째로 소실** → `keys === TARGET_SET` 성립 →
`unknown > 0` HOLD_MULTI 가드가 **발동조차 하지 않는다**. 하드닝이 다룬 «접두 누락·선행 괄호» 와 **다른 변이**.

**결함 ②  브래킷 제거 후 문장 미분리 → 기능성 끌려감**
`splitFunctions` 가 `[곰피추출물]` 브래킷을 공백으로 치환한 뒤, 앞 문장이 `)` 로 끝나 분리자에 걸리지 않아
간건강 문구와 B1 문구가 **한 세그먼트**로 남는다. `fnBelongsTo(…, '비타민B1')` 이 뒷부분으로 매칭되면서
**간 건강 표시가 비타민B1 에 붙는다** → 게시 시 **허위 기능성 표시**.

> 두 결함 모두 **생산 파서 측**이며 콘텐츠 결함이 아니다. 본 WO 는 read-only 이므로 **수정하지 않았다.**

**필요 조치(별도 WO)**
1. `SPEC_RE` 에 `값/기준(표시량의 X~Y%)` 포맷 추가.
2. **매칭 불발한 spec-like 라인을 `unknownLabels` 로 강제 편입** — 포맷을 아무리 늘려도 미지 변이는 남으므로,
   «파싱 못한 규격 라인이 있으면 HOLD» 가 안전한 기본값. (①만 고치면 다음 변이에서 동일 사고 재발.)
3. 조치 전까지 **그룹 5 생산 금지**. 조치 후 5그룹 전체 재실측 필요(다른 그룹에도 동일 변이 잠복 가능).
