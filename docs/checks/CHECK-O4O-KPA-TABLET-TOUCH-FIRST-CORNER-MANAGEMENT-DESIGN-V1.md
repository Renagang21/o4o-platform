## 0. 결론

태블릿 관리 화면(`/store/commerce/tablet-displays`)의 기본 전제를 **"PC 기기 목록 관리" → "현장 터치 코너 운영 관리"** 로 바꾼다. IA 를 **위치/코너 우선**으로, 인터랙션을 **터치 우선(카드형)** 으로 재설계한다. 기능(Screen Set / Block / content_list / product_list / idle_media / qr_guide / templateKey / 공개 URL / 미리보기 / dirty guard)은 **전부 유지**하되 **배치·진입 순서**를 바꾼다.

- 진입 = **코너 카드 홈**(태블릿 리스트 아님). 순서 = 코너 선택 → 태블릿 연결 → 화면 세트 → 콘텐츠 → 공개 화면.
- 터치 기준(44–48px, 카드, hover/작은 아이콘/좁은 테이블 행 지양, 위/아래 이동 버튼).
- 검색은 후보 많을 때만 보조.
- 구현은 5단계로 분리(§8). **이번 WO 는 설계만.**

## 1. 현재 UI 문제 (read-only 조사)

현행 `StoreTabletDisplaysPage.tsx` IA(위→아래):
```
헤더(제목 + 운영안내/미리보기/태블릿추가/저장 버튼)
→ (인라인) 태블릿 등록 폼
→ 태블릿 목록  ← 첫 작업 대상 = "기기"
→ [태블릿 선택 시] 진열 편집 + TabletScreenSetManager(세트/블록 편집기 전개)
→ 미리보기 오버레이
```
문제:
- **태블릿(기기) 우선**: 먼저 태블릿을 골라야 코너/화면 편집으로 진입. (부분적으로 `LOCATION-FIRST-UX-REFIT` 로 목록을 위치순 정렬하나, 여전히 기기-목록-우선.)
- **PC/마우스 전제**: 좁은 행·작은 아이콘 버튼(ChevronUp/Down/X)·hover·드롭다운(status select)·raw JSON(구 product_content).
- **한 화면 과다 전개**: 선택 태블릿 아래로 진열·세트·블록 편집기가 동시에 길게 펼쳐짐(운영 안내 박스 제거해도 편집기 밀도 높음).
- **검색/테이블 중심**: 상품 pool·콘텐츠 picker 가 검색·행 중심(터치 부적합).

## 2. 실제 사용 시나리오

```
매장 직원/경영자가 "구강관리 코너" 앞에 서서
→ 스마트폰/태블릿으로 관리 화면을 연다
→ 화면 첫 장면에서 "구강관리 코너" 카드를 누른다
→ 이 코너에 연결된 태블릿/적용 화면 세트/콘텐츠 요약을 본다
→ 공개 화면(고객이 보는 화면)을 바로 확인한다
→ 필요하면 콘텐츠를 추가/순서 변경한다(터치)
```
전제: **현장 · 터치 · 코너 앞 · 공개 화면을 보며 수정**.

## 3. 터치 우선 원칙 (확정)
```
- 주요 액션 버튼 min-height 44~48px, 충분한 가로 터치 영역.
- 카드형 큰 터치 영역 우선. 좁은 테이블 행 클릭 지양.
- 아이콘 단독 버튼 지양 → 아이콘+텍스트.
- hover 전제/툴팁 의존/우클릭 금지(터치엔 hover 없음).
- 정렬 = 위/아래 이동 버튼 기본, drag-and-drop 은 보조(선택).
- 드롭다운 남용 지양 → 카드 선택/토글.
- 반응형: 스마트폰(1열) → 태블릿(2열) → PC(다열). clamp/grid auto-fill.
```

## 4. 위치/코너 우선 IA (핵심 재설계)

```
[코너 홈]  (진입 첫 화면)
   ├─ 코너 카드들 (구강관리 / 피부관리 / … / + 새 코너)
   │
   └─▶ [코너 상세]
         ├─ 상단: 코너명 · 공개 화면 보기 · 운영 안내
         ├─ 중단: 연결된 태블릿 · 적용 화면 세트 · 콘텐츠 카드 요약
         └─ 하단(액션): 화면 세트 변경 · 콘텐츠 편집 · 대기화면 · QR 안내
```
- "코너"의 1차 표현체 = **태블릿(store_tablets, location/name)**. 현재 데이터상 코너 ≈ 태블릿(location 우선). → **코너 = 위치 라벨(location||name) 기준 카드**로 표현하고, 그 코너에 연결된 태블릿/current_screen_set 을 하위로.
- 순서: **코너 선택 → 태블릿 연결/확인 → 화면 세트 선택 → 콘텐츠 확인/편집 → 공개 화면 확인**. (현행 "태블릿 선택 → 상세 설정" 폐기.)

### 4.1 코너 홈 카드
```
[구강관리 코너]
  현재 화면 세트: 구강관리 기본 화면 세트
  콘텐츠 카드: 5개 · 태블릿: 연결됨(활성)
  [공개 화면 확인]  [관리]
```

### 4.2 코너 상세
- 편집기를 **한 번에 다 펼치지 않는다**. 요약 카드 + "편집" 진입(모달/서브뷰). 콘텐츠·세트·대기화면은 각 액션에서 focused 편집.

## 5. 태블릿 연결/추가 흐름 (재설계)
```
기존: "태블릿 추가" 단일 버튼 → 폼 → 목록
신규:
  1. 코너 선택
  2. "이 코너에 태블릿 연결"
  3. 사용 가능한 태블릿 카드 목록(미리보기/식별 정보)
  4. 대상 선택 → 연결
신규 태블릿 필요 시:
  1. 코너 선택 → "새 태블릿 등록"
  2. 이름/설명 입력 → 이 코너에 바로 연결
  3. 공개 URL/QR/바로가기 안내 표시
```
- 즉 **등록·연결 모두 코너 선택 이후**. 재사용: 기존 createTablet / current-screen-set apply / 공개 URL(tabletId) / QR 안내.

## 6. 화면 세트 선택 흐름 (카드형)
```
세트 카드: [현재 적용 중 배지] 이름 · 템플릿 · 콘텐츠/블록 수 · [미리보기] [적용]
```
- 작은 드롭다운/행 지양. TabletScreenSetManager 의 세트 목록을 **카드 그리드**로. 적용/편집/보관은 큰 버튼.

## 7. content_list 편집 흐름 (터치)
- 기존 ContentListEditor/ContentPickerModal(picker WO) 를 **터치 기준으로 확대**: 큰 카드, 출처 탭, 선택 목록 위/아래 버튼·표시 토글·제거(이미 버튼식), override 입력 큰 필드. raw JSON/좁은 행/hover 금지.
- product_content(구) raw JSON 은 신규 흐름에서 **미노출**(deprecated).

## 8. 모바일/태블릿 화면 구조 + PC 대응
```
스마트폰(≤640): 1열 코너 카드 → 코너 상세 풀스크린 서브뷰 → focused 편집(모달)
태블릿(641–1024): 2열 코너 카드 + 상세 패널
PC(≥1024): 코너 목록(좌) + 상세(우) 2-pane 도 가능하되, 동일 카드 컴포넌트 재사용(별도 PC 전용 화면 금지)
```
- **원칙: 터치 화면을 기본으로 만들고 PC 는 같은 컴포넌트를 넓게 배치**(그 반대 아님). "PC 화면을 줄이면 모바일" 전제 폐기.

## 10. 구현 단계 분리 (§8)
```
1. WO-O4O-KPA-TABLET-TOUCH-FIRST-CORNER-HOME-V1
     코너 카드 중심 첫 화면(코너=위치 기준). 코너 상세 진입. 기존 기능 링크만.
2. WO-O4O-KPA-TABLET-TOUCH-FIRST-TABLET-CONNECT-FLOW-V1
     코너 선택 후 태블릿 연결/신규 등록 흐름(카드형). apply/register 재사용.
3. WO-O4O-KPA-TABLET-TOUCH-FIRST-SCREEN-SET-CARDS-V1
     화면 세트 카드형 선택/적용(드롭다운/행 → 카드).
4. WO-O4O-KPA-TABLET-TOUCH-FIRST-CONTENT-LIST-EDITOR-V1
     content_list 편집 터치 확대(큰 카드/버튼).
5. WO-O4O-KPA-TABLET-TOUCH-FIRST-FINAL-SMOKE-V1
     스마트폰/태블릿 viewport 최종 확인(로그인 필요분은 인증 세션).
```
- 각 단계 additive: 기존 화면을 한 번에 갈아엎지 않고 신규 IA 를 얹은 뒤 구 진입을 전환. 단계마다 typecheck/build + (가능 범위) smoke.

## 11. PC 화면 대응 방식
- 별도 PC 전용 레이아웃 신설 금지. 터치 카드 컴포넌트를 grid 로 넓게 배치(≥1024 다열 + 선택 시 우측 상세). 동일 상태/핸들러 공유.

## 12. 위험 / 주의
```
- 코너 개념이 현재 store_tablets(location) 에 매핑됨 — "코너=위치" 표현이 데이터와 정합해야(신규 테이블 만들지 않음).
- current_screen_set_id 는 태블릿 단위 → "코너에 세트 적용" = 그 코너의 태블릿에 apply.
- 기존 편집기(TabletScreenSetManager) 재사용 시 dirty guard 유지.
- 관리 화면은 인증 필요 → 단계별 smoke 는 인증 세션/로그인 정책 준수.
- 공유 컴포넌트/공개 runtime 무접촉(이번은 KPA 관리 프론트 IA).
```
