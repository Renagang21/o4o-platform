### 관찰
- **MULTI_FUNCTIONAL 3건 전부 유산균+식이섬유**(배변활동 원활 이중 소구). 다른 2원료 조합(비타민/아연/프리바이오틱스 등)은 이번 8건에 없음.

### 모델 확장 필요 사유
- 현재 라인은 **CFU / 중량(mg·g)** 축으로 표시량·함량 신뢰 카피를 만든다. 액상은 기준량이 부피(mL)라 그 축을 못 쓴다.
- **밀도 추정·mg 환산 금지**(레지스트리 cp1 사례 명시) — 액상 밀도를 임의 가정하면 창작(HFF-R09 grounding 실패). 그러므로 중량 모델 재사용이 아니라 **부피 차원 자체를 지원하는 모델 확장**이 필요.
- 액상은 **두 하위형**으로 갈린다(§5 제안):
  - **음료형** — 65~110 mL/병, 1병 섭취(야쿠르트 계열). "1병당 100억 CFU" 카피가 자연스러움.
  - **드롭/오일형** — 0.15~0.3 mL/회, 영유아 대상, 방울 적하. 표시 단위가 매우 작고 대상·톤(영유아·보호자)이 음료형과 다름. **영유아 대상 주의문구·섭취 톤**이 별도 검증 필요.

## 3. 복합형(multi-functional) 스캔 — MULTI_FUNCTIONAL

### 판정 신호
- **A. base 시험항목** — 프로바이오틱스 외 2번째 기능성분이 **별도 정량기준**으로 존재(예: `식이섬유(%) : 표시량 … 80% 이상`).
- **B. mf_raw(인정 기능성 전문)** — 2번째 기능성 블록.

> **중요 관찰(판정 신호 함의):** 이번 4건 모두 신호 **A(base)에서만** 검출되고 신호 **B(mf_raw)는 전부 빈 값**이었다. 즉 mf_raw 에는 유산균 3기능만 기재되고 식이섬유는 **base 시험항목에만** 나타난다. **mf_raw 단독 스캔으로는 복합형을 놓친다 → base 시험항목 스캔이 1차 신호**여야 한다(§5 제안 반영).

### 결과 — 풀 내 4건 (조합 전부 유산균+식이섬유)

| 제품 | 제조사 | 2번째 기능성분(base) | 상태 |

### 복합형 파일럿 후보군 규모 추산
- 유산균 잔여 풀 735건 기준 **유산균+식이섬유 = 4건**(전체의 약 0.5%). 소규모.
- 다른 2원료 조합(비타민/아연/프리바이오틱스/프락토올리고당 등)은 이 풀에서 **0건**(17개 기능성분 사전 스캔). 즉 현 유산균 라인의 복합형은 **사실상 "유산균+식이섬유 배변 이중소구" 단일 패턴**이다.
- → **별도 복합형 파일럿의 1차 범위 = 유산균+식이섬유 4건**으로 좁게 시작 가능. 검증 골격 1종이면 커버된다(제품별 함량·제형만 상이). 다원료 복합형은 이 풀 밖(면역/항산화 등 타 기능성 그룹)에서 별도 조사 필요.

## 4. 스캔 커버리지·정합성 검증

- 대상 풀 = `poolA-remaining.json` 735건. prod-a HOLD 8건 **전부 이 풀에 잔존**(HOLD 파일이 사후 생성돼 pool 제외 목록에 미반영)함을 확인 → 스캔이 기존 HOLD 를 재검출하는지로 **재현성 교차검증** 가능.

- 액상 스캔이 `VOL_BASIS` 단독(성상 고형인데 base 에 mL)으로 잡은 오탐 = **0건**(7건 전부 성상 액상 FORM 신호).

## 5. HOLD 코드 레지스트리 보강 제안 (초안 — 원본 미수정)

> 아래는 **제안**이며 `HFF-DESCRIPTION-HOLD-CODE-REGISTRY-V1.md` 를 직접 고치지 않는다. 채택 여부는 검수자 판단.

### 제안 A — `UNSUPPORTED_DIMENSION` 하위분류(음료형 / 드롭·오일형)
현재 판정신호 "기준량이 부피(mL)"는 유효하나, 액상이 **두 제작 톤**으로 갈린다:

| 하위 | 신호 | 특성 | 모델 확장 시 고려 |
|------|------|------|------------------|
| `…:BEVERAGE` | 기준량 65~110 mL/병, 성상 액상 음료 | 1병 섭취, 성인 | "1병당 CFU" 카피 축 |
| `…:DROP_OIL` | 기준량 0.1~0.3 mL/회, 성상 액상/오일 드롭 | 영유아, 적하 | **영유아 대상 주의문구·보호자 톤** 별도 검증 |

→ 밀도 추정 금지 원칙은 공통 유지. 모델 확장 WO 시 두 톤을 분리 설계 권장.

### 제안 B — `MULTI_FUNCTIONAL` 판정신호 우선순위 명문화
현행 판정신호 "표시량에 2번째 기능성분(식이섬유 등)"에 **검출 소스 우선순위**를 추가 권장:

```text
1차 신호 = BASE_STANDARD 시험항목의 2번째 기능성분 정량기준
           (예: "식이섬유(%) : 표시량 … 80% 이상")
2차 신호 = mainFunction(mf_raw) 의 2번째 기능성 블록
주의: 식이섬유형은 mf_raw 에 유산균 기능만 기재되고 식이섬유가 base 에만
      나타나는 사례가 다수 → mf_raw 단독 스캔은 누락. base 시험항목이 1차.
```

### 제안 C — `SOURCE_ABNORMAL` 하위패턴 태깅(트리아지용)
원문 정정 요청을 유형화하면 식약처 정정/보완 경로가 명확해진다:

| 태그 | 예 | 정정 성격 |
|------|-----|-----------|
| `:OPERATOR_TYPO` | `1.0*x10^9`, `2.0 x 100,000,000` | 연산자·계수 표기 정정 |
| `:DECIMAL_THOUSAND_MIX` | `10.000,000,000` | 소수점/천단위 구분자 혼용 |
| `:UNIT_LABEL_ABSENT` | `10,000,000,000/350mg`(CFU 라벨 없음) | 단위 라벨 **보완** — GROUNDING 경계, "숫자 존재"로 구분 |
| `:VALUE_UNIT_SPLIT` | `수(CFU/2,000mg):표시량(250,000,000)` | 수치·단위 분리 표기 정규화 |

→ `:UNIT_LABEL_ABSENT` 는 GROUNDING 과 인접하나 **숫자 토큰이 존재**하므로 SOURCE_ABNORMAL 유지가 타당(레지스트리 GROUNDING 판정신호 "숫자 토큰 0" 미충족). 이 경계 판정 근거를 레지스트리에 1줄 명문화 권장.

## 6. 예외군 처리 우선순위 (검수자 판단용 입력)

| 순위 | 대상 | 규모 | 성격 | 즉시 조치 |
|:---:|------|:---:|------|-----------|
| 1 | 신규 액상 6건 격리 기록 생성 | 6 | UNSUPPORTED_DIMENSION | `*-hold.json` 추가(초안 금지). 라인에서 확실히 제외 |
| 2 | 신규 복합형 1건(슬림풀 나이트) 격리 | 1 | MULTI_FUNCTIONAL | `*-hold.json` 추가 |
| 3 | 복합형 파일럿(유산균+식이섬유) 설계 | 4 | 별도 파일럿 | 골격 1종으로 소규모 착수 가능 |
| 4 | 액상 모델 확장 WO(음료형/드롭·오일형 2톤) | 8 | 우리 모델 확장 | 영유아 톤 검증 포함 |
| 5 | SOURCE_ABNORMAL 5건 원문 정정/보완 목록 | 5 | 식약처 원문 | 하위패턴 태깅 후 정정 요청 취합 |
| 6 | GROUNDING 1건(신프로바이오틱스) | 1 | 원문 보완 | 원문 CFU 확보 전까지 대기 |

> 규모 총계: 즉시 격리 대상 **7건**(액상 6 + 복합 1) · 파일럿/모델확장 검토 대상 **12건**(액상 8 + 복합 4) · 원문 의존 **6건**(SOURCE_ABNORMAL 5 + GROUNDING 1).
> 레지스트리 원칙: 생산량 목표를 채우려 예외를 대체 후보로 보충하지 않는다 — 검증된 범위 내 정확 생산이 목표.
