## 3. 사용한 DB 접속/검증 방식

- `product_masters`(OTC 57,572행)에서 성분(name 끝 괄호), 함량(specification 첫 토큰, 한글 `밀리그램`/`마이크로그램`), 제형(name 키워드) 파싱.

- **핵심 확인:** `product_drug_extensions`의 임상/구조화 필드(`strength`·`dosage_form`·`active_ingredients`·`ingredient_summary`·`efficacy_text` 등)는 OTC 전 품목 **NULL**(보수정책 mirror). 반면 코드 필드(`mfds_code`·`drug_code`·`atc_code`)는 채워짐. 따라서 구조화 그룹핑은 코드 identifier + 원문 파싱에 의존한다.

## 14. 최종 100그룹 후보 가능성 판단

**판단: C(보류) — 현행 "단일성분·경구·자동초안" 기준으로 100그룹 불가.**

근거:
1. 정규화·필터·완료제외 후 단일·경구 clean 신규 = 32개(자동 3 / 검토강화 21 / 저grounding 8), 진짜 신규 성분 ~13–15개.
2. 100 도달은 (a) 복합제(grounded 67그룹, A급 27) 또는 (b) 국소·비경구 route 축을 열어야만 산술적으로 가능.
3. 그러나 (a)는 **복합제 그룹핑 규칙**(성분 조합 정규화·주성분 판정)이, (b)는 **route별 템플릿**(사용 안내/삽입/도포)과 수동 큐레이션이 아직 없다.
4. 저grounding·저카피 꼬리(D 124)로 수를 채우는 것은 §3.8(근거 없는 자동 보강 금지)·매장 가치 측면에서 부적합.

**조건부 가능(B) 경로:** 아래 선행 시 100그룹을 "혼합 축(단일 32 + 복합제 40~50 + route 10~15)"으로 재정의하면 가능.
