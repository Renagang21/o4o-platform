## 확인한 문제와 변경

사용자는 `/admin/operations-operators`의 초대 버튼을 누르면 오류 문구 없이 깜빡이고 끝난다고 보고했다. 기존 코드와 실제 브라우저 합성 재현에서는 요청 실패 안내가 긴 담당 업무 목록 위에만 있어 하단 버튼 위치에서 화면 밖에 남았다. 1280px/390px에서 alert viewport ratio 0으로 수정 전 회귀가 실패했다. 서버가 실제 발송을 확인한 경우에도 초대창을 곧바로 닫아 결과를 놓칠 수 있었다. 객체 형태 서버 error를 문자열로 가정해 렌더링하는 부분도 보정했다.

발송 동작 위치에 고정된 결과 영역을 두고 요청 중·실패·확인된 성공을 표시한다. 성공 시 사용자가 완료를 누를 때까지 초대창을 유지하고 다시 발송하지 않는다. 응답 `success: true`를 확인하지 못하면 성공으로 표시하지 않는다. 요청 중 대상·업무 입력을 잠그고 기존 중복 클릭 lock을 유지한다. 실패 시 입력·업무 선택을 보존하며 오류에 focus를 보낸다.

`INVITATION_MAIL_FAILED`는 초대가 이미 저장됐으나 SMTP 발송이 확인되지 않은 응답이다. 새 초대를 자동 생성/재발송하지 않고 기존 수락 대기 목록으로 이동해 확인할 수 있게 했다. 실제 SMTP 수락 계약, 기존 사용자 선택, 본인 수락, Google, 역할·메뉴·조직 경계는 바꾸지 않는다.
