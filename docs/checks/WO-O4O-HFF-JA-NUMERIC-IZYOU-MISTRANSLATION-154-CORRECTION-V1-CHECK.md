## 2. 교정 엔진 확장

착수 시점 가드는 `표시량(X)의 N 이상 M 이하` 같은 **완결된 규격 문형**만 처리했다.
실측된 미교정 문형은 범위가 더 큰 값 표현의 일부였다.

```
비타민D：4.00ug/800mg의 80% 이상 ~ 190% 이하
비타민C(%): 표시량의 80 이상 150 이하 (100mg/6000mg)
비타민C(%) : 표시량(1,000 mg / 1,100 mg)의 80 이상 150 미만
```

두 가지를 확장했다.

1. **수치 범위 일반 규칙(`NUM_RANGE`)** — 하한·상한이 **짝을 이룰 때만** 발동한다.
   두 수치와 종결어(`이하`/`미만`)를 모두 요구하므로 안전 문맥의 `이상`(이상사례·이상반응)에는 걸리지 않는다.
2. **전각 괄호 수용** — 규격 문형이 `（ ）` 를 쓰는 원문을 놓쳐 fallback 으로 밀리고 있었다.

### 2-1. 확장 중 발견·차단한 자기 결함

`NUM_RANGE` 를 넣자 괄호가 있는 값의 표기가 훼손됐다.

```
表示量（94.5 mg/3,000 mg）の80以上150以下   (정상)
表示量94.5mg/3,000 mg)の80以上150以下      (훼손 — 여는 괄호 소실)
```

앞부분이 일반 조합 경로로 흘러가며 괄호를 잃은 것이다. **앞부분에 괄호가 있으면 이 규칙을 쓰지 않도록**
막고, 괄호 형태는 문형째로 확정하는 `specValueCore` 가 처리하게 했다. 교정 후 표기 보존을 재확인했다.

확장 효과: 교정 대상 115 → **120**, `STILL_MISTRANSLATED` 14 → 9.
