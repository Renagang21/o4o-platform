# 협동조합·약국 협업체 공급 조건 및 콘텐츠 승인

> 상태: COMPLETED
> 작성일: 2026-10-17
> 범위: 코드 조사·보완·로컬 검증. 운영 적용 완료를 의미하지 않는다.

## 조사와 변경

| 흐름                             | 조사 결과                                                                                            | 이번 변경                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 공급자 협업체별 공급 조건        | `SupplyProposalService`, `/neture/supplier/supply-proposals`, 공통 운영 UI의 공급 제안 탭에 구현     | 재구현하지 않고 실제 DB에서 사업별 가격·승인 격리 확인. 협동조합 어댑터도 재사용  |
| 협업체 자체 제작                 | `SemiFranchiseContentService.operatorCreate/Update/SetStatus` 및 공통 편집기 구현                    | 작성·초안·수정·게시·보관 유지. 조합 하위 URL에서 편집·복귀하는 어댑터 추가        |
| 공급자의 특정 협업체 전용 콘텐츠 | 기존 라이브러리 handoff는 catalog 서비스 단위 CMS 전달. `semi_franchise_contents`는 운영자 작성 전용 | 별도 협업체 제출함 → 담당 운영자 승인·게시 → 기존 사업 자료·매장 사본 흐름에 연결 |
| 회원 자료·복사                   | 기존 사업 자료 조회와 `pharmacyCopy` 구현                                                            | 파일 첨부도 회원 사업 자료에서 표시. 문서와 사본은 기존 계약 유지                 |

회원 전용 콘텐츠를 공개 CMS에 담지 않는다. 기존 서비스 공용 handoff와 공개 공급자 자료 계약은 유지하며,
협업체 전용 자료는 새 ‘협업체에 제출’ 경로를 이용하도록 공급자 화면에서 구분한다.
새 제출은 `is_public`을 켜거나 CMS 공용 게시물을 만들지 않는다.

## 저장·권한·수명

- `semi_franchise_content_submissions`: 제출 대상 사업, 소유 공급자, 원본 자료 식별, 제출 당시 본문/첨부 스냅샷, 심사 기록.
- 제출은 활성 공급자의 자기 자료만 가능하다. 대상 사업은 active여야 한다.
- 대상 담당 조회/심사는 기존 `neture:operator` scope와 `requireOperatorOf`를 통과한다. 다른 사업의 ID는 404.
- 동일 원본의 같은 사업 중복 제출은 advisory lock과 부분 UNIQUE로 방지한다. 반려 후 수정·재제출은 새 심사로 처리한다.
- 승인 시 행 잠금 안에서 게시 콘텐츠 INSERT와 심사 결과를 함께 저장한다. 실패 시 모두 롤백한다.
- 승인 시점의 사업·공급자 활성 상태를 확인한다. 제출 당시 버전만 게시하며 원본의 후속 수정은 전파하지 않는다.
- 게시된 자료 조회/복사는 기존 활성 가입 약국 조건을 따른다. 보관·가입 정지는 이후 조회를 차단하지만 이미 만든 매장 사본은 유지한다.
- 외부 파일은 링크와 메타데이터를 복사한다. 외부 저장소의 실제 파일 수명은 이 사본 계약으로 보장하지 않는다.
- 새 제출함에도 기존 account-erasure writer fence를 적용한다.
- 개인 조합원 가입은 약국 조직 가입과 다르며 이 변경에서 합치거나 새 역할을 발급하지 않는다.

## 영향 소비처

| 소비처                  | 적용                                                                                                |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| Neture 공급자           | 기존 자료실에 특정 협업체 선택·제출 대화상자                                                        |
| Neture 담당 사업 운영자 | 공통 모듈에 공급자 콘텐츠 심사 탭                                                                   |
| pharmacy 및 megapharm   | 동일 약국 앱의 `BUSINESS_SITE.key`에 고정되는 공통 운영 모듈·사업 자료 화면                         |
| 협동조합 앱             | 명시적 businessKey + 인증 client + 해당 조합 운영 snapshot이 있을 때 같은 모듈을 하위 경로에서 사용 |
| 기존 내 매장            | 게시 콘텐츠의 기존 사본 API·자료함 계약 유지                                                        |
| 연합회·개인 회원·강의   | 운영 권한 자동 상속 없음. 강의는 기존 독립 서비스 이용                                              |

협동조합 앱의 실제 계정 연동·디렉토리는 아직 후속 범위다. 합성 세션/transport로 어댑터를 검증한 결과를
운영 계정의 접근 성공으로 주장하지 않는다. 공급자·운영자·가맹약국의 새 운영 데이터나 역할은 만들지 않았다.
제휴 경영지원은 구현하지 않으며 공동 상품 기획은 오프라인 업무다.

## 검증

- frozen/offline 설치, 공통 패키지 빌드.
- API, Neture, 기존 약국 서비스 타입 검사 및 Neture·약국·협동조합 프로덕션 빌드.
- PostgreSQL 15의 전용 폐기 가능 컨테이너에 canonical baseline과 전체 incremental을 순서대로 적용.
  기존 모든 prefix 지문 일치, 신규 지문 `2cc1fe67bd4d672ffbe5cb35e2f12d0f4964e18e43d35ae1a65b3daa21297629` (6721줄).
- 신규 migration down이 직전 지문을 복원함을 확인한 뒤 해당 검증 트랜잭션은 롤백.
- DB 통합 테스트: 제출 소유·사업 격리, 동시 중복 제출, 승인 전 비노출, 제출 버전 보존, 승인/반려,
  실패 롤백·동시 승인, 사본 독립성, 자체 작성·게시, 기존 공급 조건의 사업별 승인.
- UI 테스트: 공통 운영 모듈·자체 편집기, 공급자 제출·실패/재시도, 기존 약국 자료, 협동조합 경로/어댑터.
- 선택한 테스트 105개 통과: 백엔드 33개(제출/실제 DB 12개 + 기존 migration 계약 21개),
  공통 운영 UI 27개, 공급자 제출 3개, 기존 약국 자료 10개, 협동조합 32개.
  DB 관련 7개도 격리 fixture 플래그를 설정해 실행했으며 skip을 통과에 포함하지 않았다.
- migration 정적 계약 21개·변경 파일 ESLint 통과. 번들 크기/기존 브라우저 데이터 경고는 남지만 빌드는 성공했다.
- 실제 Chromium + 로컬 합성 응답: PC/모바일 공급 승인, 제출물 내용 확인·승인·게시, 조합 자체 작성·저장·복귀.
  브라우저의 합성 API 응답 검증과 실제 DB 서비스 검증은 구분한다. 운영 로그인/데이터 변경은 수행하지 않았다.
- 임시 브라우저 entry 파일은 삭제했으며, DB 테스트 제출물 0건 확인 후 검증용 컨테이너·tmpfs 데이터를 제거했다.

운영 배포에는 신규 migration 검토·적용이 선행되어야 한다. PR/CI·병합·배포는 통합 담당에게 인계하며 이 작업에서는 실행하지 않는다.
