## 0. 결론

**PASS.** 코너 관리에 **점 3개 메뉴(미리보기 / 이 화면 사용 / 코너에서 제거)** 와 **콘텐츠 미리보기**를 붙이고, 현재 사용 중 콘텐츠를 강조했다. 보호 샘플로 **다중 연결 → 전환 → 공개 반영 → 409 → 연결 제거**를 전부 실측했다. **API·DB·kiosk-core·QR·보관 정책·제작 UI 무변경.**

## 1. 선행분과의 관계

연결 목록 · 현재 표시 · 빠른 교체 · 적용 해제 · 순서 · 기존 콘텐츠 추가 · 연결 해제(409 업무 언어)는 **LINK-UI-V1 에서 이미 구현**됨. 이번 WO 의 신규분은 아래 4가지다.

| 신규 | 내용 |
|------|------|
| 점 3개 메뉴 | 표준 `RowActionMenu`(@o4o/ui) + `defineActionPolicy`/`buildRowActions`(@o4o/operator-ux-core) 재사용 |
| 콘텐츠 미리보기 | `fetchScreenSet`(저장 원본 read-only) → `previewScreenSet` → `TabletKioskPage embedded`. 태블릿/QR 모바일 전환 |
| 현재 강조 | 카드 `ring` + 인디고 배경 + `● 현재 사용 중` 필 배지 |
| 터치 우선 | 주 동작 `이 화면 사용` 큰 버튼(min-h 44px), 순서는 44px 아이콘 버튼 |

문구: `콘텐츠 연결` → **`기존 콘텐츠 추가`**.

## 2. 액션 정책 (실패 기준 대응)

```ts
preview : 항상
apply   : visible = !isCurrent      // 현재 콘텐츠엔 '이 화면 사용' 숨김
remove  : visible = !isCurrent      // 비현재만 제거 가능 (서버도 409 로 이중 방어)
          confirm = "…이 코너의 목록에서 뺍니다. 콘텐츠 자체는 삭제되지 않고,
                     다른 코너의 연결도 그대로 유지됩니다."
```
→ **'코너에서 제거'가 원본 삭제처럼 표현됨** 실패 기준을 문구로 차단.

> UI 는 현재 콘텐츠의 remove 를 숨기지만, 경합(다른 세션이 current 를 바꾼 경우) 대비로 **409 `CURRENT_CONTENT_CANNOT_BE_REMOVED` 핸들러는 유지**한다(업무 언어 toast).

### 4-1. 최종 데이터 상태 (원복·자동삭제 없음)

```
구강관리 코너 연결: [구강관리 기본 화면 세트(현재)] [피부관리 기본 화면 세트]
```
- 검증용으로 추가한 **피부↔구강 연결은 존치**한다(다중 연결 테스트 데이터 유지).
- 전환 검증 중 구강 코너의 현재 화면이 일시적으로 피부 콘텐츠였으나, **코너 의미에 맞게 현재를 구강으로 되돌렸다**. 이는 테스트 데이터 삭제·원복이 아니라 전환 기능의 정상 사용이며, 그대로 두면 구강 코너에 피부 화면이 표시되는 잘못된 운영 상태가 남기 때문이다.
- 콘텐츠 원본(구강 코너 설명 본문 등 선행 WO 의 저장분)은 **손대지 않았다**.

### 4-2. 검증 방법 메모

- 현재 콘텐츠 제거 409 는 **UI 에서 도달 불가**(정책이 remove 를 숨김) → 인증 API 직접 호출로 서버 계약을 확인했다.
- 인증 API 호출 시 쿠키만으로는 `401 AUTH_REQUIRED` — 이 앱은 **`localStorage.o4o_accessToken` Bearer** 를 쓴다(후속 smoke 참고).
