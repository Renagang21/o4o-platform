## 구현 결과

- 내 매장 제품에서 엑셀 첫 시트→바코드/상품명 열 지정→기존 DB·B2B 자료 대조→행별 상품 직접 선택→기존 멱등 master 등록 API→실패 행 재시도까지 연결했다. 파일 대조는 저장/생성을 수행하지 않는다. 원본 파일·가격·POS 코드·재고·주문은 저장하지 않는다.
- 미확보 자료는 이름·바코드만 담은 사용자 ChatGPT 조사 요청문으로 준비한다. 정부→제조사 공개 근거, 근거 없으면 미작성, 전체관리자 검토를 명시한다. 내부 유료 AI·자동 크롤러·자동 상품 생성은 추가하지 않았다.
- 기존 설명자료 JSON의 선택적 aiSections·근거를 후보 raw_payload에 보존하고 관리자 화면에서 검토한다. HTML 편집으로 본문이 바뀌면 이전 구조를 해제한다. 본문이 같아도 근거/구조가 바뀐 명시적 승인은 새 canonical에 반영한다. 기존 일반 canonical 승격의 동일 본문 no-op은 유지한다.
- 현재 매장의 활성 등록상품만 B2B/정확한 언어로 조회한다. 사실/전문 참고/판단지원/미분류를 구분해 기존 상담자료 작성 근거에 명시적으로 적용한다. 기존 약사 상담지원 요청에도 구조화 B2B만 근거로 추가하고 근거 변경을 sourceVersion으로 검증한다. STORE/다른 언어/검토 후보를 대체 조회하지 않는다.
- 공통 상품 QR의 관리자 발급·STORE 승인본 조회는 변경하지 않았다. 매장 자체 콘텐츠/마케팅 QR도 별도 자산으로 유지하며 일반 사용자에게 공통 QR 원본 작성권한을 부여하지 않았다.

## 한계·인계

운영 DB·실상품·실계정·공통 QR·설정·IAM·스케줄러·외부 AI 호출 변경은 없다. 새 schema/migration·의존성/lockfile 변경도 없다. 실제 테스트 계정 파일을 사용하지 않았으므로 실제 권한별 운영 이용이나 운영 배포 성공을 주장하지 않는다. 파일 대조는 세션 작업으로 새로고침 후 미등록 행이 유지되지 않는다. 공개 근거 조사/제작은 사용자 ChatGPT 수동 과정이며 외부 연결 담당의 MCP/OAuth를 변경하지 않는다.

공식 main 통합·배포는 사용자 지시에 따라 수행하지 않는다. 전용 branch/worktree를 유지하고 최종 PR·HEAD·CI/리뷰·미확인 운영 항목을 인계한다. CHECK는 원격 검사 성공을 미리 단정하지 않으며 후속 실패가 있으면 수정·재검증 후 보고한다.

## 실제 양식·리뷰 보완

사용자가 제공한 실제 엑셀은 3행이 머리글이며 3,077개 후속 행·47열이다. 원본 행/가격은 기록하지 않고 머리글 구조만 확인했다. 자동 머리글 탐지(앞 20행)·직접 선택, 관리번호(바코드) 열 인식과 5,000행 상한을 반영했다. 합성 양식 회귀와 별도로 실제 파일을 새 parser에 읽기 전용으로 통과시키며 운영 DB 매칭·상품 등록은 수행하지 않는다.

PR #887 Codex의 B2B 인용 ID와 전체 입력 예산 지적을 반영했다. 기존 p/r 인용 namespace를 유지하고 사용자 참고 r1은 예약한다. 게시 원문+B2B+사용자 참고 전체를 runner의 18,000자 예산 안에 구성하고 실제 extension prepare/parse 계약으로 회귀 검증한다. 초기 로컬 mock runner 검증만으로 이 경계를 확인하지 못했던 부분을 보완했다. 최종 재검증 수치는 후속 결과를 따른다.

실제 양식 보완·인용 계약·통합 예산·순차 처리/접근성 정비 후 API 8 suites/60개, 매장 전체 82 files/878개 및 최종 집중 7개(중복), 관리자 관련 7개가 PASS다. 실제 파일 parser는 머리글3행·후속3,077행·47열·바코드2열/상품명4열을 확인했다. 실제 상품 행과 가격은 공개 결과에 기록하지 않았다. Sonar의 기존 17건은 코드 보완 후 최신 HEAD에서 재분석하며 규칙/게이트를 완화하지 않는다.

## 인계 전 main 정합

`7d81e1a406`의 공식 CI 40883697917·Sonar gate·Codex 재리뷰가 성공했다. 최신 main `f2e8b678a8`의 별도 고객 상담 복구를 전용 branch에 통합했고 직접 충돌은 없었다. 원래 작업 밖 고객 화면의 변경은 임의 수정하지 않고 최신 main 코드와 관련 회귀를 확인했다. Sonar 잔여 경미 지적 5건(문자열 변환·조건 표현·마지막 항목 접근·새 상담 함수 복잡도)은 동작 보존 정비한다. 이후 최종 push의 원격 검사는 PR #887 최신 HEAD를 기준으로 재확인한다.

최신 main 통합 후 고객 상담 복구와 이번 변경의 집중 4 files/23개, PC/모바일 실제 앱 2개를 다시 통과했다. 최종 API 관련 8 suites/60개·API 타입/모든 bundle·매장 타입/production build·변경 lint 오류0·문서/정적 guard를 확인했다. 이전 전체 매장 878개와 집중 23개는 중복 합산하지 않는다.


## main 통합 재개 — 2026-10-30 (Asia/Seoul)

사용자 요청으로 PR #887의 main 병합·배포를 진행한다. 최신 main을 충돌 없이 반영했고 재리뷰에서 기존 catalog의 긴 section/40개 초과 항목이 구조화 한도에 걸리는 호환성 문제를 확인했다. 구조화 입력이 없는 기존 JSON은 선택 필드 aiSections를 자동 생성하지 않고 본문·근거를 그대로 보존하며, 기존 backend의 미분류 legacy 처리 경로를 유지한다. 명시적인 구조화 입력 검증 한도는 완화하지 않는다. 긴 본문·41개 section 회귀를 추가하며 최종 HEAD의 CI·리뷰·배포 결과는 기존 PR #887의 통합 기록으로 연결한다. 과거 개발 인계 범위는 당시 기록으로 보존한다.


추가 리뷰 보완: 숫자형 XLSX 바코드의 General 표시가 지수 표기로 바뀌는 경우 원래 안전한 정수 값을 십진 문자열로 사용한다. 명시적인 0 채움 표시·텍스트 바코드는 보존하고 상품명 등 다른 열의 표시 형식은 바꾸지 않는다. 실제 XLSX 생성→읽기→기존 상품 후보 대조의 숫자/0 채움 회귀를 추가한다. 파일·원시 행을 저장하거나 응답에 추가하지 않으며 기존 등록·조직 인가는 유지한다. 최종 검증 근거는 PR에 기록한다.


행 위치 회귀 보완: XLSX의 사용 범위 이전 빈 행도 표시값/원시값 변환에 함께 포함하도록 range=0으로 고정한다. 실제 3행 머리글 자동 탐지·직접 지정과 결과의 실제 4/5행 번호 및 첫 상품 보존을 실제 XLSX fixture로 확인한다.
