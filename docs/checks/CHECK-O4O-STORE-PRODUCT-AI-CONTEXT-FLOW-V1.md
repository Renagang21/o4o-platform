## 구현 결과

- 내 매장 제품에서 엑셀 첫 시트→바코드/상품명 열 지정→기존 DB·B2B 자료 대조→행별 상품 직접 선택→기존 멱등 master 등록 API→실패 행 재시도까지 연결했다. 파일 대조는 저장/생성을 수행하지 않는다. 원본 파일·가격·POS 코드·재고·주문은 저장하지 않는다.
- 미확보 자료는 이름·바코드만 담은 사용자 ChatGPT 조사 요청문으로 준비한다. 정부→제조사 공개 근거, 근거 없으면 미작성, 전체관리자 검토를 명시한다. 내부 유료 AI·자동 크롤러·자동 상품 생성은 추가하지 않았다.
- 기존 설명자료 JSON의 선택적 aiSections·근거를 후보 raw_payload에 보존하고 관리자 화면에서 검토한다. HTML 편집으로 본문이 바뀌면 이전 구조를 해제한다. 본문이 같아도 근거/구조가 바뀐 명시적 승인은 새 canonical에 반영한다. 기존 일반 canonical 승격의 동일 본문 no-op은 유지한다.
- 현재 매장의 활성 등록상품만 B2B/정확한 언어로 조회한다. 사실/전문 참고/판단지원/미분류를 구분해 기존 상담자료 작성 근거에 명시적으로 적용한다. 기존 약사 상담지원 요청에도 구조화 B2B만 근거로 추가하고 근거 변경을 sourceVersion으로 검증한다. STORE/다른 언어/검토 후보를 대체 조회하지 않는다.
- 공통 상품 QR의 관리자 발급·STORE 승인본 조회는 변경하지 않았다. 매장 자체 콘텐츠/마케팅 QR도 별도 자산으로 유지하며 일반 사용자에게 공통 QR 원본 작성권한을 부여하지 않았다.

## 한계·인계

운영 DB·실상품·실계정·공통 QR·설정·IAM·스케줄러·외부 AI 호출 변경은 없다. 새 schema/migration·의존성/lockfile 변경도 없다. 실제 테스트 계정 파일을 사용하지 않았으므로 실제 권한별 운영 이용이나 운영 배포 성공을 주장하지 않는다. 파일 대조는 세션 작업으로 새로고침 후 미등록 행이 유지되지 않는다. 공개 근거 조사/제작은 사용자 ChatGPT 수동 과정이며 외부 연결 담당의 MCP/OAuth를 변경하지 않는다.

공식 main 통합·배포는 사용자 지시에 따라 수행하지 않는다. 전용 branch/worktree를 유지하고 최종 PR·HEAD·CI/리뷰·미확인 운영 항목을 인계한다. CHECK는 원격 검사 성공을 미리 단정하지 않으며 후속 실패가 있으면 수정·재검증 후 보고한다.
