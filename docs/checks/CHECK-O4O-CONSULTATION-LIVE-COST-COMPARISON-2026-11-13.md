## 1. 연결과 검증 범위 변경

사용자가 TinyFish를 연결하고 검증용 브라우저에서 직접 운영자 로그인 후 상태를 저장했다. 그 저장 상태로 admin.neture.co.kr/settings의 인증과 AI 운영 관리 → 사용량·비용 조회를 실제 확인했다. 이전 기록의 “관리자 계정·조회 연결 없음”은 이 후속 검증에서 해소됐다. 운영 DB 직접 연결이나 credential 전달을 사용하지 않았다.

사용자는 **전문 상담의 최종 품질 검수를 별도 세션에서 진행**한다고 명시했다. 이번 작업은 이를 대신 판정하지 않고 기술적 비용·응답 및 관리자 자료 준비 조회를 진행했다. 약사 품질 검수를 현재 세션 진행의 차단 조건으로 재요청하지 않는다.

TinyFish는 ChatGPT의 브라우저 연결 도구이며 O4O 관리자 메뉴에 설치되는 기능이 아니다. 이후 반복 검증에도 저장 프로필을 선택해 대상 사이트의 실제 인증 상태를 먼저 확인할 수 있다. 로그인 만료 시 사용자가 다시 로그인·저장하며, 비밀번호/쿠키/토큰/프로필 접근 링크를 저장소에 복제하지 않는다. 저장 프로필이 있다는 사실로 다른 계정·매장 권한이나 상태 변경 권한을 추정하지 않는다.

## 2. 운영자 사용량 스냅샷

실제로 읽힌 화면의 공급자/모델은 세 scope 모두 `gemini / gemini-3.8-flash`였다. 최근 7일 기간 시작은 2026-11-07 00:00 KST이며 종료는 조회 시점이다. 아래는 운영 응답 원문이 아닌 화면 집계의 요약이다.

| 관측 시점(KST) | 전체 기록 | 전체 추정 USD | 번역 기록 | 번역 입력 token | 번역 출력 token | 번역 추정 USD |
|---|---:|---:|---:|---:|---:|---:|
| 11:31:57, 추가 시험 전 | 16 | 0.17541550 | 3 | 432 | 270 | 0.00062100 |
| 11:34:46~47, 기준 2회 후 | 18 | 0.17632000 | 5 | 720 | 777 | 0.00152550 |
| 11:38:00, 동일 세션 2회 후 | 19 | 0.17651200 | 6 | 864 | 857 | 0.00171750 |

번역은 `CONTENT_TRANSLATION`의 매장 콘텐츠 번역·약국 상담 번역 공용 집계다. 세 관측에서 오류 기록·비용 미집계 기록은 화면상 0이었다. 미계측 token 여부를 별도로 확정할 필드가 보이지 않았으므로 전체 과금/usage coverage를 완전하다고 판정하지 않는다.

다른 scope는 세 관측에서 그대로였다.

| scope | 기록 | 입력 token | 출력 token | 추정 USD |
|---|---:|---:|---:|---:|
| OPERATOR_INSIGHT | 1 | 239 | 778 | 0.00128650 |
| SERVICE_QUERY | 12 | 274,215 | 24,267 | 0.17350800 |

`PRODUCT_CONTENT`의 비용 행은 보이지 않았다. 이는 해당 기간 이 화면에 기록된 행이 없다는 뜻이며 그 업무가 무료·미사용·실행 불가라는 증거는 아니다. SERVICE_QUERY는 홈 대화 외 여러 사용처를 공유하므로 이 합계를 neture 초기화면 비용이라고 단정하지 않는다.

화면은 기존 로그와 전문 호출 예약 이력을 중복 없이 집계하되 일부 호출은 미연결일 수 있고 기록 수는 실제 유료 attempt 수와 다를 수 있다고 안내한다. 추정 비용은 공급자 청구액이 아니다. 가격 버전은 이번 화면 조회에서 확인하지 못했다. 단위/통화는 USD로 표시됐다.

## 3. 동일 조건의 실제 번역 시험

운영 경영자 Demo의 현재 허용된 `floor-staff` 모드로, `welcome` 인사말·`en`·`to-customer`를 사용했다. 고객/건강정보를 넣지 않았고 station은 지정하지 않았다. 이전과 별도의 추가 시험 4회이며 자동 재시도는 추가하지 않았다. 기준 두 번은 `reuseSession`을 생략했고, 다음 두 번은 새 UUID를 동일하게 보냈다. 계정·모드·인사말·언어를 바꾸거나 운영 설정을 수정하지 않았다.

| 시험 | 실제 요청 창(KST) | HTTP 결과 | 왕복 시간 |
|---|---|---|---|
| 기준 2회 | 11:33:55.737~11:34:03.897 | 200 / 200 | 3,655 / 4,503 ms |
| 동일 세션 첫 요청·반복 | 11:35:43.066~11:35:46.507 | 200 / 200 | 2,950 / 488 ms |

모두 `private, no-store`였다. 기준 그룹 안의 두 응답은 같았고 재사용 그룹 안의 두 응답도 같았다. **기준 그룹과 재사용 그룹 사이의 번역 문자열은 달랐다**(동일 길이·다른 digest). 모델의 새 생성 결과를 서로 완전히 같다고 판정하지 않는다. 원문 출력이나 digest 자체를 저장소에 복제하지 않고 동일성 판정만 기록한다.

화면 집계의 차이를 독립적으로 계산하면 다음과 같다.

| 측정 항목 | 기준 HTTP 2회 뒤 증가 | 동일 세션 HTTP 2회 뒤 증가 |
|---|---:|---:|
| CONTENT_TRANSLATION 기록 | 2 | 1 |
| 입력 token | 288 | 144 |
| 출력 token | 507 | 80 |
| 추정 USD | 0.00090450 | 0.00019200 |

다른 scope 기록·비용은 변하지 않았고 전체 합계 증가도 번역 행 증가와 일치한다. 이는 **이 표본에서 동일 세션의 반복 생성·비용 집계 감소를 뒷받침하는 운영 증거**다. 수집 도구의 서술 중 SERVICE_QUERY에 번역이 반영될 수 있다는 추측은 채택하지 않았다. 실제 변한 행은 CONTENT_TRANSLATION이며 SERVICE_QUERY 값은 동일하다.

다만 조회 API는 7/30/90일의 공급자·모델·scope 합계만 제공하며 특정 actor/10초 구간/요청 ID를 분리하지 않는다. 같은 시간 다른 사용자의 번역이 섞이지 않았음을 원시 로그로 증명한 것은 아니다. 공급자 내부 attempt·retry/fallback·확정 청구도 확인하지 못했다. 기록 증가 2→1을 검증된 공급자 attempt 2→1이라고 표현하지 않는다.

출력 token이 두 그룹 사이에서 크게 다르므로 추정 비용 차이를 전부 재사용만의 고정 절감률로 설명하지 않는다. 표본 4개로 전체 서비스 비용 절감률·운영 p50/p95·동시 부하를 판정하지 않는다. 시간에는 환경 proxy와 클라이언트 왕복이 포함된다. TinyFish 등 검증 도구 자체의 비용은 이 O4O 사용량 집계에 포함되지 않으며 별도 비용도 이번에 대조하지 않았다.

## 4. 관리자 공통 자료 준비 조회

실제 운영자 화면에서 O4O 상품 DB → 설명서 접수 → 공통 자료 준비 패널을 조회했다.

- 패널이 로드됐고 화면에서 확인된 오류/사용 불가 상태는 없었다.
- 목적 선택의 `CONSULTATION/상담자료`와 `STORE/표준설명서`가 구분돼 있었다. QR 표준설명서 열도 별도로 표시됐다.
- 검토 대기·상품 등록 요청·설명서 검수의 표시 건수는 각각 0이었다. 이 숫자를 전체 공통 상품 수나 자료 완비율로 해석하지 않는다.
- 자료를 선택·생성·접수·승인·게시하지 않았다. 제품명·ID·원문을 기록하지 않았다. 정기 준비/실제 상품에 대한 자료 완성까지 검증한 것은 아니다.

직접 DB 조회나 신규 API/원장을 추가하지 않고 기존 관리자 집계로 가능한 대조를 수행했다. 여기까지를 7차 전체 운영 완료로 바꾸지 않는다. neture 초기화면의 ChatGPT 요금제 연동도 이번 번역 표본과 별개로 실제 참여 조건 이후 범위다.

## 문서 정합·작업 인계

앞선 CHECK의 연결 부재·관리자 조회 미실행은 당시 상태이며, 현재 상태는 이 날짜의 후속 증거로 보완한다. 약사 검수는 사용자가 분리한 범위임을 명시한다. 기존 비용·권한·보존 정본을 변경하지 않았다.

업무 데이터·station·게시 자료·권한·설정·운영 DB를 수정하거나 생성·삭제하지 않았다. 실제 AI 이용 및 로그인/조회에 수반되는 비용·보안 메타데이터는 기존 보존 정책을 따른다. 원장 삭제나 보존 정책 우회는 하지 않았다. 프로필/인증 상태는 사용자가 승인한 TinyFish 연결에서 보관되며 저장소에 노출하지 않는다.

이번 branch는 문서/집계 검산 기록만 포함한다. source·dependency·schema·배포 변경은 없다. PR 생성·병합·배포는 통합 세션 담당이다.
