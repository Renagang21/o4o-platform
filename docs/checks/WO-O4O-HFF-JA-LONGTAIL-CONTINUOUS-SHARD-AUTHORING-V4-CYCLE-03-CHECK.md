## 2. 게이트 차단 해소 (§4-B) — 680 → 6

### 2-1. 신규 도구 — `hff-ja-b04-gate-mine.mjs`

게이트는 조립 사고를 막지만 **어느 KO 문구가 사고를 냈는지** 말해주지 않았다.
이 도구는 차단 문서를 슬롯 단위로 재조립해 사고를 내는 슬롯의 KO 원문을 특정한다.
그 원문을 개별 사전 항목으로 저작하면 조립 경로를 타지 않아 사고가 사라진다 — 규칙 완화가 아니다.

첫 실행 결과: **build 가능한 680건이 전부 게이트 차단**이었다(직전 사이클 미적재분). 원인 문구는 239개.

### 2-2. 게이트 오탐 제거 — 차단의 주원인

원인 문구의 실제 출력을 확인하니 **차단의 대부분이 게이트 자체의 오탐**이었다.

| 출력 | 게이트 판정 | 실제 |
|------|-------------|------|
| `血中中性脂質の改善` | KANJI_DUP (中中) | **정상 복합어** |
| `身体組織の構成成分` | KANJI_DUP (成成) | **정상 복합어** |
| `直接接触しうる形態` | KANJI_DUP (接接) | **정상 복합어** |
| `包装材でけがをするおそれ` | PARTICLE_DUP (がを) | **정상** — `けが`(負傷) + `を` |
| `…役立つことがある2.体脂肪…` | CLAIM_RUN | **정상** — `2.` 이 항목 경계 |
| `そのまままたはを水とともに` | PARTICLE_DUP (はを) | **진짜 결함** |

교정 내용(규칙을 넓힌 것이 아니라 **오탐만 제거**):

| 규칙 | 변경 |
|------|------|
| `KANJI_DUP` | 임의 한자 중첩 → **색·정도 수식어에 한정** `[濃淡暗明濁微鮮黄白赤黒緑青紫褐灰桃橙]` |
| `PARTICLE_DUP` | `がを` 제외 (が 로 끝나는 명사 + を 는 정상) |
| `CLAIM_RUN` | 열거 번호(`2.` `(3)` `3)`)도 경계로 인정 |

**게이트 회귀 테스트**로 확인했다 — 정상 7종 통과 · 진짜 결함 6종(`はを` · `をが`+`濃濃` · `黄黄` ·
경계 없는 `役立つ` 연속 · 수치 뒤 `異常` · `。。`) 전부 차단. **오탐 0 / 미탐 0**.

### 2-3. 남은 진짜 결함 — 색 어근 중첩

`노란 연두색` 이 `黄`(노란) + `黄緑`(연두) 로 조립돼 `黄黄緑` 이 됐다. 일본어에 없는 표기다.
기존 `のの`→`の` 와 같은 계열의 **표기 정리 규칙**으로 폈다: `黄黄緑` → `黄みがかった黄緑`
(수식을 버리지 않고 색 이름도 바꾸지 않는다). 정도 수식어 중첩(`濃濃`)도 같은 자리에서 1회로 줄인다.
