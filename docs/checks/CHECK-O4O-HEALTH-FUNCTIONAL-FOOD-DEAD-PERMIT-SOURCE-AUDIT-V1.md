## 1. 결론 — per-item "폐업/취소" **flagged 원천은 없음**. 실효 신호는 회수·판매중지(조인 가능·범위 좁음). 전부 활용신청(사용자 조치) 선행.

- **우리 적재 데이터(HtfsInfoService03 / data 15056760)** raw.source 11필드에 **허가상태·취소·폐업 컬럼 없음**(기존 확인). MFDS 품목제조 계열은 취소/폐업/취하 품목을 **플래그가 아니라 목록에서 제외**하는 방식(공개 API 한계 명시) → 우리 41,261 은 적재 시점 기준 유효 레지스트리로 **죽은 허가가 애초에 포함돼 있지 않을 가능성**이 큼.
- 따라서 "죽은 허가로 대량 추출·삭제"는 **현 open 데이터로 직접 성립하지 않음**. 아래 3 원천이 부분 대안:
  1. **회수·판매중지(15074318)** — `품목제조보고번호` 포함 → 우리 STTEMNT_NO 조인 가능, 회수등급·사유 flagged. 단 "안전 회수/판매중지"이지 허가 말소 아님, 그리고 회수는 드물어 매칭 소수 예상.
  2. **품목제조 신고사항 현황(15058865)** — 상태 미플래그(제외방식). 현재 유효목록을 받아 우리 목록과 **absence-diff**(우리엔 있고 현황엔 없는 STTEMNT_NO = 사후 말소) 로만 활용. 단 적재 후 경과가 1일이라 현재 delta ≈ 0.
  3. **행정처분결과(식품판매업)(15124559)** — 업체(영업자) 단위 처분. 품목 단위 취소 아님(간접 신호).
- **공통 블로커**: 15074318 / 15058865 는 우리 data.go.kr 키에 대해 **활용신청(구독) 선행 필요** — data.go.kr 정책상 데이터셋별 수동 신청, **사용자 조치**(에이전트 불가).
- **DB write 0 / 수집 미실행**(구독 전).

**한 줄 결론:** MFDS open 데이터에는 건강기능식품 품목의 폐업/취소/취하를 **직접 표시하는 원천이 없다**(품목제조 계열은 말소품목을 제외해 버림). 실효적 "판매 부적합" 신호는 **회수·판매중지(15074318, 품목제조보고번호로 조인 가능)** 뿐이며 범위가 좁다. 이 원천들은 data.go.kr **활용신청(사용자 수동 조치)** 후에야 수집 가능하다 → 사용자가 15074318(및 선택적으로 15058865) 활용신청을 하면, 그 다음 WO에서 fetch·교차조회로 회수/판매중지 품목을 flag(리뷰/삭제 후보)한다.

## 5. 권장 경로

1. **사용자 조치**: data.go.kr 에서 우리 키(PUBLIC_DATA_SERVICE_KEY)로 **15074318(식품 회수·판매중지) 활용신청**(자동승인). 선택적으로 15058865(현황)도.
2. 승인 후 별도 WO: 15074318 fetch → `품목제조보고번호` 로 우리 41,261 STTEMNT_NO 교차조회 → 매칭 품목을 **review_required 또는 삭제 후보**(회수/판매중지 이력)로 flag. snapshot+승인 후 처리.
3. 15058865 는 **주기적 absence-diff**(월 단위 등)로 사후 말소 탐지 — 지금 즉시 이득은 없음.
4. **"죽은 허가 대량 삭제"는 현 open 데이터로는 비권장** — per-item 폐업/취소 원천 부재. 회수·판매중지 flag(소수) + 시장성 조사(별도)로 보수적 정리가 현실적.
