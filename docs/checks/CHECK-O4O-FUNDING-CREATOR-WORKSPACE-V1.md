# 유통참여형 펀딩 개설자 업무공간 검증

> 상태: IN_PROGRESS · 작성/갱신: 2026-10-11 · WO: [개설·심사·포럼·개설자 운영 정비](../work-orders/WO-O4O-FUNDING-CREATOR-WORKSPACE-V1.md)

## 변경과 경계

개설 주체는 활성 공급자, 실무 호스트는 funding.neture.co.kr이다. 개설자 자격은 현재 공급자 조직 owner/ACTIVE 상태와 정상 계정으로 판정한다. 신규 펀딩은 개설 당시 공급자 계정·조직을 상태 이력에 보존하고 자기 펀딩만 수정·신청·운영한다. 과거 user ID 소유 데이터는 보존하며 조직을 임의 배정하지 않는다.

신청 → 운영자 승인 이력 저장 → 전용 폐쇄형 포럼 생성 및 개설자 owner 연결 → 모집 시작 순서다. 포럼 실패 시 승인은 보존되고 submitted에서 복구한다. 반려는 사유·처리자를 보존하고 draft로 복귀한다. 일반 공개 경로는 초안·심사 중·승인 여부를 판별할 수 없는 과거 closed 자료를 노출하지 않는다.

포럼 원장은 기존 forum_category_requests/forum_category_members/forum_join_requests를 사용한다. 신규 게시판은 고유 slug funding-<UUID>와 코드 funding:<UUID>로 연결하고 market_trial_forums의 과거 게시글 ID와 구분한다. 참여·입금 확인·포럼 회원 원장은 별개다. 개설자가 포럼 회원 승인·반려·제거를 담당하며 입금 자동 승인·자동 제거는 없다. 공지·고정·참여자 글 삭제는 개설자와 현재 펀딩 운영자만 가능하고 일반 회원은 자기 글을 관리한다. 종료된 포럼은 읽기 전용이다.

schema/migration·대량 backfill·주문·PG·배송·상품 전환 변경은 없다. 오프라인 입금 확인과 처리 기록의 기존 운영자 경계를 보존했다.

## 자동 검증

- API 집중 회귀: 신규 개설·심사·포럼·회원·참여·공개/소유권 및 공유 포럼 테스트 186개 통과. 새 권한 해제·공급자 자격 재확인·심사 경합·실패 롤백·미공개 직접 주소·다른 게시판/펀딩·요청 역할 스푸핑을 확인했다.
- Neture 전체 Vitest: 60파일, 503개 통과. 호스트 이전 주소·신규 포럼 API·개설자 동작·비동기 응답·기존 커뮤니티 고정/회원관리 소비처 포함.
- API 및 Neture 빌드: 통과. 패키지 Market Trial 빌드 및 타입 검사 통과. 마지막 구현 변경 뒤 CI에서 동일 계약을 재검증한다.
- Chromium production preview: 1440px/390px에서 초안 신청, 보완 사유, 신규/수정, 가입 신청, 회원관리, 글쓰기 공지 선택, 종료 읽기, 운영자 포럼 개설 재처리 18상황 통과. JS 오류/전체 화면 가로 넘침 0. 모든 API 응답·쓰기 요청은 fixture로 차단·처리했으며 실제 운영 DB를 수정하지 않았다.
- 실제 PostgreSQL 동시 요청은 미검증이다. 단위 테스트로 트랜잭션 경계·행 잠금·상태 전제·롤백을 검증했으며 실계정·운영 원장 적용 결과와 구분한다.

## 직접 확인할 항목

인증된 브라우저 세션이 없어 다음은 사용자 수동 확인으로 남긴다. 비밀번호·토큰·이메일 등 계정 정보는 공개 문서에 넣지 않는다. 승인/진행 변경은 되돌릴 수 없는 단계가 있으므로 폐기 가능한 테스트 펀딩을 사용한다.

| 상황 | 기대 결과 |
|---|---|
| 활성 공급자, 일반 회원, 정지 공급자로 개설 공간 접근 | 활성 공급자만 생성·신청 가능; 일반 회원/정지 공급자는 차단 |
| 공급자 조직이 둘 이상 | 명시적 조직 선택; 다른 조직 컨텍스트/소유 펀딩 변경 차단 |
| 초안 저장·신청·반려·보완·재신청 | 사유 보존; 보완 가능; 동일 초안 재사용; 공개 접근 차단 |
| funding admin/operator 심사; 다른 서비스 운영자 접근 | 현재 펀딩 권한만 허용; 회수 후 기존 로그인 요청 차단 |
| 승인/재처리 동시 요청 또는 포럼 오류 후 재시도 | 승인·포럼 중복 없음; 포럼 준비 전에 모집 안 함; 승인 사실 보존 |
| 개설자가 자기 펀딩의 공지·고정·회원 승인/반려/제거·진행 관리 | 자기 펀딩만; 다른 펀딩/일반 서비스 포럼 접근 차단 |
| 일반 참여자가 가입 신청 후 승인, 입금 전 포럼 이용 | 승인 후 읽기·자기 글/댓글; 공지·고정·다른 글 삭제 불가 |
| 포럼 회원 제거; 운영자 입금 확인; 종료된 포럼 쓰기 | 참여·입금·처리 기록 보존; 입금 자동 가입 없음; 종료는 읽기만 |
| 기존 supplier 펀딩 주소·알림·과거 공고 링크 | 새 개설 공간 직접 연결; 과거 게시글 링크 보존; 신규 게시판 ID 혼용 없음 |

## 통합·배포

push·required CI·Codex blocker 확인·main PR 병합·Delivery 판정 및 서빙 SHA 확인 대기. 권한 관련 코드가 LEVEL 3으로 판정되면 현재 정책의 Promote 경로로 진행한다. 이 변경에는 운영 migration이 없다. 완료 후 이 절을 실제 PR/run/SHA로 갱신한다.

## 문서 정합

역할별 업무공간·content-only 경계·초기 운영 모델에 공급자 개설과 funding 실무 공간, 서비스 운영자 심사, 개설자 수동 포럼 운영을 반영했다. 오프라인 입금 정책과 productId legacy 정책은 유지한다. 과거 WO/실행 기록은 현행 구현으로 덮어쓰지 않는다.

### 통합 중 보완

공유 Guide route 계약 검사에서 공급자 업무공간의 옛 펀딩 주소 2곳이 확인되어 개설자 공간으로 수정했다. shared-space-ui 전체 Vitest 65개가 통과했다. 최신 main 공급자 identity/business 추출 소비처 83개도 통과했다. 추가 권한 검토에서 개설자 자격 회수 뒤 남아 있는 Forum owner 행을 이용한 회원 명단 조회를 현재 개설자 판정으로 차단하고 회귀 2개를 추가했다.
