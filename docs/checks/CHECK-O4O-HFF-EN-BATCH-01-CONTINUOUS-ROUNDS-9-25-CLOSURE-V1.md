## 3. 번역 이외의 원인으로 해소된 154건 — 두 건의 구조·게이트 결함

### 3-1. `composeTail` 부재 (73건 해소)

`탄수화물과 에너지 대사에 필요 * 비타민B2` 처럼 **절 뒤에 다음 항목의 라벨이 붙어 잘린 형태**가 원문에 다수 존재한다.
좌·우 조각이 모두 기존 자산으로 해석될 때만 성립하는 분해 규칙을 추가했다(오조합 위험 없음).

```
lookup(clause, k)
  → composeTail(k): k 를 '*' / '-' 구분자 또는 알려진 라벨 접미로 분해
     좌(절) · 우(라벨) 둘 다 해석되면 `절 * 라벨` 로 합성
```

미해결 문구 1,513종 → **1,254종**, 미커버 0개 문서 98 → **171**.

### 3-2. 단위 표기 대소문자·전각 미접힘 (81건 해소)

수치 검증이 `200ml`(KO) vs `200 mL`(EN) 을 **다른 값으로 판정**해 정상 번역을 NUMBER_DRIFT 로 막고 있었다.
`㎎→mg` · `㎍/μg/mcg→ug` · `㎖→ml` 정규화 + 소문자 접기를 추가했다.

`HOLD_NUMBER_STRUCTURE_AMBIGUOUS` **93 → 8**.

> **교훈(재확인).** `TRANSLATION_ASSET_MISSING` 이 줄지 않을 때는 문구를 더 번역하기 전에
> **NO_ENTRY / CLEAN / NUMBER_ONLY / STRUCTURE / FALSE_GATE 분포를 다시 산출**해야 한다.

## 9. 함정 기록

1. **문구당 해소 효율은 라운드가 갈수록 급락한다.** R2 는 문구 1종당 1.6문서였으나 R24 는 0.26문서다. 남은 문서일수록 미커버 문구를 여러 개 동시에 갖기 때문이며, 정상적인 감쇠다.
2. **효율이 급락하면 번역이 아니라 규칙·게이트를 의심해야 한다.** 이번 구간 최대 단발 해소는 번역이 아니라 `composeTail`(73) 과 단위 접기(81) 였다.
3. **구분자·어미는 유니코드 이형이 계속 나온다.** U+0387(그리스어 아노 텔레이아)까지 섞여 있었다. 사전에 있는데 조회가 안 되면 **키 정규화부터** 확인한다.
4. **EN 본문에 `<`/`>` 를 그대로 넣으면 렌더 `rawHtml` 로 막힌다.** 꺾쇠는 대괄호로 바꾼다.
5. **동시 세션이 같은 테이블에 쓰고 있다.** `spd_all` 전역 카운트는 이 세션 write 없이도 증가한다. 전역 카운트 불변식으로 검증하지 말고 **대상 집합 기준**으로만 검증한다.
6. **Cloud SQL Auth Proxy 토큰은 약 1시간에 만료된다.** 만료되면 리스닝은 유지된 채 `ECONNRESET` 이 난다. 같은 포트를 재사용하려면 **이전 프로세스를 먼저 종료**해야 한다.
