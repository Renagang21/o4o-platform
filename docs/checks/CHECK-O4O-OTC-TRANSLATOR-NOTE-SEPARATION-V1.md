## 1. 결론

> **분리 구조는 이미 데이터에 존재한다.** 주석은 `bodyMarkdown` 에만 있고, **구조화 4필드는 33/33 전건 오염 0**이다.
> 따라서 필요한 것은 "주석 제거"가 아니라 **"소비자 렌더 소스를 구조화 필드로 고정"** 하는 것이다 — 삭제가 아니라 **경계 명시**.
>
> ⚠️ **단, 잠재 결함 1건 발견**: 유일한 마크다운→HTML 변환기 `mdToHtml` 에 **인용 블록 처리가 없다.**
> `bodyMarkdown` 을 렌더하면 주석이 `<p>&gt; 같은 성분 550mg 정은 전문의약품이다…</p>` 로 **소비자 화면에 그대로 나간다.**
> **아직 발생하지 않았다** — 이미 승격된 27건(복합비타민)이 **우연히 주석 0건**이었기 때문. **주석 보유 33건은 전부 미승격**이다(§3-3).

## 3. 조사 — 경계와 누출 지점

### 3-1. 구조화 필드 오염 여부 → **33/33 오염 0**

| 필드 | 주석 오염 |
|---|---|
| `efficacy` | **0** |
| `usage` | **0** |
| `caution` | **0** |
| `summaryTable` | **0** |
| 기존 `translatorNote` 필드 | 없음(미존재) |

**경계는 이미 데이터에 있다**: 파서(`drug-otc-description-draft-content.ts`)가 `**볼드 섹션**`·파이프 표만 구조화 필드로 뽑고, `bodyMarkdown` 은 **"원문 섹션 마크다운(무손실 보존)"** 으로 주석까지 통째 보관한다.

```text
efficacy · usage · caution · summaryTable · ingredientSelection   ← 소비자 본문 (주석 없음)
bodyMarkdown                                                       ← 원문 무손실 (주석 포함)
```

### 3-2. 누출 지점 = `mdToHtml` **1곳**

`apps/api-server/src/scripts/drug-otc-nutrition-combo-canonical-promotion.ts:86` — 저장소 내 **유일한** md→HTML 변환기.

처리 분기: 빈 줄 / `#` 제목 / `|` 표 / **그 외 전부 문단**. **인용(`>`) 분기가 없다.**
→ `>` 로 시작하는 줄은 `para.push()` 되고 `esc()` 가 `>` 를 `&gt;` 로 escape → **`<p>&gt; …</p>` 로 소비자 화면에 출력**.

(`drug-otc-description-promotion-dryrun.ts` 는 커버리지 집계 전용 — 변환 없음, write 0.)

### 3-3. 실제 누출 여부 → **아직 없음 (운 좋게 비껴감)**

| 확인 | 결과 |
|---|---|
| 승격된 SPD 1,915행에 `<p>&gt;` 선두 주석 | **0** |
| 승격된 SPD 에 `별개 그룹`·`전문의약품이다`·`큐레이션` 문구 | **0** |
| 승격 계열(복합비타민 27건) 중 **주석 보유** | **0** ← 비껴간 이유 |
| **미승격 초안 중 주석 보유** | **33** ← 지금 승격하면 **누출** |

> **결론: 잠재 결함.** 33건을 현재 파이프라인으로 승격하면 주석이 소비자 화면에 나간다.

## 4. 설계

### 4-1. 원칙

```text
소비자 노출 대상에서 제외  ≠  번역자 입력에서 제거
```

- 주석 **삭제 금지**. `bodyMarkdown` 의 무손실 보존은 유지한다(원본 = 감사 근거).
- 소비자 본문은 **구조화 필드에서만** 만든다 → 주석이 **원천적으로 들어올 수 없다**.
- 주석 내용을 영문 본문에 **자동 추가하지 않는다**. 주석은 **번역자의 판단 근거**일 뿐, 번역 대상이 아니다.

### 4-2. 주석 식별 방식

```text
translatorNote = bodyMarkdown 선두의 연속된 '>' 인용 블록
consumerBody   = 그 이후 (또는 구조화 필드)
```

| 근거 | 값 |
|---|---|
| 선두 인용 = 주석 | 33/33 (예외 0) |
| 본문 중간 인용 | **0** → 오탐 위험 없음 |
| 주석 없는 초안 | 62건 → `translatorNote = null` |

> **파싱 규칙은 이미 검증된 사실에만 의존한다.** 문자열 매칭(`별개 그룹` 등 내용 기반)은 **쓰지 않는다** — 주석 문구는 자유 서술이라 깨진다.

### 4-3. 번역 입력 데이터 구조 (제안)

```jsonc
{
  "source": {                    // 번역 대상 (이것만 번역한다)
    "efficacy": "...",
    "usage": "...",
    "usageLabel": "복용 안내",   // 경로 신호 (DR-019)
    "caution": "...",
    "summaryTable": { }
  },
  "translatorNote": "> 같은 성분 550mg 정은 전문의약품이다(§6)…",  // 참고 전용 — 번역·저장 대상 아님
  "meta": { "groupKey": "...", "reviewStatus": "needs_review" }
}
```

| 규칙 | 내용 |
|---|---|
| 번역 대상 | `source` **만** |
| `translatorNote` | 번역자·검수자에게 **표시**. 영문 산출물에 **미포함** |
| 자동 반영 금지 | 주석 내용을 영문 문장으로 옮기지 않는다 (CR-021·T-04 원문에 없는 정보 추가 금지) |
| 주석이 안전정보 누락을 시사하면 | **TEST-LOG 기록** 후 한국어 정본 보완 여부를 별도 판단(T-05 — 번역에서 고치지 않음) |

### 4-4. 소비자 본문 ↔ 번역자 참고정보 경계

| 구분 | 소스 | 소비자 노출 | 번역자 열람 |
|---|---|---|---|
| 본문 | `efficacy`·`usage`·`caution`·`summaryTable`·`ingredientSelection` | **O** | O |
| **주석** | `bodyMarkdown` 선두 인용 | **X** | **O** |
| 원본 마크다운 | `bodyMarkdown` 전체 | **X** | O (감사용) |

### 4-5. 저장 시 제외 지점

| # | 지점 | 조치 |
|---|---|---|
| **1 (권장)** | **승격 파이프라인의 렌더 소스** | `bodyMarkdown` → **구조화 필드**로 전환. 주석이 원천 배제됨 — **파일럿에서 이미 실증**(시안 5건, 주석 누출 0 · `<table>` 0) |
| **2 (보강)** | `mdToHtml` | 인용 블록 **분기 추가**. 단 "문자열 삭제"가 아니라 **블록 인식 후 렌더 대상 제외** |
| **3 (게이트)** | 저장 직전 | 산출 HTML 에 `&gt;`·주석 문구 잔존 시 **저장 거부**(assert). 회귀 방지 |

> 1 이 근본 해법이고 2·3 은 안전망이다. **1만으로도 누출은 사라진다.**

### 4-6. 기존 데이터 마이그레이션 → **불필요**

| 판단 | 근거 |
|---|---|
| 초안 95건 | **변경 불필요** — 주석은 `bodyMarkdown` 에 그대로 두고, `translatorNote` 는 **읽는 시점에 파생**하면 된다(선두 인용 추출). DB write 0 |
| 승격된 SPD 1,915행 | **정정 불필요** — 누출 0 (§3-3) |
| `content_json` 스키마 | jsonb 라 필드 추가 시에도 **마이그레이션 불요**. 다만 파생으로 충분하므로 **필드 신설도 선택** |

> **DB write 0 으로 해결 가능한 문제다.**

### 4-7. 자동화 범위 vs 수동 검토

| 자동화 가능 | 근거 |
|---|---|
| 주석 **식별·분리** | 패턴 단일(선두 인용) · 예외 0 · 오탐 0 |
| 소비자 본문 **생성** | 구조화 필드에서 조립 |
| 저장 게이트(§4-5-3) | 기계적 assert |

| **수동 검토 필수** | 근거 |
|---|---|
| **B 유형 8건**(§2-3) | 주석이 **번역 판단**을 바꾼다. 기계는 "질정=insert"·"550mg=RX"를 못 지킨다 |
| **D 유형 11건**(수동 큐레이션·약사 검토 강화) | 초안 자체가 검토 대상으로 표시됨 |
| **C 유형 5건**(grounding 얇음·rx 혼입) | 원문 신뢰도 문제 → 번역 이전에 판단 |
| 민감 약효군(DR-008) | 자동 채택 금지 |

> **자동화는 "주석을 소비자에서 빼는 것"까지.** "주석을 읽고 번역을 바로잡는 것"은 **사람**이다.
