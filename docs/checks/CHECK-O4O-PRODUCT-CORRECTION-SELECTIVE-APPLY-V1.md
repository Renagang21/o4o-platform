## 결과

- 기존 수동 보정 기록의 원본 미적용 계약을 유지하고 별도 구조화 근거·변경안·승인·선택 반영 경로를 추가했다.
- 초기 범위는 상품명·브랜드명·규격·원산지·태그·설명서 본문이다. 보호 필드·상태·이미지·분류·매장 제작물·QR을 변경하지 않는다. 설명서 요약과 다른 유형·언어는 유지한다.
- 원본 전체 fingerprint, 변경안 revision/행 잠금, 명시적 승인과 실제 반영 선택, 상품 단위 transaction, 멱등 요청을 구현했다. 성공 이력 저장 실패 시 상품·canonical 변경도 rollback한다.
- 상품 사실/전문 참고 근거와 출처·확인일·관련 항목·확인 상태를 변경안에 보존한다. 독립적인 자료 파일 수집·자료 라이브러리는 이번 범위가 아니다.
- 전체 변경안 처리 현황과 특정 변경안 직접 재개, 버전·실패 요청 조회를 지원한다. 반영 차단·실패는 완료로 표시하지 않는다. DB 자체 장애 시 실패 요청의 별도 기록도 보장할 수 없으며 성공 응답하지 않는다.
- 변경안 수정은 새 변경안 작성 방식이며, 반영 후 남은 항목과 되돌리기도 최신 원본 기준 새 변경안으로 처리한다. 자동 복원·자동 원본 재기준화는 없다.
- 최신 base에 있던 AI 기능은 변경하지 않았다. 신규 경로에서 AI 호출·예약·운영 보정을 실행하지 않았다.

## 검증

- PostgreSQL 15 합성 데이터 포함 API Jest 5개 suite / 127개 통과. 기존 P1 통합 8개와 신규 P2 통합 9개, 신규 입력 계약, API 권한, 기존 공통 상품 DB 권한 계약 포함.
- P2: 생성·승인 시 원본 무변경, 선택 필드만 적용, 보호 필드 유지, HTML 정화, 같은 유형/언어 canonical 교체, 이전 Resource·다른 유형 보존, 첫 설명서 생성, 원본 충돌, 근거 요건, 반려·미승인 차단, 동시 같은 요청 멱등성, 경쟁 변경안 충돌, 이력 실패 rollback·재시도, 날짜·보호 필드·상태·revision 검증.
- 관리자 Vitest 3개 파일 / 21개 통과. 기존 작업·AI 초안 흐름 회귀, 근거·변경안 저장, 승인과 반영 분리, 명시적 선택·확인, 충돌 입력 보존, 과거 변경안 직접 열기, 권한 없는 편집 차단, 현황 조회 실패·오류 조건 확인.
- Node 22 / pnpm 10의 frozen lockfile 설치 및 의존 패키지 빌드 후 types build, API·관리자 TypeScript 검사, 관리자 Vite production build 통과. 변경 파일 ESLint 통과.
- Chromium 합성 fixture: 실제 관리자 빌드 CSS를 사용해 1440px/390px에서 등록→충돌 입력 보존→초안 저장→승인→선택 반영→새로고침→버전/현황 재개를 확인했다. 페이지 오류·실패 HTTP 자산 요청·가로 넘침 없음. 서버 검증은 별도 격리 PostgreSQL 테스트로 수행했으며 fixture를 운영 API 검증으로 해석하지 않는다.
- 테스트는 세션 전용 로컬 correction_review DB의 무작위 schema에서 수행하고 finally로 자체 schema를 삭제·연결 종료한다. 운영 상품·계정을 사용하지 않았다. 테스트 계정 기준 파일은 이 worktree와 기준 checkout에 없으므로 운영 로그인 smoke는 수행하지 않았다.
- 초기 검증의 누락 패키지 dist는 SETUP의 패키지 빌드로 해결했다. 포맷 변경으로 기존 소스 문자열 권한 검사가 실패한 건은 기존 파일 포맷을 보존하여 해소했고 최종 127개가 통과했다.

## 후속
