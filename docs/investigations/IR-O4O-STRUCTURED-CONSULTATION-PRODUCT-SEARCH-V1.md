## 문제와 변경

기존 맥락 검색은 상품명·분류·규격·태그와 B2B HTML 본문을 검색했다. aiSections는 상품을 고른 뒤 읽으므로, 구조화 자료에만 있는 표현으로는 후보를 찾지 못했다.

이제 승인된 상품 상담자료의 구조화 항목 제목·내용도 검색한다. 상품 사실·전문 참고·상담 보조를 대상으로 하며 미분류는 근거 검색 대상에서 제외한다. 검색 용어는 기존 맥락 플래너가 만든 구문의 부분 문자열 일치를 사용한다. 후보는 자료 확인을 위한 상품 식별이며 임상 판단·재고 확인·자동 추천 결과가 아니다.

검색과 최종 상담자료 조회는 `consultationDescriptionSql`과 `consultationEntry`를 공유한다. 한국어 CONSULTATION 정본을 먼저 선택하고, 없을 때만 기존의 유효한 구조화 B2B 접수 자료를 호환한다. 전용 자료가 오래되거나 원천과 불일치하면 이전 B2B·QR·다른 언어로 대체하지 않는다. 일반 B2B 본문은 검색 근거에서 제거했다.

## 검색·권한·자원 경계

- 현재 매장의 활성 listing 및 활성 공통 상품으로 범위를 제한한 뒤 검색한다. 같은 master의 중복 listing은 한 후보로 표시한다. 직접 등록 상품은 기존 매장 내 상품명 검색을 유지하며 공통 상담자료를 임의 연결하지 않는다.
- SQL은 구조화 텍스트의 일치 가능성을 거르는 단계다. 서버의 공통 스키마 검증에서 목적·언어·본문 버전·출처·섹션 근거를 확인한 뒤 실제 일치 점수를 계산한다. 근거가 무효해도 상품명 등 기존 식별 정보가 일치하면 이름으로 찾을 수 있다. 무효한 본문을 상담 근거로 사용하는 것은 아니다.
- 50건씩 keyset으로 읽고 검증한다. 먼저 읽은 12개에서 멈추지 않으며 뒤의 유효한 자료·더 높은 일치 점수도 반영한다. 최종 12개만 유지하고 이름·ID로 동점을 안정적으로 정렬한다. 원문·출처·내부 점수는 후보 응답에 넣지 않는다.
- 1,000개를 넘는 일치 가능 행은 `422 CONSULTATION_SEARCH_TOO_BROAD`로 조건 구체화를 안내한다. 일부 후보를 조용히 자르거나 빈 결과로 위장하지 않는다. 정확히 1,000개일 때는 종료 확인 후 정상 결과를 반환할 수 있다. 메모리에는 현재 묶음과 최종 후보만 유지한다.
- 기존 약사 모드·매장 접근 guard를 유지한다. 계획 전·후·반환 전 확인하고, 여러 묶음으로 이어질 때도 접근을 재확인한다. 권한 거부·DB 실패·검색 범위 초과는 유료 대체 생성으로 우회하지 않는다.
- 기존 맥락 계획 호출 1회를 유지한다. 이번 후보 검색은 DB·코드로 처리하며 임베딩·추가 모델 호출·캐시 원장·DB schema·운영 데이터 변경을 추가하지 않는다. 실제 절감액은 미측정이다.

## 검증

- API 관련 21 suites / 178 tests 통과. 상담 맥락·새 후보 검색·공통 자료 리더·기존 상담 근거/번역/지원·외부 콘텐츠 연결 범위를 실행했다.
- 전용 로컬 PostgreSQL 연결이 필요한 기존 통합 suite의 11개 테스트는 skip했다. 이 suite에는 새 상담자료 승인→구조화 검색→일반 편집 후 무효화의 실제 DB 시나리오도 보강했다.
- 저장소 dependency를 바꾸지 않고 별도 작업 디렉터리의 PGlite 0.3.15 격리 PostgreSQL 엔진에서 실제 검색 SQL·부분 유일성 인덱스를 실행했다. 구조화 전용 성분·용도·주의사항, 타 매장·비활성·미승인·다른 언어·삭제·미분류·잘못된 출처·잘못된 JSON, 정본 우선순위·stale 무효화, 중복 listing, literal 검색, 50건 이후 유효 후보·더 높은 점수, 접근 철회를 검증했다. 실제 운영 데이터에 대한 부하 검증이나 TypeORM 전체 통합 검증의 대체는 아니다.
- API typecheck 및 변경 TS 파일 ESLint 검증. 환경은 Node 24.22.1 / pnpm 10.25.0으로 저장소 안내 Node 정확 버전과 차이가 있다. 의존 패키지를 먼저 빌드했다.
- 운영 DB·실제 공급자 호출·유료 청구·배포·실제 약사 화면 smoke는 미실행이다. 배포 후 관리자 승인 자료에만 있는 질문으로 현재 매장 후보→자료 확인→판단 지원 흐름과 권한 철회·자료 변경을 확인한다.

## 통합과 후속

3차가 아직 main에 없어 원래 `wo/product-consultation-resource-separation`의 `f56c1b3ed`를 최신 main 기반의 이 branch로 cherry-pick했다(`1b2ab0813`). 이번 branch는 3차 선행 변경과 4차 검색을 포함하는 묶음이다. 통합 시 같은 변경을 중복 반영하지 않는다. 원래 3차 branch는 이 묶음 **병합 후 삭제 가능**이며 이 세션에서 삭제하지 않는다. PR 생성·병합·배포는 통합 세션에 맡긴다.

5차는 직접 등록 상품의 공통 상품 연결·관리자 정기 준비·중앙 상담자료/표준설명서 재사용과 자료 소비처 이관이다. 이번에 직접 등록 DB를 삭제하거나 자체 상담자료 전체를 중앙 정본으로 승격하지 않는다. 역할·표현 설정과 반복 생성 감소, SIWC는 기존 후속 단계로 남긴다.
