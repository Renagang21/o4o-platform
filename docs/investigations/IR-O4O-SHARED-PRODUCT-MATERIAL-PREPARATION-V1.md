## 구현한 흐름

1. 매장의 제품 등록에서 **공통 상품에서 찾아 등록 / 공통 상품에 없는 제품 등록 요청**을 우선 제공한다. 기존 관리자 식별·승인 및 offer_id=NULL 취급 등록을 재사용한다. o4o 거래 상품만을 대상으로 하지 않는다.
2. 기존 직접 등록 상품을 하나 선택하면 **공통 상품과 대조·등록**을 열고 상품명을 검색 초깃값으로 전달한다. 이름 일치로 자동 등록하지 않고 상품·규격을 선택한 뒤 기존 멱등 등록을 실행한다. 기존 직접 등록 자료·QR 보존을 화면에 설명한다.
3. 관리자 **공개자료·매장 제안 설명서 → 공통 자료 준비 현황**은 활성 취급 연결이 있는 공통 상품을 상품당 한 번 표시한다. 취급 매장 수는 DISTINCT organization 기준이다. 상담자료와 QR 표준설명서 준비 상태를 독립적으로 확인한다.
4. 선택 상품의 상담자료/QR 조사 요청문을 별도로 받는다. 요청 시 현재 상품·취급 상태·자료 상태를 다시 확인하고 이미 준비된 해당 자료는 제외한다. 전부 준비되어 있으면 기존 자료 재사용을 안내한다. 요청문은 코드로 작성하며 외부 AI에 자동 전송하거나 유료 생성하지 않는다.
5. 사용자의 외부 AI에서 준비한 결과는 기존 JSON 가져오기 → 상품 대조 → 관리자 검토 → 유형·언어별 공통 정본 승인으로 이어진다. 여러 매장은 같은 master의 승인본을 읽는다. 매장별 원본 복제나 등록 시 자동 QR 교체를 추가하지 않는다.
6. 기존 데이터 정비의 보정 기준에 CONSULTATION 유형과 선택적인 **취급 공통 상품만** 범위를 연결했다. 상담자료/QR 정기 검토 초안은 한국어·30일·사용 꺼짐으로 시작한다. 관리자가 검토·사용 설정·저장한 뒤 기존 정기 점검에서 실행 시간을 정한다. UI에서 준비 현황·접수와 정기 점검으로 왕복할 수 있다. 실제 일정·worker·운영 설정은 이번 세션에서 활성화하지 않았다.

## 준비 상태와 조회 경계

상담자료는 3·4차 공통 리더의 목적·언어·본문·원천·섹션 근거 검증을 사용한다. 구조화 승인 자료만 준비됨이며 미분류·원천 불일치는 준비/검토 대상으로 남는다. 전용 CONSULTATION 우선 및 유효한 이전 구조화 B2B 호환은 유지한다. QR은 정확한 언어의 STORE 정본에 실제 텍스트 본문이 있어야 준비됨이다. 준비됨은 자료 확보 상태이며 근거의 현행성 판단은 정기 검토에서 별도로 수행한다.

관리자 조회는 기존 접수 화면의 인증·관리자 guard 안에 둔다. 새 GET preparation 및 POST preparation/request는 읽기만 수행하고 private/no-store로 응답한다. 요청문은 최대 25개 선택의 공통 상품 식별 정보만 명시적으로 추린다. 매장 식별자·가격·고객·상담 원문은 외부 요청문에 넣지 않는다. 선택 상품이 비활성·미취급·삭제로 바뀌면 409로 다시 확인하도록 한다.

목록은 25개 단위로 읽고 한 요청에서 최대 250개를 확인한다. 준비 필요 대상이 드문 구간에서도 continuation을 반환하므로 빈 현재 범위를 전체 준비 완료로 오해하지 않게 한다. 조회 실패를 0%·준비 완료로 표시하지 않는다. 필터·범위 변경 시 선택과 요청문을 정리하고 쓰기/게시 작업 없이 선택 ActionBar에서 조사 요청문을 받는다.

## 직접 등록 상품의 실제 소비처와 보존 판정

| 소비처 | 현재 연결 | 이번 처리 |
|---|---|---|
| 취급 목록·자체 진열 | store_local_products ID, 이름·이미지·설명·가격 표시 | 보존. 공통 상품과 대조하는 명시적 경로 추가 |
| 태블릿·공개 진열 | platform/store-tablet 및 store-public resolver | 기존 ID·경로 보존 |
| 매장 상담 작성·기여 | consultation-content, kpa_store_content_product_links의 local ID | 자동 변경하지 않음 |
| 매장 다국어 콘텐츠 | store-product-content의 target_kind=local / target_id | 별도 매장 자산으로 보존 |
| POP·매장 QR 자료 | pop-v2-source 및 store-content/진열 참조 | 기존 내용·URL·사용 지정 보존 |

직접 등록 상품은 실제 Display 소비처가 있어 즉시 제거할 수 없다. 공통 상품 대조·등록은 **같은 물리 상품의 공통 취급 등록을 새로 확인하는 절차**이며 기존 local 객체를 Commerce 객체로 바꾸거나 자료 참조를 자동 재배치하는 작업이 아니다. 기존 자료 이관 완료라고 선언하지 않는다. 운영 전환은 실제 참조 목록·상품 동일성·매장별 표현/이미지·기존 QR 유지 조건을 확인하고 참조별로 이관해야 한다. 기존 데이터를 일괄 삭제·비활성화하거나 임의 master를 생성하지 않았다.

- 운영 DB write·스키마·일정 활성화·자료 이관·배포·실제 관리자 화면 smoke·실제 절감액 검증은 미실행이다. 배포 후 관리자 계정으로 조회→선택→요청문→파일 접수·대조·승인 및 정기 점검 설정을 확인하고, 두 매장에서 공통 자료 ID 재사용·기존 직접 등록/QR 보존을 확인한다.
