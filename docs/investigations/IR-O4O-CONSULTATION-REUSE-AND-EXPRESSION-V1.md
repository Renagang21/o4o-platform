## 변경 범위

같은 로그인 이용자·매장·상담 세션에서 동일 요청이 반복되면 검증된 결과를 짧게 재사용한다. 대상은 상품 검색의 맥락 계획, 게시 자료 문단 선택, 약사 판단 지원 초안, 텍스트 번역이다. 검색 후보 DB 조회와 원천 자료·권한 확인은 매번 수행한다. 제품 후보 자체나 권한 판정은 캐시하지 않는다. 음성 인식·합성, 서버 정기 대량 처리, neture 초기화면의 ChatGPT 요금제 연결은 이번 변경에 포함하지 않는다.

프런트는 임의 UUID `reuseSession`을 생성한다. 서버는 로그인 actor·현재 organization과 이 값, 화면 mode·station/epoch, 검증한 요청·근거 버전·모델 설정을 묶어 SHA-256 키를 만든다. UUID는 인증 수단이 아니다. 클라이언트가 actor나 캐시 키를 지정해 권한을 우회할 수 없다. 다음 고객·화면 재생성·페이지 종료 시 세션을 새로 만들고 구형 클라이언트가 UUID를 보내지 않으면 기존 비재사용 동작을 유지한다.

각 단계는 프로세스 메모리에 완료 후 60초, 최대 64개·총 1,000,000바이트의 결과를 유지한다. 단계별 진행 중 합류 대상도 최대 64개이며 초과 요청은 저장·합류 없이 기존 방식으로 처리한다. 완료 결과의 타이머·용량 초과 퇴출이 메모리에서 값을 제거한다. 실패·잘못된 출력·큰 결과는 저장하지 않는다. 읽기·대기 합류 뒤에도 현재 권한을 재확인한다. 질문과 근거 원문은 키·별도 로그·DB에 기록하지 않지만 번역·초안 결과 자체는 이 짧은 메모리에 남을 수 있다. 고객 전환은 이전 세션의 결과 재접근을 막으며 기존 메모리의 즉시 삭제를 의미하지 않는다.

이는 인스턴스별 최선의 중복 감소다. 재시작·여러 서버·만료·용량 초과에서는 다시 생성될 수 있다. 공유 캐시나 상담 이력 DB를 추가하지 않는다. 실제 재사용 시 공급자 호출이 없으므로 기존 유료 호출 원장도 추가하지 않는다. 캐시가 없을 때의 비용·쿼터·정책 실행은 유지한다. 번역은 재사용 시에도 현재 기능 정책의 허용 여부를 확인한다.

## 근거 변경과 매장 표현

경영자는 기존 `organizations.metadata.consultationExpression`에 다음 고정 선택만 저장한다.

| 항목 | 선택 |
|---|---|
| 말투 | 담백하게 / 친절하게 |
| 문장 끝맺음 | 경어체 / 평서체 |
| 길이 | 짧게 / 필요한 설명 |

기본값은 담백하게·경어체·필요한 설명이다. 자유 프롬프트·역할·모델 지정 필드는 거부한다. 현재 매장 owner·계정 상태·Neture 가입·약국 승인을 확인하고 쓰기 SQL에서도 owner·계정·매장 상태를 다시 확인한다. 직원은 읽기만 가능하다. 기존 metadata의 화면 설정과 다른 키를 보존하며 schema/migration은 추가하지 않는다. 설정 화면은 조회 실패 재시도, 저장 실패, 매장 전환 뒤 이전 응답 무시를 지원한다.

표현 설정은 약사가 검토할 **고객 설명 초안**에 적용한다. 전문 참고사항은 전문 내용으로 유지하고 수치·부정·주의사항·불확실성을 표현 때문에 생략하지 않도록 지시한다. 기존 출처·수치 검증은 그대로 수행한다. 실제 문체 준수와 임상 설명 품질은 공급자를 호출하지 않는 단위 테스트로 확정할 수 없으며 운영 검증이 필요하다. 직원의 게시 자료 인용을 임의로 재작성하지 않는다. 화면 선택은 접근 권한을 만들지 않으며 약사 자격·승인 직원·공개 소비자 화면의 기존 경계를 유지한다.

현재 서버 표현 설정과 모델 설정을 약사 초안의 근거 버전에 포함한다. 저장/모델 변경은 재사용을 무효화하고 이미 열린 초안의 사용 전 검증도 실패시켜 다시 준비하게 한다. 설정 저장은 다른 화면에 즉시 변경을 푸시하지 않는다. 새 버전 배포 시 이전 근거 버전의 초안 역시 다시 준비해야 한다.

## 검증

- 상담 API 14 suites / 138 tests 통과 후 표현·초안 검증 2건 추가 및 해당 suite 재검증. 같은 요청의 생성 2회→1회, 동시 요청 합류, 다른 이용자·매장·세션·질문·원천·설정 분리, 만료·용량·출력 복제·실패 미보관·권한 철회를 확인한다.
- 매장 화면 5 files / 65 tests 통과. 경영자 저장·직원 읽기·매장 전환·조회 재시도, 기존 상담 준비·번역·고객 전환 및 업무공간 회귀를 포함한다. 마지막 화면 수정 후 설정 4건 재검증.
- API·매장 TypeScript 검사와 변경 TS/TSX ESLint. 원래 routes의 미사용 `_next` 경고는 별도 범위로 보존한다.
- 격리 PGlite에서 **실제 저장 SQL** 실행: 다른 metadata 보존, 직원·다른 매장·퇴사·이메일 미확인·비활성 약국 쓰기 거부. 운영 DB에는 연결/쓰기하지 않았다.
- Node 24.22.1 / pnpm 10.25.0. 저장소 안내 Node 22.23.4와 차이가 있으며 dependency·lockfile 변경 없음. API 테스트의 기존 강제 종료 옵션을 사용했다.
- 실제 공급자 호출·운영 자료·절감률·사용자 화면 smoke·부하·배포는 미실행이다. 테스트 호출 횟수 감소를 실제 절감액으로 보고하지 않는다.
