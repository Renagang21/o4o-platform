# 상품 상담자료와 주문·QR 자료의 논리 분리

> **상태**: DRAFT — 개발 검증, 병합·배포 전.
> **작성일**: 2026-11-12
> **실행 위치**: CLOUD
> **기준 코드**: `006a7767996ea24af79bc6b55d3512dfb0eb6242`
> **작업 branch**: `wo/product-consultation-resource-separation`
> **근거**: AI 비용 절감 3차 진행 지시. 기존 자료를 보존하며 상담의 B2B 분류 의존을 제거한다.

## 구현한 구분

| 용도 | 저장 유형 | 이번 변경 |
|---|---|---|
| B2B 주문용 정보 | B2B | 기존 행·기본 입력 호환 유지 |
| B2C 상품정보 | B2C | 유지 |
| 상품 상담자료 | CONSULTATION | 관리자 자료 접수·대조·승인으로 별도 정본 작성 |
| 상품 표준설명서(QR) | STORE | 기존 저장 값·QR 조회·URL 유지 |
| 기존 공급자 매장용 정보 | SUPPLIER_STORE | 유지. 이번에 제거·통합하지 않음 |

DB의 description_type은 varchar(32)이며 정본 유일성은 상품·유형·언어별이다. 기존 서비스의 유형별 승인·교체를 재사용한다. 새 테이블·컬럼·마이그레이션·운영 backfill은 없다. CONSULTATION을 승인해도 B2B·STORE를 강등하거나 본문을 바꾸지 않는다. 관리자 직접 HTML 수정으로 원천과 본문이 달라지면 기존처럼 구조화 근거를 무효화한다.

관리자 접수 화면의 새 가져오기 기본 목적은 ‘상품 상담자료’다. B2B·B2C·QR·공급자 유형은 별도 선택한다. 과거 API 입력의 descriptionType 생략 기본값 B2B는 바꾸지 않는다. 기존 파일을 승인 없이 상담자료로 재분류하지 않는다.

## 기존 자료 보존과 읽기 규칙

1. 정확한 언어의 CONSULTATION 승인본이 있으면 우선한다.
2. 전용 승인본이 없을 때만 이전 접수 체계의 B2B 승인본 중 유효한 aiSections가 연결된 자료를 호환 조회한다. 원천 라벨·연결·유형·언어·본문 일치와 섹션 근거를 확인한다. 이는 이미 승인된 구조화 상담자료의 호환 읽기이며 일반 B2B 본문 대체 기능이 아니다.
3. 전용 승인본이 있으나 구조화 연결이 무효해졌으면 missing으로 반환한다. 이전 B2B 자료·QR·다른 언어·후보로 몰래 대체하지 않는다.
4. 일반 B2B 자유 본문, 출처가 누락되거나 달라진 자료는 상담자료가 없는 상태로 처리한다. 미분류 섹션만 있으면 준비 완료로 계산하지 않는다.
5. 매장 활성 취급 연결·활성 공통 상품 확인은 기존 조회 경계를 유지한다. 공통 상품 연결 없는 직접 등록 상품의 자동 승격·삭제는 하지 않는다.

공통 리더를 상담자료 조회·매장 자료 확보 현황·Excel 대조에서 함께 사용한다. Excel은 상품 식별·취급 연결 준비이며 자료를 생성하거나 QR을 교체하지 않는다. 자료 현황 응답의 resourcePurpose=CONSULTATION은 새 논리 목적이다. 배포된 구형 화면과 호환하기 위해 기존 purpose=B2B 필드는 deprecated 전송 메타데이터로 남기며 DB 선택에 사용하지 않는다. 새 화면은 resourcePurpose를 우선하고 구형 응답도 수용한다.

## 권한·비용 경계

기존 매장 상담자료 조회 권한을 변경하지 않는다. ChatGPT의 일반 상품 조회에 새 CONSULTATION 자료가 자동 노출되지 않도록 매장·공급자 외부 어댑터 조회에서 제외한다. 약사 전용 자료를 일반 외부 scope에 공개하는 변경은 없다. 자료별 audience·약사 자격·승인 근무자·표현 설정의 세부 계약은 후속 작업으로 남는다.

공통 자산을 B2B 주문과 별도로 관리·재사용할 기반을 만든 변경이다. 새 유료 AI 호출·자동 생성·예약 생성·SIWC는 추가하지 않는다. 실제 비용 절감액은 측정하지 않았다.

## 다음 작업 및 통합 주의

- **4차:** 구조화 상담자료의 성분·용도·주의사항을 상품 후보 검색에 반영한다. 현재 자연어 상담 검색의 B2B 본문 참조는 이번에 고치지 않았다. 이번 변경만으로 검색 결함이 해결됐다고 판단하면 안 된다.
- **5차:** 공통 상품 연결·관리자 정기 준비·중앙 자료 재사용, 직접 등록 자료 소비처 이관을 진행한다.
- 구형 API는 CONSULTATION 읽기를 지원하지 않는다. 운영 자료를 새 유형으로 만들기 전에 API·관리자 배포를 확인한다. 롤백 시 새 자료를 삭제하거나 B2B로 일괄 덮어쓰지 않는다.
- 공통 snapshot 타입은 union 값 하나만 추가한다. 여러 서비스 소비처의 문자열 호환을 유지하며 API·관리자 접수·매장 표시는 같은 기능 묶음으로 검증한다. 공통 UI·인증·route·가격·quota 변경은 없다.

## 문서 정합

기존 비용·전문 자료 정책은 유지한다. [매장 엑셀·AI 자료 흐름](../guides/products/O4O-STORE-PRODUCT-AI-CONTEXT-FLOW-V1.md)의 B2B 전용 조회 및 기존 자유 본문 표시 설명은 이번 변경과 달라진다. 정본 내용 변경을 기능 변경에 섞지 않고 별도 문서 정비로 인계한다. 과거 실행 기록은 소급 수정하지 않는다. 운영 적용 전 이 분리와 호환 조회 조건을 사용 안내에 반영해야 한다.

## 검증 기록

- API 관련 20 suites / 154 tests 통과. 실제 PostgreSQL 접속을 요구하는 기존 통합 suite의 11개 테스트는 전용 연결 미설정으로 skip했다. 무관한 범위까지 매칭된 초기 Jest 실행은 중단하고 `/src/modules/`로 범위를 고정하여 재실행했다.
- 관리자 접수·파일 변환 10건, 매장 Excel·근거 적용·자료 현황 10건 검증. 구형 API 응답과 새 resourcePurpose 응답을 모두 확인하고 타 매장·언어·자료 목적 불일치를 거부한다.
- API·관리자·매장 TypeScript 검사 및 공통 types 빌드 검증. 매장은 해당 workspace의 TypeScript 5.9.3을 사용했다. API/UI 의존 패키지를 먼저 빌드했다. Node 24.22.1 / pnpm 10.25.0 환경으로 저장소 안내 Node 정확 버전과는 차이가 있다.
- 별도 작업 디렉터리에 설치한 PGlite 0.3.15의 격리 PostgreSQL 엔진에서 실제 공통 리더 SQL을 실행했다. 유형·언어별 partial unique index, 일반 B2B/QR 제외, 언어·검수·삭제 필터, 구조화 legacy 호환, 전용 자료 우선 및 stale 무효화를 확인했다. 저장소 dependency·lockfile은 변경하지 않았다. 이 검증은 운영 DB 및 TypeORM 접수·승인 전체 통합 검증의 대체가 아니다.
- 운영 데이터·설정·권한·배포·공급자 유료 호출·실제 관리자 화면 smoke는 실행하지 않았다. 배포 후 관리자 계정으로 접수→검토→승인, 매장에서 자료 조회·Excel 현황, QR 기존 본문·URL 유지, 약사 상담의 sourceVersion 무효화를 확인해야 한다.
