## 제작과 수정

제목 입력 → 동영상 추가 → 별도 선택 창에서 복수 선택 → 제작 화면 복귀 → 반복 추가 → 선택 영상 순서 변경/제거 → 태그 입력 → 저장이다. 같은 제작 화면에서 이미 추가한 영상은 중복 선택하지 않는다. 제목은 필수다. 순서는 드래그와 위·아래 버튼을 지원하며 선택 창을 취소하면 기존 구성을 유지한다.

전체 영상 수·확인된 길이의 합·길이 미확인 개수를 표시한다. 미확인 영상을 0초짜리 영상으로 확정하거나 전체 길이가 정확한 것처럼 표시하지 않는다. 필수 영상은 현재 게시기간 기준으로 합산한다. 선택한 재생목록의 기존 상단 수정·삭제 흐름을 유지하며 이름/태그와 항목 순서를 수정한다.

작성 요청은 매장+요청 UUID로 재사용한다. 응답이 끊겨도 동일 요청의 헤더와 영상 항목을 다시 확인해 이어서 저장한다. 직접 영상의 복사와 항목 추가는 하나의 트랜잭션으로 처리하고 같은 작성 요청의 중복 영상을 막는다. 명시적인 새 재생목록 제작은 새로운 사본을 만들 수 있다. 전체 제작은 여러 요청이므로 일부 항목 저장 후 실패할 수 있으며, 성공한 항목을 유지하고 같은 초안으로 재시도한다. 강제 전체 롤백이나 기존 자료 삭제로 처리하지 않는다.

## 필수 영상

현재 전체 운영자 권한 정본은 `platform:super_admin`이다. 새 role을 만들거나 서비스 운영자 권한을 전체 운영 권한으로 확대하지 않는다. 전체 운영자 화면은 `/operator/signage/required`, API는 기존 `/api/signage/:serviceKey/hq/forced-content`이다. 직접 관리하는 필수 영상의 이 API는 전체 운영자만 사용한다. 기존 캠페인 승인 처리 등 별도 생성 경로의 정책은 이 작업에서 변경하지 않는다.

현재 통합 Store의 서비스 문맥은 `kpa-society`다. 필수 정책의 기존 service_key 격리를 유지하며 모든 서비스에 무차별 UNION하지 않는다. 커뮤니티/협업체 운영자는 일반 제공 자료를 관리하는 주체이며 전체 매장 필수 지정을 할 수 없다.

게시 일시는 한국 시간으로 입력하고 UTC로 저장한다. 서버 기준으로 `시작 <= 현재 < 종료`만 매장에 반환한다. 시작 전·종료 후에는 매장 목록, 재생목록, 재생 대상에서 모두 숨긴다. 전체 운영자 관리 화면에는 예약/적용/만료를 관리하기 위해 남긴다. 기간 종료를 데이터 삭제로 구현하지 않는다.

재생목록은 저장된 매장 항목에 현재 유효한 signage/both 필수 영상을 합산한다. 태블릿 전용 자료는 사이니지에 포함하지 않는다. 기존 재생목록과 새 재생목록에 같은 정책을 적용하고, 필수 항목의 삭제는 서버에서 차단한다. 순서는 기존 필수 영상 위치 테이블에 재생목록별로 저장한다. 다른 매장/서비스 항목 ID와 중복 순서 ID를 거부한다.

열린 화면과 TV는 15초마다 서버 변경을 확인한다. 새 필수 지정/기간 변경 반영은 온라인 상태에서 최대 약 15초+요청 시간이다. 이미 받은 종료 일시는 별도 1초 시계로 검사하여 재생 중이어도 다음 항목으로 전환한다. 검증된 API 시각과 단조 증가 시간을 사용해 PC 시계 변경이 만료를 늘리지 않도록 한다. 네트워크가 끊기면 새 지정은 받을 수 없지만 캐시된 영상의 기간 검사는 계속한다. 이 갱신 간격을 실시간 push나 기기 재생 성공 보장으로 표현하지 않는다.

## 매장 사본의 독립성

O4O 콘텐츠를 내 매장으로 가져오는 것은 복사다. 사본 조회·재생은 원본 게시자의 이후 수정·삭제·비공개·복사 제한 여부를 다시 확인해 회수하지 않는다. 출처 ID는 메타데이터이며 원본과 FK로 묶어 사본을 삭제하지 않는다. 사후 저작권 판단·회수·차단 로직은 추가하지 않는다.

필수 영상의 기간 정책은 일반 사본과 구분한다. 일반 사본에 필수 정책을 소급 적용하지 않는다. YouTube/Vimeo 주소 사본은 외부 호스팅 파일의 존속을 보장하지 않는다.

## 조사에서 남은 범위

커뮤니티는 현재 영상 등록·목록·매장 복사 경로가 있다. 협업체는 담당 운영자의 일반 콘텐츠 작성 및 가입 매장별 제공 자료/복사 경로가 있다. 그러나 이 두 공간에 Store와 같은 재생목록 제작기를 제공하는 작업, 협업체 동영상 전용 카탈로그와 수정·삭제 화면을 연결하는 작업은 이번 Store 엔진/전체 운영자 구현으로 완료됐다고 간주하지 않는다. 각 공간의 실제 등록 권한·사업 키·대상 카탈로그에 맞춘 후속 구현이 필요하다. 서로 다른 Store 실행자산/HQ 방송 카탈로그 테이블을 합치거나 관리 권한을 임의 확대하지 않는다.

## 적용 조건

태그와 작성 요청 식별자용 additive migration `AddStorePlaylistTags1793857542325`가 필요하다. 격리 PostgreSQL 15에서 canonical bootstrap, incremental 적용, 스키마 fingerprint와 down 복원을 확인한다. 적용 이력·스키마 지문은 정식 registry에 등록하며 운영에서는 정식 migration job보다 먼저 새 API를 배포하지 않는다. 개발 단계에서는 운영 migration, seed, main 병합, 배포를 실행하지 않았다. 이후 사용자가 이 공간의 미반영 작업 통합·배포를 요청하여 PR #947에서 정식 migration 포함 배포를 진행한다. 실제 반영 상태는 PR의 CI·production 결과와 최종 기록을 확인한다.
