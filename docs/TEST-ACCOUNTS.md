# 테스트 계정

> **상태**: ACTIVE · **갱신일**: 2026-11-08
> **승인 근거**: 통합 담당 지시(2026-11-08) — 클라우드 · 로컬 세션이 같은 테스트 계정으로 브라우저 검증을 한다. 사용자 테스트는 로그인 화면의 테스트 로그인 버튼을 쓴다.

검증용 테스트 계정의 기준 파일이다. 저장소에 추적되므로 새 clone · worktree · 클라우드 세션에서도 그대로 읽는다.

## 사용자 테스트 — 로그인 화면의 「테스트 로그인」 버튼

사용자 화면을 검증할 때는 계정을 입력하지 않고 **로그인 화면의 테스트 로그인 버튼**을 누른다.
버튼은 사용자 서비스 로그인 화면(로그인 모달 포함)에 있다.

| 역할 | 로그인 화면 버튼 | 권한 범위 |
|---|---|---|
| 매장 경영자 | 「매장 경영자 테스트 로그인」 | 체험 약국 · 매장의 경영자 |
| 공급자 | 「공급자 테스트 로그인」 | 체험 공급자 |
| 매장 직원 | 「매장 직원 테스트 로그인」 | 같은 체험 약국의 직원 권한만 |

- 세 계정은 공개 Demo 계정이다. 정책 정본은 [`O4O-CANONICAL-DEMO-ACCOUNTS-V1`](baseline/O4O-CANONICAL-DEMO-ACCOUNTS-V1.md),
  주소 · 비밀번호의 코드 정본은 `packages/auth-utils/src/demoAccounts.ts` 하나다. 값을 이 파일이나 다른 문서에 복제하지 않는다
  ([DOCUMENT-LIFECYCLE §10-4](rules/DOCUMENT-LIFECYCLE-AND-ARCHIVE-RULES-V1.md)).
- 자동화 스크립트가 버튼을 쓸 수 없어 값이 필요하면 실행할 때 위 코드 정본에서 읽는다.
- 운영자 · 관리자 계정은 Demo 에 없다. 운영자 · 관리자 화면 검증은 작업 지시에 계정 확보 방법이 있을 때만 한다.
- **Google · 카카오 로그인**은 이 파일의 대상이 아니다. 외부 계정 로그인 화면은 사용자에게 넘기고 사용자가 직접 로그인한다.

## 사용 규칙

- 로그인 후 화면 조회는 자유롭게 한다. **값을 바꾸는 동작**(저장 · 삭제 · 주문 등)은 작업 지시에 있을 때만 하고,
  바꾼 값은 원래대로 되돌린다(테스트 데이터 정리 규칙은 `AGENTS.md` §5). Demo 계정은 여러 세션이 함께 쓴다.
- 버튼을 눌러 화면이 열렸다는 사실과 서비스별 역할 · 가입 상태 검증이 통과했다는 사실은 구분해 보고한다.
- 버튼이 없거나 로그인이 실패하면 다른 계정으로 대체하지 않고 실패로 보고한다.
- 2026-10-16 ~ 2026-11-07 의 기준 파일 `docs/local/TEST-ACCOUNTS.local.md`(로컬 전용)와 그 이전 `TEST-ACCOUNT.txt` 는 더 이상 기준이 아니다.
