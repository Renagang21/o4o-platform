## 계정과 서비스 가입

`neture.co.kr`에서 공통 계정을 관리한다. Google 로그인과 이메일·비밀번호 로그인을 병행하며 카카오 로그인을 추가한다. 소셜 계정은 서버에서 검증한 제공자 고유 ID(Google `sub`, 카카오 사용자 ID)로 식별하고 이메일이 같다는 이유로 다른 계정과 자동 연결·병합하지 않는다. 비밀번호는 공통 계정의 별도 credential이며 서비스마다 만들지 않는다. 전체관리자 로그인은 기존 Google 전용 경계를 유지한다. 카카오 구현은 위 WO의 후속 단계다.

현재 메인 가입 완료는 **정상 계정 + 이메일 확인**이다. 메인 이용을 위해 운영자의 수동 승인을 기다리지 않는다. Google은 서버에서 확인한 이메일, 이메일 가입은 확인 링크를 기준으로 한다. 명시적인 메인 이용 정지·해지는 유지한다. 과거 메인 가입 신청의 pending/rejected만으로 이메일 확인된 정상 계정을 수동 승인 대기로 두지 않는다. 유료화에 따른 추가 자격은 후속 테스트에서 결정한다.

메인 가입 완료는 연결 서비스의 신청·이용 전제다. 로그인은 공유하며, 서비스 미가입이나 승인 대기를 로그인 거부로 처리하지 않는다. 직접 URL과 배너 이동 모두 같은 원칙을 적용한다. 서비스는 미가입 안내·신청·대기·반려·정지 상태에 맞는 화면을 제공하고, 보호 API는 서비스별 가입·역할·사업자 관계를 검증한다. handoff는 세션 이동만 하며 회원 가입이나 권한을 생성하지 않는다.

매장 경영자·공급자·운영자 역할은 서비스별로 부여한다. 한 서비스의 가입 승인이 다른 서비스의 승인이나 역할을 대신하지 않는다.

## My Home과 계정 관리

개인 통합 공간의 명칭은 **My Home**이다. 참여 서비스·커뮤니티 활동·권한 있는 매장의 경영 현황을 모아 보고 계정 설정으로 연결하며, 로그인 후 공통 헤더에서 직접 진입한다. 구성·진입은 [My Home 정본](O4O-MY-HOME-CANONICAL-V1.md)을 따른다. 공통 계정은 기존대로 `neture.co.kr`에서 관리한다. My Home 진입이나 서비스 카드 노출은 다른 서비스의 가입·승인·조직·역할을 생성하지 않는다. 이번 문서 정비로 인증·로그인·handoff·세션 폐기 계약을 바꾸거나 화면 구현 완료를 주장하지 않는다.

## 공통 개인 정보

가입에는 이름과 개인 모바일 번호를 받는다. 모바일 번호는 일반 사업장 전화와 별개이고, 이 단계에서 SMS 본인 인증을 주장하지 않는다. 커뮤니티 가입에는 닉네임이 필요하며 My Home의 계정 설정에서 내 프로필로 연결한다. 현재 프로필 편집 경로는 유지하며 My Home 화면 반영은 후속 구현이다. 공통 개인 정보는 서브도메인마다 재등록하지 않는다.

## 사업자와 약국

공급자와 약국은 사업자등록증에 기재된 사업장명·사업자등록번호·대표자·사업장 주소·업태·종목과 사업자등록증 사본을 제출한다. 별도 상호를 중복 요구하지 않는다. 사업장 전화는 개인 모바일과 구분한다. 공급자의 업무 담당자·정산 정보는 기존 공급자 프로필에서 관리한다.

사본은 비공개 파일로 보관하고 본인과 권한이 있는 검토 운영자만 접근한다. 약국 제출은 PDF/JPG/PNG 10MB 이하를 허용한다. 공급자는 기존 PDF 제출 흐름을 유지한다. 호출자가 임의 URL을 증빙으로 등록할 수 없다. 재신청은 이미 제출한 본인 문서와 사업자 정보를 재사용할 수 있다.

`store.neture.co.kr`의 신규 매장 가입은 **약국 전용**이다. 별도 약국 신청 원장(`neture_pharmacy_memberships`)으로 승인한다. 추가 입력은 약사 면허번호와 약국 전화이며 **면허증 파일을 받지 않는다**. 운영자가 오프라인으로 약국 여부를 확인한 뒤 승인한다. KPA 회원 승인이나 활동 유형 변경으로 약국 조직·매장 권한을 자동 생성하거나 복구하지 않는다.

약국 협력사업은 개설 시 운영자와 정한 조건을 해당 서비스에 저장한다. 신청자는 표시된 조건에 동의하고 필요한 추가 설명을 제출하며, 운영자는 신청 당시 조건과 설명을 확인한다. 현재 약국 약국 협력사업은 승인된 약국 사업자 정보를 그대로 사용한다. 다른 업종이나 별도 증빙 조건은 서비스 개설 정책에 맞춰 후속 테스트에서 보완한다.

## 공개 테스트 계정

모든 사용자 서비스 로그인 화면은 매장 경영자·공급자 테스트 로그인 버튼을 제공한다. 공통 credential 정본은 `packages/auth-utils/src/demoAccounts.ts`, 서버 Demo 식별 정본은 `demo_accounts.user_id`다. 이메일 문자열로 Demo 여부를 판단하지 않는다.

버튼은 일반 이메일 로그인 API를 사용한다. Demo 전용 인가 우회나 운영자 권한을 만들지 않는다. 합성 체험용 약국 원장은 CLI에서 Demo registry 확인 후 마련하며, 일반 가입의 증빙·운영자 검토를 대신하지 않는다. 운영 DB 반영은 본 WO의 로컬 검증·PR 작성과 별개다.

버튼으로 로그인한 뒤 서비스의 의미 있는 샘플 기능을 체험할 수 있어야 한다. 사용자는 현재 계정과 데이터를 모두 테스트 데이터로 지정했다. 재사용할 데이터는 대표 Demo 계정에 연결하고, 재사용하지 않는 데이터와 개발을 방해하는 계정은 정리한다. 과거 실사용 분류만으로 보존하지 않는다. 대상 DB·참조 관계·복구 자료를 확인하여 데이터 연결과 기능 검증을 먼저 수행하고, 불필요 데이터와 계정은 마지막에 삭제한다.

## 로그아웃과 세션 보안

일반 로그아웃은 해당 서브도메인의 현재 브라우저 세션만 종료한다. 같은 서비스의 모든 기기를 종료하는 기능과 사용자용 전체 로그아웃은 제공하지 않는다. 비밀번호 변경·재설정은 보안 처리로 모든 서비스의 기존 세션을 무효화한다. access token, refresh, handoff에 동일한 폐기 판정을 적용한다. 단계 2 구현은 `(user_id, service_key, session_id)` 브라우저 폐기 원장을 사용한다. 로그인·handoff는 새 `session_id`, refresh는 기존 ID를 승계한다. 비밀번호 저장·재설정 토큰 소비·계정 보안 세대 회전은 같은 transaction으로 묶고, access·refresh·handoff가 현재 DB 세대와 브라우저 폐기를 확인한다. 세션 ID가 없는 이전 토큰은 배포 후 재로그인이 필요하다. 단계 2의 main 통합·운영 적용 여부는 [검증 기록](../checks/CHECK-O4O-AUTH-REFACTOR-PHASE2-V1.md)을 따른다.

## 관리자 용어

`admin.neture.co.kr`의 플랫폼 전체 관리 주체는 문서에서 **전체관리자**로 표기한다. 서비스 관리자는 특정 서비스의 관리 주체, 서비스 운영자는 해당 서비스의 운영 담당자다. 이 용어 구분으로 기술 role 코드나 권한 범위를 변경하지 않는다. 공개 테스트 계정은 전체관리자·서비스 관리자·운영자 권한을 갖지 않는다.

## 적용 관계

이 문서는 이전 문서의 메인 수동 승인 대기, Store 다업종 신규 가입, KPA 승인에 따른 매장 자동 생성·복구, 특정 서비스의 미가입 로그인 거부 서술을 대체한다. 위 추가 정책의 변경 범위 외에는 기존 역할 격리·개별 서비스 승인 계약을 유지한다. 유료화 시점·무료 기간·무료 종료 후 기능과 데이터 처리는 미정이며 이번 구현에 결제 제한을 추가하지 않는다.


### My Home 대표 진입 목적지 (2026-10-11)

[My Home 정본](O4O-MY-HOME-CANONICAL-V1.md)의 공통 진입은 `targetServiceKey=neture`의 기존 대표 진입 세션 전달을 사용한다. 허용 `returnPath`는 `/`, `/mypage`, `/mypage?from=`의 열거된 `store`, `study`, `community`, `funding`, `supplier`, `pharmacy`, `kpa`, `admin`뿐이다. 임의 계정/관리 경로·외부 origin·추가 query를 허용하지 않는다. 활성 계정·검증된 세션·교환 origin·토큰 소비·폐기 조건은 그대로 적용하며 서비스 membership이나 역할을 만들지 않는다. `from`은 복귀 안내용이며 인증·권한 판정에 사용하지 않는다. [구현 CHECK](../checks/CHECK-O4O-MY-HOME-IMPLEMENTATION-V1.md) 기준 소스·로컬 검증 완료, 운영 배포 대기다.
