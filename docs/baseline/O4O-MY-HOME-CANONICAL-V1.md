# O4O My Home 명칭 · 역할 · 진입 정본

> **상태**: ACTIVE
> **작성일**: 2026-10-11 · **최종 갱신**: 2026-10-12
> **근거 WO/IR**: [WO-O4O-MY-HOME-DOCUMENT-ALIGNMENT-V1](../work-orders/WO-O4O-MY-HOME-DOCUMENT-ALIGNMENT-V1.md) · 사용자 My Home 명칭 확정 및 관련 문서 정비 지시
> **범위**: 개인 통합 공간의 사용자용 명칭, 정보구조, 공통 진입, 내 매장과의 관계. 구현·검증 근거는 아래 실행 문서로 구분한다.

## 1. 명칭과 목적

개인 통합 공간의 표준 이름은 **My Home**이다. 메뉴·화면 제목·현행 안내 문서에서 같은 표기를 사용한다. `My Page`, `MyPage`, `마이페이지`는 종전 사용자용 명칭이며 새 화면 이름으로 사용하지 않는다. My Home은 일반 회원과 매장 경영자가 모두 이용하는 **사람 기준 개인 통합 공간**이다.

`study`, `community`, `funding`, `store` 등 독립 서비스의 참여·활동 현황을 모아 보고 해당 서비스로 이동한다. 약국 경영자는 매장 관리 외에도 커뮤니티·학습·개별 사업 참여 활동을 이용하므로 My Home을 매장 경영자 전용 화면으로 제한하지 않는다.

대표 홈은 공개 서비스 발견과 플랫폼 진입, My Home은 로그인한 본인의 현황 확인, 내 매장은 조직의 실제 운영 업무를 담당한다. My Home의 Home은 서비스마다 별도 소개 Home을 만들자는 의미가 아니다.

## 2. 화면 구성

전체 공간을 단일 화면에 모두 넣지 않고 공통 내비게이션으로 연결된 여러 화면으로 구성한다. 기본 구분은 다음과 같다. 실제 데이터와 구현이 준비되지 않은 항목은 제공 중이라고 표시하지 않는다.

| 영역 | 제공할 내용 | 원본 업무 위치 |
|---|---|---|
| 모아보기 | 최근 알림 3건·역할별 대표 업무·상세 화면 링크 | My Home의 짧은 첫 화면 |
| 참여 서비스 | 본인이 가입·신청·참여한 서비스와 약국 협력사업의 상태·이동 | 신청·승인·업무는 해당 서비스 |
| 커뮤니티 활동 | 본인의 가입 커뮤니티·작성 글·댓글 등 활동 현황 | 공통 커뮤니티 또는 해당 협력사업 참여자 공간 |
| 경영 현황 | 접근 권한이 있는 매장과 협력사업의 경영 통계·추이·요약 | 운영 업무는 내 매장, 사업 참여 업무는 해당 사업 |
| 계정 설정 | 프로필·로그인 수단·알림 등 개인 설정 | 공통 계정·기존 보안 계약 적용 |

학습·펀딩 등 활동은 참여 서비스에서 연결한다. 각 서비스의 상세 업무 화면과 데이터 원장을 My Home에 복제하지 않는다. 경영 현황은 매장 권한이 있는 사용자에게 제공하고 일반 회원에게 매장 개설이나 경영자 역할을 요구하지 않는다.

## 3. 진입 위치

- **공통 헤더**: 로그인 후 `My Home`을 항상 식별할 수 있는 직접 링크로 표시한다. 아바타·프로필 드롭다운 안에만 넣지 않는다. 데스크톱은 헤더 오른쪽 사용자 영역에 배치한다.
- **모바일**: 같은 공통 진입을 유지한다. 기존 공통 하단 탐색이 있는 화면은 `My Home`을 고정 항목으로 제공하고, 하단 탐색이 없는 화면은 헤더의 직접 진입을 유지한다. 이 결정만으로 모든 서비스에 새 하단 탐색을 만들지 않는다.
- **독립 서비스**: 로그인한 사용자가 같은 이름으로 개인 통합 공간에 돌아올 수 있도록 공통 위치에서 연결한다. 사용자에게 서비스마다 서로 다른 개인 통합 공간으로 보이게 만들지 않는다.
- **내 매장**: 해당 매장 업무 권한이 있는 사용자에게는 `My Home · 내 매장`을 구분해 제공한다. My Home의 경영 요약에서도 내 매장의 해당 업무로 이동할 수 있게 한다.
- **비로그인**: 기존 로그인·가입 진입을 사용한다. My Home 진입 정책이 공개 커뮤니티·강의의 항목별 접근 정책을 일괄 로그인 필수로 바꾸지 않는다.

대표 목적지는 `neture.co.kr/mypage`이며 독립 서비스에서는 기존 세션 handoff로 이동한다. 대표 홈 내부에서는 직접 이동한다. 새 My Home 전용 서브도메인이나 `/my-home` 경로를 이 문서만으로 생성하지 않는다. 연결되지 않은 메뉴를 완료된 진입으로 노출하지 않는다.

## 4. 내 매장과 서비스의 관계

My Home은 **User**, 내 매장은 **Store / organizationId** 기준이다. 약국 경영자의 같은 약국에서 이용하는 여러 약국 협력사업 기능은 한 내 매장 안에서 사업별로 구획한다. study·community·funding을 내 매장 아래로 편입하지 않는다.

My Home의 참여 서비스는 개인의 서비스·커뮤니티·사업 참여를 모아 보는 범위다. 기존 Store의 `My Services`는 매장 가입 서비스·업무 진입 범위이므로 두 목록을 같은 원장으로 간주하지 않는다. `service_memberships`, `community_memberships`, `semi_franchise_memberships`, 매장 enrollment는 각 정본의 소유·가입·승인 판정을 유지한다.

경영 통계는 본인이 조회 권한을 가진 매장·사업 범위만 보여준다. 개인 공간 진입이나 카드 노출이 다른 매장·사업의 열람·운영 권한을 만들지 않는다. 현재 QR 방문 통계의 출처·집계 기간은 §6에 명시하며 존재하지 않는 통계·수치를 생성하지 않는다. 소비자 commerce를 복구하거나 외부 POS 매출을 O4O 주문 집계로 간주하지 않는다.

## 5. 계정 관리와 호환성

공통 계정은 [인증·가입 정본](O4O-NETURE-AUTH-AND-SERVICE-MEMBERSHIP-V1.md)에 따라 `neture.co.kr`에서 관리한다. 로그인 수단·프로필의 계약은 [Identity V3](../architecture/O4O-IDENTITY-ARCHITECTURE-V3.md)를 따른다. My Home의 계정 설정을 서비스마다 새로운 계정·비밀번호를 만드는 기능으로 해석하지 않는다.

종전 [계정 관리 위치 정본](O4O-MYPAGE-CANONICAL-V1.md)의 `/mypage`, `/mypage/profile`, `/mypage/settings`와 기존 `/account`·`MyPageShell`·`MyPageLayout` 등은 현재 또는 과거 구현의 기술 식별자다. 사용자용 명칭 변경으로 URL·파일명·컴포넌트·API·문서 경로를 일괄 개명하지 않는다. 현재 구현은 기존 계정·사업자·커뮤니티 운영자 경로를 유지하며 호환 링크를 검증한다.

My Home을 `web-account`로 이전하거나 그 앱의 금지 기능을 해제하는 결정이 아니다. 종전 문서의 **개인 공간 전체를 계정 관리나 서비스별 활동 화면으로만 한정하는 설명**은 이 정본으로 대체하고, 인증·보안·소유권·서비스별 권한 경계는 유지한다.

## 6. 구현 상태와 검증 기준

[구현 WO](../work-orders/WO-O4O-MY-HOME-IMPLEMENTATION-V1.md)와 [CHECK](../checks/CHECK-O4O-MY-HOME-IMPLEMENTATION-V1.md)에 소스·로컬 검증·main 통합·운영 배포 상태를 기록한다. 모아보기(`/mypage`), 참여 서비스(`/mypage/services`), 커뮤니티 활동(`/mypage/activity`), 경영 현황(`/mypage/management`), 계정 설정(`/mypage/settings`)을 제공한다. `/mypage/profile`과 공급자 사업자 정보·커뮤니티 운영자 화면은 계정·업무 하위 기능으로 유지한다.

대표 메인에서는 O4O AI 아래에 My Home 요약·전체보기·업무 바로가기를 두고 전체 서비스 탐색을 이어서 제공한다. 공통 헤더와 기존 Neture·KPA 하단 탐색에서 같은 대표 공간으로 진입한다. 서비스 복귀 맥락은 고정 origin만 사용하며 권한을 바꾸지 않는다.

### 현재 화면 범위 — 최소 모아보기와 AI 별도 개발

모아보기에는 최근 본인 알림 3건, 이용 가능한 역할별 대표 업무 1개(최대 4개), 참여 서비스·커뮤니티 활동·경영 현황·계정 설정의 상세 링크를 표시한다. 추가 업무와 가입·이용 상태의 상세는 참여 서비스에서 확인한다. 미사용 역할 카드를 반복하지 않으며 승인 매장이 없는 일반 회원에게 경영 요약 카드나 매장 개설을 요구하지 않는다. 기존 경영 현황 직접 URL과 권한 없는 매장의 빈 상태는 유지한다.

첫 화면에는 Study·Funding·커뮤니티 글·매장 협력사업·QR 통계 컴포넌트를 마운트하지 않고 해당 상세 API를 호출하지 않는다. 참여 서비스에서 Study 수강 상태·진도와 Funding 참여·펀딩 처리 상태를 10건씩 확인하고 원래 업무로 이동한다. Study는 활성 membership과 서버의 lecture 고정 scope·기존 세션 handoff를 유지하며, Funding 본인 참여 조회에 membership을 추가로 요구하지 않는다. Funding은 해당 호스트의 기존 링크와 로그인을 사용한다. 커뮤니티 활동에서 접근 가능한 커뮤니티별 본인 글을 10건씩 조회하며 임시 저장·승인 대기 등 원본 상태를 구분한다. 댓글·금액·매출/POS·사업 성과를 새로 집계하지 않는다.

알림은 같은 화면에서 전체보기로 펼쳐 10건씩 조회하고 기존 서버의 `isRead` 조건으로 전체·읽지 않음·읽음 상태를 구분한다. 접으면 최근 3건으로 돌아간다. 다른 소비처의 기본 최근 5건은 유지하며 실제 표시 수를 안내한다. 계정 변경 시 필터·페이지를 초기화하고 늦은 이전 응답을 버린다. 읽음 처리는 각 서비스의 기존 기능을 유지한다.

승인 매장의 협력사업은 참여 서비스의 10건 상세와 경영 현황의 최대 3건 요약에서 조회한다. 기존 `GET /neture/pharmacy/semi-franchises`와 선택 매장 header를 사용하고 membershipStatus가 있는 사업만 표시한다. 경영 현황의 QR은 기존 `/kpa/pharmacy/analytics/marketing`의 오늘·최근 7일·누적 방문·활성 QR·최근 14일 일별 기록을 사용한다. 서버가 organizationId의 소유권을 다시 판정하며 누락 날짜를 0으로 생성하지 않는다. 선택 매장은 같은 탭·계정과 현재 승인 매장 목록으로 대조하고 상세 화면 사이에서 유지한다. 참여 서비스의 사업 조회는 QR API를 호출하지 않는다. 원본 Store 업무로 이동한 복수 매장은 Store에서 다시 선택하며 보조 선택값이 서버 권한을 대신하지 않는다.

**My Home AI는 별도 개발한다.** 이번 최소 화면 Phase에는 AI 입력·모델/API·요청·Task 상태·결과 UI를 제공하지 않는다. 후속 AI 기능의 연결 위치는 My Home 모아보기 상단이며, 실제 동작·데이터·승인 범위는 별도 AI WO에서 결정한다. 개발 전 빈 입력창이나 미구현 메뉴를 제공 중으로 표시하지 않는다. 대표 홈의 기존 O4O AI와 My Home 요약, 모든 서비스의 공통 헤더·기존 하단 진입은 유지한다.
