# 현재 전체 관리자와 폐기 역할 정책

> **상태**: ACTIVE

> **근거 WO**: [통합 운영 책임 정비](../work-orders/WO-O4O-UNIFIED-OPERATING-RESPONSIBILITY-V1.md) · [관리자 메뉴·역할 정비](../work-orders/WO-O4O-ADMIN-PLATFORM-MENU-ROLE-CLEANUP-V1.md)
> **부분 대체 대상**: [ROLE-POLICY-AND-GUARD-V1](ROLE-POLICY-AND-GUARD-V1.md)의 전체 관리자 역할·역할 종류 편집·폐기 역할 취급 범위

## 현재 결정

**2026-11-01 사용자 재확인:** 관리자 사이트(`admin.neture.co.kr`)에는 **전체 관리자(Admin)**와 **업무 운영자(Operator)**를 둔다. 일상업무 화면 `/operations`의 명칭은 **업무 운영**으로 통일한다.

- 전체 관리자 역할은 기존 `platform:super_admin`이다. 모든 현재 전체 관리자는 관리자 사이트 전체와 업무 운영을 별도 지정 없이 이용한다. 특정 이메일을 코드의 권한 근거로 사용하지 않는다.
- 업무 운영자는 전체 관리자가 **업무 운영자 지정**에서 초대·업무 변경·지정 해제를 관리한다. 본인이 초대를 수락한 뒤 Google 인증으로 지정된 일상업무를 처리한다. `/operations` 밖의 전체 관리자 화면·계정 관리·운영자 재위임 권한은 얻지 않는다.
- 업무 운영자 지정은 각 서비스의 Admin을 지정하는 기능이 아니다. 사용자는 대상 서비스나 Admin 역할을 선택하지 않는다. 기본 범위는 위임 가능한 일상업무 전체이며 필요한 업무만 선택할 수도 있다. 기존 업무별 Operator 역할·`scope_type=o4o-direct`·메뉴 제한을 재사용하며 새 전역 역할이나 새 권한 원장은 만들지 않는다.
- 전체 관리자 전용·서비스 Admin 전용 설정/중요 관리 업무와 개별 조합·분회·MegaPharm·CarePharm의 내부 운영은 위임하지 않는다. 업무 API의 역할·membership·조직·전문 자격 검사는 유지한다.
- 서비스 Admin의 별도 지정·관리는 기존 서비스 관리자 화면에 유지한다. 2026-10-29의 “중앙에서는 서비스 Admin만 지정”은 **서비스 역할 지정**의 기준이며, 관리자 사이트의 업무 운영자 지정을 막는 기준으로 적용하지 않는다. 서비스 Admin 지정만으로 업무 운영 권한을 자동 부여하지 않는다.
- 기존 전체 관리자·서비스/조직 역할과 이미 수락한 중앙 위임을 자동 삭제·변환하지 않는다. 기존 별도 서비스 역할·조직 범위·유효기간과 충돌하면 자동 덮어쓰기 대신 검토를 요구한다. 업무 운영자 해제는 중앙 Operator 지정만 회수한다.

2026-10-29 이전 중앙 Operator 초대는 당시 차단 상태를 유지한다. 새 업무 운영자 초대는 기존 초대 원장의 명시적 `admin-operations` 범위로 구분하며, 한 번의 본인 수락에서 담당 업무에 필요한 기존 Operator 역할과 메뉴 제한을 같은 transaction으로 활성화한다. 초대·수락·회수·감사·개인정보 보존 경계는 유지한다.

일반 회원의 Google·카카오·이메일 로그인은 유지한다. 공통 상품 DB의 중요 관리 권한, 서비스 관리·서비스 대상 정책·역할 종류 편집의 퇴역 메뉴는 이번 업무 운영자 지정으로 확대·복원하지 않는다.

| 폐기 역할 | 현재 취급 |
| --- | --- |
| `platform:admin/operator/manager/vendor/member/contributor` | 현재 역할 조회·발급·인가에서 제외 |
| `kpa:district_admin/branch_admin/branch_operator` | 폐기된 조직 역할. 현행 `kpa-branch:*`와 구분 |
| `kpa:pharmacist/student` | 자격 프로필은 유지하고 과거 역할은 현재 권한에서 제외 |
| `lms:instructor` | 현행 강의 서비스 `lecture:*`를 대신하지 않음 |

위 역할은 DB의 활성 이력 행이 남아 있더라도 현재 카탈로그·권한 목록·권한 판정에 사용하지 않는다. 관리자 사용자 목록과 서비스 회원 콘솔의 목록·상세도 같은 퇴역 판정을 따른다. cosmetics·PharmacyHub의 기존 퇴역 경계는 유지한다.

## 유지하는 경계

2026-10-31 사용자 확인: 제거된 `kpa-society`는 중앙의 신규 서비스 관리자 지정·초대 대상에서 제외한다. 기존 역할 설명·할당 이력은 보존하며 `kpa-branch` 분회와 `neture:pharmacy_admin` 약국 협력사업은 이 제외 범위에 포함하지 않는다. 기존 미수락 초대도 신규 권한을 만들 수 없고 재발송하지 않는다. 중앙 담당자 지정은 위 Admin 초대·본인 수락·직영 업무 위임 계약을 유지한다.

- 현재 `platform:super_admin`, 각 서비스의 admin/operator, `kpa:store_owner`, `kpa-branch:*`, `lecture:*`는 이 문서의 폐기 대상이 아니다.
- 중앙 관리자 역할은 다른 서비스 업무를 수행할 권한을 자동으로 만들지 않는다. 서비스별 scope·조직 소속 검사를 유지한다.
- [KPA 역할](KPA-ROLE-MATRIX-V1.md)과 [분회 역할](KPA-BRANCH-ROLE-MATRIX-V1.md)은 독립 권한 경계다.
- 원본 역할 정의·할당 이력의 물리 삭제나 운영 DB 정리 완료를 뜻하지 않는다.
- 기존 Frozen baseline의 나머지 유효한 계층·서비스 격리·guard 원칙은 유지한다. 이 문서가 그 범위의 정책을 새로 확장하지 않는다.

종전 메뉴·역할 정비의 구현·검증·배포 상태는 [검증 기록](../checks/CHECK-O4O-ADMIN-PLATFORM-MENU-ROLE-CLEANUP-V1.md)에서 구분한다. 2026-10-28 통합 정책의 구현·검증 결과는 위 통합 구현 WO에서 기록하며 종전 CHECK로 완료를 대신하지 않는다.
