# 운영자 초대·본인 수락 및 보존 정책 V1

> **상태**: ACTIVE — 사용자 확정 정책. 구현·배포 완료와 구분한다.
> **확정일**: 2026-10-25 (한국시간)
> **승인 근거**: 사용자가 권장 개인정보 처리 기준과 전체 관리자·서비스 관리자의 신규 권한 부여에 `초대 → 본인 수락 → 활성화`를 승인했다.
> **범위**: #641 연속 작업. 플랫폼 전체 관리자 계정의 특별 부여 절차를 확대하지 않는다.

## 권한 부여·회수

- 전체 관리자의 서비스 Admin 지정, 서비스 Admin의 자기 서비스·사업 Operator 지정, 분회 운영자와 개별 조합 관리 역할의 신규 지정은 초대에 본인이 수락한 뒤에만 활성화한다.
- 서비스 운영자는 이메일 인증된 이메일·비밀번호 계정으로도 초대를 수락한다. Google 연결을 필수로 요구하지 않는다. `platform:*`·전체 관리자 화면의 Google 전용 경계는 유지한다.
- 기존 활성 운영자는 추가 수락을 요구하지 않으며 기존 권한을 유지한다. 초대 요청은 현재 계정·가입·인증 정책·사업/조직 소속 및 지정 가능 역할 범위를 확대하거나 정지 상태를 되살리지 않는다.
- 서비스·사업·분회·조합 경계를 초대 생성 시와 수락 시 모두 확인한다. 수락 시 초대자의 현재 지정 권한과 대상자의 현재 자격을 다시 확인한다.
- 권한 회수는 기존 권한 범위·마지막 관리자 보호를 유지하여 즉시 처리한다. 상대의 수락을 기다리지 않는다.
- 초대는 지정한 계정·이메일에 결합한다. 이메일로 계정을 자동 병합하지 않고, token 소지만으로 다른 계정에 권한을 부여하지 않는다. 실제 token을 관리자 화면·URL query·로그·영구 browser storage에 기록하지 않는다.

### 지정 주체 정리 (2026-10-27 사용자 결정)

전체관리자 등록에서는 서비스 Admin만 새로 초대한다. 서비스 Operator는 해당 서비스의 활성 Admin이 자기 범위에서 초대한다. 기존 활성 Operator와 회수 경로는 유지하며, 과거 전체관리자가 만든 대기 Operator 초대는 새로 수락·재발송하지 않고 취소 후 서비스 Admin 경로를 사용한다. 분회·개별 조합의 기존 지정 경계는 유지한다. Demo 계정은 검색·초대 대상에서 제외하며 계정 자체를 삭제하지 않는다.

같은 계정·서비스·역할·범위의 대기 초대가 있으면 최초 등록 화면에서도 재발송한다. 본인 수락 여부와 무관하게 1분 후 재발송할 수 있고 링크 secret만 교체한다. 최초 7일 만료는 연장하지 않는다. SMTP 수락은 수신함 도착 보장이 아니며 발송 실패를 성공으로 표시하지 않는다.

## 개인정보와 기간

| 데이터 | 종료·파기 기준 |
|---|---|
| 초대 링크 | 최초 생성 후 7일. 재발송은 secret만 교체하고 최초 만료를 연장하지 않는다 |
| 초대용 이메일·token hash | 수락·취소 시 같은 transaction에서 파기. 만료 정보는 1분 주기 job 및 접근 시 정리 |
| 최소 권한 변경 이력 | 생성 후 **Asia/Seoul 달력 1년**. 초대/수락/취소/만료/회수 상태, 역할·범위, 최소 actor/대상 식별자와 시각만 남김 |
| 계정 제거 | 개인정보·식별 연결은 제거하고 다른 사람의 계정·역할은 보존. 최소 사건 정보도 원래 기산점이 끝나면 파기 |

- 달력 1년은 고정 365일이 아니다. 2월29일의 다음 해 기념일이 없으면 3월1일 같은 한국 시각으로 한다. 재발송·수락·재가입은 이력의 원래 생성 시점을 다시 시작하지 않는다.
- 초대 메일 발송 경로는 주소·본문·token·preview URL·transport error를 별도 메일 로그에 복제하지 않는다. 실제 전달된 수신자 mailbox는 O4O 저장소의 파기 완료 범위가 아니다.
- 실제 법정 보존·분쟁 예외는 기존 개인정보 정책의 분리·최소 보존 절차를 따른다. 운영 편의를 위해 초대 본문이나 연락처를 무기한 보관하지 않는다.
- background job의 실행 주기와 만료 판정은 구분한다. 만료된 token은 job 실행 여부와 관계없이 수락할 수 없다. 인스턴스 실행·모니터링과 backlog는 배포 전 점검한다.

## 게시·운영 경계

정책 확정은 실제 메일 발송·실계정 권한 변경·운영 DB migration 승인과 다르다. 현재 게시된 개인정보 처리방침 원문을 덮어쓰지 않는다. 신규 흐름의 화면·메일에 위 목적과 기간을 안내하고, 다음 개인정보 처리방침 개정·운영 migration·배포는 검토 가능한 변경과 실행 범위를 확인한 뒤 진행한다.
