## 1. 적용 범위와 기존 문서 관계

O4O 내부 AI 비용을 줄이고, 사용자가 본인의 ChatGPT에서 O4O 자료와 업무 기능을 이용하는 연결을 확대한다. 새 기술은 사용자 업무시간과 운영비용 개선에 기여하는 경우에 도입한다.

| 기존 기준 | 이 정책에서의 관계 |
|---|---|
| [AI 자동화 진화 원칙](O4O-AI-AUTOMATION-EVOLUTION-PRINCIPLES-V1.md) §11~§13·§22 | 검증된 실행 재사용·시간 절감·사용자 편의 우선 원칙을 계승하고 비용 판단 방법만 보완한다 |
| [Personal Assistant V2](O4O-PERSONAL-ASSISTANT-ARCHITECTURE-V2.md) §3·§7·§9·§17·§18 | ONE Assistant·Task·Experience·Memory·실행 노드 및 개발 순서는 그대로 적용한다 |
| [AI Core + Extension](../architecture/O4O-AI-CORE-EXTENSION-FOUNDATION-V1.md) §2~§4 | 기존 실행기·업무 Extension·모델 선택·가격·quota·이력 계약을 재사용한다 |
| [매장 콘텐츠 제작 운영 원칙](O4O-STORE-CONTENT-PRODUCTION-OPERATING-PRINCIPLES-V1.md) §2~§5 | 사용자 외부 AI와 O4O 제작환경의 역할 분리 및 provider 중립성을 유지한다 |

이 문서는 위 구조·소유권·권한·승인·보존 계약을 변경하지 않는다. 정책 채택과 기능 구현·운영 활성화는 별개다. 구현·실사용 증거는 각 기능의 기존 TODO·CHECK에서 확인한다.

## 2. O4O 내부 AI 비용 절감

### 2-1. 검증된 자동화를 재사용한다

- 실제 업무에서 검증된 Experience·Skill·Procedure와 기존 결정적 실행을 먼저 재사용한다. 사용자의 현재 목적·상태·권한과 재사용 조건이 맞는지 확인한다.
- 같은 자료의 중복 해석, 불필요한 재생성·재시도, 이미 확인한 화면의 반복 추론을 줄인다. 캐시·결과 재사용은 원문 버전·소유·허용 audience·유효기간을 확인하며 다른 사용자·매장 자료를 섞지 않는다.
- 반복 절차가 깨졌거나 새로운 판단이 필요한 경우 AI로 돌아간다. 오래된 절차를 비용 때문에 강제로 적용하지 않는다. Shared Candidate를 모든 사용자의 표준 Workflow로 강제하지 않는다.
- 새로운 업무의 탐색 비용은 허용한다. 사용자에게 상세 prompt·모델 선택·절차 사전 구조화를 요구해 비용을 떠넘기지 않는다.

### 2-2. 업무에 맞는 실행 수단과 모델을 선택한다

선택 순서는 **검증된 기존 실행·재사용 가능성 확인 → 남은 판단에 적합한 AI 선택 → 결과 검증**이다. 저렴한 모델이나 브라우저 내장 모델을 모든 업무의 필수 첫 단계로 만들지 않는다.

| 판단 항목 | 적용 기준 |
|---|---|
| 품질·업무 난도 | 정확도·한국어·구조화 출력·이미지/도구 지원·지연·실패율을 업무 표본으로 비교한다. 추가 검수·재작업 비용까지 포함한다 |
| 모델·부담 선택 | 기존 AI Core 정책과 업무 Extension을 통해 선택한다. 별도 모델 registry·가격/사용량 원장·직접 호출 체계를 중복 생성하지 않는다 |
| 장애·미지원 | 기존 명시적 fallback 후보와 자료 전송·비용·quota 정책을 따른다. 불필요한 무한 재시도나 다른 부담 주체로의 자동 유료 전환을 하지 않는다 |
| 비용 기록 | O4O가 부담하는 호출은 기존 가격 버전·예약/정산·이력으로 관측한다. 추정 비용과 확정 청구를 구분하고 미계측은 0원으로 간주하지 않는다 |

필요한 유료 호출을 O4O가 부담할 수 있다는 기존 정책은 유지한다. 비용 절감은 품질·사용자 편의·업무 성공 가능성과 함께 평가한다.

### 2-3. Chrome 내장 AI 등은 검증할 후보로 다룬다

Chrome 내장 AI는 단순 요약·분류·정리 등 적합한 업무의 후보로 검토한다. 도입 전 지원 브라우저/버전·OS·하드웨어·언어·API 상태·모델 다운로드·실행 위치·약관·품질·지연을 실제 대상 환경에서 확인한다.

브라우저 탑재, 로컬 처리, 무료 이용 또는 전 사용자 지원을 가정하지 않는다. 로컬 모델이라는 이유만으로 자료 전송·보존 검토를 생략하지 않는다. 미지원 환경의 기존 수동 작업·기존 허용 경로를 유지하고, 대체 유료 호출은 명시된 부담·한도 정책을 따른다. 채택 시에도 기존 실행 경계 안에서 연결하며 별도 Assistant·Memory를 만들지 않는다.

## 3. 사용자의 ChatGPT에서 O4O 이용 확대

### 3-1. 비용과 책임을 분리한다

- 사용자의 ChatGPT가 수행하는 추론·콘텐츠 생성은 사용자 본인의 외부 이용 계약과 계정 범위에서 처리한다. 이 연결의 생성을 위해 O4O가 별도 모델 API를 대신 호출·과금하는 구조를 추가하지 않는다.
- O4O는 허용 자료 조회·업무 도구·기존 초안 저장·다시 열기 환경을 제공한다. 서버·저장·네트워크·인증·운영 비용은 O4O에 남으므로 전체 이용이 무비용이라고 안내하지 않는다.
- ChatGPT 구독은 API 크레딧이나 O4O 내부 모델 호출 자격과 동일하지 않다. OAuth 연결 역시 사용자의 모델 API key를 받는 기능이 아니다.
- 외부 모델·구독·토큰·생성비용·대화 이력·개별 모델 이용량을 O4O가 수집·관리하지 않는 기존 연결 정책을 유지한다. 사용자 ChatGPT 장애·한도·미지원 시 O4O 유료 모델로 몰래 전환하지 않는다.

### 3-2. 기존 MCP·OAuth와 업무 기능을 확장한다

현재 외부 연결 모듈과 기존 업무 저장처를 재사용한다. 새 연결 기능은 기존 O4O 로그인·명시적 동의·scope·선택한 작업공간과 실행 시 권한 재확인 안에서 제공한다. 자료 조회·초안 저장 이후 검수·게시·주문 등 확정 행위는 해당 도메인의 기존 계약을 따른다.

ChatGPT 연결 확대가 별도 Assistant·Task·Memory·콘텐츠 원장이나 모든 도메인 쓰기 권한을 허용하는 것은 아니다. 현재 지원 밖 업무는 범위·권한·실행 확인·검증을 명시한 별도 WO로 진행한다.

실제 ChatGPT 앱/커넥터 제공 조건, 사용자 플랜·지역·조직 제한, OAuth 왕복, 도구 호출, 연결 해제, 초안 저장 후 기존 화면에서 이어가기까지 검증한다. MCP endpoint 구현·배포만으로 ChatGPT 공개 등록이나 사용자 이용 완료를 선언하지 않는다. ChatGPT를 우선 검토하되 기존 provider 중립성은 유지한다.

## 4. 월간 기술 변화 점검과 중복 방지

AI 기술 운영 담당은 **월 1회 기존 O4O AI 연동 점검 회차에 기술 변화 검토를 통합**한다. 기존 회차가 없으면 첫 회차에서 담당 역할·점검일·다음 점검일을 정한다. 보안 공지·호환성 중단처럼 긴급한 변화는 같은 기록에서 수시로 다룬다. 이 정책은 예약 작업·자동 조사·알림의 구현을 뜻하지 않는다.

| 대상 | 우선 확인할 공식 근거 | O4O에서 확인할 질문 |
|---|---|---|
| Chrome 내장 AI·브라우저 기능 | [Chrome AI 문서](https://developer.chrome.com/docs/ai)·공식 변경 기록 | 실제 지원 환경과 품질이 내부 호출·사용자 대기시간을 줄이는가 |
| OpenAI·ChatGPT 앱/연결 | [OpenAI Apps SDK 문서](https://developers.openai.com/apps-sdk/)·[OpenAI 공식 도움말](https://help.openai.com/)·공식 변경 기록 | 기존 MCP·OAuth 연결의 호환성·배포/등록 조건·사용자 접근성이 개선되는가 |
| MCP·WebMCP | [MCP 공식 문서](https://modelcontextprotocol.io/)·[WebMCP 제안](https://github.com/webmachinelearning/webmcp)·브라우저 구현 문서 | 기존 도구 계약과 연결할 실익이 있는가. 제안·시험 지원·안정 지원을 구분했는가 |

WebMCP와 원격 MCP·OAuth를 같은 기능이나 상호 대체재로 간주하지 않는다. 발표·예고와 실제 제공, 테스트 환경과 운영 지원을 구분한다. 외부 커뮤니티 사례는 발견 자료로 활용하되 공식 지원 조건과 실제 재현으로 확인한다.

### 점검 기록을 한 곳에 모은다

- 같은 월·기술/기능·적용 업무는 기존 AI 연동 점검 기록의 한 항목으로 관리한다. 이미 있는 항목은 갱신하고 별도 기술 뉴스·평가·개발 TODO에 중복 등록하지 않는다.
- 첫 회차에 기존 점검 기록의 실제 경로를 지정하고 이후 회차에서 이전/다음 기록을 연결한다. 관련 [외부 연결 TODO](../work-orders/TODO-O4O-EXTERNAL-AI-CONTENT-CONNECTION-V1.md)·[AI 업무 정비 TODO](../work-orders/TODO-O4O-AI-WORK-EXTENSION-REALIGNMENT-V1.md)가 같은 사안을 추적하면 기존 항목을 링크한다.
- 항목별로 확인일·공식 출처/버전·변경 내용·기존 기능 영향·지원/비용/자료 조건·판정·근거·담당 역할·다음 검토일·연결된 TEST/WO와 중복 여부를 기록한다. 변화가 없으면 KEEP과 그 근거만 남긴다.
- 이번 정책 정비에서 전용 월간 점검 원장은 식별하지 못했다. 새 점검 서비스나 별도 데이터 원장을 만들지 않고, 실제 첫 운영 회차에서 기존 연동 점검과 기록 위치를 합친다. 월간 조사가 이미 수행됐다는 의미가 아니다.

## 5. 기술 도입 판정

| 판정 | 적용 기준 | 다음 행동 |
|---|---|---|
| KEEP | 기존 방식이 충분하거나 새 방식의 개선 가치가 확인되지 않음 | 기존 구현 유지, 변경 이유가 생길 때 재검토 |
| WATCH | 관련성은 있지만 지원·안정성·약관·효과 근거가 부족함 | 남은 질문과 다음 확인일 기록. 개발을 자동 개시하지 않음 |
| TEST | 개선 가설과 대상 업무가 구체적이고 제한된 검증이 가능함 | 범위·담당·비용 상한·대표 표본·성공/중단 기준을 정하고 허용된 격리 환경에서 검증 |
| ACTION | 비교 검증에서 사용자 시간/비용 개선이 확인되고 품질·권한·호환성 조건을 충족함 | 기존 담당 WO를 재사용하거나 범위를 명시한 WO로 개발 연결. 적용·검증·복구 방법을 기록 |

TEST/ACTION은 새 아키텍처 채택이나 운영 실행 승인을 대신하지 않는다. 유료 시험·외부 자료 전송·운영 DB·배포·계정/설정 변경은 기존 승인 경계를 따른다. 후속 TEST에서 효과가 없거나 회귀가 있으면 KEEP/WATCH로 되돌리고 근거를 남긴다. 기술 공개 자체는 ACTION의 근거가 아니다.

## 6. 성과 평가

같은 업무·비슷한 난도·같은 완료 기준의 전후 표본을 비교한다. 표본 수·관측 기간·미계측 범위를 함께 적는다.

| 평가 축 | 확인할 내용 |
|---|---|
| 사용자 시간 | 실제 사용자 작업시간·조작/수정 횟수·대기시간·인계 후 재작업 |
| O4O AI 비용 | 성공한 업무 1건당 O4O 부담 호출/토큰/추정 비용·반복 추론·재시도·검증된 실행 재사용 정도 |
| 총 운영 부담 | 모델 비용 외 서버·저장·전송·브라우저 다운로드/기기 부담·유지보수와 검수 비용 |
| 품질·안정성 | 완료 기준 충족·근거 정확성·오류/수정·권한 거부·지원 환경·fallback 동작 |
| 외부 ChatGPT 연결 | 허용 범위의 연결/저장 오류와 사용자가 기존 화면에서 이어갈 수 있는지. 선택적 사용성 피드백으로 시간 절감 확인 |

외부 ChatGPT 생성 비용·개별 모델 이용량을 수집해 절감액을 계산하지 않는다. 사용자에게 구독료를 새로 요구하거나 작업을 떠넘긴 결과를 O4O 비용 절감만으로 성공 처리하지 않는다. 계측이 없으면 미검증으로 기록하며 절감률·공개 등록·실사용 효과를 추정해 완료로 보고하지 않는다.

## 7. 적용 경계

이 정책의 저장소 반영은 문서 정비다. Chrome 내장 AI·WebMCP 도입, 신규 ChatGPT 도구, 모델 변경, 예약 점검, 코드·DB·운영 설정 변경을 함께 실행하지 않는다. 이후 개발에서는 본 정책의 선택·평가 기준을 적용하고 기존 구조 정본과 해당 업무의 승인 절차를 따른다.
