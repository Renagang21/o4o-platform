# O4O 통합 회원 가입·관리 기준

상태: ACTIVE 정책 · 사용자 확정 2026-11-04. 구현·검증 상태는 [TODO](../work-orders/TODO-O4O-UNIFIED-MEMBER-REGISTRATION-V1.md)와 [CHECK](../checks/CHECK-O4O-UNIFIED-MEMBER-REGISTRATION-V1.md)를 따른다. 문서 등록 자체가 main 반영·운영 배포 완료를 뜻하지 않는다. 사용자 후속 통합·배포 지시와 실제 상태는 TODO/CHECK 및 PR에서 구분한다.

## 가입과 승인

Google·카카오 우선, 이메일 보조의 기존 인증 화면과 계정 연결·자동 병합 금지, 중앙 운영 Google 전용 경계를 유지한다. 인증 수단을 만든 뒤 신규 회원은 약사·약국경영자·공급자·파트너·기타 중 하나를 선택한다. 분류는 권한 role이 아니다. 닉네임을 포함한 공통 정보와 해당 유형의 가입 정보를 제출하고 운영자가 확인·정정해 한 번 승인한다. 추가 사용자 자격 취득과 실제 사업자 변경은 가입 정정과 구분되는 기존 My Home 절차를 따른다.

약국경영자는 약사여야 한다. 승인 시 약사 자격, 약국 조직/owner 관계·약국 원장·Store 및 Pharmacy 기본 회원 연결을 같은 transaction으로 처리한다. 별도 약사 검토 대기나 약국경영자 신청·심사를 반복시키지 않는다. 약사 유형은 자격 원장만, 공급자는 기존 공급자 조직/owner·서비스 이용 역할을 연결한다. 파트너 분류는 독립 커뮤니티·사업 공간의 자동 가입/운영권을 만들지 않는다. 공급자 상품·공급 공개 승인, 독립 사업별 참여·거래 조건은 그대로다.

사업자 정보는 사업장명·사업자번호·대표자·업태·종목·사업자 구분·개업일·우편번호·주소/상세주소·사업장 전화·담당자 연락처·세금계산서 이메일·선택 증빙이다. 공급자의 공개 문의 이메일과 비공개 담당자 이메일을 구분한다. 약사 면허번호, 사업장명·사업자번호를 해당 유형의 최소 식별 정보로 확인하고 부가 정보·증빙 미완성만으로 승인을 막지 않는다. 약사 면허증 이미지를 받지 않는다. 비밀번호·제공자 식별자·정산 계좌를 회원 수정 필드로 복제하지 않는다.

통합 가입/운영자 정정 폼의 선택 서류는 PDF·JPG·PNG **8MB 이하(8,000,000바이트 상한)** 한 개다. 추가 multipart 필드는 거부한다. 기존 별도 사업자 관리 업로드의 한도는 해당 절차를 따른다.

## 운영자 화면과 정정

목록은 체크박스와 상단 작업을 유지하며 이름·닉네임·이메일·로그인 방식·가입 유형·회원 상태를 각각 한 줄의 열로 표시한다. 제공된 이메일이 없으면 미제공, 기존 분류가 없으면 미등록으로 표시하며 소셜 내부 ID를 보여주지 않는다. 약사 자격·약국 신청·Neture 이용·공통 계정의 상태를 독립 열로 나열하지 않는다. 미정인 유료 등급을 만들지 않는다.

회원 정보는 같은 폼으로 조회·수정한다. 현재 위임된 회원 담당자는 공통 항목과 해당 유형의 가입 항목·증빙을 정정하고 가입 승인/반려를 처리한다. 별도 자격·약국 업무 API의 기존 위임 범위와 전체 관리자 보호는 유지한다. 운영자가 확인한 이메일 정정은 다시 확인메일을 요구하지 않는다. 이메일 중복 방지·이전 인증 링크와 세션 폐기는 유지한다. 면허 오기 정정은 기존 승인 자격을 불필요하게 재심사하지 않지만 철회된 자격을 자동 복원하지 않는다. 임시 비밀번호의 해시 저장·만료·본인 요청 확인·일회 표시·My Home 변경 경로를 유지한다.

현재 사업체 소유자와 실제 조직/공급자 저장 위치를 기준으로 읽고 수정한다. 승인 후 My Home에서 바뀐 정보를 과거 가입 스냅샷으로 덮어쓰지 않는다. 사용자·면허·사업체 버전 및 현재 관계를 확인하고 충돌은 409로 처리한다. 이전 소유자의 공통 정보 정정은 가능하되 이전 사업체를 수정할 수 없다. 여러 사업체가 연결되어 대상이 불명확하면 임의 선택하지 않고 해당 사업체 관리에서 처리한다. 증빙은 대상 회원 또는 현재 소유 사업체의 비공개 서류인지 서버에서 검사한다.

## 해지·복구와 직원 경계

운영자 회원 상태 조작은 회원 해지·이용복구로 통일한다. 해당 Neture 회원 상태만 변경하며 공통 계정 삭제나 타 서비스 상태 변경을 하지 않는다. 해지 후 복구할 수 있고 기존 suspended도 복구 대상이다. 공통 계정 자체가 막힌 경우 일반 회원 복구로 풀지 않는다.

직원의 초대·소속·직원 권한 해제는 매장 경영자의 업무다. 회원 운영자는 회원 해지와 함께 직원 소속·역할·매장 권한을 해제하거나 복구하지 않는다. 직원의 매장 업무에 개인 Neture 가입을 새로 요구하지 않는다. 전체 계정·개인자료 완전삭제, 약국 매도·폐업은 기존 Admin 전용 절차로 구분한다.

## 저장·호환·정책 적용 범위

예약된 `users.businessInfo.o4oMembershipRegistrationV1`은 서버 전용 가입 스냅샷이며 일반 프로필/business patch에서 수정할 수 없다. 신청 ID로 해당 제출의 게시 약관 동의 증적을 연결하고 운영자는 동의를 대신 생성하지 않는다. 실제 인가·사업자·자격 원장은 기존 테이블을 사용하며 DB migration과 기존 사용자 일괄 backfill을 추가하지 않는다.

신규 가입 writer만 미입력 표식을 만든다. 기존 활성 회원의 정보를 정정하면서 대기/반려 자격 상태를 저장해도 종전 메인 이용은 서버 전용 호환 표식으로 유지한다. 이는 자격·사업자 승인을 만들거나 명시적인 이용 해지를 풀지 않는다. 표식이 없는 기존 사용자의 이메일 확인 기반 메인 이용은 유지한다. 명시적인 해지/정지는 신규 승인 표식보다 우선한다. 기존 유형은 현재 자격/소유 사업체에서 읽기 호환하며 추측으로 일괄 승인하거나 역할을 만들지 않는다.

이 문서는 인증/서비스 가입 V1의 신규 회원 이메일 확인만으로 메인 가입 완료되는 설명, 운영 책임 V2의 별도 약사 자격 검토 단계, 약국 commerce의 별도 최초 약국 신청·승인 UI 설명을 **신규 통합 가입 및 회원 정정 범위에서만** 대체한다. 기존 원장·보호 기능·사업별 독립 승인·판매/폐업·직원 접근의 경계는 대체하지 않는다.
