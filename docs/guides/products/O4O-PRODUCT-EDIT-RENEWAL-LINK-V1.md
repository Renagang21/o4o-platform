# 기존 상품·설명서 편집의 갱신 검토 연결 V1

> **상태**: ACTIVE · **작성일**: 2026-10-25

> **근거**: 기존 일반 편집 경로의 변경을 갱신 작업에 연결하고 검증·push까지 한 번에 진행하라는 사용자 지시.
> **선행**: [보정 후속 운영](O4O-PRODUCT-CORRECTION-PERIODIC-OPERATIONS-V1.md) · [실행 WO](../../work-orders/WO-O4O-PRODUCT-EDIT-RENEWAL-LINK-V1.md)

## 연결한 저장 경로

| 경로 | 변경 판단 | 처리 |
|---|---|---|
| NetureCatalogService.updateProductMaster | 상품명·브랜드명·규격·원산지·태그·분류 참조·브랜드 참조·의약품 분류의 실제 저장 값 | 관련 canonical 설명서 유형·언어별 갱신 검토 |
| 관리자 공용 설명서 POST /masters/:id/store-descriptions | 관리자 직접 저장의 본문·요약 변경 또는 최초 정본 등록 | 저장된 정본 및 다른 관련 유형·언어의 갱신 검토 |
| P2 보정 승인·선택 반영 | 기존 P2 계약 | 기존 경로 유지 |

카탈로그 수정은 기존 Neture 관리자 PATCH와 상품 등록 후 확장 필드 저장에서 호출된다. 요청 처리자를 전달한다. 기존 역할·인증·immutable 보호 필드는 변경하지 않으며 서비스 관리자에게 공통 갱신 화면 권한을 추가하지 않는다. 레거시 서비스 편집 경로의 권한 계약을 새 권한 정책으로 확대·승격하지 않는다.

관리자 설명서 연결은 setCanonical의 명시적인 관리자 편집 옵션에서만 수행한다. 공급자 후보 제출·별도 검수/승격·일괄 수집·직접 SQL 쓰기의 전체 변경 감지는 이번 범위가 아니다. 기존 데이터 소급 반영·backfill·AI 호출·QR 변경·예약 변경은 없다.

## 실제 변경과 중복 방지

- 제출한 키 목록이 아니라 허용 필드의 변경 전후 값을 비교한다. DB 저장 후 다시 읽은 실제 값을 기록하므로 DB가 문자열 등으로 정규화한 값을 입력 형태로 잘못 기록하지 않는다.
- 동일한 실제 값의 재저장은 갱신 이벤트를 추가하지 않는다. 정상적인 같은 값 요청은 상품 save와 updatedAt 변경도 생략한다. 태그는 저장된 배열 순서까지 비교한다.
- 상품 행 잠금으로 동시 동일 변경을 직렬화한다. 응답이 유실된 뒤 같은 값으로 다시 저장해도 중복 검토가 생기지 않는다. 값을 되돌렸다가 다시 바꾸는 별도 실변경은 각각 기록한다.
- 관리자 설명서는 상품→대상 설명서 순서로 잠근 뒤 현재 정본과 본문·요약을 비교한다. 같으면 기존 정본 ID를 반환하고 정본을 교체하지 않으며 새 검토를 만들지 않는다. 여러 언어·유형은 각자의 canonical 계약을 유지한다.
- 기존 createCandidate→setCanonical 구조는 유지한다. 같은 내용 재저장이나 승격 실패로 생성된 미적용 candidate가 남을 수 있으며 이를 자동 삭제하지 않는다. 동일 내용 중복 방지의 대상은 정본 교체·갱신 이벤트·검토 작업이다.
- 편집·실변경 이벤트·갱신 검토·알림은 동일 transaction이다. 갱신 저장 실패 시 원본 수정·정본 교체도 rollback한다. 관리자 설명서의 앞서 저장된 candidate는 미적용 상태로 유지한다.

## 갱신 화면에서 확인할 내용

일반 편집도 관리자 → O4O 상품 DB → 데이터 정비 → 설명서 갱신 검토에 나타난다. 변경 경로를 **일반 상품 편집 / 관리자 설명서 저장 / 상품 보정 반영**으로 구분한다. 일반 편집에는 실제 처리자와 항목별 전후 값을 표시한다. 호출 경로에서 처리자를 전달하지 못한 내부 저장은 처리자를 추정하지 않고 null로 보존한다.

일반 편집은 P2 승인 작업으로 위장하지 않는다. 별도 변경 이벤트 ID를 사용하고 가짜 proposalId/batchId/taskId를 만들지 않는다. 기존 P2 작업과 과거 갱신 기록도 계속 조회할 수 있다.

일반 편집의 이용 목적은 **미지정** 상태다. 검토자가 전문인용·AI 판단지원용·소비자 QR용 중 실제 사용 목적을 지정하고 메모를 남겨야 검토 상태를 저장할 수 있다. 유형만 보고 목적을 자동 확정하지 않는다.

대상은 현재 canonical 설명서의 유형·언어다. 설명서가 하나도 없으면 STORE/ko의 미등록 설명서 검토를 남기며 본문을 자동 생성하지 않는다. 모든 작업은 검토 후보이며 자동 오류 판정이나 게시 완료가 아니다. 최신 원문 fingerprint와 작업 revision 충돌 검사는 유지한다.

## 저장·운영 경계

기존 settings에 product-correction:edit-event:<UUID>의 실제 변경 이벤트와 기존 renewal/notice 기록을 저장한다. 이벤트에는 변경 경로·처리자·시각·실제 전후 값을 보존하며 같은 이벤트 ID의 중복 전달도 막는다. ProductMaster 스키마에 설명서 FK를 추가하지 않는다. migration·외부 메시지 발송·운영 데이터 보정은 없다.

이 branch는 최신 main 23717b6dc0에 미병합 상품 관리 선행 c88dbaf014를 포함한다. 최신 초대 보관 worker와 상품 정기 관리 worker를 모두 유지했다. 이번 결과는 push까지이며 PR 생성·main 병합·운영 배포를 의미하지 않는다.
