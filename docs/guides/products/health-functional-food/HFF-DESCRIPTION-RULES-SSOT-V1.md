**이 문서는 건강기능식품 설명서 작성 규칙의 SSOT다.** 다른 건기식 문서(README·AGENT-KICKOFF 등)는 규칙을 다시 길게 적지 않고 규칙 ID(HFF-RNN)로만 참조한다.

> **소실 규칙 대체 (2026-07-12).** 과거 건기식 실행 문서는 일반식품 `general-food/README.md` 의 R1~R10 을 SSOT로 참조했으나, 일반식품이 **Legacy / Existing Content Only** 로 전환되며 그 규칙이 제거되어 참조가 끊겼다. 본 문서는 그 규칙을 **복원·복사하지 않고**, 현재 확정된 [O4O 매장용 상품 상세설명서 정책](../O4O-STORE-PRODUCT-DESCRIPTION-POLICY-V1.md)을 기준으로 건강기능식품 전용으로 **새로 구성**한 것이다. 충돌 시 최상위 정책 → 본 문서 순으로 우선한다.

## 1. 최상위 원칙 — 구매 지원

건강기능식품 설명서의 가장 중요한 목적은 **소비자의 구매를 돕는 것**이다.

```text
소비자의 관심과 고민
→ 제품의 매력과 선택 이유
→ 구체적인 제품 사실과 공식 근거
→ 제품에 대한 신뢰
→ 구매 또는 매장 문의
```

제품 신뢰는 구매를 제한하는 장치가 아니라, **소비자가 제품의 장점을 믿고 안심하여 구매 결정을 내리도록 돕는 판매 요소**다. 정확성과 주의사항을 이유로 설명서를 지나치게 경고 중심·제한 중심으로 만들지 않는다.

모든 HFF-R 규칙은 이 체인을 실현하기 위해 존재한다. 규칙이 이 체인과 충돌하게 해석되면 잘못 적용한 것이다.

## 2. 규칙 (HFF-R01 ~ HFF-R10)

각 규칙은 공통 규칙([CR-NNN](../../common/CONTENT-RULE-REGISTRY.md))을 건강기능식품 맥락으로 구체화한 것이다. 공통 규칙 본문은 CR을 참조하고 여기서 재정의하지 않는다.

### HFF-R01 — 구매 지원 우선 (CR-001)

건강기능식품 설명서는 성분표나 식약처 정보를 정리하는 문서가 아니다. 소비자가 제품에 관심을 갖고, 자신의 필요와 연결하며, 구매를 고려하도록 작성한다. "정확하지만 소비자의 구매 판단을 돕지 못하는 설명서"는 완성본으로 승인하지 않는다.

### HFF-R02 — 제품 단위 설명서

```text
제품 1건 = 설명서 1건
```

의약품처럼 성분 그룹으로 묶지 않는다. 같은 기능성 원료를 사용하더라도 **제품명·함량·제형·구성·섭취방법·제조사·포장이 다르면 별도 설명서**다.

### HFF-R03 — 제품 매력과 선택 이유 (CR-001)

성분과 기능성만 나열하지 않는다. 확인된 사실을 바탕으로 다음을 설명한다.

- 왜 이 제품을 살펴볼 만한가
- 어떤 소비자 관심과 연결되는가
- 어떤 특징이 선택 이유가 되는가
- 섭취가 얼마나 간편한가
- 본인용·가족용·선물용으로 어떤 가치가 있는가

**제품별 `why this product` 가 반드시 보여야 한다.** 제품 이름만 바꾸면 다른 제품에도 쓸 수 있는 설명서는 실패다.

### HFF-R04 — 제품 신뢰 형성 (CR-002)

제품 신뢰는 다음의 **구체성**으로 만든다.

- 기능성 원료
- 하루 섭취량 기준 실제 함량
- 식약처 인정 기능성
- 제조사·수입사
- 품목보고 정보
- 원산지·제조국
- 인증·특허 원료
- 제형·포장·구성
- 섭취방법

"좋은 원료", "프리미엄", "엄선된 성분"처럼 **근거 없는 추상어만** 사용하지 않는다. (특허 원료는 인용 사실로만 쓰고 제품 효능으로 전이하지 않는다 — HFF-R06.)

### HFF-R05 — 공식정보는 판매 근거로 활용 (CR-002)

식약처 기능성·품목정보는 설명서의 전부가 아니다. 공식정보를 소비자가 이해하기 쉬운 언어로 풀어 **제품의 장점과 신뢰를 뒷받침하는 근거**로 사용한다.

- 원문을 그대로 복사하지 않는다.
- 기능성 표현은 **확인된 식약처 인정 범위를 벗어나지 않는다**(표시 그대로 "~에 필요"/"~에 도움을 줄 수 있음").
- 비인정 기능성을 제품 기능으로 단정하지 않는다.

### HFF-R06 — 적극적 표현과 최소 제한 (CR-001 · CR-003)

다음 표현은 소비자의 구매 판단을 돕기 위해 **적극적으로 사용할 수 있다**(로그인 회원 전용 매장 콘텐츠 전제).

- 질환·증상과 관련된 건강 관심
- 생활 속 고민
- 연령·성별별 관심
- 본인·가족·부모님을 위한 구매 상황
- 선물 가치 · 섭취 편의성 · 건강관리 목적 · 제품 선택 상황

다만 다음은 **금지**한다.

```text
확인되지 않은 제품 사실
치료·예방·효과 보장
누구에게나 효과가 있다는 단정
원료 일반정보를 제품의 확정 효과로 표현
```

이 최소 금지 외의 과도한 제한은 두지 않는다.

### HFF-R07 — 소비자 화면 문구만 작성 (CR-001)

설명서 본문에는 소비자가 실제로 읽는 내용만 넣는다. 다음은 소비자 콘텐츠에 넣지 않는다.

- 작성 지시 · 편집 라벨 · 근거 메모 · 검수 상태 · 내부 source ID
- "관심 유발", "판매 포인트" 같은 작업용 제목

근거와 내부 메모는 **별도 필드(`source_check_memo`)나 CHECK**에 남긴다.

### HFF-R08 — 주의사항은 구매를 돕는 범위로 (CR-006)

주의사항은 소비자가 자신에게 맞는 제품인지 안전하게 판단하도록 돕기 위한 것이다.

- 필요한 내용만 짧고 명확하게 작성
- 제품 장점보다 크게 강조하지 않음
- 모든 가능성을 장황하게 나열하지 않음
- 불필요한 불안 조성 금지
- 제품별 **공식 주의사항은 누락하지 않음**

공통 상담 문구는 본문을 위축시키는 경고가 아니라 **매장 문의로 자연스럽게 연결**하는 용도로 사용한다. 상담 주체 용어는 서비스 중립적으로 "매장 내 전문성이 있는 도우미"(약국 맥락은 "약사").

### HFF-R09 — 원천과 grounding (CR-002 · CR-004 · CR-007)

제품 사실은 다음 우선순위로 확인한다.

```text
1. 식약처 공식 품목정보
2. 제품 표시사항·포장 이미지
3. 제조사·수입사 공식 정보
4. 기존 O4O ProductMaster·Identifier·Description 데이터
5. 보조 웹 조사
```

웹 쇼핑몰·블로그·후기는 제품 사실의 **단독 근거로 사용하지 않는다**(효능·질병 개선 후기·마케팅 과장 채택 금지). 웹은 시판 여부·제품 이미지·구성·제조사 공식자료 보강용이다. **확인되지 않은 항목은 비우거나 보류**한다(추정으로 채우지 않음).

### HFF-R10 — 검수·승격·이중게이트 (CR-008 · CR-009)

설명서 초안 작성과 canonical 반영을 분리한다.

```text
초안 작성 → 원천 검증 → 내용 검수 → 사용자/승인권자 확인 → 이중게이트 → canonical 반영
```

다음은 **승인 없이 수행하지 않는다.**

```text
DB write · canonical 승격 · 기존 canonical 교체
대량 설명서 생성 · ProductLanding 연결 · QR 노출 · 운영 배포
```

DB 비밀정보는 문서·커밋에 기록하지 않고 env에서만 추출한다(CR-014).

## 3. 표준 설명서 구조

모바일 QR 스크롤 랜딩. 성분 카드만 나열하지 말고 읽을거리를 갖춘 랜딩으로 구성한다.

```text
1. 소비자의 관심과 고민
2. 제품의 핵심 포지셔닝
3. 왜 이 제품인가
4. 핵심 기능성 원료와 의미
5. 함량·구성·제형의 선택 포인트
6. 생활 속 섭취 가치
7. 이런 분께
8. 섭취방법
9. 필요한 확인사항
10. 구매 또는 매장 문의 연결
```

**모든 제품에 동일한 길이와 순서를 강제하지 않는다.** 제품의 매력이 가장 잘 드러나도록 일부 섹션은 합치거나 순서를 조정할 수 있다. 형식(시맨틱 `sd-*` HTML, `<style>` 금지)·폰트·반응형·테마는 공용 렌더러가 담당한다 — 상세는 [AGENT-KICKOFF §5](AGENT-KICKOFF.md).

## 4. 언어 정책

건강기능식품 STORE 설명서의 현재 기준 언어는 **`ko + en`** 이다(2026-07-11 확정, [PROCESSED-LEDGER](PROCESSED-LEDGER.md) · [AGENT-KICKOFF §3](AGENT-KICKOFF.md)).

```text
한국어 = 정본
영어    = 한국어 정본 기반, 영어권 소비자 톤(단순 번역 아님). 기능성은 MFDS-recognized 프레임
숫자·함량·제품명·기능성 범위 변경 금지
판매 표현을 임의로 강화하지 않음
```

- 과거 기본이던 `zh` 는 **더 이상 신규 정본 언어가 아니다.** 기존 photo 배치의 `ko+zh` 산출물은 임시 예제이며(정본 아님, LEDGER 헤더), 신규 제작은 `ko+en` 으로 한다.
- 다국어는 승인된 한국어 기준본이 확정된 뒤 진행한다.

## 5. 샘플·예제의 지위

예제는 **문체·구조 참고용이며 사실 기준이 아니다.**

```text
샘플 제품의 문구를 다른 제품에 복사하지 않는다.
제품별 사실은 해당 제품 원천으로 다시 확인한다(HFF-R09).
```

- **정본 예제** = [examples/byeonenjang.semantic.html](examples/byeonenjang.semantic.html) (시맨틱 `sd-*`, `<style>` 없음, 식약처 grounding).
- **사진 기반 임시 예제**(맨파워포텐 등 photo 배치, `ko+zh`)는 문장 예시용이며 정본이 아니다(추후 삭제 예정, LEDGER 헤더).
