## 1. 목적

제품 단위로 O4O 매장용 공통 상세설명서를 작성할 때 사용하는 실행 가이드다.

설명서의 목적은 정보를 정리하는 것이 아니라, 소비자가 제품에 관심을 갖고 제품의 장점과 신뢰 요소를 이해하여 구매를 고려하도록 돕는 것이다.

```text
관심과 고민
→ 제품의 매력과 선택 이유
→ 구체적인 제품 사실과 공식 근거
→ 제품 신뢰
→ 구매 또는 매장 문의
```

---

## 2. 현재 적용 범위

### O4O 직접 제작

- **건강기능식품**: 제품 1건 = 설명서 1건

### 별도 특수 트랙

- **일반의약품**: 성분·함량·제형·투여경로·허가사항 기준 그룹 설명서
- **처방의약품**: 제작하지 않음

### 이 가이드로 신규 제작하지 않음

- **일반식품**: 신규 제작 중단. 기존 설명서와 연결은 유지
- **화장품**: 공급자 제작 영역
- **기타 일반제품**: 별도 승인 없이는 제작하지 않음

의료기기와 의약외품은 분류별 제작 기준이 확정된 뒤 별도 가이드를 적용한다.

---

## 3. 제품 단위 작성 원칙

- **제품 1건 = 설명서 1건**이다.
- 성분·공식정보만 나열하지 않는다.
- 소비자의 질환·증상·생활 고민과 제품을 자연스럽게 연결한다.
- 제품의 원료·함량·기능·제형·구성·편의성·제조정보에서 선택 이유를 찾아 설명한다.
- 공식 기능성·품목정보·제조사·인증 등은 제품의 매력을 믿게 하는 근거로 사용한다.
- 확인되지 않은 제품 사실은 만들지 않는다.
- 치료·예방·효과 보장은 단정하지 않는다.
- 원료의 일반 정보를 해당 제품의 확정 효과로 바꾸지 않는다.
- 주의사항은 구매 판단에 필요한 범위에서 짧고 명확하게 제공한다.
- 소비자 화면 문구만 저장하고 편집자용 라벨이나 작업 지시를 넣지 않는다.

---

## 4. 한국어 설명서 권장 구조

```text
title                    제품명
subtitle                 소비자 관심과 핵심 가치
summary                  제품 포지셔닝
why_this_product         제품을 선택할 이유
key_points               핵심 원료·함량·기능·구성
trust_points             공식 기능성·제조사·품목·인증 등 신뢰 근거
who_is_it_for            이런 분께
how_to_use_or_take       섭취·사용 방법
necessary_notice         꼭 필요한 확인사항
purchase_or_consult      구매 판단 또는 매장 문의 연결
source_check_memo        내부 근거 메모(소비자 비노출)
```

문단은 짧고 모바일에서 빠르게 읽을 수 있게 작성하되, 제품의 매력과 선택 이유가 충분히 드러나야 한다.

---

## 5. 문체

- 소비자의 실제 고민이나 선택 상황에서 시작한다.
- 제품의 가장 강한 장점을 초반에 보여준다.
- 어려운 공식 문구는 의미를 바꾸지 않고 쉽게 풀어 쓴다.
- 막연한 칭찬보다 구체적인 함량·구성·제형·제조정보를 사용한다.
- 제품을 섭취·사용·휴대·선물하는 장면을 떠올릴 수 있게 한다.
- 경고문으로 끝내지 않고 구매 판단이나 매장 문의로 자연스럽게 연결한다.

설명서의 첫 번째 품질 질문:

> 이 설명서를 읽은 소비자가 제품의 장점을 믿고 구매를 고려하게 되는가?

---

## 6. 건강기능식품 기준

### 확인 원천

- 제품명·제조사·품목보고번호
- 기능성 원료와 식약처 인정 기능성
- 기준규격과 실제 함량
- 1일 섭취량과 섭취 방법
- 섭취 시 주의사항
- 원산지·제형·포장·구성
- 현재 시판 여부와 제조사 공식자료

### 작성 방향

- 식약처 인정 기능성은 제품 신뢰의 핵심 근거로 사용한다.
- 기능성 문구만 복사하지 않고 소비자의 고민과 생활 상황에 연결한다.
- 함량·복합 기능·원료 형태·섭취 편의성·포장·제조사 등에서 구체적인 선택 이유를 제시한다.
- 웹 검색은 시판 확인, 제품 이미지, 구성, 제조사 공식정보 보강에 사용한다.
- 쇼핑몰 후기나 과장된 효능 주장을 제품 사실로 채택하지 않는다.

## 7. 보류 기준

다음 경우 자동 작성을 중단하고 보류한다.

```text
의약품 가능성              → blocked_drug_track
제품 분류 불명확            → review_required
제품명·제조사·식별정보 불명  → source_required
건강기능식품 여부 불명       → review_required
기능성 원료·함량 미확인      → source_required
기존 제품 중복 가능성 높음   → review_required
행정처분 확인               → blocked_admin_action
```

근거가 부족하면 추정하여 채우지 않는다. 다만 구매에 도움이 되는 생활 맥락과 선택 이유는 확인된 제품 사실에서 적극적으로 도출한다.

---

## 8. 저장·디자인·다국어

- O4O 공통 설명서는 ProductMaster에 연결되는 공통 설명 계층에서 관리한다.
- 실제 DB 저장과 canonical 승격은 승인·이중게이트를 거친다.
- 내부 `source_check_memo`에 핵심 문구의 근거를 남긴다.
- 콘텐츠는 현재 표준 `sd-*` 시맨틱 HTML 구조를 사용하고, 디자인은 공통 렌더러가 담당한다.
- 다국어는 승인된 한국어 기준본을 바탕으로 진행하며 제품 사실과 표현 강도를 임의로 바꾸지 않는다.

공급자가 제작한 설명서는 O4O 직접 제작 설명서와 구분하며, 제작원 표시는 최상위 정책을 따른다.

---

## 9. 승인하지 않는 설명서

- 성분·함량·공식 원문만 나열한 설명서
- 제품의 매력과 선택 이유가 보이지 않는 설명서
- 제품 이름만 바꾸면 다른 제품에도 사용할 수 있는 설명서
- 자극적인 표현만 있고 신뢰할 근거가 없는 설명서
- 주의사항이 중심이 되어 구매를 위축시키는 설명서
- 정확하지만 소비자의 구매 판단을 돕지 못하는 설명서

---

## 절대 원칙

```text
구매를 돕는 것이 최우선 목적이다.
제품의 매력과 신뢰를 함께 보여준다.
확인되지 않은 제품 사실은 만들지 않는다.
과도한 제한으로 설명서를 밋밋하게 만들지 않는다.
일반식품은 신규 제작하지 않고 기존 설명서만 유지한다.
화장품은 O4O가 제작하지 않고 공급자가 제작한다.
DB 반영은 승인·이중게이트 후에만 한다.
```
