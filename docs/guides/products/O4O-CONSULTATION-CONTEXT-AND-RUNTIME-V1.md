## 상담 순서

1. 고객 문장을 입력하거나 선택한 언어로 말한다. 고객→직원 번역에서 자동 감지를 켜면 현재 번역 수단이 문자 언어를 감지한다. 감지 언어를 확인하고 틀리면 직접 고른다. 문장 번역은 답변·상품 추천을 생성하지 않는다.
2. 약사 판단 지원에서 현재 고객 질문을 가져오거나 확인할 질문을 입력한다. ‘상담 맥락으로 매장 상품 찾기’는 최근 질문 3개와 이번 질문을 읽어 상품 자료가 필요한지 판단한다. 일반 대화는 상품 선택 없이 이어가고 조건이 부족하면 한 가지를 확인한다. 정정·철회한 내용은 이번 질문에 적는다. ‘이번 상담 맥락 비우기’로 잘못된 조건을 없앨 수 있다.
3. 필요한 경우 현재 매장의 활성 취급 상품에서 후보를 찾는다. 서버가 현재 조직을 정하며 전역 검색 결과를 먼저 제한한 뒤 매장 필터를 적용하지 않는다. 동일 master의 여러 연결은 후보 하나로 표시한다. 상품·규격을 확인해 직접 고른다. 후보 없음은 전역 상품 추천으로 자동 대체하지 않는다. 취급 등록은 실시간 재고를 보장하지 않는다.
4. 선택한 listing에서 공통 master의 정확한 한국어 B2B 승인 자료를 읽는다. STORE/QR·다른 언어·미승인 후보는 자동 대체하지 않는다. 자체 상품에는 공통 표준자료를 임의 연결하지 않는다. 현재 상품에 연결한 게시 자료는 별도 근거다.
5. 제품 사실·전문 참고·상담 보조를 나누고 실제 출처 URL·확인일·버전을 확인한다. 미분류는 근거로 승격하지 않는다. 질문 관련 부분과 주의사항을 우선하며 전체 18,000자·항목 5,000자 한도를 지킨다. 문장 중간의 용량·부정 표현을 잘라 전달하지 않으며 생략은 표시한다. 근거가 부족하면 확인한 참고자료를 명시적으로 추가하거나 자료 보완 절차를 이용한다.
6. 약사가 초안을 검토하고 ‘검토한 고객 설명 사용’을 누른다. 번역과 고객 공유는 각각 실행한다. 원천 버전이 바뀌면 초안 사용·번역·고객 공유·고객 조회·연결 기기 읽어주기를 차단하고 현재 자료로 다시 준비한다. 한 화면 크게 보기·읽어주기도 직전에 자료를 확인한다.
7. 새 고객은 ‘새 상담 · 내용 지우기’ 또는 상담 종료 후 새로 시작한다. 이전 질문·후보·번역·감지 언어·녹음은 비워진다. 매장·계정·모드·epoch 변경과 화면 이탈에서도 이전 결과를 재사용하지 않는다.

## 접근 오류와 자료 현황

로그인 401, 개인 약사 자격, 매장 소속/승인, 매장 기능 제공, 직원별 기능 허용은 서로 다른 상태다. 로그인이나 매장 경영자라는 사실만으로 약사 자격을 승인하지 않는다. My Home의 개인 자격·근무자 설정에서 확인한다. 승인 직원의 일반 상품 접근과 약사 전용 판단 지원은 기존 서버 guard를 각각 따른다.

`GET /api/v1/store/handled-products`는 권한 해석 거절을 빈 목록 200으로 바꾸지 않는다. 합법적으로 접근한 빈 목록만 total 0이다. `GET /api/v1/store/products/ai-context/readiness?language=ko`는 인증·현재 매장 권한을 거쳐 활성 연결 행 수와 고유 master의 자료 상태를 집계한다. 권한/조회 실패는 현황 조회 실패이며 0% 확보율이 아니다.

엑셀의 ‘구조화 근거 준비 / 미분류 / 기존 설명만 / 자료 없음’은 중앙 자료 준비 상태다. 현황과 파일 대조의 언어는 정확히 일치하며 자체 상품을 공통 master 확보율에 포함하지 않는다. 중앙 관리자 접수·검토·승인이 필요하다. 기존 상품 보완 예약은 구조화 B2B 자료를 자동 생성·승인하는 예약과 같지 않다. 실제 주기·책임자·제공 일정을 확정하기 전 자동 갱신 완료로 안내하지 않는다.

## 관리자 실행 수단

관리자 AI 설정의 기존 model-control 문서·revision·원자 변경 잠금을 사용한다. 별도 provider registry나 원장을 만들지 않는다. 같은 revision의 동시 변경은 409이며 최신 목록을 다시 조회해야 한다.

| 용도 | 기본 | 연결한 선택지 | 적용·중지 경계 |
|---|---|---|---|
| 음성 인식 | 브라우저 Web Speech | Google Speech-to-Text v2 `short` | 외부 실행은 CONTENT_TRANSLATION 중지·한도 |
| 문자 번역 | `pharmacy.consultation` 정책 모델 | Google Translation v3 `general-nmt` | 모델 선택은 독립, 콘텐츠 번역과 CONTENT_TRANSLATION 중지·한도 공유 |
| 읽어주기 | 브라우저 speechSynthesis | Google TTS Standard | 외부 실행은 CONTENT_TRANSLATION 중지·한도 |
| 맥락·약사 판단 | PRODUCT_CONTENT의 기존 기본 모델 상속 | `pharmacy.support`에서 Gemini/OpenAI 독립 선택 | PRODUCT_CONTENT 중지·한도 공유 |

서버의 선택은 다음 요청부터 읽는다. 녹음/읽기 수단을 바꾼 뒤 직원·고객 화면을 다시 열어 최신 설정을 받는다. 이미 시작한 요청은 시작 시 설정으로 마치되 현재 접근·상담 세대·자료 버전은 재확인한다. 오류가 나도 다른 제공자나 브라우저로 조용히 전환하지 않는다. 이전 설정으로 복구하려면 같은 관리자 저장 절차로 선택을 되돌린다. 새 제공자의 최초 연동은 필요하며 목록에 이름만 추가해서 지원으로 취급하지 않는다. DeepSeek는 상담 adapter 미지원, KIWI는 서비스/API 식별 대기다.

### 자동 언어 감지

- **브라우저 Web Speech**: 선택한 언어로 음성 인식한다. 음성을 듣고 모든 언어를 자동 식별하는 기능으로 표시하지 않는다. Chrome LanguageDetector는 텍스트 기능이며 이번 구현의 필수 의존성이 아니다. 모바일·태블릿 지원을 가정하지 않는다.
- **문자 번역**: 고객→직원 요청에서 자동 감지를 명시하면 기존 정책 모델의 감지 결과 또는 Google Translation의 source 자동 감지를 사용한다. 지원 일곱 언어 밖이거나 불확실하면 422로 수동 언어 선택을 요청한다. 감지 언어는 원문 요청의 언어와 분리해 현재 상담에만 반영한다.
- **Google STT**: 관리자가 고른 최대 3개 후보 언어에서 고른다. 모든 언어를 제한 없이 동시에 감지한다고 약속하지 않는다. 현재 구현은 global recognizer·short 모델이다. 명시 confidence가 0.5 미만이거나 서로 다른 언어의 결과가 섞이면 수동 확인을 요청한다. confidence가 생략됐다고 정확성을 인증하지 않는다. 사용 프로젝트/지역·언어 조합의 공식 지원과 실제 현장 품질은 운영 활성화 전에 확인한다.
- **수동 수정**: 자동 감지를 끄고 언어를 직접 선택할 수 있다. 연결 상담에서는 최초 언어·epoch 비교와 기존 응답 version 역행 방지가 수동 변경 이후 도착한 자동 감지 결과의 덮어쓰기를 막는다.

지원 코드 `ko/en/zh/ja/vi/th/id`의 전달 계약을 합성 테스트한다. 이는 일곱 언어의 실제 음성/번역 품질 인증이 아니다. 중앙 B2B 원천 자료는 현재 `ko/en/ja/zh`의 정확한 언어 승인본이며 고객 번역 언어 지원과 자료 확보율을 섞지 않는다.

### Google 연결 전 준비

서버 GoogleAuth ADC와 프로젝트가 필요하다. 클라이언트에 서비스 계정/키를 전달하지 않는다. 이 개발은 IAM·API 활성화·운영 credential·가격·관리자 설정을 변경하지 않았다. GCP 운영 확인은 기존 결정대로 사용자 로컬에서 한다.

기존 `AI_PRICING_CATALOG`에 제공자 `google-cloud`의 정확한 모델 가격이 필요하다. 실제 가격을 검토해 등록하며 예제 수치를 운영 가격으로 복사하지 않는다.

| 모델 식별 | native kind | 측정 단위 | 입력 범위 |
|---|---|---|---|
| `general-nmt` | `translation` | Unicode 문자 `character` | 원문 최대 1,000자 |
| `stt-short` | `stt` | 실제 PCM 길이의 올림 초 `second` | mono PCM 16bit/16kHz WAV, 0.2~60초, base64 2,600,000자 이내 |
| `tts-standard` | `tts` | 입력 Unicode 문자 `character` | 최대 4,000자, 고정 Standard voice·MP3 |

문자/초 단위 전용 profile은 `maxInputTokens=0`, `maxOutputTokens=0`, 해당 `unit`과 검토한 `perUnit`을 사용한다. token 비용도 부과하는 profile을 쓰면 그 상한·가격을 별도로 검토한다. 명시 가격이 없으면 호출 전 차단하고 미계측을 무료로 처리하지 않는다. 기존 오프라인 가격 manifest도 `translation/stt/second`를 지원하며 미확정 요금의 draft는 실제 가격 loader를 통과하지 않는다. 기존 scope·서비스·사용자 quota의 예약/정산을 사용하고 한도 초과 시 provider를 호출하지 않는다. 실패가 이미 과금됐을 수 있는 경우 기존 불확실 예약 정책을 유지한다.

프로젝트/API/할당량·후보 언어·과금 단위·비용 상한·외부 전송/보존 조건·의약품 발음·수치/부정 표현 보존은 실제 활성화 전 별도 검수한다. 관리자 저장 성공과 연결 준비/실제 실행 성공을 구분한다.

### 녹음·실패·기기 경계

녹음은 사용자 버튼으로 시작하고 메모리에서만 처리한다. 최대 59초에서 녹음을 종료해 변환 후 60초 한도를 검증한다. 브라우저/마이크 미지원·거절·음성 없음·연결 오류에는 문자 경로를 유지한다. 범위 변경·취소·pagehide·화면 숨김에서 트랙·플레이어·object URL을 해제하고 늦은 결과를 버린다. 원문 오디오를 일반 로그나 영구 업무 자산에 저장하지 않는다. Google 요청은 고정 host, 15초 timeout, 자동 재시도 없음이다. 이미 전송한 요청은 클라이언트 취소 이후에도 제공자에서 처리·과금될 수 있어 결과 폐기와 외부 취소를 동일하게 보고하지 않는다.

고객 기기의 외부 음성은 기존 별도 capability와 담당자·매장 기능/자격·최근 응답·epoch를 재확인한다. 직원 로그인 토큰/조직 header를 고객 기기에 넘기지 않는다. 고객 기기 TTS는 서버에 현재 공유된 안내만 읽고 임의 요청 문장을 읽지 않는다. 자료가 바뀌면 공유 안내 읽기도 거절한다.

## 검토 자산의 재사용·평가

자료 부족·오류는 **상품/자료 버전·확인할 항목·검토한 공개 출처**로 정리한다. 식별 가능한 고객 원문·음성·이름·연락처는 옮기지 않는다. 약사 판단 지원의 ‘검토한 자료 보완·재사용’에서 기존 상품 편집을 열고 명시 저장·중앙 제안·검토·승인을 거친다. 전역 표준자료는 중앙 승인 후 다음 상담 조회에 반영하며 상담 반복을 이유로 자동 학습·자동 승인·개별 매장 표준 DB를 만들지 않는다.

같은 비식별 합성 표본과 자료 revision·설정 revision·모델로 비교한다. 이번 테스트는 기술 계약 검증이며 임상 개선 효과/응답 속도/비용 절감 수치를 주장하지 않는다.

| 평가 표본 | 확인할 결과 | 현재 증거 |
|---|---|---|
| 인사·일반 대화 | 상품 조회 없음 | context Jest |
| 조건 부족·정정 | 한 질문, 최신 정정 우선, 확인되지 않은 사실 생성 금지 | 엄격 planner 계약·가상 출력; 실제 모델 적합성은 현장 검수 |
| 다른 매장·비활성·중복 master | 현재 매장 후보만·중복 없음 | 실제 PostgreSQL fixture |
| 뒤쪽 주의·0.5 mg 부정 문장 | 관련 근거 우선·수치/부정 중간 절단 없음 | evidence Jest |
| 근거 변경 후 공유/재생 | 초안·공유 거절, 고객 조회 감춤 | 실제 PostgreSQL fixture |
| 일곱 언어·자동/수동 | 전달 계약·불확실 시 복구 | 합성 provider/UI; 실발음·약사 품질은 미확인 |
| 다음 고객·권한 회수 | 이전 문장/후보/감지 언어/늦은 결과 제거 | UI·SQL·Chromium |
| 지연·비용·할당량 | 가격/단위/예약, 가격·한도 없으면 호출 차단 | native 회계 테스트; 실측은 미실행 |

새 버전의 임상/언어 품질 비교는 실제 약사가 검토한 표본으로 별도 수행한다. 지연·비용은 해당 모델과 호출 길이에 대한 실제 측정 없이는 개선됐다고 판단하지 않는다.
