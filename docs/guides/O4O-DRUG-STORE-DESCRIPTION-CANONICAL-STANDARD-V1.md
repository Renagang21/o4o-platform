# O4O 일반의약품 소비자 설명서 표준 (Canonical Standard) V1

## 1. 목적

이 문서는 **"소비자가 이해하기 쉬운 설명서를 어떻게 설계하는가"** 를 정의한다.

WRITING-GUIDE가 **작성 규칙**(성분 표기·요약표·문체·금지 표현)이라면, 본 문서는 **설계 철학**(설명서 계층·질환 중심·분리 원칙·MFDS 우선·Canonical 조건)을 정의한다.

에이전트가 바뀌더라도 동일한 원칙으로 일관된 품질을 유지하는 것이 목표다.

### 1.1 설명서 목적 우선순위

설명서가 무엇을 가장 중요하게 하는지 순서로 고정한다. **성분 설명 자체가 목적이 아니다.**

```
① 올바른 약 선택   (가장 중요)
      ↓
② 안전한 사용
      ↓
③ 약사 상담 연결
      ↓
④ 성분·허가 정보   (그 다음 단계)
```

- 소비자가 **올바른 약을 선택**하도록 돕는 것이 최우선.
- 그다음 **안전하게 사용**하도록 안내하고, **약사가 상담하기 쉽게** 만든다.
- 성분·허가 정보는 이 목적을 뒷받침하는 근거이지, 그 자체가 목적이 아니다.

### 1.2 Non-Goal — 이 표준이 두지 않는 규칙

- **"전문용어를 쉬운 말로 반드시 바꾼다" 규칙은 두지 않는다.** O4O 설명서는 일반 소비자가 직접 작성하거나 소비자만을 위한 문서가 아니라, **약국에서 약사가 활용하는 소비자 설명서**이기 때문이다.
- **의학적 정확성 유지가 우선**이며, 질환명·증상명을 회피하지 않는다(WRITING-GUIDE §4.2). 필요한 경우에만 쉬운 설명을 덧붙이는 것은 작성자 판단에 맡긴다.

## 2. 설명서 계층 (Hierarchy)

모든 OTC 설명서는 다음 계층으로 구성한다.

```
질환 → 약효군(계열) → 성분 → 함량 → 제품
```

예:

```
비염 → 2세대 항히스타민 → 세티리진 → 10mg → 제품
무좀 → 항진균 외용 → (성분) → (농도) → 제품
```

- **소비자 진입은 질환/약효군**(위쪽), **canonical 승격 단위는 성분·함량**(아래쪽).
- 대표(소비자) 설명 1건이 상위 계층을, 성분·함량 초안이 하위 canonical을 담당하는 **3단계 구조**를 기본으로 한다.
  - `소비자 대표 설명 → 성분 canonical → 제품`

---

## 3. 질환 중심 원칙

설명서는 **성분보다 질환을 먼저** 보여준다. 소비자는 질환/증상으로 약을 찾기 때문이다.

```
무좀 · 벌레물림 · 상처 · 화상 · 치질 · 비염 · 변비 · 설사 · 속쓰림 · 눈 건조 …
```

- 표제·요약표 최상단은 질환/사용 목적. 성분·함량은 그 아래.
- **성분 중심 X / 증상 중심 O** (§10과 동일 원칙).

---

## 4. 소비자가 혼동하는 약은 반드시 분리 (Non-Merge)

같은 약효군·같은 ATC라도 소비자가 혼동하거나 사용법·주의가 다르면 **하나의 대표로 묶지 않는다.** 실제 트랙에서 확정된 분리 축:

| 분리 | 근거 트랙 |
|---|---|
| 인공눈물 ≠ 충혈완화제 | OPHTHALMIC |
| 1세대 항히스타민 ≠ 2세대 항히스타민 | RHINITIS-ALLERGY |
| 좌약 ≠ 관장제 | RECTAL-LAXATIVE |
| 먹는 약 ≠ 바르는 약 ≠ 코에 뿌리는 약 ≠ 눈에 넣는 약 | DERMATOLOGY·OPHTHALMIC·RHINITIS |
| 치질 연고 ≠ 치질 좌제 ≠ 주입형 | HEMORRHOID |
| 가려움 ≠ 무좀 | DERMATOLOGY |
| 위장약(속쓰림) ≠ 소화제(소화불량) | ANTACID-GASTRIC |
| 자극성 하제 ≠ 삼투성 ≠ 팽창성 | LAXATIVE |

- **투여경로가 다르면 반드시 분리**(경구/비강/점안/직장/외용). WRITING-GUIDE §3.6·§3.10 참조.
- **함량이 허가구분(OTC/RX)이나 용법을 가르면 분리**. WRITING-GUIDE §3.5 참조.

### 4.1 대표 설명서 분리 기준 (4축)

완료된 8개 트랙에서 실제 사용한 분리 축을 명문화한다. 아래 중 하나라도 갈리면 별도 대표로 분리한다.

| # | 분리 축 | 실제 예시 |
|:-:|---|---|
| ① | **투여경로** | 좌약 ↔ 관장제 · 점안액 ↔ 안연고 · 먹는 약 ↔ 바르는 약 ↔ 코 분무 |
| ② | **작용기전** | 자극성 ↔ 삼투성 ↔ 팽창성 하제 · 제산(중화) ↔ H2(분비억제) · 장운동억제 ↔ 흡착 |
| ③ | **소비자 선택축** | 1세대 ↔ 2세대 항히스타민(졸림) · 인공눈물 ↔ 충혈완화제 · 위장약(속쓰림) ↔ 소화제 |
| ④ | **안전성** | 항생 외용·H2·비충혈 점비 = 약사 검토 강화 / 스테로이드·좌제·질정 = 수동 큐레이션 |

- ①②는 **사용법·금기가 근본적으로 달라** 반드시 분리, ③은 **소비자 혼동 방지**, ④는 **오남용·민감군 관리**를 위한 분리다.
- 함량축(§4 상단·WRITING-GUIDE §3.5)은 ①~④와 독립적으로 적용한다(예: 펙소페나딘 60mg 1일 2회 ↔ 120mg 1일 1회).

## 5. Selection Point 표준 (선택 포인트)

모든 설명서는 가능하면 **선택 포인트**를 가진다. 소비자가 "어떤 상황에서 이 계열을 고르는가"를 판단하도록 돕는다.

```
졸림이 적은 약   → 2세대 항히스타민
코막힘이 심하다  → 비충혈 완화제
눈이 건조하다    → 인공눈물
빠른 배변이 필요  → 자극성(단기) / 부드럽게 → 삼투·팽창성
```

- 세대·계열이 나뉘는 약효군은 **선택 포인트 비교표**를 대표 설명 상단에 배치(예: 항히스타민 1세대/2세대 졸림 비교).
- **"졸림 없음" 등 절대 단정 금지**(개인차 명시). WRITING-GUIDE §3.9·§4.3.

---

## 6. Counseling Point 표준 (복약상담 포인트)

모든 설명서는 가능하면 **복약상담 포인트** 블록을 가진다. 이것을 **O4O 설명서의 특징**으로 정의한다(약국 상담 환경 전제).

```
■ 졸릴 수 있습니다.
■ 운전 전 주의하세요.
■ 술과 함께 복용하지 마세요.
■ 감기약과 중복될 수 있습니다.
```

- **원문 주의사항 근거로만 작성**(창작 0). MFDS 원문에 없는 상호작용·부작용을 만들지 않는다.
- 성분별/대표 초안의 기본 요소로 삽입한다.

---

## 7. MFDS 원문 우선 (Source of Truth)

가장 중요한 원칙. 정보 우선순위는 **오직 하나로 고정**한다.

```
MFDS 허가 원문(e약은요·허가사항)  >  기타 모든 정보
```

절대 우선하지 않는 것:

```
기억 · AI 지식 · 인터넷 · 제조사 홍보 · 브랜드 인지
```

**적용 예 (실측)**: 비충혈 점비제 사용 기간 — 리뷰에서 "3일"이 제안되었으나 e약은요 재조사 결과 원문은 전부 **"7일 이상 계속 사용하지 마십시오"**(3일 문구 0건). → 사용자·에이전트 제안이 허가 원문과 다르면 **원문에 고정**하고 정정 사유를 CHECK에 명시한다.

```
점비제 3일? 7일?  →  허가 원문이 7일이면 7일.
```

## 8. SOURCE GAP

조성 원천(원료·분량)이 e약은요·ProductDrugExtension·name·ATC 어디에도 없어 세분 설명서를 만들 수 없는 상태 = **SOURCE GAP**.

- 정의·처리·HOLD_SOURCE·ETL 분리는 **WRITING-GUIDE §3.11** 을 참조한다(본 문서는 재정의하지 않는다).
- 본 문서에서는 §9의 **"대표 설명서를 언제 허용하는가"** 게이트만 강조한다.

### 8.1 HOLD_SOURCE 철학

`HOLD_SOURCE`는 실패가 아니라 **안전 판단**이다.

```
HOLD_SOURCE 는 설명서를 만들지 "못한" 상태가 아니다.
설명서를 만드는 것이 "안전하지 않은" 상태이다.
```

```
근거가 부족하면 설명서를 작성하지 않는 것이,
설명서를 추정해서 만드는 것보다 우선한다.
```

- 조성·용량·일수를 추정해 채우는 것보다 **비워 두고 HOLD** 하는 것이 신뢰성 우선 원칙(§7 MFDS 원문 우선)의 자연스러운 귀결이다.
- HOLD_SOURCE는 후속 MFDS 원료·분량 ETL로 해소하며(WRITING-GUIDE §3.11.5), 그 전까지 **대표 설명서로 뭉개지 않는다.**

## 9. Canonical(대표 설명서) 작성 원칙

대표 설명서는 다음이 **모두 수렴할 때만** 작성한다(WRITING-GUIDE §3.11.3 대표 허용 게이트와 동일).

```
효능 · 용법 · 주의사항 이 수렴 → 대표 설명서 작성
하나라도 불만족           → HOLD_SOURCE (대표도 작성하지 않음)
```

- 조성이 확인되면 **성분 canonical** 로 세분, 확인 불가하면 **대표 + HOLD_SOURCE**.
- 조성 추정(스테로이드/항생/항진균 종류·마취 포함 여부)은 **금지**.

---

## 10. 증상 중심 표준

```
성분 중심  X
증상 중심  O
```

소비자가 먼저 판단하는 축(무좀·눈 건조·코막힘·가려움·설사·변비·속쓰림 …)으로 표제·진입을 구성한다. 성분·함량은 canonical·약사 확인 축으로 뒤에 둔다.

---

## 11. 안전성 블록 (병원에 가야 하는 경우)

모든 설명서는 질환별로 **"병원에 가야 하는 경우"** 를 반드시 가진다. 자가치료를 멈추고 진료로 전환하는 기준을 명확히 한다.

```
혈변 · 흑변 · 고열 · 호흡곤란 · 심한 통증 · 시력저하 · 고름/분비물 · 원인 모를 체중감소 …
```

트랙별 실제 안전 축(예):

| 질환 | 안전 경고 |
|---|---|
| 지사제 | 고열·혈변·탈수·소아 조기 진료 |
| 변비약 | 심한 복통·구토·혈변·체중감소 |
| 치질 | 반복·다량 항문 출혈·고름·발열 |
| 안과 | 눈 통증·시력저하·심한 충혈·분비물 |
| 비염 | 고열·누런 콧물·심한 얼굴 통증·호흡곤란 |
| 피부 | 무좀 손발톱 침범 / 벌레물림 호흡곤란·얼굴부종 |

## 12. 사용 확인 포인트

모든 설명서 마지막에는 **사용 확인 포인트**(약사 확인 연결)를 넣는다.

```
무좀인지 습진인지 구분이 어려우면 약사에게 확인하세요.
좌약인지 관장제인지, 인공눈물인지 충혈완화제인지 약사에게 확인하세요.
```

- 하단 GMP 공통 문구(**성분 기준 선택**)는 WRITING-GUIDE §6 유지.

---

## 12-A. 설명서 표준 Template (Canonical Template)

완료된 8개 트랙에서 사실상 공통 구조가 확정되었다. 아래를 **Canonical Template**로 명문화한다.

```
어떤 경우에 사용하는가
      ↓
사용 방법
      ↓
주의사항
      ↓
병원에 가야 하는 경우      (§11 안전성 블록 — 필수)
      ↓
사용 확인 포인트           (§12 — 필수)
      ↓
성분 기준 선택             (WRITING-GUIDE §6 GMP 공통 문구 — 필수)
```

**질환·약효군에 따라 선택적으로 추가**(권장):

```
Selection Point (선택 포인트)   — §5, 세대·계열이 나뉘는 약효군
Counseling Point (복약상담 포인트) — §6, 성분별/대표 초안
```

- **필수 블록**: 어떤 경우에 사용 / 사용(복용) 방법 / 주의사항 / 병원에 가야 하는 경우 / 사용 확인 포인트 / 성분 기준 선택.
- **선택 블록**: Selection Point · Counseling Point(원문 근거, 창작 0).
- 요약표·성분 표기 등 세부 형식은 WRITING-GUIDE §5 를 따른다.

## 13. CHECKLIST (설명서 작성자 필수 점검)

설명서/트랙 작성 시 아래를 모두 점검한다.

```
□ 질환 중심인가 (성분보다 질환·증상 먼저)
□ 소비자가 이해하기 쉬운가
□ 소비자 혼동 약을 분리했는가 (경로·세대·제형)
□ Selection Point(선택 포인트)가 있는가
□ Counseling Point(복약상담 포인트)가 있는가
□ 안전성 블록(병원에 가야 하는 경우)이 있는가
□ 사용 확인 포인트가 있는가
□ 허가 원문(MFDS)만 사용했는가 (기억·AI·인터넷 미사용)
□ 성분·조성·용량·일수를 추정하지 않았는가
□ SOURCE GAP을 확인했는가 (§8 / WRITING-GUIDE §3.11)
□ Canonical 허용 게이트(효능·용법·주의 수렴)를 만족하는가
□ 만족하지 않으면 HOLD_SOURCE로 분리했는가
```
