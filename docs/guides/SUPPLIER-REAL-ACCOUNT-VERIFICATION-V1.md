# 공급자 실계정 검증 절차

> **상태**: ACTIVE
> **작성일**: 2026-10-13 · **최종 갱신**: 2026-10-13 (KST)
> **근거 WO**: [공급자 잔여 보완](../work-orders/WO-O4O-SUPPLIER-REMAINING-BATCH-V1.md)

사용자가 나중에 진행하기로 한 실계정 검증을 한 번에 수행할 절차다. 아직 실행하지 않았다.
이번 branch는 push만 하므로 신규 동작 확인은 사용자가 별도로 main 통합/배포한 버전에서 수행한다.
계정 기준은 [SETUP.md](../../SETUP.md#테스트-계정-찾기--브라우저운영-검증-전)의 비공개 계정 문서다.
계정·이메일·토큰·실제 주문 응답은 공개 결과에 붙이지 않는다.

## 준비

변경해도 되는 검증용 상품·주문·정산만 선택한다. 운영 DB 직접 수정·실사용 주문 상태 변경으로 샘플을 만들지 않는다.
배송 기록은 물류 실행을 호출하지 않으며 정산 지급 처리는 은행 송금을 검증하는 것이 아니다.
원본 재고/예약량·공급자/서비스·결제/배송/정산 상태를 비공개로 메모하고 변경 후 복구 가능 범위를 확인한다.
실제 결제·취소·지급은 사전에 승인된 검증 범위에서만 실행한다. 적합한 샘플이 없으면 해당 행은 NOT_RUN으로 남긴다.

## 한 묶음 검증

| 순서 | 화면/행동 | 확인할 결과 |
|---|---|---|
| 1 | 공급자 로그인·사업자 문맥 확인 | 본인 상품/주문만 표시. 다른 사업자 문맥이 섞이지 않음 |
| 2 | 상품 등록·수정, 운영자 승인/거절 | 기존 권한·승인 흐름과 목록/상세 갱신. 공급자 직접 ProductMaster 생성 없음 |
| 3 | `/supplier/orders` 통합 목록과 처리 상세 | paid 주문·서비스·공급자 일치. 연결된 주문은 중복 없음. 연결 전 checkout은 읽기만 가능 |
| 4 | 승인된 검증 주문 준비→송장→배송 완료 | 배송/주문 상태 일치, 재고 효과 1회. 반복 요청은 중복 송장·차감 없음 |
| 5 | 재고 화면을 같은 상품으로 두 탭에서 열기 | A에서 변경 후 B의 오래된 수정은 거절. 최신 상태를 다시 조회하고 직접 재검토한 뒤 수정 |
| 6 | 재고 편집 중 승인된 샘플의 배송 완료 | 이전 편집값 저장이 배송 차감을 덮어쓰지 않음. 충돌 조회 실패는 명시적 오류/재시도 |
| 7 | 운영자 검증 기간 정산 계산과 공급자 상세 | PAID+DELIVERED만 대상. 합계·수수료·주문 연결 일치. 반복 계산은 중복 없음 |
| 8 | 취소 가능한 검증 정산 취소·재계산 | 취소와 주문 연결 해제가 함께 반영. 취소 후 재계산 가능. paid 취소 불가 |
| 9 | 별도 허용된 샘플의 승인/지급 표시 | 기존 상태 전이·중복 지급 거절·정산 완료 알림 확인. 은행 송금 성공으로 판정하지 않음 |

혼합 공급자 주문의 연결 충돌 안내가 나오면 주문 공급자 관계를 조사한다. 이를 해결하려고 금액을 임의 분할하거나 schema/운영 DB를 수정하지 않는다.
재고 추적 토글/수정 응답도 확인하며 필요 시 최신 수량으로 다시 진입한다. 반복 충돌을 우회하려고 version 정보를 제거하지 않는다.

## 결과 기록과 호환 조회 판정

결과는 PASS/FAIL/NOT_RUN으로 구분하고 서비스·검증 버전·시각·현상·복구 결과만 요약한다.
영수증·주문/사용자 식별자는 공개 기록에 남기지 않는다.
호환 조회 제거를 판단하려면 지원 서비스별 실제 paid 주문의 bridge 연결·복구 결과와 unbridged 주문 유무를 확인해야 한다.
이번 문서는 그 근거를 확보하거나 호환 조회 제거를 결정한 기록이 아니다.
