# GROUNDING-GUARD-CHECKLIST — 작성 전·후 이중 가드 (기계 검사)

상태: Active · **V1** (2026-07-15) · 진입: [DOCUMENT-INDEX](../common/DOCUMENT-INDEX.md)
적용: **전 제품군 공통** (건기식·의약품·의료기기·의약외품 및 향후 상품군)

> **신규 규칙이 아니다.** [CONTENT-AUTHORING-PRINCIPLES §3·§4·§4-1](CONTENT-AUTHORING-PRINCIPLES.md)(CR-002·CR-003·CR-004·CR-007)의 **기계적 집행 도구**다. 규칙은 거기, 검사 절차는 여기.
>
> **왜 필요한가**: 유산균 20-pilot 20-A 에서 **규칙을 문서화한 작성자 본인이 같은 유형을 반복 위반**했다(a2 = 5건 파일럿 뉴로랩스와 동일 유형). **문서 규칙만으로는 재발을 막지 못한다**가 실증됨 → 제작 흐름에 기계 검사를 끼워 넣는다.

---

## 0. 사용법 — 작성 전·후 **이중** 가드

```text
grounding memo (§A 환산식 확정)
  → [가드 1: 작성 전] §A 계산 불가 항목 = 생성 금지 목록 확정
  → 초안 작성
  → [가드 2: 작성 후] §B·§C·§D 기계 검사 + §E 표 기록
  → 위반 0 이어야 다음 단계(en / 다음 소배치)
```

**검수 도구가 아니라 작성 전에도 돈다.** 작성 전에 "쓰면 안 되는 수치"를 먼저 확정해야 초안에 들어가지 않는다.

## A. 기준량·함량 (계산 가드)

작성 전 grounding memo 에 **반드시 4값을 분리 기록**한다.

```text
① 표시량 기준 단위      (예: 100억 CFU / 900mg)
② 1회 섭취량            (예: 1캅셀 450mg)
③ 1일 섭취 횟수         (예: 2회)
④ 1일 총 섭취량         (② × ③ = 900mg)
환산식                  ①과 ④의 관계를 명시적으로 기록
```

**판정**

| 상태 | 조치 |
|---|---|
| ①의 기준량 = ④ 1일 총량 | "1일 총 N" 사용 가능. **"1회분 N"은 금지**(= ①÷횟수) |
| ①의 기준량 = ② 1회 섭취량 | "1회 N" + "1일 총 N×횟수" 사용 가능 |
| **환산 근거 없음**(캡슐 중량 미표시 등) | **표시량 기준 수치만 기술.** "1캡슐 N" · "1일 총 N" **둘 다 금지** |

**실사례 (20-A)**

```text
김치생유산균바이오캡슐 : 100억/900mg · 1캅셀 450mg × 2회 → 900mg = 1일 총량
                        ∴ 1일 총 100억 O / 1캡슐 100억 ✗ (실제 1캡슐 50억 — 2배 과장)
비피스앤(N)            : 1억/1,000mg · 1캡슐 × 2회 · 캡슐 중량 미표시
                        ∴ 1일 총량 산출 불가 → "1,000mg당 1억" 만 기술
```

> ⚠️ **`50억 CFU/500mg` 과 `1일 섭취량 기준 50억`을 자동으로 같은 뜻으로 보지 않는다.** 셋(표시량·1회·1일)은 각각 다른 값이다.

## B. 최상급·비교급 (표현 차단)

**전수 비교 결과가 기록되지 않았으면 자동 FAIL.**

```text
가장   최대   최소   높은   낮은   많은   적은   대표적인   유일한   특별한
```

- "그룹에서 제일/최다/최소" 류는 **대상 전수를 실제 비교한 근거**(측정 쿼리·CHECK 인용)가 있을 때만.
- 근거가 없으면 **비교를 지우고 사실만** 쓴다.

```text
✗ 이 그룹에서 가장 낮은 균수 구간
✓ 1억 CFU 기준으로 설계된 제품입니다.
```

> 주의: "낮은/높은"은 **비교 맥락이 아니어도** 차단 대상이다(암묵 비교를 만든다). 수치를 그대로 쓰는 것으로 대체한다.

## C. 부재 ≠ 허용 / 부존재 (해석 차단)

**원문에 없다는 사실만으로** 아래를 쓰면 FAIL.

```text
냉장 보관이 필요하지 않습니다      별도 보관 조건이 없습니다
실온 보관 제품입니다               장용성 제품이 아닙니다
특정 성분이 들어 있지 않습니다      (원문에 지시 없음 → "해도 된다")
```

**허용 = 공식 원문이 직접 뒷받침할 때만.**

```text
원문에 "실온 보관" 명시      → 실온 보관 가능 (사실 기술)
원문에 냉장 언급 없음        → 아무 표현도 하지 않음
```

> ⚠️ 원문에 있는 사실이라도 **그룹 공통 사항을 그 제품만의 장점처럼 배치하면 별도 FAIL**(허위 차별화, CR-003). 보관·붕해·대장균군 음성 등은 대개 그룹 공통이다 → "왜 이 제품인가"가 아니라 사실 섹션에.

## D. 표현 차단 목록 (원문 근거 위치 없으면 FAIL)

```text
효과가 좋다   흡수율이 높다   살아남는다   장까지 도달한다   부담이 적다 / 부담 없이 / 부담이 없는
누구나       안심하고        냉장 없이     특허            프리미엄
```

각 표현은 **원문 근거 위치**(필드명 + 원문 인용)를 §E 표에 적지 못하면 삭제한다.

> **어미 변형까지 잡을 것** (20-A 실측): `부담이 적다`만 막으면 **`부담 없이`가 통과**한다. 검사는 어간(`부담`)으로 하고 사람이 판정한다.
>
> **제품 주장 vs 소비자 상황은 구분한다** — 차단 대상은 **제품 주장**이다.
> ```text
> ✗ (제품 주장)   부담 없이 이어갈 수 있습니다        → 근거 없으면 삭제
> ✓ (소비자 상황) 큰 알을 삼키기 부담스러운 분         → 증상·고민 소구, 허용
> ```

## E. 필수 기록 표 (초안 1건마다)

```text
| 제품 | 기준량 환산 | 최상급 | 부재 추론 | 제품 고유 주장 | 공식 근거 위치 | 수정 | 최종 판정 |
```

- **기준량 환산**: 가능/불가 + 환산식
- **최상급 / 부재 추론**: 검출 표현 그대로 인용 (0이면 `0`)
- **제품 고유 주장**: 그 제품만의 주장 + 근거 필드
- **최종 판정**: PASS / 수정 후 PASS / HOLD

## F. 기계 검사 (grep)

```bash
# B: 최상급·비교급
grep -nE "가장|최대|최소|높은|낮은|많은|적은|대표적인|유일한|특별한" <draft>
# C: 부재 추론
grep -nE "필요하지 않|않습니다|없습니다|아닙니다|들어 있지" <draft>
# D: 표현 차단
grep -nE "효과가 좋|흡수율|살아남|장까지 도달|부담이 적|누구나|안심하고|냉장|특허|프리미엄" <draft>
```

검출 = 자동 FAIL 아님 = **근거 제시 의무 발생**. §E 표에 원문 위치를 못 쓰면 삭제.
