# 유통참여형 펀딩 운영 안내

> **상태**: ACTIVE · **작성일**: 2026-10-27
> **구현 WO**: [운영 흐름 보완](../work-orders/WO-O4O-FUNDING-OPERATIONS-COMPLETENESS-V1.md)

## 운영 흐름

활성 공급자가 `funding.neture.co.kr/market-trial/manage`에서 개설 신청한다. 펀딩 운영자가 검토·승인한 뒤 전용 포럼을 개설하고 모집을 시작한다. 참여 신청은 관심 표시이며 입금 확인이나 포럼 가입 승인이 아니다. 포럼 이용은 개설자가 별도로 승인한다.

운영자는 `/operator/market-trial/:id`에서 실제 외부 송금 내역을 확인한 뒤 입금 확인 금액을 기록한다. 약정 참여금과 실제 확인 금액은 다를 수 있으므로 예외 현황에서 누락·불일치 여부를 확인한다. 최초 입금 확인일은 보존하고 재확인일을 별도로 기록한다. 이 화면에서 실제 송금은 실행되지 않는다.

모집 결과와 진행 중지는 오프라인 운영 영역에서 사유를 남겨 처리한다. 참여 철회·진행 중지는 환급 완료를 뜻하지 않는다. 실제 외부 환급을 확인한 뒤 누적 환급액·처리일·사유를 기록하며, 부분 환급과 정정도 이 경로를 사용한다. 누적 환급액은 확인 입금액을 넘을 수 없다.

## 다른 운영자가 먼저 수정했을 때

다른 처리가 먼저 저장되면 오래된 화면의 입금 수정은 409로 거절된다. 입력 내용은 성공으로 표시되지 않으며 자동 재전송하지 않는다. 현황을 다시 조회한 뒤 입금 확인·정정 버튼으로 최신 값을 열고, 실제 송금 내역과 대조해 다시 입력한다. 단순 네트워크 오류도 먼저 현황과 이력을 확인하고 재입력한다. 이전 요청이 이미 반영됐다면 같은 요청을 반복하지 않는다.

입금 수정과 환급·철회·약정 수정은 같은 참여자 버전을 사용한다. 버전 없는 구 화면은 저장할 수 없으므로 새 화면을 불러온다. API를 먼저 배포하고 새 프런트를 배포하는 기존 배포 순서를 따른다.

## 이력과 참여자 확인

대상 참여자 처리 이력에는 입금·이행·환급·철회·약정 기록이 함께 나온다. `이전 이력 더 보기`로 이전 기록을 조회한다. 펀딩 전체의 결과 확인·중지와 사후 처리는 별도 사후 처리 이력에서 `이전 사후 처리 이력 더 보기`로 조회한다. 조회 실패 시 기존 이력을 보존하며 같은 페이지를 다시 시도할 수 있다. 이력 조회는 입력 중인 참여자 현황·버전을 새 값으로 교체하지 않는다.

참여자는 자신의 참여 목록·상세에서 약정 참여금과 입금 확인 금액·상태를 구분해 보고, 상세에서 최초/마지막 확인일과 누적 환급 기록을 확인한다. 송금 참조·운영자 입금 메모·처리자·사후 처리 사유는 참여자용 입금 정보에 추가하지 않는다. 문의가 있으면 운영자에게 실제 내역 확인을 요청한다.

본 기능은 콘텐츠형 모집과 오프라인 처리 기록이다. PG 결제·자동 환급·상품 주문·배송·자동 포럼 가입 기능을 제공하지 않는다.
