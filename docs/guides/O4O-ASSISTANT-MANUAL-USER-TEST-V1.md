## 1. 준비

기존 SETUP.md의 Node/pnpm·frozen install·공통 패키지 build·로컬 API 및 web-neture 절차를 따른다. 기존 개발 계정과 설정된 모델을 사용한다. 모의 응답 검증과 실제 모델 품질/비용 검증을 구분한다. 새 DB migration이나 운영 credential은 요구하지 않는다.

이번 사용자 제공 유팜 24쪽과 팜POS 11쪽을 실제 PDF로 읽어 비공개 테스트 자료함을 준비했다. 이 클라우드의 `/workspace/shared/o4o-assistant-user-test/manual-library.private.json`을 승인된 비공개 전달로 테스트 기기에 옮길 수 있다. 공개 Git에 PDF·추출 전문·이 파일을 추가하지 않는다. 통합 PMPLUS20 대형 파일은 도구 전송 한도로 미수신이므로 포함하지 않았다. 팜POS는 PMPLUS20과 연동되는 POS 자료이며 통합 PMPLUS20 전체 매뉴얼이 아니다.

## 2. 사용자 흐름

1. Main에서 로그인하고 기존 이용 자격을 확인한다. 업무 입력 아래 **업무 매뉴얼**을 연다.
2. PDF 또는 내보낸 자료함 JSON을 가져온다. PDF 원본은 HTTPS 또는 localhost의 브라우저 안에서 해석되며 업로드하지 않는다. 프로그램 이름은 입력하거나 파일명을 기본값으로 쓴다.
3. 사용할 매뉴얼을 체크한다. 같은 프로그램은 한 기준 매뉴얼만 선택한다. 다시 접속하거나 다른 기기에 가져온 뒤에는 사용할 자료를 명시적으로 선택한다.
4. 업무를 자연어로 요청한다. 예: 유팜의 사입 명세서 수량/단가 확인 방법, 팜POS의 판매현황 메뉴 확인 방법. 고정 업무 버튼·새 실행 모드는 없다.
5. **참조한 매뉴얼**에서 제목·프로그램·페이지와 발췌를 펼쳐 확인한다. 관련 내용이 없으면 미참조 안내가 표시된다. 모델의 답변만으로 실제 화면 확인·저장 완료를 판단하지 않는다.
6. 현재 화면과 대조한 뒤 일치/차이·보완을 기록한다. 원본 설명은 유지되고 사용자 보고가 별도로 저장되며 다음 관련 요청에 함께 전달된다. 환자·고객·처방·인증 정보는 기록하지 않는다.
7. 다른 PC/모바일에서는 **자료함 내보내기** 파일을 가져온다. 자료는 계정별·브라우저별이며 자동 Cloud 동기화가 아니다. 같은 출처 파일을 재등록해도 기존 보완 기록과 사용 횟수는 지우지 않는다. 삭제는 현재 계정의 이 브라우저 자료에만 적용한다.

## 3. 경계·실패 처리

- PDF: 12MB·400쪽·추출 80만 문자, 자료함 최대 10개. PDF worker와 parser는 로컬 처리이며 모델을 호출하지 않는다. 암호·손상·스캔본/빈 텍스트는 성공 처리하지 않는다.
- 모델 입력: 선택 자료의 관련 페이지 최대 4개·페이지당 최대 1,400자. source/user report는 UNTRUSTED다. 서버가 형식·개수·페이지·길이를 다시 검증하며 원문 요청·도구 선택·권한·과금/한도 경로를 바꾸지 않는다.
- 참조 응답 횟수는 자료 사용의 로컬 수치이며 업무 완료·성공률·비용 절감 실측이 아니다. 사용자 일치 보고는 실제 run 검증·Experience/Skill 승격이 아니다. 기존 runtime의 사용자 도움·성공 경험 재사용 경로는 유지한다.
- 원본·발췌·보완은 서버 DB·Task·로그에 저장하지 않는다. 선택한 발췌만 해당 요청의 provider 입력으로 보낸다. 자료함 내보내기는 문서와 보완 기록을 담으므로 비공개로 전달한다.
- 매뉴얼 연결은 등록되지 않은 Windows 프로그램의 실행 권한이 아니다. 실제 유팜·PMPLUS 프로세스/창 정보와 사용자 PC의 capability를 확인하기 전에는 추측 등재·조작하지 않는다. 조제/마약류 보고·발주·결제·법적 확정은 언제나 사용자 직접 확정이다.
- ChatGPT의 기존 콘텐츠 MCP·카카오 로그인은 이 Main 매뉴얼 자료함의 자동 동기화/업무 ingress를 뜻하지 않는다. 외부 업무 채널과 인증은 별도 범위다.

## 4. 검증 기준

실제 PDF 가져오기 → 선택 → 질문에 맞는 페이지 전송 → 출처 확인 → 차이 기록 → 다음 질문에 반영 → 재접속 유지 → 계정 분리 → 모바일 가져오기까지 한 업무 흐름으로 검증한다. 전송량은 요청 발췌 문자 수로 확인하고, 실제 모델 품질·유료 비용·Windows 현장 실행은 별도 기록한다.
