# 약국 협력사업 운영 개통 검증 절차

> **상태**: ACTIVE
> **작성일**: 2026-10-27 · **최종 갱신**: 2026-10-31
> **근거 WO**: [운영 개통·실사용 검증](../work-orders/WO-O4O-COOPERATION-OPERATIONAL-READINESS-V1.md)

## 1. 가입 단위와 검증 계정

| 공간 | 가입 단위 | 실계정 검증에 필요한 역할 |
|---|---|---|
| Pharmacy | 약국 조직 단위, 약국 경영자 승인 시 기본 회원 자동 연결 | 선택 약국의 경영 권한·승인된 약사 자격, 사업 운영은 해당 담당자 |
| 드럭스토어형 약국·CarePharm | 약국 조직별 독립 사업 가입 | 선택 약국의 경영 권한, 해당 사업 담당 운영자, 필요한 경우 사업 Admin |
| Pharmcoop | 특정 조합의 개인 조합원 가입 | 지정 조합의 개인 회원, 해당 조합 운영자/Admin |

같은 계정이 여러 약국을 관리해도 약국별 가입 상태·신청·탈퇴를 구분한다. Pharmcoop 개인 자격을 약국 자격으로 변환하지 않는다. 서로 다른 서비스의 역할이 자동으로 통용된다고 가정하지 않는다. 기준은 [역할별 업무공간 구조](../baseline/O4O-ROLE-WORKSPACE-ARCHITECTURE-V1.md)다.

2026-10-28 이후 약국 경영 검증에는 [운영 책임 V2](../baseline/O4O-ROLE-WORKSPACE-ARCHITECTURE-V2.md)의 **현재 승인된 개인 약사 자격 + 해당 약국 경영 권한**을 함께 확인한다. 본인 `/qualifications/pharmacist/me`에서 신청 상태를 조회하되 면허번호·검토 사유 원문은 기록하지 않는다. 과거 약국 승인·owner 역할만으로 공통 약사 자격을 대체하지 않는다. Pharmcoop 개인 조합원에게 이 자격 조건을 추가하지 않는다. 실제 자격 승인은 면허 근거와 중앙의 위임된 검토 담당자가 필요한 운영 절차이며 테스트 통과를 위한 자동 승인·backfill을 하지 않는다.

계정 출처는 [SETUP의 테스트 계정 절차](../../SETUP.md#테스트-계정-찾기--브라우저운영-검증-전)를 따른다. Secret 연결 후에는 변수 이름만 공유한다. 비밀번호·토큰·실제 약국/개인 식별자·운영 응답 원문은 CHECK나 공개 자료에 넣지 않는다. 정정되지 않은 실패 자격증명을 반복 시도하지 않는다.

## 2. 먼저 읽기만 확인할 항목

1. 네 공개 홈과 로그인 진입을 확인한다.
2. 각 계정의 현재 역할·소속과 테스트 대상 약국/조합을 확인한다. 매장이 여러 개면 임의의 첫 매장을 고르지 않는다.
3. Pharmacy/드럭스토어형 약국의 `/my/participation?store=<선택 약국>`에서 표시 약국과 가입 상태를 확인한다. 약국이 여러 개이고 미선택이면 가입 상태 조회와 신청·탈퇴를 시작하지 않아야 한다. 임의의 타 약국 URL을 넣었을 때 자동으로 다른 약국으로 바뀌면 안 된다.
4. CarePharm은 같은 주소의 기존 약국 선택을 확인한다. Pharmcoop은 공개 목록에서 확정한 조합 slug로 진입해 개인 가입 상태를 확인한다. 목록이 비었다고 가짜 slug나 business alias를 사용하지 않는다.
5. 운영자는 담당 사업/조합만 조회되는지, 회원 화면에 보이는 자료·공지·활동과 운영자 목록이 같은 범위를 가리키는지 확인한다.

Pharmacy/드럭스토어형 약국의 가입 상태 조회·신청·탈퇴는 선택된 조직을 기존 `X-Store-Organization-Id`로 전달한다. 서버가 현행 소속·약국 승인·경영 권한·사업 자격을 최종 판정한다. UI에서 약국을 선택했다고 승인된 것은 아니다. 담당 운영자는 회원용 매장을 선택하지 않아도 자기 운영 안내에 진입할 수 있어야 한다.

## 3. 운영 설정과 신규 가입 준비

- Pharmacy 기본 회원은 약국 승인과 함께 연결되므로 별도 사업 가입 심사를 요구하지 않는다. 이전 승인 약국의 누락은 참여 안내의 ‘기본 회원 연결 확인’으로 선택 약국·현재 경영 권한·약사 자격을 검증해 연결한다. 기존 정지·반려·탈퇴는 자동 해제하지 않는다. 기존 약국 신청 약관 증적을 유지하며 독립 사업/거래 약관 동의를 자동 작성하지 않는다. [배포 완료 기록](../checks/CHECK-O4O-PHARMACY-APPROVAL-AUTO-MEMBERSHIP-V1.md)을 따른다. 아래 독립 사업 가입 정책과 구분한다.

- Pharmacy/드럭스토어형 약국/CarePharm의 기존 `/operator/semi-franchises?key=<사업 키>&tab=settings`에서 담당 사업·공개 진열·현장 요구·사업 약관 진입을 확인한다. 약관 편집은 서버가 허용한 Admin에게만 제공되며 일반 Operator에게 권한을 추가하지 않는다.
- 제공 기능과 담당 운영자는 기존 Admin 설정에서 확인한다. 약국의 직원 허용 설정은 약국 경영자가 확인한다. 사업 제공 기능과 직원 권한은 서로 다른 설정이며 로그인 성공으로 대신 검증하지 않는다.
- 사업별 실제 운영 주체·문의 연락처·개인정보 처리 관계를 확정한 뒤 기존 법정정보/약관 관리에서 검토·게시한다. 플랫폼 공통 약관을 독립 사업 약관의 대체물로 취급하지 않는다.
- CarePharm의 미정 회사 정보는 초안의 빈칸을 유지한다. 미정 정보를 만들어 채우거나 신규 가입을 열기 위해 임의 게시하지 않는다.
- 공개 가입 정책이 준비되지 않았으면 신규 신청은 막힌 상태를 유지한다. 기존 활성 회원의 읽기·업무 검증과 신규 가입 개통을 구분한다.
- Pharmcoop은 실제 조합의 공개 상태와 운영자 연결을 확인한다. 목록을 채우기 위한 임의 조합/개인 회원 seed를 만들지 않는다.

## 4. 운영자↔회원 상태 연결 검증

다음 상태 전이는 먼저 격리 fixture에서 확인한다. 운영 환경에서는 대상·행위·생성 및 연결 데이터·완전 정리 가능 여부를 확정하기 전 테스트 쓰기를 시작하지 않는다. 공유 업무 증적이나 보존 대상 기록의 삭제가 필요한 테스트는 격리 환경에서 수행한다.

| 업무 | 운영자 조작 | 회원 확인 | 운영자 후속 확인 |
|---|---|---|---|
| 공지 | 대상·중요도·기한·필수 여부를 정해 게시 | 대상에게만 노출, 해당 게시 버전 확인 | 미확인 수 감소, 이전 버전 증적 유지 |
| 자료 | 분류·공개 범위·본문·첨부·관련 교육 검토 및 개정 | 허용된 원본의 전체 내용·첨부 열람 | 동일 개정 확인; 이미 만든 매장 사본은 변경하지 않음 |
| 활동 | 모집→신청 심사→승인→실제 진행→완료 | 신청·승인·진행·완료 상태 확인 | 대기 건과 후속 행동 반영 |
| 지원 | 담당 배정·기한·답변·상태 처리 | 내 문의와 발송 완료 답변 확인 | 미배정·처리 중·완료 상태와 대기 수 일치 |
| 가입 | 지정 약국/개인의 신청을 기존 심사 화면에서 처리 | 같은 가입 단위의 결과 확인 | 다른 약국/개인 자격에 영향 없음 |

약국을 바꿀 때 기존 신청 입력·동의·상태가 새 약국으로 넘어가면 안 된다. 처리 중 선택 변경을 막고, 외부 URL/계정 전환으로 화면이 바뀌었을 때 이전 요청의 늦은 응답이 새 화면을 갱신하거나 이동시키지 않아야 한다. 약관 미게시·개정 변경·조회 실패를 미가입/0건/완료로 표현하지 않는다.

## 5. 실매장과 최종 판정

약사·일반 직원으로 PC·태블릿을 확인한다. 허용 기능·읽기/쓰기 제한, 지원 진입, 자료 열람, 음성 입력·읽어주기, 마이크 거절·음성 미지원 시 대체 입력을 점검한다. 합성 브라우저와 mocked speech 테스트는 실제 장치 검증의 대체 증거가 아니다.

결과는 [현재 CHECK](../checks/CHECK-O4O-COOPERATION-OPERATIONAL-READINESS-V1.md)에 추가한다. 개발 검증·push·main 통합·배포·운영 개통은 각각 구분한다. 계정·약관·실장치 검증이 남으면 운영 개통은 ACTIVE로 유지한다.
