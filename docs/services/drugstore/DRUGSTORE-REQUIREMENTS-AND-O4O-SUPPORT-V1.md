> **상태**: DRAFT
> **작성일**: 2026-10-23 · **최종 갱신**: 2026-10-23 (한국시간)
> **근거**: 사용자와의 드럭스토어형 약국 협업체 기획 대화 및 현장 요구 정리
> **기능 확인 기준**: main `5a6ab8f23582d8708186459c8c887d68da00ceff`

이 문서는 드럭스토어형 약국 사업의 요구를 정리하고, 기존 O4O 서비스로 지원할 부분과 추가 개발 후보를 구분한다. 요구 전체를 O4O의 개발 범위로 확정하거나 기존 정책·권한을 변경하는 문서는 아니다. 구현·운영 상태는 작성 시점의 기록이며 후속 작업 때 최신 main과 실제 설정을 다시 확인한다.

## 1. 사업의 목표와 O4O의 역할

드럭스토어형 약국(`drugstore.neture.co.kr`)은 약 3,000 SKU 전후를 취급하고 근무자가 대략 5~10명인 드럭스토어형 약국을 주요 대상으로 한다. 이는 기획 대상의 특성이며 서비스 이용을 판정하는 고정 조건은 아니다.

핵심 목표는 **Out the Counter 매약·진열 모델**이다. 고객이 상품이 진열된 공간에서 정보를 확인하고, 필요한 경우 직원·약사의 도움으로 상품을 이해하고 선택하도록 한다.

사업의 두 가지 집중 요구는 **ERP Assistant를 통한 반복 업무 감소**, **뷰티·글로벌 고객 커뮤니케이션 지원**이다. 공급자와 연계한 상품 랜딩·콘텐츠 서비스는 초기 재원을 마련하는 사업 구상이다.

**O4O의 drugstore은 약국 협업체 사업을 지원하는 정보 인프라의 하나다.** O4O의 개발 방향은 매장 공간을 활용하고 매장 근무자의 일을 돕는 데 둔다. 협업체 사업자가 수행할 상품 기획·공급자 협상·사업 운영까지 O4O가 모두 맡는 것으로 해석하지 않는다.

## 2. 현장의 요구사항

### 2.1. Out the Counter와 고객 커뮤니케이션

| 요구 | 필요한 지원 |
|---|---|
| 진열 공간에서 상품 이해 | 상품 특징·용도·사용법·주의사항과 이미지·영상·안내자료를 고객이 이해하기 쉽게 제공 |
| 상품 탐색과 위치 안내 | 매장 취급 상품과 진열 위치를 직원이 빠르게 찾고 고객에게 안내 |
| 약사의 상품 이해·비교·추천 | 신뢰할 수 있는 상품 자료와 비교 근거를 찾기 쉽게 제공하여 약사의 판단과 설명을 지원 |
| 비전문 직원의 간단한 응대 | 짧은 상품 안내·위치 안내·다국어 의사소통을 지원하고 전문 상담은 약사에게 연결 |
| 뷰티 상품 안내 | 상품 특성에 맞는 설명·비교 자료와 진열 콘텐츠 제공 |
| 글로벌 고객 응대 | 다국어 문자 양방향 번역, 음성 입력·읽어주기, 고객에게 크게 보여주는 화면 |
| 현장 경험 반영 | 반복되는 질문과 미충족 요구를 O4O가 공통 자료·서비스 개선에 반영 |

**매장 안의 약사는 상품을 이해하고 비교·추천할 수 있다.** 지원 도구는 그 일을 돕는다. 현재 번역 기능이 문장 번역만 한다는 사실을 약사의 업무 제한으로 해석하지 않는다.

일반약국의 상담은 주로 카운터의 약사와 고객의 직접 조회를 중심으로 한다. 드럭스토어형 약국에서는 매장 안에서 약사와 비전문 직원이 함께 도구를 사용한다. 같은 서비스 메뉴를 사용하면서 허용된 세부 기능과 응대 방식을 다르게 제공한다.

### 2.2. ERP Assistant

| 현장 문제 | 필요한 결과 | O4O에서 검토할 지원 |
|---|---|---|
| POS 데이터가 업무 판단으로 이어지지 않음 | 판매·상품·재고 현황 파악 | 허용된 데이터의 읽기·식별·정리·요약 |
| 적정 재고 판단이 어려움 | 부족·과잉·장기 재고 후보 파악 | 판매 추세·재고 비교와 판단 근거 제시 |
| 공급자별 주문처가 분산됨 | 발주 대상·수량·주문처 정리 | 공급자별 목록·발주 초안 작성 지원 |
| 사입 검수에 인력이 소요됨 | 발주·입고 차이 확인 | 자료 대조와 누락·수량 차이 표시 |
| 반품 판단과 처리가 복잡함 | 반품 검토 대상 정리 | 재고·기간·공급 조건에 따른 후보 목록 |
| 보충·진열 업무가 반복됨 | 먼저 확인할 상품·위치 파악 | 기존 상품·위치 정보와 연결한 간단한 확인 목록 |

이는 **협업체 사업의 요구**다. 현재 O4O의 기존 POS 연동·약국 ERP 구현이 완료됐다는 뜻은 아니다. 현장 업무 부담에 관한 의견은 요구의 근거로 사용하며 업계 전체의 검증된 통계로 제시하지 않는다.

실제 지원 범위는 데이터 접근 권한, 내보내기 형식, 상품 식별자, 갱신 주기와 정확도를 확인한 뒤 정한다. 먼저 읽기·분석·대조·초안의 실효성을 판단한다. 전체 ERP/POS 대체나 외부 주문 자동 실행을 전제로 삼지 않는다. 기존 B2B 계약상 POS 연동·새 ERP는 현재 비개발 영역이므로 착수 범위는 별도로 확정해야 한다.

## 3. 사업 수행 주체와 공급자 협력

| 주체 | 주된 책임 |
|---|---|
| 약국 협업체 사업자 | 참여 약국 모집, 공급자 선정·협상, 상품 공동 기획, 서비스비·진열·홍보 조건 결정, 사업 운영 |
| 공급자 | 상품 정보와 설명자료 제공, 공급 조건·제품 책임, 협의한 상품·콘텐츠 사업 수행 |
| 약국 경영자·근무자 | 매장 운영, 사용 권한 승인, 현장 정보 확인, 전문 판단과 실제 상담·판매 |
| O4O | 협업체 공간, 상품·콘텐츠·매장 도구, 고객 커뮤니케이션, 가입·이용 판정, 합의된 범위의 업무 지원 인프라 |

공급자와 함께 제품을 개발하거나 유통 사업을 기획하는 방법은 협업체 사업자가 선택한다.

- **직접 협력:** 협업체가 공급자와 상품 기획·공급·홍보 조건을 정하고 기존 O4O 상품·자료·제안 도구를 활용한다.
- **유통참여형 펀딩 활용:** 공급자가 신규 제품·유통안을 콘텐츠로 소개하고 참여 의향을 모으는 기존 서비스를 활용한다. 현재 개설 주체는 활성 공급자다.
- **혼용:** 직접 협력과 참여 모집을 함께 사용한다. 펀딩 이용을 필수 조건으로 만들지 않는다.

유통참여형 펀딩은 콘텐츠 작성·심사·모집·참여 현황·포럼 등 협업을 지원한다. 참여를 상품 주문·결제·정산·배송으로 자동 전환하지 않는다. 기존 오프라인 입금 확인·처리 기록도 결제 실행 기능과 구분한다.

공급자 상품 랜딩 사업은 실제 약국의 상품 설명·진열·고객 안내와 연결하는 것이 요구다. 공급자가 부담할 비용, 참여 약국의 활동, 성과 확인 기준은 사업자가 구체화한다. 상품 공동 개발이나 수익 발생이 O4O 기능만으로 보장되는 것은 아니다.

## 4. 기존 O4O 서비스로 지원하는 부분

아래의 ‘기존’은 기능·공통 기반이 있다는 뜻이다. 드럭스토어형 약국의 실제 사업 설정·회원 자격·자료 등록과 현장 사용까지 모두 완료됐다는 뜻은 아니다.

| 기존 서비스·기반 | 드럭스토어형 약국에 활용할 부분 | 현재 구분해야 할 한계 |
|---|---|---|
| 협력사업 홈·가입·자료함·커뮤니티·운영 화면 | 협업체 안내, 회원 자료, 공급 제안·콘텐츠 운영 | 공통 계정과 사업별 가입·자료 권한은 별도 |
| 관리자 기능 설정·유료회원 원장·My Home 직원 허용 | 제공 기능을 설정으로 판정하고 경영자가 직원 사용 범위 관리 | 실제 제공 설정·경영자 승인 필요 |
| 공급자 상품 등록·설명자료·콘텐츠·공급 제안 | 상품 랜딩과 약국 설명자료의 원천 | 상품 기획·계약·공급 조건은 사업 주체 책임 |
| 내 매장 상품·콘텐츠 작성/가져오기·편집 | 약국에 맞는 상품 설명과 자료 활용 | 매장 사본은 독립적으로 관리 |
| QR·태블릿·사이니지 | 진열대·고객 화면에서 설명자료·이미지·영상 활용 | 실제 기기·위치·자료 배치와 재생 확인 필요 |
| 직원 상품·위치 검색·짧은 숙지 자료 | 비숙련 직원의 간단한 응대 지원 | 별도 담당자·교육 과제 관리 체계를 요구하지 않음 |
| 고객 요구 간단 기록·월별 집계 | 위치 못 찾음 / 미취급 상품 / 약사 연결의 세 가지 사유 축적 | 상세 상담일지나 직원 업무 보고를 요구하지 않음 |
| 다국어 상담 | 카운터 약사 / 매장 직원 / 매장 약사 모드, 문자 번역·고객 화면·음성 입력·읽어주기 | 문자 번역은 AI Core의 LLM 경로, 음성은 브라우저 Web Speech API. Google 음성 API 연동은 없음 |
| 공통 AI 도움·상품 검색 기반 | 질문·요약·초안 및 상품명·태그 기반 탐색에 활용 | 선택 상품의 검증 자료에 근거한 약사 비교·추천 지원은 완성된 상태가 아님 |
| 유통참여형 펀딩 | 공급자의 신규 상품·유통안 소개, 참여 모집·운영 | 상품 공동 개발·실제 거래를 자동 수행하지 않음 |

다국어 상담은 현재 **직원과 고객이 입력한 문장을 번역하는 도구**다. 상품 질문에 자동 답변하거나 의약품을 자동 추천하는 기능으로 설명하지 않는다. 상담 원문·번역을 업무 이력으로 저장하지 않는 현재 원칙을 유지한다.

## 5. 개발·계획 상태와 추가 개발 후보

### 5.1. 기존 진행 과제와의 관계

| 과제 | 작성 시점의 상태 | 드럭스토어형 약국과의 관계 |
|---|---|---|
| 사업별 법정정보·약관·가입 동의, 운영 집계·직원 숙지 자료 | 코드 병합·배포 기록 있음. 실제 사업 문안 게시·실계정·실기기 검증은 별도 | 기존 기능을 설정하고 검증하여 활용 |
| 상담 방향별 입력 유지·콘텐츠 사용처·위치별 수정·업무 상태 표시 보완 | [PR #772](https://github.com/Renagang21/o4o-platform/pull/772) 병합·관련 배포 기록 있음 | 기존 내 매장 사용 흐름의 보완이며 ERP 구현과는 별개 |
| 약국 협력사업 독립 정비 | 일부 완료. 미사용 API 제거 [PR #765](https://github.com/Renagang21/o4o-platform/pull/765)는 병합, 상위 작업의 잔여 정비는 별도 추적 | 사업별 데이터·권한 경계를 유지하며 사용 |
| 외부 AI 콘텐츠 연결 | 연결·초안 저장 코드와 후속 보완이 main에 있음. 운영 허용·실제 외부 계정 연결은 별도 확인 | 공급자·약국 등의 자료 조회와 콘텐츠 초안 제작 기반으로 검토 |
| 공급자 AI 지원 확대 | 기존 작성 보조가 있고, 확대 WO는 실행 계획을 기록한 문서 | 콘텐츠 작성·공급 제안·공통 Assistant 연결 전체가 완료됐다고 보지 않음 |
| Personal Work Assistant | 공통 Task·실행 기반 개발이 진행 중 | 약국 업무에 재사용 가능성을 검토. 약국 ERP Assistant가 완성된 것은 아님 |

기존 문서의 `ACTIVE` 표기나 관련 코드의 존재만으로 실제 이용 가능·배포·운영 활성화를 판단하지 않는다.

### 5.2. 비즈니스에 도움이 되는 추가 개발 후보

| 후보 | 기대하는 업무 결과 | 먼저 확인할 것 |
|---|---|---|
| 검증 상품 자료를 연결한 약사 지원 | 상품 이해·비교·추천에 필요한 근거를 빠르게 확인 | 자료 출처·갱신·상품 식별, 약사의 확인 방식 |
| 같은 상품의 직원 안내·고객 설명 연결 | 직원은 짧게 숙지하고 고객은 QR·태블릿으로 자세히 확인 | 기존 상품·자료·화면 재사용, 전문 상담 연결 |
| 공급자 랜딩과 매장 활용 연결 보완 | 자료가 어느 매장에서 어떤 설명·진열에 쓰이는지 확인 | 현재 제공 지표, 집계 범위와 미확인 상태. 조회를 매출로 간주하지 않음 |
| POS·외부 주문 자료의 분석 보조 | 부족·과잉 재고, 발주·검수·반품 후보를 정리 | 데이터 제공 가능 여부, 권한·정확도, 가장 부담이 큰 실제 업무 |

추가 개발은 사업자가 실제로 사용할 업무 결과를 기준으로 묶어 정한다. 기존 공통 상품·콘텐츠·Assistant를 우선 검토하며 드럭스토어형 약국 전용 정책 엔진·별도 AI 엔진·ERP 전체를 먼저 만들지 않는다. 발주 초안과 실제 발주 확정은 구분하고, 확정은 사용자의 직접 승인을 따른다.

## 6. 단순한 이용 설정과 직원 운영 원칙

1. **기능 이용과 매장 접근을 구분한다.** 내 매장 접근은 경영자 승인·소속 매장을 따른다. 무료 초대 직원도 승인받은 매장에 접근할 수 있다.
2. **기능은 기본 제공·경영자 유료 자격·유효한 협력사업 제공을 합산한다.** 유료 기준은 매장 결제가 아닌 경영자 회원의 자격이다. 협업체 미가입 대형약국도 해당 유료 기능을 이용할 수 있다.
3. **복수 제공은 중복 허용한다.** 한 협업체를 탈퇴해도 다른 유효한 가입·유료 자격이 제공하는 기능은 유지한다. 다른 매장 접근을 허용하지 않는다.
4. **관리자는 대상별 가능한 기능을 최소한으로 설정한다.** 사업이 생기거나 정책이 바뀔 때마다 메뉴·판정에 사업별 조건을 추가하는 방식을 피한다. 서버 실행 판정도 같은 기준을 따른다.
5. **경영자는 My Home에서 직원에게 허용한다.** 경영자에게 허용된 기능 안에서 직원 사용 범위를 정한다. 약사 전용 사용 확인도 경영자가 관리하며 별도 중앙 면허 검증 체계를 추가하지 않는다.
6. **기능 이용권과 협업체 전용 자료 권한을 구분한다.** 공통 도구를 쓸 수 있어도 가입하지 않은 사업의 경쟁력 자료까지 제공받는 것은 아니다. 복사 자료·탈퇴 후 이용은 계약 관리 원칙을 우선하며 복잡한 회수·복제 방지 체계를 추가하지 않는다.
7. **조회 실패는 미가입·0건과 다르게 표시한다.** 설정·가입·집계 확인에 실패하면 확인 불가와 재시도를 안내한다.
8. **직원에게 새 관리 업무를 만들지 않는다.** 짧은 숙지 자료·최소 입력을 사용한다. 별도 데이터 관리 담당자, 업무 배정, 교육 시험, 상세 상담 기록 체계는 요구하지 않는다. 공용 태블릿의 직원 전환은 후속 직원 초대 정비에서 판단한다.

## 7. 실제 사용 전에 구체화할 사항

| 구분 | 확인할 내용 |
|---|---|
| 사업 운영 | 사업자가 확인한 법정정보·사업별 약관 게시, 실제 가입·제공 기능 설정 |
| 매장 권한 | 경영자·유료 자격·무료 초대 직원, 복수 가입·탈퇴·권한 회수, 다른 매장 차단 |
| 고객 응대 | 주요 상품군·언어, 약사/직원 응대 흐름, 고객 화면 가독성과 실제 상품 자료 |
| 음성 | 실제 PC·태블릿의 마이크·스피커·소음·브라우저·언어별 인식/읽기 품질. Google API 도입은 점검 후 판단 |
| ERP 후보 | 사용할 수 있는 데이터와 표본, 가장 부담이 큰 업무, 분석·초안과 실제 실행의 경계 |
| 공급자 사업 | 서비스비 범위, 참여 약국의 활용 활동, 자료 책임·갱신, 제공할 성과 정보 |

실제 계정·현장 기기의 사용 검증은 자동 테스트나 합성 브라우저 확인과 구분해 기록한다. 새 데이터 연계나 상담 데이터 보관은 이 문서만으로 허용하지 않는다. 소비자 판매·결제는 기존 O4O 경계를 따르고, 공급자→약국 B2B 주문과 구분한다.
