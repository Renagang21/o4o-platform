# 인증 개편에 따른 약관·개인정보 처리방침 변경 검토안

상태: DRAFT · 작성일: 2026-10-10 · 게시/시행일: 승인 후 확정

연결 WO: [인증·명시적 연결](../work-orders/WO-O4O-AUTH-KAKAO-AND-EXPLICIT-LINK-V1.md).
이 문서는 검토안이며 현재 게시된 v1, 정책 DB, 동의 버전과 보유기간을 변경하지 않는다.

[인증·서비스 가입 정본](../baseline/O4O-NETURE-AUTH-AND-SERVICE-MEMBERSHIP-V1.md),

## 이용약관 대체 문구 제안

적용 범위·회원 가입 조항에 다음 내용을 반영한다.

> 본 약관은 O4O 공통 계정 및 위 서비스의 이용에 적용됩니다. 계정 생성과 각 서비스의
> 이용 승인은 구분됩니다. 서비스별 신청·승인 및 업무 권한에 따라 이용 가능한 기능이 달라집니다.
> 회원은 이메일과 비밀번호, Google 또는 카카오 인증으로 로그인할 수 있습니다.
> 공통 계정 생성에는 이메일, 이름과 개인 휴대전화가 필요합니다. 휴대전화 본인 인증은 수행하지
> 않으며, 필요한 경우 이메일 소유 확인을 요청합니다. 외부 계정의 이메일이 같다는 이유만으로
> 계정을 합치지 않습니다. 로그인한 회원이 계정 연결을 명시적으로 요청하고 해당 외부 계정의
> 인증을 완료한 경우 로그인 수단을 연결할 수 있습니다.

계정 관리 조항에는 다음을 제안한다.

> 로그아웃은 현재 서비스 도메인의 해당 브라우저 세션에 적용됩니다. 비밀번호 변경·재설정 시에는
> 기존 세션이 폐기되어 다시 로그인해야 합니다. 로그인 수단 해제는 이후 로그인이 가능한 수단을
> 남기는 조건으로 제공됩니다. 전체관리자 인증에는 별도 정책이 적용됩니다.

두 O4O 회원 계정 자체를 통합하는 기능을 약속하지 않는다. 같은 이메일의 Google·카카오 연결은
회원의 명시적 요청·재인증·중복 연결 검증을 거친 로그인 수단 추가다.

## 개인정보 처리방침 변경표

| 항목 | 확인한 코드·정책 사실 | 제안 |
| --- | --- | --- |
| 회원 가입 | 공통 이메일·이름·개인 휴대전화, 비밀번호 가입 수단 | 수집 목적을 계정 생성·연락·인증으로 구분하고 비밀번호는 인증 정보로 설명 |
| Google 인증 | google-identity.service.ts가 서명·issuer·audience·만료·sub 및 이메일/확인 여부 검증 | 외부 사용자 식별자와 이메일/확인 여부 처리 설명 추가 |
| 카카오 인증 | kakao-identity.service.ts는 code 교환 후 user/me의 id·이메일·확인 여부만 반환; provider token 저장 없음 | 카카오 식별자·이메일/확인 여부 설명 추가. 이름·전화번호를 카카오에서 받는다고 쓰지 않음 |
| 계정 연결 | linked_accounts의 provider/providerId로 연결; 이메일 자동 병합 없음 | 연결·해제 목적과 회원 명시적 요청 절차 설명 |
| 서비스 승인 | 계정 인증과 서비스 membership/업무 권한 별도 | 가입·승인 신청 때 받는 업무 정보를 공통 인증 수집과 구분 |
| 보유·파기 | 보유기간 정본 §15; 자체 탈퇴 및 미디어 탈퇴 자동 삭제에는 미구현 경로 존재 | 현행 기간 유지. 실제 지원하지 않는 자동 파기를 확정 문구로 추가하지 않음 |

처리방침 인증 항목 문구 제안:

> Google 또는 카카오로 인증하는 경우 외부 서비스의 사용자 식별자, 제공되는 이메일 및 이메일
> 확인 여부를 처리하여 본 서비스 계정을 인증하고 요청한 로그인 수단을 연결합니다. 공통 계정의
> 이름과 개인 휴대전화는 가입 화면에서 입력받습니다. 이메일 주소 일치만으로 기존 계정을
> 자동 통합하지 않습니다. 인증 코드와 토큰은 인증 처리에 사용하며 문서·화면의 오류 안내에
> 노출하지 않습니다.

이 문구는 외부 서비스가 반환하는 원본 응답 전체의 저장을 의미하지 않는다.
Google/Kakao 제공자와의 데이터 이동을 개인정보 제3자 제공·위탁·국외 이전 중 무엇으로
설명할지는 아래 검토 후 확정한다. 공급자 인증 흐름만으로 법적 분류를 단정하지 않는다.

## 결정·검토가 필요한 항목

1. 위 서비스 목록과 약국 협력사업·전체관리자 용어 승인.
2. 필수 이름·개인 휴대전화의 목적 및 필수 수집 근거 승인(휴대전화 본인 인증 없음 명시).
3. Google·카카오 데이터 이동의 법적 분류, 실제 제공자 계약·처리 위치·필요 고지 확인.
4. 현재 처리방침의 처리자·담당자·연락처가 운영 주체와 맞는지 확인. 기존 공개 원문을 참조하며
   이 검토안에 실제 담당자 개인정보를 복제하지 않는다.
5. 시행일·게시일·새 버전 확정. 현행 약관의 일반 변경 7일/중요 변경 30일 사전 고지 조항 검토.

## 화면·게시 실행 순서

- 정책 링크를 입력/체크박스에서 분리하고 새 창에서 읽도록 유지한다. 회원 입력을 잃지 않는다.
- 본문은 제목·조항·단락을 구분하고 PC·모바일에서 읽기 쉬운 폭과 간격을 확인한다.
- 카카오 자체 동의 화면은 개발자 콘솔 설정으로 별도 확인한다. 서비스 웹 수정으로 제공자 화면까지
  변경됐다고 판단하지 않는다.
- 승인된 본문과 시행일을 새 정책 버전으로 등록한다. 기존 version/document/hash 동의 기록은 보존한다.
- alias 도메인의 Neture 정책 조회 및 약사회 별도 정책을 확인한다. 로그인·가입·변경 고지와 필요한
  재동의 gate를 PC/mobile로 검증한다. 검토안 push가 정책 게시를 의미하지 않는다.
