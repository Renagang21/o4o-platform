## 0. 사용자 결정 (2026-10-25)

**‘상담 원문 없이, 확인한 상품·컨텐츠와 업무 결과를 재사용’**한다. 개인/매장별 상담 원문 이력이나 직원 간 대화 검색을 새로 만들지 않는다. 확인한 안내는 기존 상품 설명·다국어 컨텐츠 편집기에서 명시 저장/발행하고 기존 QR·태블릿·사이니지 적용 이력으로 재사용한다. 여러 매장의 고객 대화를 자동 합치거나 학습 자료로 전환하지 않는다.

전문 판단 지원의 질문·직접 넣은 전문 참고자료·AI 초안은 현재 상담 화면에서만 사용한다. 담당자가 확인한 고객용 문장만 기존 전달 입력에 넣으며 번역·고객 공유는 별도로 실행한다. 원문 상담을 공통 개인 AI 이력·Task·Memory에 저장하지 않는다. 장기 저장을 추가하는 별도 API·schema는 이번 선택에 필요하지 않다.

## 1. 먼저 유지할 현재 계약

현재 한국어/다국어 상담은 독립 직원 화면과 고객 화면을 사용한다. 매장 한 기기에서는 직원 확인 뒤 고객용 dialog를 보여주며, 매대 두 기기에서는 자리별 현재 상담만 전달한다. 관리 화면·개인 채팅을 고객에게 공개하는 구조가 아니다.

| 데이터 | 현재 저장·전달 범위 | 권한·종료 |
|---|---|---|
| 직원의 입력·방향별 번역 초안·선택 상품 | 현재 화면 메모리. 상담 문장·음성 파일을 Local/Session Storage에 저장하지 않음 | 계정/매장/모드 변경·새 상담·pagehide 때 비움. 언어 수정은 입력/상품 선택을 보존하고 이전 결과를 무효화 |
| 현재 기기 간 상담 | `store_consultation_stations`의 매장/자리당 1행. 담당자·epoch·마지막 준비 결과·공유 안내·미확인 답변 | 현재 매장 접근·기능·개별 허용·약사 사용 확인을 기존 서버가 판정. 종료/새 세대에서 본문을 비움 |
| 고객 기기 연결 | 브라우저에는 별도 capability 토큰, 서버에는 해시 | 직원 로그인·매장 선택과 분리. 고객 요청에 직원 cookie/Bearer/조직 header를 보내지 않음 |
| 게시 상담 자료 | 현재 매장의 활성 상품과 연결된 공개 키·비보관 그룹의 게시 페이지 | 게시/상품 상태를 준비·공유·고객 조회에서 재확인. 직원 확인 전 고객에게 자동 전달하지 않음 |
| AI 사용 metadata | 기존 정책·회계 runtime의 actor/모델/토큰/상태/추정 비용 | [보존 정본 §8](../baseline/O4O-PRIVACY-DATA-RETENTION-POLICY-V1.md#8-ai-사용기록-ai_usage_logs)의 1년. 원문 상담의 보존기간으로 확대하지 않음 |
| 공통 개인 AI 질의 이력 | `ai_query_logs`: 사용자 ID 기준 질문/응답/문맥 저장·조회 경로 | 매장별 이력 API가 아님. 현재 상담 원문/매장 비공개 자료를 이 경로에 연결하지 않음 |

담당 화면 응답이 90초 이상 없으면 고객 조회는 대기 상태를 반환한다. 새 정리 job은 같은 연결 만료 기준을 사용해 현재 전달 본문·미확인 답변·연결 코드를 비우고 active를 해제하며 epoch를 교체한다. 기기 해시·자리와 저장된 업무 자산은 유지한다. 60초 주기·회당 최대 200행·잠긴 행 건너뛰기로 동시 heartbeat를 보호하며 대량 적체는 여러 회차에 나누어 처리한다.

**job 자체의 기본 실행은 dry-run이며 운영 자동 파기가 활성화됐다는 의미가 아니다.** 후속 [배포 연결 TODO](../work-orders/TODO-O4O-STORE-CONSULTATION-CLEANUP-DEPLOYMENT-V1.md)는 기존 API 배포에 `CONSULTATION_STATE_CLEANUP_MODE=apply`를 명시하고 현재 중지 값을 보존한다. main/배포 전에는 활성화 완료가 아니며 통합 담당자가 적용/관측 결과를 확인한다. `CONSULTATION_STATE_CLEANUP_ENABLED=false`로 중지한다. job은 시작 시와 프로세스가 실행 중인 동안 timer로 확인하므로 Cloud Run scale-to-zero/CPU 중지·batch 적체까지 포함한 90초 내 물리 파기 SLA는 보장하지 않는다. 이 기준은 현재 화면 전달 상태의 정리 기준이며 백업·다른 저장 자산의 보존기간이나 AI 사용 metadata 1년을 바꾸지 않는다. 명시 종료/다음 상담에서 본문을 비우는 기존 계약도 유지한다.

근거: [약국 설계 §15-8](DESIGN-NETURE-PHARMACY-STORE-COMMERCE-V1.md#15-8-내-매장-상담다국어와-현장-실행-2026-10-24-사용자-확정), `services/web-store/src/pages/pharmacy/useConsultationDrafts.ts`, `consultation/CustomerConsultationPage.tsx`, `apps/api-server/src/modules/neture-pharmacy/services/consultation-stations.ts`, `apps/api-server/src/controllers/ai/AiQueryController.ts#getHistory`, `apps/api-server/src/services/ai-query.service.ts#getUserLogs`.

## 2. 직원 접근 해제와 매장 전환

기존 [매장 접근 정본](../baseline/O4O-STORE-ACCESS-AND-MEMBERSHIP-V1.md)은 현재 Role와 활성 직원 관계를 매 요청 재확인한다. 직원 접근 해제는 해당 매장에 적용하며 다른 매장의 관계까지 회수하지 않는다. 이번 작업은 이 인가 계약을 바꾸지 않는다.

이번 사용성 수정은 서버의 401/403을 받은 상담 연결 hook이 현재 room·연결 코드와 늦은 응답 세대를 해제하도록 한다. 부모 화면은 연결 상실을 확인하면 입력/준비 결과/음성을 비운다. 일시적인 503·네트워크 오류에서는 현재 상담과 입력을 유지하여 재시도할 수 있게 한다. 종료 작업의 실패와 heartbeat 실패는 분리하여, 정상 heartbeat만으로 종료 실패 안내를 지우지 않는다.

이는 서버 거부 이후의 화면 정리다. 이미 표시된 한 기기 화면을 오프라인에서 즉시 회수하거나 모든 브라우저 캐시를 원격 삭제한다는 보장이 아니다. 운영 권한 회수·복수 매장 격리는 실계정으로 별도 확인해야 한다.

## 4. 상품 근거 → 상담 → 고객 안내의 연결 순서

최근 반영된 [상품설명서 전문 판단·AI 활용 원칙](../guides/products/O4O-PRODUCT-DESCRIPTION-PROFESSIONAL-USE-POLICY-V1.md)의 이용 목적·상품 근거·전문 근거 입력을 재사용한다. 목적별 편집기나 AI provider를 새로 복제하지 않는다.

1. 현재 매장 상품을 선택하고 사용할 수 있는 자료·출처·검수 상태를 확인한다.
2. 상품 고유 사실, 전문 참고정보, 판단 지원, 고객 설명을 구분한다. 근거 있는 전문 정보를 의료 영역이라는 이유로 일괄 제거하지 않는다.
3. 필요한 확인 하나를 받고 짧은 첫 결과를 제시한다. 전문인 판단 지원과 고객에게 전달할 내용은 각각 확인한다.
4. 담당자가 확인한 고객 안내만 고객 언어/화면 또는 기존 태블릿·QR·사이니지 적용 흐름으로 전달한다. 미리보기·AI 결과가 게시/적용 승인을 대신하지 않는다.

새 판단 지원 Extension은 상품 사실/전문 참고/확인할 질문 최대 하나/고객용 초안을 구분한다. 모든 설명의 출처 ID와 인용 자료에 없는 수치를 검증하고 상품 사실에 전문 일반 자료를 섞어 확정하지 않는다. 호출 후와 고객용 초안 사용 전 현재 권한/게시 자료 버전을 다시 확인한다. 이는 근거 정리와 검토 초안이며 실제 약사 언어/전문 품질 검수의 완료를 뜻하지 않는다.

상품 편집에서는 기존 저장 원문을 확인해 현재 초안에 추가할 수 있다. 확인/삽입/저장/발행을 분리하고 기존 입력을 보존한다. 기존 ProductDescriptionAssist의 목적·상품 근거·전문 자료 항목도 재사용한다(외부 AI 복사/붙여넣기 보조이며 자동 유료 호출이 아님). 기존 QR 설명서의 공식 지식 기반 채택은 여전히 판정 보류다. 작성 세션의 근거를 영구 공식 DB로 승인했다고 표시하지 않는다.

O4O 취급 상품 원문은 기존 `storeDescriptionApi.list`의 `canonical` 매장용(STORE) 설명만 사용한다. 다국어 안내 페이지의 `published` 상태와 구분하며 요청 언어 → 한국어 → 첫 원문 순으로 선택한다. 원문 확인/편집기 삽입이 원본 설명서 변경이나 새 안내의 저장·발행을 대신하지 않는다.

다국어 편집의 한국어 첫 원문은 상품 설명 작성으로 준비한다. 다른 언어는 기준 본문이 없어도 결과 언어 지시를 유지하는 번역/현지화 prompt를 사용한다. 기준 본문이 있으면 그 원문/언어를 전달한다. 모든 결과는 현재 언어 초안에만 반영하며 자동 저장·발행하지 않는다.

저장·발행된 안내에서 기존 매장 QR 편집기로 이동할 때 scope/자료 ID/언어만 전달하고 원문이나 비밀 토큰을 router state에 넣지 않는다. 그룹 상태와 이미 발급된 공개 QR 주소를 조회해 연결 입력만 채운 뒤 사용자가 ‘QR 저장’을 누른다. 태블릿/사이니지는 기존 관리 탭에서 미리보기·선택·적용을 거친다. 태블릿 되돌리기는 현재 할당을 다시 확인해 예전 작업이 새 선택을 덮어쓰지 않게 하지만 다른 작업자와의 원자적 CAS를 새로 제공하지는 않는다.

## 5. 정본 정합과 실제 검증의 남은 범위

보존 정본 §8에는 `ai_query_logs`가 당시 미사용이었다는 운영 상태 설명이 있다. 최신 코드에는 `/api/ai/query`의 질문/응답 저장과 `/api/ai/history`의 사용자 기준 조회가 연결돼 있다. 코드 연결은 확인했지만 현재 운영 row 수·실제 이용량·보존 집행 상태는 조회하지 않았다. 과거 운영 수치를 현행 사실로 복제하지 않으며, 개인정보/공통 AI 담당이 현재 사용 상태·처리방침 정합을 확인할 후속 항목으로 인계한다. 이번에 개인정보 정본이나 공통 저장 동작을 임의로 바꾸지 않는다.

실제 마이크·현장 소음·약사 언어 검수·provider 응답 품질/비용·권한 회수·물리 QR/기기 재생은 브라우저 합성 검증과 구분한다. 특히 운영 상담의 준비·공유·기기 pairing은 업무 상태를 기록하므로 읽기 전용 로그인 승인만으로 실행하지 않는다.
