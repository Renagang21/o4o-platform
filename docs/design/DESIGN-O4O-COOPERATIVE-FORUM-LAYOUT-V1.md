## 화면 트리

```text
연합회 /
├─ 연합회 홈·소개 /about
├─ 소속 협동조합 /cooperatives
├─ 내 협동조합 /cooperatives/mine
├─ 내 처리 소식 /cooperatives/updates
└─ 연합회 운영 /operator [연합회 담당자]
   ├─ 산하 조합·가입 심사 [기존 조합별 admin 지정 포함]
   ├─ 연합회 운영자 관리 ?work=operators [연합회 admin]
   └─ 홈 화면 편집 /operator/home-presentation

개별 협동조합 /{slug}
├─ 조합 홈
│  ├─ 본문: 주요 소식·자료(진열 순서 최대 3건)
│  ├─ 본문: 최근 조합원 이야기(최대 5건)
│  └─ 보조: 내 참여 상태·서비스·담당자 전용 운영 진입
├─ 조합 소식·자료 /materials
│  ├─ 운영자가 게시한 공식 소식·자료 목록
│  └─ 상세 ?item={content-id}
├─ 조합원 이야기 /community
│  ├─ 일반 포럼 목록·페이지 이동
│  ├─ 본문 ?post={post-id}
│  └─ 조합원 글쓰기
├─ 조합 서비스 /services
│  ├─ 기존 승인 제품·콘텐츠 진열
│  ├─ 기존 강의 서비스 링크
│  └─ 기존 내 매장 링크
├─ 가입·내 참여 /membership
└─ 조합 운영 /operator [해당 조합 담당자]
   ├─ 운영 개요
   ├─ 조합원 관리 ?work=members
   ├─ 소식·자료 관리 ?work=contents
   │  ├─ 자체 콘텐츠 작성·수정 /operator/contents/...
   │  └─ 공급자 자료 검토·승인·게시
   ├─ 조합원 이야기 관리 ?work=boards
   │  └─ 게시판 목록·개설
   ├─ 공급 제안 심사 ?work=proposals
   ├─ 가입 자격·운영자 설정 ?work=settings [조합 admin]
   └─ 홈 화면 편집 /operator/home-presentation
```

## 두 게시 공간의 의미

일반 포럼은 사업의 communityKey를 사용하고 조합원이 질문·경험을 게시한다. 운영자만 게시판을 개설한다. 공통 독립 커뮤니티 회원 원장을 추가하지 않는다.

운영자 게시 공간은 기존 `semi_franchise_contents`를 사용한다. 자체 작성 초안 → 게시, 공급자 요청 → 해당 조합 승인·게시 흐름을 유지한다. 일반 포럼과 별도 목록·상세를 제공하며 회원의 글쓰기 폼을 표시하지 않는다. 회원 조회는 기존 showcase API가 허용한 게시·노출 콘텐츠만 사용한다. 운영자 조회도 hidden 항목을 회원 화면에 표시하지 않는다. 본문은 기존 공통 콘텐츠 렌더러의 정제 경로를 따른다.

기존 API는 진열 순서와 최대 60개 항목을 반환하며 게시일·공지 분류·상시 고정 메타데이터를 제공하지 않는다. 따라서 이번 화면은 진열 목록의 content 항목만 표시하고 홈에는 앞 3건을 표시한다. 별도 공지 분류·검색·무제한 자료 전체 목록·고정 공지는 이번 구현에 포함하지 않는다. 일반 포럼 댓글·수정·삭제·중재 도구도 기존 후속 과제로 남는다. '조합원 이야기 관리'는 현재 게시판 개설 기능까지다.

## 배치와 접근

데스크톱 홈은 넓은 본문과 오른쪽 참여 안내를 배치한다. 대형 조합 Hero는 홈에만 표시하고 자료·포럼·운영 등 내부 화면은 간결한 조합 제목을 표시해 업무 본문을 앞에 둔다. 모바일은 본문 두 섹션 후 참여 안내를 세로로 표시한다. 운영 화면은 업무 메뉴와 선택한 업무 본문으로 나누며 모바일에서는 업무 메뉴가 줄바꿈된다. 운영 개요에서는 회원·공급·콘텐츠 관리 요청을 동시에 실행하지 않는다.

기존 `/materials`, `/community`, `/operator?tab=contents`, `?tab=proposals`와 콘텐츠 작성·편집 URL을 유지한다. 업무 탐색은 `work` 쿼리로 남겨 직접 진입과 브라우저 이동을 지원한다. 선택이 바뀌면 기존 작업 컴포넌트를 해제한다. 업무를 옮기기 전에 작성 중인 내용은 저장해야 한다.

조합 운영 메뉴는 해당 조합 담당자에게만 노출하지만 직접 URL의 기존 접근 검사도 유지한다. federation 역할·다른 조합 역할은 로컬 관리 권한이 아니다. 비회원 홈은 개인 회원 데이터 API를 요청하지 않는다. 가입·약사 자격·약국 조직·내 매장 권한을 새로 만들거나 합성하지 않는다. 개인 조합원은 소식·자료를 읽을 수 있으며 약국 사본 복사는 기존 내 매장의 별도 자격으로 처리한다.

## 변경 영향

변경은 `services/web-pharmacy-coop`과 이 작업 문서에 한정한다. 공통 운영 UI의 기존 허용 탭 인자에 한 개의 업무만 전달한다. 콘텐츠·공급 원장, 승인 API, shared 패키지, 의존성, DB, 배포 설정을 수정하지 않는다. 연합회·조합 Hero 편집과 기존 공급/콘텐츠 운영의 상세 흐름을 보존한다.
