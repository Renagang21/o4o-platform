## 2. 검수 질문 답변

### Q1. 공통 골격이 제품별 설명을 지나치게 비슷하게 만들지 않는가
**부분 통과.** 인정 기능성·보장균수 정의·CTA·표준 주의는 **의도적으로 동일**(§1-1). 반면 도입부 훅, "왜 이 제품인가" 5항, "이런 분께", 섭취 안내는 5건 모두 다른 문장이다.
- 남은 위험: `sd-core` 첫 카드("장 건강 기능성")의 첫 문장은 5건이 거의 동일하다. 이는 인정 기능성 문구를 그대로 써야 하는 제약의 결과라 **허용 가능**하나, 두 번째 문장(제품 고유 보장균수·기준량)에서 반드시 갈리게 유지해야 한다.

### Q2. 보장균수와 1일 섭취량을 정확히 구분했는가

> ## ❌ 정정 (2026-07-15, 20-pilot 20-D 소급 검사) — **이 항목의 원래 "통과" 판정은 틀렸다**
>
> 원래 본 절은 아래를 **"이번 파일럿의 최대 수확"** 으로 제시했다:
> ```text
> 락토핏    100억/포 × 1일 2회   = 1일 200억          ← ✗ 틀림
> 디노키즈  100억/포 × 연령별 1~3회 = 1일 100~300억    ← ✗ 틀림
> ```
> **원문에는 "1포당" 이 없다.** 실제 표기는 기준량 기준이고, **1포 중량은 표시사항에 없다**:
> ```text
> 락토핏   BASE "표시량(10,000,000,000(100억) CFU/4g)"  · SRV "1회 1포"      → 포 중량 미표시
> 디노키즈 BASE "표시량(10,000,000,000(100억) CFU/2g)"  · SRV "1회 1포"      → 포 중량 미표시
> 프로바   BASE "표시량(100,000,000(1억) CFU/2000mg)"   · SRV "1회 1포"      → 포 중량 미표시
> ```
> 즉 **"1포 = 기준량" 을 가정**한 뒤 락토핏은 거기에 ×2회를 곱해 **1일 200억**까지 도출했다. 4g 이 1일분(2포)이면 실제 1일 총량은 **100억** — **2배 오차**다.
> 이는 20-A 에서 김치생유산균(900mg = 450mg×2 = **1일분**)으로 **정확히 같은 함정을 잡아낸 것**과 동일 유형인데, 가드가 없던 5건 파일럿에서는 **함정에 빠진 채 "최대 수확"이라고 선언**했다.
>
> **정정 결과** — 3건(프로바·락토핏·디노키즈) 초안 ko·en 전부 수정: "1포당 N" · "1일 총 N" 삭제 → **표시 기준량만** 기술 + "1포 중량이 표시사항에 없어 1포당·1일 총 섭취 균수는 별도 확인 필요" 명시.
> 무변경 2건(듀오락 350mg · 뉴로랩스 340mg)은 **SRV_USE 에 캡슐 중량이 명시**되어 있어 원래부터 정확했다.
>
> **교훈**: 가드 없이 작성한 산출물은 **"검수 통과"라고 자신 있게 선언한 항목조차 틀릴 수 있다.** 자체 검수는 자기가 세운 가정을 검사하지 못한다. → [GROUNDING-GUARD-CHECKLIST §A](../../../content-authoring/GROUNDING-GUARD-CHECKLIST.md) 가 이 유형을 기계적으로 차단한다.

**정정 후 실제 상태**: 5건 중 **기준량 = 1회 섭취량이 확정되는 것은 2건뿐**(듀오락·뉴로랩스, 캡슐 중량 명시). 나머지 3건은 **1일 총량 산출 불가 → 미기재**.
```text
듀오락   10억/350mg  · SRV "1회 1캡슐(350mg)"  → 기준량=1회분 확정 → 1일 10억   ✅
뉴로랩스 100억/340mg · SRV "1회 1캡슐(340mg)"  → 기준량=1회분 확정 → 1일 100억  ✅
프로바   1억/2,000mg · SRV "1회 1포"           → 포 중량 미표시 → 총량 미기재
락토핏   100억/4g    · SRV "1회 1포" ×2회      → 포 중량 미표시 → 총량 미기재
디노키즈 100억/2g    · SRV "1회 1포" 연령별    → 포 중량 미표시 → 총량 미기재
```

### Q5. 각 제품마다 실제로 다른 선택 이유가 존재하는가
**통과.** 5건이 서로 다른 구매 사유로 갈린다 — 맛·간편(듀오락) / 가벼운 시작(프로바) / 최소 단위 고밀도(뉴로랩스) / 물 없이·분할(락토핏) / 연령별 기준(디노키즈). 모두 원문 사실에서 파생.
- 단, 듀오락(10억 캡슐)과 뉴로랩스(100억 캡슐)는 **제형이 같아** 차별점이 균수·용량 축에만 의존한다. 그룹 확대 시 캡슐 제품이 많아지면 이 축만으로는 반복될 위험 → §3 참조.

### Q6. 영어 설명에서 기능성이 확대되지 않았는가

### Q7. 이 방식으로 같은 그룹의 나머지 제품을 안정적으로 제작할 수 있는가
**조건부 가능.** 828건 중 **소비자 완제품 246건**에 대해서는 가능. 단 아래 3개 선결 조건이 있다.


렌더러는 900px↑에서 `sd-core`를 3열로 고정하는데 **초안의 `sd-item`은 2개**라 세 번째 칸이 비고 카드 폭이 좁아진다. **정본 예제(변엔장)도 `sd-item` 2개라 동일** — 초안 결함이 아니라 구조적 현상.

- **영향 제한적**: 주 소비 표면이 QR 모바일(폰 폭)·매장 태블릿/모달이라 대부분 1~2열 구간. 3열은 와이드 모달·태블릿 가로에서만.
- **채택 안 한 대안**: ⑴ `sd-item` 3개로 늘리기 → 근거 있는 세 번째 축이 없어 **창작(CR-007 위반) 위험** ⑵ 렌더러를 `sd-core:has(> :nth-child(3))` 조건부 3열로 → 디자인 시스템 변경이라 별도 WO + 기존 콘텐츠 전체 영향.
- → **렌더러 무변경 · `sd-item` 강제 추가 없음.** 그룹 확대 시에도 3열을 채우려고 근거 없는 카드를 만들지 않는다.
